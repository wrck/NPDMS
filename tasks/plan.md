# 项目实施交付管理平台 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在已确认需求规格基础上，建设以Yudao为技术底座、PMS为核心业务域的项目实施交付管理平台，先完成V1业务闭环，再交付V2效率能力，并为V3智能化演进保留数据和契约基础。

**Architecture:** 首期采用模块化单体，由`yudao-server`统一装配。基础骨架来自`yudao-boot-mini master-jdk25`，mini缺失的Yudao模块从`YunaiV/ruoyi-vue-pro master-jdk25`按需引入；新增业务能力归属`pms-module-*`模块。实施采用纵向切片，每个切片同时完成数据迁移、后端规则、API、权限、前端交互、自动化测试和真实浏览器验收。

**Tech Stack:** JDK 25、Spring Boot 4.1.0、Yudao revision `2026.06-jdk25-SNAPSHOT`、MyBatis Plus、Spring Security、Flowable/BPM、Redis、Vue 3、TypeScript、Element Plus、关系型数据库【待确认具体产品】。

## Global Constraints

- Markdown规格是唯一事实来源；实现必须保持`REQ → FR → BR/DR/API/NFR → AC → Test`追溯。
- V1、V2必须按详细规格实现；V3只定义范围和演进前提，不形成当前开发任务。
- Yudao平台接口的路径、请求、响应、鉴权和错误语义以上游平台为准。
- 新增PMS Business API执行`/api/v1/pms/...`及`{DOMAIN}-{RESOURCE}-{TYPE}-{SEQ}`契约规范。
- PMS模块统一使用`pms-module-*`命名；存在稳定跨模块调用时才建立`-api`契约模块，禁止空API模块。
- 禁止跨模块依赖目标模块`-biz`、Service、Mapper、Repository或直接访问其业务表。
- 项目组合与项目父子树分离；项目树和任务WBS均为非固定层级。
- 所有业务对象具备状态、版本、审计字段和逻辑删除语义；状态只能通过显式业务动作改变。
- 首期单租户运行，但表结构、权限上下文和接口契约保留多租户扩展能力。
- 首期响应式Web优先；移动端和桌面客户端不进入V1、V2实现范围。
- 后端核心规则单元测试覆盖率不低于80%；新增后端代码行覆盖率建议不低于70%。
- 普通查询P95不超过2秒，写操作P95不超过3秒，树全后代汇总P95不超过5秒。
- 不得用静态页面、编译通过、接口文件存在或API单测替代真实业务闭环验收。
- 不提交密码、设备凭证、密钥、生产连接信息或未脱敏数据。

## 7. V1：基础业务闭环

### IU-01：平台能力与PMS公共约束

**覆盖：** `FR-PLT-001`至`FR-PLT-011`。

**纵向结果：**

- 用户使用Yudao本地账号登录。
- 角色、组织、菜单、按钮、API和数据权限可以配置。
- BPM、待办、通知、文件、字典、审计和事件能力可由PMS模块复用。
- PMS公共对象具备租户、版本、逻辑删除和审计字段。

**关键契约：**

- Yudao平台接口保持上游定义。
- PMS权限标识、错误码段、文件引用和业务事件公共约定冻结。
- 项目层级权限、成员权限和对象创建人权限的合并策略可自动测试。

**检查点：**

- 未登录、无功能权限、无数据权限和越级访问均被服务端拒绝。
- 关键操作、文件下载、导出和权限变更产生审计记录。
- 同一事件重复投递不会产生重复待办和通知。

### IU-02：客户、项目、层级、WBS与设备主档

**覆盖：**

- `FR-PROJ-002`至`FR-PROJ-005`、`FR-PROJ-007`至`FR-PROJ-013`。
- `FR-RES-001`至`FR-RES-003`。

**纵向结果：**

- 创建客户、联系人和项目。
- 创建任意深度项目树和任务WBS，支持子树移动、拆分、合并和后代查询。
- 项目组合不与项目父子关系混用。
- 项目关联设备、序列号、版本和配置Log档案。
- 刷新页面后数据、层级、权限和版本保持正确。

**关键契约：**

- `pms-module-project-api`只暴露其他模块稳定依赖的项目、任务、阶段、成员和风险查询/命令。
- `pms-module-asset-api`只在工程、割接或服务模块存在稳定依赖时创建。
- 树数据使用`parent_id/root_id/path/depth/sort/version`，禁止固定层级字段。

**检查点：**

- 循环挂接、跨租户挂接、越权移动和版本冲突被拒绝。
- 10万项目基线下直接子节点查询P95不超过2秒。
- 500万任务基线下全后代汇总P95不超过5秒。

### IU-03：项目阶段、计划、团队、风险与门禁

**覆盖：** `FR-PROJ-015`至`FR-PROJ-017`、`FR-PROJ-019`、`FR-PROJ-021`、`FR-PROJ-026`。

**纵向结果：**

- 项目按类型选择阶段模板，不强制所有项目使用同一生命周期。
- 项目经理维护团队、阶段计划、实际时间、进度和风险。
- 阶段完成动作校验任务、交付件、问题、审批和前置阶段。
- 超期产生预警，项目全景显示当前阶段、风险和后续待办。

**检查点：**

- 阶段名称和标准顺序经业务负责人确认并写回规格。
- 状态不能通过普通编辑绕过动作和门禁。
- 项目回退、暂停、取消和重开均保留原因和历史版本。

### IU-04：工程准备与现场实施闭环

**覆盖：** `FR-ENG-001`、`FR-ENG-004`、`FR-ENG-005`、`FR-ENG-011`、`FR-ENG-013`、`FR-ENG-016`、`FR-ENG-018`、`FR-ENG-021`至`FR-ENG-024`、`FR-ENG-026`、`FR-ENG-027`。

**纵向结果：**

- 完成工勘、需求分析、业务接口规划和实施方案编制。
- 方案经过分级审核后形成不可覆盖基线。
- 完成资源就绪、到货、安装、配置、联调和实施问题整改。
- 阶段交付件自动归集并参与完成门禁。

**检查点：**

- 工勘或资源未就绪时不能进入受控实施动作。
- 方案审核前后版本可追溯，客户导入数据不会覆盖已基线版本。
- 安装、配置、联调记录与项目、任务、设备和责任人关联。

### IU-05：割接准备、执行、回退与观察

**覆盖：** `FR-CUT-001`至`FR-CUT-006`、`FR-CUT-008`、`FR-CUT-009`、`FR-CUT-011`至`FR-CUT-014`。

**纵向结果：**

- 从项目、任务或授权入口创建割接任务。
- 完成类型、组网、风险、信息采集、等级评估、方案和评审。
- 执行过程实时记录检查项、操作者和时间。
- 异常时停止或回退，正常时进入稳定观察并关闭遗留项。
- 结果归档并回写项目、任务、设备和交付件。

**检查点：**

- 不适用割接的项目不会被强制进入割接阶段。
- 未通过评审、超出时间窗或无权限时不能开始执行。
- 回退不会造成部分状态提交，执行证据和审计完整保留。

### IU-06：在线/离线巡检与整改闭环

**覆盖：** `FR-SRV-001`至`FR-SRV-004`、`FR-SRV-006`至`FR-SRV-009`、`FR-SRV-011`、`FR-SRV-012`、`FR-SRV-018`。

**纵向结果：**

- 从项目、设备或服务计划创建巡检任务。
- 选择在线或离线方式，校验连接账号和规则版本。
- 在线执行反馈状态；离线文件解析为结构化结果。
- 生成巡检报告，人工确认检出问题并下发整改待办。
- 按确认规则关闭巡检，更新设备维保状态。

**检查点：**

- 设备凭据不进入普通业务表、日志或前端响应。
- 同一原始文件重复上传不会生成重复结果。
- 报告、问题、待办、设备和项目之间可双向追溯。

### IU-07：验收、归档、项目闭环与维护移交

**覆盖：** `FR-ACC-002`、`FR-ACC-004`至`FR-ACC-006`、`FR-ACC-009`、`FR-ACC-010`。

**纵向结果：**

- 收集电子完工证明，完成初验和终验。
- 自动检查交付件完整性并形成不可覆盖归档版本。
- 通过闭环审批将项目从实施状态转入已闭环或维护中。
- 资产、遗留问题和服务责任移交到维护视图。

**检查点：**

## 12. 风险与缓解

| 风险 | 影响 | 缓解措施 |
| --- | --- | --- |
| 双上游提交虽版本号相同但文件存在差异 | 构建失败或运行时不兼容 | 共享文件以mini为准；扩展依赖只提取最小兼容补丁并记录来源 |
| 当前仓库无代码基础 | 计划中的文件和命令无法立即验证 | CP-01、CP-02先建立可运行基线，业务任务不得提前 |
| 数据库产品未确认 | SQL、索引、树查询和测试方案不稳定 | PD-003确认后才创建业务迁移 |
| 项目与任务非固定层级且数据量大 | 查询、移动和权限继承性能风险 | IU-02优先实现并进行容量测试，失败则在后续模块前调整模型 |
| 权限同时涉及组织、区域、项目树和成员 | 越权和缓存失效风险 | 权限策略服务端集中校验，子树移动触发继承重算和缓存清理 |
| BPM与业务状态机双重状态 | 状态不一致和重复审批 | 业务状态为领域权威，流程实例保存关联键，通过动作服务统一提交 |
| 145项V1/V2 FR范围较大 | 水平铺开后无法形成可验收闭环 | 按IU纵向交付，每个检查点要求可运行旅程 |
| 外部系统边界未确认 | V2集成返工 | 先稳定内部数据所有权，集成任务在权威源确认后启动 |
| 客户签字和设备凭据涉及高敏感数据 | 合规和泄露风险 | 法务/安全确认前不实现正式签署或真实设备凭据托管 |
