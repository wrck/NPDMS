# 通用数据迁移与同步

本模块按本任务批准的专项计划实施。已完成测试库 EHR 接管和无变化同步的真实运行验收，不代表全部专项验收通过、生产可用或 INT-01/INT-05 整体完成。

## 实现边界

- 执行基础使用 Spring Batch 6.0.4（当前 Spring Boot BOM 管理），调度使用现有 Quartz；任务配置与业务执行结果归 INTEGRATION。
- MySQL 连接引用 INFRA 数据源配置；密码使用既有加密存储，连接写请求关闭参数日志。
- 来源留存、迁移分类和问题证据通过 PLATFORM 的公开迁移 API，持续身份与检查点保存在本模块。
- 业务适配器位于 integration-api；首个生产适配器为 EHR 公司/部门，测试适配器验证独立业务对象接入。
- SYSTEM 的公司和部门实体、原 Service、原页面均不改写。通用并发协调和受管删除保护通过新增继承重载服务实现，归属元数据独立保存，不继承或扩展公司/部门实体。
- 公开组织接口复用原实体，不按方法参数列举全部业务字段。受管字段仍按 Owner 规则写入，不执行无条件全字段覆盖。
- 前端使用 Frontend UI Engineering，沿用 Vue 3/Element Plus。四个入口为连接、任务、运行和映射。

PRD 参考：12.2.2 集成一致性总则、INT-01 的游标与对账机制、INT-05 的来源隔离与最近有效快照。EHR 本次授权不覆盖 LDAP/AD 已映射组织，不包含人员、认证或通知接入。

## 配置与行为

1. 经授权的管理员创建/引用 MySQL 连接，再创建任务或使用 EHR 模板。
2. 支持表/视图与结构化筛选，或单条只读 SQL；使用已有 JSqlParser 与 Spring JDBC 参数绑定。
3. 任务保存后暂停；完整预览成功后才能启用调度。预览不是业务提交。
4. 同步读取完整来源后，在本地事务内调用业务适配器，提交业务、来源映射、检查点和成功结果；失败不推进检查点。
5. 增量窗口由连接器统一添加，默认重读 300 秒并周期全量对账；只有完整快照可以处理消失记录。
6. EHR 显式失效映射为停用，NULL 表示未失效；消失保留停用，重新出现沿用目标 ID。
7. 已存在的组织必须显式接管：校验编码、名称、启停、排序和父级，禁止仅凭 creator 或同名接管。
8. 来源身份已建立映射后不能直接替换连接、源主键列或适配器，防止旧身份被静默重解释。同租户“来源系统＋适配器”保持唯一；配置预检返回已有任务 ID 和名称，页面提供“打开已有任务”，不再以改名新建作为处理入口。新增时的数据库唯一键竞争返回明确的任务冲突，不包装为来源连接失败。
9. 调度使用统一 Handler dataSyncDispatchJob；批次执行由 Spring Batch JobOperator 管理，缓存刷新失败作为提交后的待补偿处理。
10. 2026-09-14 需求方补充批准：基础平台同步字段仍允许人工修改并保存，下次同步按上游字段覆盖；不复制或替换原公司/部门页面。人工修改仍经过原有唯一性、父级及适用版本校验。负责人、电话、邮箱等非同步字段保留，受管组织删除保护不变。
11. 2026-09-14 补充：来源对象可配置 `syncPrimaryKey`，默认关闭；开启后目标物理 ID 必须与源主键一致。首个适配器支持规范的正整数 Long，不将字符串、溢出值或有损转换当作有效 ID。复用原实体与 MyBatis-Plus 指定 ID 插入；主键/编码冲突失败而非自动换号。已有映射的源目标主键一致时可启用，关闭不重新编号；不一致时可在原任务选择下述截断重建或仅重置映射，不再笼统提示“新建任务”。此选项不是新的主键游标增量模式。
12. 需求方明确选择业务适配器加载，不建设任意目标表写入器。`loadingMode` 支持 `INSERT_ONLY`（追加，已存在整批报错）、`INSERT_IGNORE`（新增并跳过已受管记录）、`UPSERT`（默认新增并更新同步字段）。适配器声明支持列表；跳过不改写业务版本或既有映射，不绕过租户、归属、字段和关联校验，未受管组织仍需显式接管预检。上游缺失仍按独立缺失策略处理。
13. 同步前阶段沿用配置/连接检查、来源读取转换与业务预检，目标写事务仅在读取完成后开启。不新增任意执行脚本、不关闭约束、不使用原生 `REPLACE INTO`。
14. 需求方明确批准“清空目标公司的全部记录和目标部门的全部记录”：`clearBeforeLoad` 清理当前租户全部公司、部门（含非任务受管与逻辑删除行），不是只清理当前任务数据。通过 SYSTEM 公开组织接口在本地事务内执行 DELETE 后重建，不使用不可回滚且无租户条件的 TRUNCATE。旧实体及清理动作进入运行结果；历史批次和来源证据不删除。同步归属、同目标适配器映射一并清理；其他受影响任务暂停、作废预览与检查点。任何写入或成功证据失败整批回滚，跨租户主键冲突不能覆盖其他租户。
15. 需求方随后批准“不截断表，清除主键映射，追加更新”：`resetMappingsBeforeLoad` 仅重置当前任务的持续映射，保留全部目标组织及其他任务/租户映射。全部对象开启源主键同步，以 UPSERT 调用原业务校验与写入；目标 ID 必须等于源主键。旧目标不改号、不同主键的旧记录不被删除；同编码不同主键仍冲突，不能靠清映射绕过编码唯一性。旧映射中的消失项保留、不停用。完整预览不清映射；正式提交才将旧映射删除、新映射、业务写入及检查点一起提交，失败恢复旧映射。清空目标与仅重置映射互斥。
16. 两种准备操作均默认关闭、须完整快照、拒绝全空来源；先完成当前配置版本的完整预览，再手动确认执行（`confirmPreparation`，执行权限＋现有受控接管权限），不允许自动调度/自动重试。成功后关闭准备选项、重新预览，可恢复常规周期同步。截断额外检查 SYSTEM 用户/授权/角色部门范围、PROJ 项目/组织关系/成员历史引用和 BPM 已部署流程部门引用；各 Owner 通过新增 `OrganizationClearGuard` SPI 自查，无跨模块查业务表。动态部门/表达式审批不能自动证明无引用时阻止截断，需流程管理员处理。实际截断需在停止新增业务引用的维护窗口执行，本增量不改写其他 Owner 原写入口，不宣称全平台并发引用创建已被统一锁定。

页面/API：/data-integration/workspace；/api/v1/pms/integration。
