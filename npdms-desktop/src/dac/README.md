# DAC native foundation

Baseline: wrck/NPDMS d4f6918d67c3f5b32559d7eba6deb6e9a847858a. These CommonJS modules use Node built-ins only. No module starts Java at import time or performs network calls. Tests use injected fake children and probes, never actual DAC.

- `protocol.cjs`: exact native connect URI parsing, environment validation, cryptographic nonce generation, and protocol-v3 Ed25519 READY verification. Caller MUST supply the trusted installation public key and expected instance from protected runtime metadata; never trust discovery to establish its own public key. Native connect tenant IDs remain strings to avoid precision loss.
- `key-vault.cjs`: fail-closed interface for a real Linux OS key vault adapter. The sibling `../key-store.cjs` provides an Electron safeStorage-backed Linux adapter, but real keyring integration has not yet been exercised. There is no plaintext/basic_text fallback. Adapter must implement availability, read, atomic createIfAbsent, return 32-byte Buffers, and enforce its own access controls. `create:true` is only for a proven fresh installation. Existing data with a missing key must enter recovery, never silently generate a replacement. Caller wipes returned key after passing it to launch. Do not expose key to renderer or logs.
- `supervisor.cjs`: controlled Java25 launch, inherited injection-variable scrubbing, loopback ports 8280–8289, exit98-only retries, injected exclusive lifetime lock and signed readiness probe, and owned-child SIGTERM. A hung process retains the lock; there is intentionally no unknown-PID kill or forced takeover. It does not install services or launch automatically.

- `probe.cjs`: concrete protected runtime-file and bounded loopback HTTP readiness reader. It checks process metadata, no-follow file reads, permissions, response shape, timeouts and cancellation; the supervisor still verifies the pinned signature. Tests inject HTTP, so real Linux network/process integration remains untested.

## Main-process runtime wiring

`linux-lock.cjs` now supplies `createLinuxLockHost()` with a util-linux flock-based `acquireLock` and child `spawn` adapter. The inherited file descriptor retains the exclusive lock across retries and parent crash until the owned child exits. This was proven with small Node children, not a Java/DAC runtime. `acquireLock(dataDirectory)` must atomically obtain a real cross-process exclusive lifetime lock, returning a release callback. It must fail if another writer owns the database; no stale-file unlink heuristic. `probe({child,port,nonce,signal})` must fetch only the fixed loopback status path with the nonce and honor AbortSignal. Return `{pid,instanceId,status}` only after reading the protected runtime properties file and matching its PID to the actual spawned child; do not obtain instanceId/PID merely from an untrusted HTTP response. Supervisor cryptographically verifies status against configured publicKey. Runtime file should be cleared or generation-fenced before launch; never regard stale metadata as proof. Bound response sizes/timeouts and never follow redirects. Caller must validate bundled Java/JAR/parser integrity and provision protected directories before start.

`identity.cjs` now provides authenticated read and fresh-install-only atomic provisioning in the exact Java DesktopIdentity format. Existing identity corruption or key mismatch remains blocked. Its compatibility was checked against baseline source and cryptographic fixtures, not by launching Java.

`runtime.cjs` composes the adapters behind explicit start/stop IPC from the trusted local shell. It validates the real package-builder schema and every DAC payload file before accessing keys, binds private storage to the exact server environment, acquires the lifetime lock before key/identity operations, and rejects incomplete recovery rather than regenerating credentials. Status is read-only. Only fixed states/reasons, control availability, and READY public pairing code/port leave the coordinator. The main process retains the control window if bounded shutdown leaves a live or uncertain owned lease. Runtime and main/DOM tests use synthetic child/HTTP/keyring adapters, not a running Java service. Real Linux keyring integration, initial web pairing and package installation are not claimed complete.

Persist the independent DAC H2/identity/outbox in a DAC-specific per-environment directory (baseline SHA256 of normalized server URL). Preserve data and stable master key on updates. Bundle platform-specific Java25 and parser release device-command-output-1.4.0. Windows DPAPI/WinSW and jdk.crypto.mscapi are not Linux dependencies. Do not use local-debug authentication.

Every protected DAC desktop operation still resolves an NPDMS ticket online with exact configured HTTP(S) Origin. file:// and custom application origins are not supported by the baseline. Main-process mediation must preserve original authorization, not disable CORS/security checks. New offline collection is unsupported. Accepted tasks may continue offline and deliver the same immutable result after reconnection. Even task reads and connection listings require online ticket resolution. Generic APIs and actuator are denied under desktop profile; use signed status for readiness.

Source contracts: device-ops-platform/device-ops-server/src/main/java/com/dp/plat/deviceops/server/desktop; packaging/windows/RuntimeHost.cs, ClientConfiguration.cs, Launcher.cs; scripts/package-dac-desktop.ps1.

The current actual staged resources report `blocked / DAC_RESOURCES_MISSING`, with start disabled and no data directory, key, lock or process created by the status check. Main-process service controls do not by themselves implement the Vue native connection and operation bridge; that separate integration must retain the server challenge, pinned identity and online ticket verification.
