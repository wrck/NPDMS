# 割接高置信输入对照审查（过程材料）

## 审查边界

- 高置信割接输入：`需求/割接0807需求分析报告.md`。
- 原始结构化证据：`需求/售后平台（割接+巡检）/1、割接平台/4、割接平台设计-数据整理（0807).xlsx`。
- 对照对象：PRD V1.7 第十章、CUT领域规格、SDS Phase 1/2、P3-E09当前DDL及迁移契约。
- 用户后续明确决策优先于0807输入：项目是同一平台核心数据；设备连接与采集由现有平台/子应用承接，本平台只负责凭证、下发、回调；已确认排除或后置内容不得无端进入当前表结构或迁移表。
- 本轮只审查，不修改正式基线。

## CLAIM

当前 CUT-11 不是0807割接需求的正确细化，而是把原WO-06工单状态机迁入CUT领域；它污染了割接领域模型、状态机、权限、追溯和P3-E09 DDL。正确方向应以一个 CutoverTask 主流程为核心，把保障人员安排作为割接方案/任务的从属事实，审批通过后生成待办或通知，不另建“派单—接管—转单—挂起—关闭”的保障工单聚合。

## 二、确定性偏差

### C-01 CUT-11错误继承原工单语义

- 0807报告没有“独立割接保障任务”需求；“割接任务是否支持挂起/暂停/转派”仍列为待确认。
- 原始Excel只定义：方案中维护保障人员安排（角色、姓名、任务描述、联系电话、到位时间）；审批通过后推送保障任务。
- 当前PRD却声明“原WO-06完整迁移”，新增服务经理派单、接管、转单、挂起、恢复、关闭、责任区间、状态机版本等完整工单语义。
- 用户裁决（2026-08-14）：CUT-11就是把工单语义整体搬入割接，无需继续确认；该需求整体后置并纳入工单领域，不再归属CUT领域或当前V1/V2范围。
- 结论：从CUT领域删除当前CUT-11需求及编号引用；删除CutoverSupportTask、ResponsibilityInterval及其CUT侧独立状态机/权限/API/事件/表设计。原WO-06业务语义保留为后续工单领域候选及来源记录，当前不得建表或实现。原始割接需求中的“保障人员安排”回归CutoverPlan从属事实，“审批通过后推送保障任务”按基础平台待办/通知能力落位，不继承WO-06，也不形成新的割接业务聚合。

### C-02 P3-E09错误增加3张CUT-11表

- 当前DDL新增 `cut_cutover_support_task`、`cut_cutover_support_history`、`cut_cutover_support_responsibility_interval`。
- 三表只回指错误CUT-11，且没有历史迁移来源；其余CUT-01～10新平台对象并未进入该核心迁移DDL。
- 结论：三表应从P3-E09当前DDL、对象表映射、领域迁移契约、字段目录和批准候选中删除，不应替换为其他工单/责任区间表。

### C-03 CUT-02把后续建议算法提前为V1强制评分

- Excel明确“最终由人工确定割接等级”，系统自动推送建议等级是后续能力。
- 当前PRD同时写“V2/V3算法”与“V1自动计算建议等级、评分规则未发布则禁止提交”，内部自相矛盾。
- 结论：V1删除自动评分、分值、等级区间、评分规则发布门禁；保留5项问卷和人工A/B/C/D等级。谁负责最终人工确定，现有证据未明确，应询问业务方。

### C-04 CUT-06从结果闭环表被扩张为执行编排与稳定观察引擎

- 0807输入定义P6为结果与闭环记录：4项是/否、回退原因、附件、遗留项、成功/失败、提交结束。
- 当前PRD新增逐步骤串行执行、停止条件/回退条件命中、稳定观察时长与窗口、验证项、观察未结束阻断等强制状态机。
- 这些规则在0807输入中不存在；“割接前/中/后操作清单”属于方案内容，不等于要求平台逐步骤驱动执行。
- 结论：V1回归“方案引用 + 结果闭环记录”；设备连接与采集入口按后续已确认决策保留，但只形成执行证据，不自动创造步骤/稳定观察门禁。逐步骤执行编排和稳定观察应另立增强需求并重新确认优先级。

### C-05 遗留项阻断归档没有来源

- Excel只要求填写遗留项，点击提交后割接申请流程结束并归档数据。
- 当前PRD规定“全部遗留项闭环后方可归档”。
- 结论：不得把此规则作为现行强制门禁。推荐割接闭环记录可归档，未解决遗留项继续在待办中跟踪，并在归档快照中显示未结状态；是否禁止业务闭环需业务方确认。

### C-06 V1多角色执行权限超出已确认边界

- 0807分析报告已写明V1闭环内容统一填写，V2再按角色拆分。
- 当前PRD却在V1授权二线、研发、用服经理记录验证、确认人工证据、执行停止/回退决策或闭环复核。
- 结论：V1只定义统一闭环填写者及审批角色，不提前设计角色化执行分工；V2再细化。

### C-07 CUT-01增加了无证据的派单/取消能力

- 0807输入明确一线工程师办理/自建，列表展示负责人；自动派单仅为V3建议。
- 当前PRD赋予服务经理创建、指派、取消未执行任务，并新增取消状态和规则。
- 结论：任务创建、负责人来源、取消能力须回到证据；没有确认前不把“服务经理派单/取消”作为V1业务规则。

### C-08 CUT-07配置范围被扩大

- 0807系统管理明确业务调研项、风险考察项配置；分析报告归并为统一采集项配置。
- 当前PRD额外把V1评分规则、等级区间、方案模板发布均纳入CUT-07强制Owner。
- 结论：评分配置随C-03后置；方案模板是否支持后台版本化配置没有充分来源，应与“方案编辑模块提供模板”区分，未确认前不能作为V1配置中心范围。

### C-09 备件业务被本地复制

- 0807输入仅要求携带上下文跳转外部备件系统；用户也已明确备件业务由外部系统承接。
- 当前CUT-08让V1本地维护备件编号、型号、数量、到货时间、申请状态和人工就位门禁，形成了外部备件业务副本。
- 结论：平台只保存是否需要备件、外部申请引用、必要状态快照和证据；不本地承接备件申请/库存/到货明细业务。版本与接口时点另按已确认优先级落位。

### C-10 双机检查项数量口径错误

- Excel Sheet使用范围是124行，但有效检查项为：VSM 15、静默双机24、DRP双机21、普通双机23、集群8，共91项。
- 分析报告写17+25+23+24+8=97，却又称共124行；当前PRD进一步把124行写成124项。
- 结论：124是工作表行数，不是检查项数量。当前正式需求和种子数据应按91条有效业务记录逐行校验；不能继续使用“124项”。

## 三、保持不变的后续已确认修正

1. PMS项目不是外部系统：项目来源改为平台内部项目事件/引用，保留ITR外部触发。
2. CUT-06保留设备凭证、连接与采集入口；外部采集平台负责连接/采集，本平台负责凭证、下发、回调和业务证据。
3. 技术公告不作为独立CUT流程；只作为风险采集项的外部数据源/人工证据，并遵循已确认版本优先级。
4. 不恢复通用工单、通用工单时效或历史工单/工时迁移。

## 四、建议的正确对象边界

```text
CutoverTask（割接主任务）
├─ CutoverAssessment（5项输入 + 人工等级）
├─ CutoverSurvey（调研/风险/双机检查实例与结果）
├─ CutoverPlanRevision
│  ├─ 操作/验证/回退清单
│  └─ SupportAssignment（角色、人员/外部联系人、任务描述、电话、到位时间）
├─ CutoverApproval（分级审批实例与意见）
├─ CutoverClosure（4项结果、回退说明、附件、成功/失败）
└─ CutoverLegacyItem（遗留项，可继续跟踪）

审批通过
→ 冻结SupportAssignment
→ 对内部人员生成基础平台待办/通知
→ 对外部联系人只保留方案快照，不创建系统账号或独立工单
```

不建立：`CutoverSupportTask`独立聚合、责任区间状态机、工单式接管/转单/挂起/关闭。
