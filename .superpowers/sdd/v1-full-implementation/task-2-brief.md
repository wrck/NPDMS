# Task brief: T-CP-009 创建测试与追溯骨架

## Goal

建立可执行的单元、集成、契约、E2E、性能和安全测试骨架，并让测试证据能够稳定关联任务 ID 与功能需求 FR。

## Scope

- 审计并接管工作树中已有但未提交的 `pom.xml`、`tests/e2e/`、`tests/performance/`、`tests/security/` 草稿；保留有价值内容，修正不完整或错误实现。
- 为 Java 单元、集成、契约测试提供可独立运行的 Maven 入口；不得破坏上游已有测试命名与默认构建。
- 为 E2E、性能、安全测试提供实际可执行的健康检查，不得只检查目录或文件存在。
- 在追溯文档中定义并落地测试结果关联 `Task ID`、`FR`、命令、时间、结果和证据路径的最小字段。
- 更新 `tasks/todo.md` 中 T-CP-009 的状态与必要追溯证据。

## Acceptance

- 单元、集成、契约、E2E、性能和安全六类入口均能在当前环境执行并返回可信退出码。
- 健康测试包含正反例，能够证明缺失入口、非法追溯字段或失败测试不会被误报为成功。
- 测试结果/证据规范能关联任务 ID 和 FR，且至少为 T-CP-009 产生一条真实证据。
- 现有 `tests/e2e/platform-smoke.cjs` 若被纳入，必须确认其用途、依赖和可执行条件；不得用 API-only 冒烟冒充浏览器业务验收。
- 不修改或提交用户保留的 `sql/mysql/*.sql`。

## Validation

- 分别运行六类骨架健康测试或其统一验证器。
- 运行 Maven 测试分类入口的最小健康验证，确认 profile/命名规则实际生效。
- 验证追溯记录的必填字段和失败路径。
- `git diff --check`、精确暂存检查。

## Commit

- 完成 TDD、自审和验证后自动提交一次逻辑完整的 T-CP-009 变更。
- 提交前完整读取并遵循 `git-commit` skill。
- 不推送，不纳入 `sql/mysql/*.sql` 或其他无关变更。
