# F-IMP-004 配置 Log 采集解析 Feature Spec

> 文档状态：`DRAFT`
> Feature Ready：`NOT_READY`
> Requirement：`EXE-03（V1/P0）`
> Requirement切片覆盖：`EXE-03@V1=FULL`
> Owner Context：`IMP（现场实施）`
> 前置Feature：INT-12 Owner Feature、EQP-02 Owner Feature；冻结模板要求EXE-02时才依赖`F-IMP-003`

## 1. 业务目标与范围

保留IMP配置调试入口，支持人工上传Log或通过INT-12统一采集任务下发手工选择/提供的命令脚本；按设备序列号形成不可覆盖原始Log引用、解析版本和框/槽/板卡候选关系。本Feature不建设设备连接或原始采集引擎。

## 2. 核心规则

- 只有属于当前配置范围且满足冻结模板适用前置的设备可发起；模板要求EXE-02时才须F-IMP-003安装完成。售前测试等不配置EXE-02的路径不得补造安装前置；任务冻结设备、命令/脚本快照和认证方式。
- 保存凭证模式的凭证ID/版本/授权快照；临时模式仅保存用户名，不保存密码；只有显式选择才保存为加密凭证。
- 每次在线尝试或人工上传生成独立记录；失败任务、解析失败、无设备归属文件不计入完成事实。
- 盒式设备按序列号归档；框式设备保留整机Log并提取机框/槽位/板卡候选。人工绑定不修改原始Log，板卡更换使用时态关系。
- 当前目标设备全部有至少一条有效配置Log时才完成；设备范围或有效版本变化使来源事实版本变化。

## 3. 公开事实契约

`ConfigurationCompletionFactApi.inspect/lockAndRevalidate`返回`configurationFactId`、`COMPLETED/NOT_COMPLETED`、`factVersion`、`scopeWatermark`、每台设备当前有效结果ID/版本、未满足设备和`reopened`。不返回原始Log、解析正文、凭证或临时密码。

## 4. 数据、UI与验收

- Owner表：`imp_configuration_collection_result`、`imp_configuration_collection_parse_attempt`、`imp_configuration_component_candidate`；原始不可变Log由EQP-02统一管理。
- UI覆盖在线/手工路径、凭证/临时认证、任务与解析状态、按项目/序列号/操作人/时间查询、下载/对比/检索。
- 验收覆盖手工上传正向、INT-12回调幂等、Provider不可用、解析失败、框板候选与人工绑定、凭证权限/明文零命中、范围重开、真实MySQL和浏览器。

## 5. Feature Ready Gate

`NOT_READY`：须锁定INT-12与EQP-02公开契约、模板适用时的F-IMP-003安装完成事实、框板数据元/迁移证据和旧配置记录复用映射。

## 6. 已授权的设备日志文件增量（2026-10-06）

需求方明确授权“日志拆分、设备关联及最新文件判定进行实现”，并指定 DAC 按 show run / show tech 等内容块中的设备序列号拆分完整设备日志。此增量不代替本 Feature 的配置业务完成事实、框板候选绑定或全范围完成判定。

### 2026-10-09 FB-18 已确认反馈差量

需求方确认取消新增配置时的人工设备选择、调试人员/时间/结果录入，按日志中的现有设备序列号拆分关联；无法识别、SN不匹配或归属不符拒绝并提示。成功上传只形成记录，调试完成另行办理。新增IMP上传入口调用AST公开导入能力，不访问AST表。AST保留拆分、归属、脱敏和文件历史职责；IMP为每个成功归档文件建立初始待调试记录，并以租户和归档文件ID唯一关联，重放不重复建记录。原手工记录、采集历史及已完成记录保留，原状态动作仍按0→1→2办理；导入事务失败不留下部分设备的配置记录或日志。此差量不宣称框板候选、模板完成事实或全范围完成判定已实现。

- DAC 负责内容边界识别、唯一整机序列号提取和敏感内容脱敏；不根据主机名猜设备，不执行设备命令。NPDMS 的 AST 负责当前租户、当前项目内的设备关联及不可变文件归档，INT 只承接 DAC 调用。
- 新增独立设备日志归档页面及上传接口。上传的多设备大日志保留脱敏后的完整来源文件，并按设备保留完整命令输出；任一设备缺失、重复或不属于当前项目时整批拒绝，不产生部分成功的设备文件。旧配置页、旧 URL 日志表及原采集历史不修改。
- 每台设备的成功归档版本在设备锁下递增，手工上传与配置采集回传使用同一序列。最新文件为当前项目内该设备的最高可用归档版本，依据成功接收归档先后判定，不把上传时间当作设备实际配置生效时间。旧文件变成历史，不覆盖或删除。
- 导入请求以租户和来源键幂等。重复回调及同一上传请求复用原批次；同一来源键不能替换内容、操作人或项目。并发成功输入形成不同版本；文件写入失败时整批事务回滚。
- 配置采集归档随既有DAC接入开关启用；文件必须来自已验签的 PLT 文件版本，并重验 IMP 配置记录、当前设备/项目、任务结果版本及原发起人数据范围。成功且完整的命令输出（含stdout和stderr）才进入有效日志归档；失败、截断、无唯一序列号及设备不一致的来源不推进最新文件，不代表配置业务完成。
- 原设备日志历史能力直接保留；PLT 的内容校验、扫描、持久存储回执、不可变引用、统一材料和下载票据直接复用；DAC 内容拆分、AST 归档及 IMP 附加归档接入使用新类和新页面。配置交付件的模板确认规则和其他未接通的 Owner 完成事实仍为独立缺口。
- 2026-10-07需求方确认：在网版本取每台设备最新日志的有效解析结果。多设备归档后须分别保留解析任务/版本和SN关联，由AST维护当前软件版本及历史；旧设备日志重开不得回退当前版本，解析失败或未提取软件版本不伪造更新。
- 2026-10-07项目详情接入（需求方最终位置修正）：日志上传和文件历史属于当前项目所有设备，入口与“新增配置”“新增联调”并列，并接入项目详情“配置Log”页；自动使用当前工作台的项目，不依赖某一配置或联调记录。记录行的“手工命令 / 日志”“命令采集与日志”只承接对应记录的命令和采集日志，不展示项目级上传历史。采用旧实现复制增强，仅项目工作台消费增强页；原页面、原URL附件和原采集历史保留。多设备文件仍按项目内SN归档到AST，不将归档成功视为单一配置/联调记录的业务完成。阶段强制只读时项目文件只可查看，不能上传；记录级命令仍遵循原业务来源可执行性和授权校验。
- 2026-10-08入口细化：序列号行的配置Log在当前工作台打开设备抽屉，不跳转页面或切换项目级面板；按设备合并展示新归档和已有旧日志。项目配置Log不再按新旧存储拆两个平行页签；旧历史仅在当前项目确有记录时提供折叠查看，没有旧记录时隐藏，不新增旧日志操作入口或删除已有历史。
- 2026-10-08列表展示细化：项目配置Log及共享归档窗口只列出已有最新有效归档的设备，不把项目全部序列号作为空日志记录列出；使用现有分页组件展示已归档设备，分页总数只计算有日志的设备。序列号详情仍为完整设备清单，日志版本历史和来源追溯保持原查询语义。
- 2026-10-09真实日志修复（按需求方最新确认自动识别）：项目日志上传不再要求选择编码，前端优先按 BOM 识别 UTF-8/UTF-16，无 BOM 时严格尝试 UTF-8、再尝试 GB18030（兼容 GBK），统一转为 UTF-8 后调用原归档接口；解码失败、空文本、NUL 内容和转码后超过 20 MiB 均在上传前明确拒绝，不忽略损坏字节。DAC 对同主机提示符的多设备日志按完整命令输出中的唯一序列号拆分，重复设备输出仍合并；单个命令输出含多个序列号，或无序列号的实际输出夹在不同设备之间时仍整批拒绝。此修复不更改项目设备归属、原归档授权、脱敏、历史保护或调试完成动作。
- 2026-10-10插槽增量（需求方三项确认）：将日志明确给出的插槽号、板卡型号、子设备SN、PCB/CPLD版本交给AST结构化保存至设备装配树。子设备softVersion、cpldVersion、pcbVersion、basicBootloaderVersion逐字段优先取独立解析值，缺失的字段分别继承整机对应版本；整机对应值也缺失时不伪造值。证据逐字段区分继承与独立来源（需求方随后明确扩展为全部四版本）。未知子设备SN允许建立DEVICE_LOG来源、待来源核对的主档，不伪造MES产品映射或改变现有项目归属；未知整机SN仍沿用整批拒绝规则。冲突装配关系结束旧有效区间并建立新关系，未出现的插槽关系保留；历史日志不得回退较新关系。整机项目授权、租户隔离、环检测、图更新串行锁和整批事务回滚保持有效，子设备版本写入须有当前项目整机的有效直接插槽关系。解析结果查看只读，不重新投影历史或重提解析。
