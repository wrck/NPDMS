## 1. 目标与业务结果

本Feature在AST内建立设备当前可解析产品类型的受控副本和模块内公开查询契约，使消费方可以按稳定编码批量校验产品类型存在/停用事实，并按授权设备取得当前产品类型编码与显示名称。CRM/MES继续拥有产品和设备来源事实；本Feature不实现外部连接器，不维护第二套自由产品类型主数据。

本Feature完成只表示AST本地副本、来源证据、授权查询和历史解释形成可独立验收子闭环，不表示EQP-01全部设备档案、EQP-04 MES同步运行闭环、INS-03/09规则管理或外部联调完成。

## 2. 范围

### 2.1 包含

- 产品类型受控副本：稳定编码、显示名称、存在事实、启用/停用事实、来源系统、来源键、来源版本、来源更新时间、最近成功同步时间和同步状态。
- 设备当前产品类型引用：设备ID、产品类型稳定编码、来源记录引用、解析状态和版本。
- 受控导入：只接收带来源系统、来源键、来源版本和可审计映射证据的数据；重复来源版本幂等，旧版本不得覆盖新事实。
- 按稳定编码批量查询存在/停用事实。
- 按授权设备查询当前产品类型编码和显示名称。
- 租户、设备和数据范围校验；空设备范围返回空，不省略条件扩大查询。
- 停用后的新消费拒绝与历史引用解释。
- 来源不可用时保留最近成功副本并明确同步状态。
- 模块公开契约位于`pms-module-asset-api`，DTO不暴露DO、Mapper或业务表结构。

### 2.2 不包含

- CRM/MES协议适配、网络连接、认证、调度、游标、批次拉取、重试、补偿和对账连接器。
- EQP-04设备信息MES同步运行闭环或其Implementation Done声明。
- 产品类型人工自由创建、无来源自由改名或猜测映射。
- 使用`conpType`、旧字典、设备型号或手工文本替代产品类型稳定编码。
- Inspection规则、命令、安全审核、发布、停用或任务选择实现。
- 产品类型业务生命周期、审批节点、固定示例编码或未经权威来源确认的种子值。

## 3. Owner与来源边界

- CRM/MES拥有产品和设备来源事实以及来源稳定键。
- AST拥有平台业务所需的产品类型受控副本、设备当前产品类型引用、来源映射证据和公开查询契约。
- Inspection只消费AST公开契约，保存规则发布时的稳定编码和显示名称快照，不直读AST表，不修改AST事实。
- EQP-04或后续独立连接器Feature负责把CRM/MES来源事实按已批准映射写入AST；连接器未完成时，本Feature可使用保留完整来源证据的受控导入完成本地闭环验收，但不得将其声明为连接器完成。

## 4. 不变量

- 同一租户内产品类型稳定编码唯一，停用或软删除后继续占用，不得复用为不同业务含义。
- 同一来源系统和来源键只能映射一个当前产品类型；映射冲突进入待处理，不自动覆盖。
- 显示名称变化必须保留来源版本和历史证据；不得反向改写消费方已冻结快照。
- 设备当前产品类型必须引用存在的受控副本；未知、冲突或无法解析时记录明确解析状态，不猜测编码。
- 产品类型停用后，批量校验明确返回停用事实，授权设备查询不得把停用事实伪装为可用。
- 来源顺序固定以同一`tenantId + sourceSystem + sourceKey`的`sourceUpdatedAt`为水位；`sourceVersion`只作不透明等值键，不按字符串、数字、语义版本或接收顺序排序。
- 更早`sourceUpdatedAt`拒绝；同水位仅当`sourceVersion + payloadHash + targetProductTypeCode`全部相同才幂等重放，否则进入来源冲突；更晚水位才允许继续校验并写入。
- 来源空响应、更早水位或部分失败不得清空最近成功副本；来源冲突不得覆盖当前映射目标，冲突摘要必须在导入拒绝后仍可审计。
- 无权设备不泄露其存在性、产品类型或映射状态。

## 5. 权限与数据范围

- 产品类型批量校验仅向已授权模块服务身份开放，按当前租户返回请求编码逐项结果。
- 授权设备查询同时校验租户、调用方设备数据范围和设备当前事实；空权限集合返回空。
- 受控导入只允许AST授权维护主体或集成服务身份执行，并记录来源证据和操作审计；角色名称本身不授予写权限。
- 任何公开DTO不得返回客户、项目、设备敏感详情、凭证或来源载荷正文。

## 6. 公开查询契约

模块内公开契约固定为：

- `AssetProductTypeApi.getByCodes(ProductTypeCodesQuery)`：按稳定编码批量返回每个请求编码的存在事实、启用/停用事实、显示名称、来源系统、来源版本、同步状态、最近成功同步时间和是否来自最近成功副本；未知编码必须返回明确不存在结果，不猜测名称。
- `AssetProductTypeApi.getAuthorizedDeviceProductType(AuthorizedDeviceProductTypeQuery)`：按设备和调用主体返回当前产品类型稳定编码、显示名称、启用/停用事实、来源版本、解析状态、同步状态、最近成功同步时间和是否来自最近成功副本；空请求设备集合或数据范围计算后为空时返回空结果，跨租户或设备不可见时同样返回空结果且不泄露存在性。

查询对象必须场景化，不使用长位置参数、`Map`或万能查询对象。跨模块消费者只依赖`pms-module-asset-api`及DTO，不依赖AST `-biz`、Service、Mapper、Repository或业务表。

## 7. 数据边界

- 产品类型受控副本独立保存稳定编码、显示名称、可用事实和来源证据；设备主档或其当前事实投影只保存产品类型稳定编码及来源记录引用。
- 来源映射保存来源系统、来源键、来源版本、目标稳定编码和映射状态；冲突与未解析事实不可静默丢弃。
- 历史消费按冻结编码和名称快照解释，产品类型名称变化或停用不回写Inspection历史revision及任务。
- 所有表和迁移在实施计划中使用前向Flyway；本规格不批准修改已执行迁移。

## 8. 异常、并发与审计

- 同一稳定编码或来源映射并发写入最多一个成功；更早来源水位、重复稳定编码、同源多目标和跨租户引用均拒绝且无半写入。
- 同水位异事实和同源多目标的当前业务事实保持不变；冲突摘要通过独立可提交事务边界持久化，不能随被拒绝的导入事务回滚。
- 来源不可用时查询返回最近成功副本及同步状态；没有可证明副本时明确返回不可用，不使用替身值。
- 审计记录来源版本、映射前后值、启停事实、受控导入、查询拒绝和冲突处置，不记录外部凭证或完整敏感载荷。

## 9. 验收标准

- `AC-FAST002-001`：带完整来源证据的受控导入可幂等建立产品类型副本；`sourceUpdatedAt`更早时拒绝，同水位同版本同摘要同目标时不重复写，同水位异事实形成可查询冲突证据，更晚水位才可更新；`sourceVersion`不参与排序。
- `AC-FAST002-002`：同租户稳定编码唯一且不可复用；来源键映射冲突进入待处理，不覆盖既有映射。
- `AC-FAST002-003`：批量查询对每个请求编码返回存在、启用/停用、显示名称、来源版本、同步状态、最近成功同步时间和最近成功副本标记；未知编码不返回猜测名称。
- `AC-FAST002-004`：有权调用方可按授权设备取得当前产品类型；空请求设备集合、无设备范围、跨租户和不可见设备统一返回空结果且不泄露存在性。
- `AC-FAST002-005`：设备产品类型未知、冲突或未解析时返回明确解析状态，不以`conpType`、旧字典、型号或自由文本替代。
- `AC-FAST002-006`：停用产品类型不再可供新业务消费，历史编码、名称和来源版本继续可解释。
- `AC-FAST002-007`：来源失败或空响应不清空最近成功副本；两个公开查询均返回同步状态、最近成功同步时间和是否来自最近成功副本。
- `AC-FAST002-008`：公开契约位于`pms-module-asset-api`且DTO不暴露DO；Inspection契约测试只依赖API模块，不直读AST表。
- `AC-FAST002-009`：空权限或空设备范围返回空；批量和设备查询通过租户、数据范围与授权负向测试。
- `AC-FAST002-010`：本Feature测试和证据不包含CRM/MES连接器实现，也不宣称EQP-04、INS-03、INS-09、外部联调或发布完成。
