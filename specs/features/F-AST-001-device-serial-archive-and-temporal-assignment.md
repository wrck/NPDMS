# F-AST-001 设备序列号档案与时态归属 Feature Spec

> 文档状态：`BASELINE`
> Feature Ready：`READY`
> Requirement：`EQP-01（V1）`
> 关联Requirement：`EQP-02`、`EQP-03`、`EQP-04`、`CUS-03`、`INT-02`、`INT-04`；不宣称关联Requirement完成
> Owner Context：`AST（资产管理）`
> 外部协作Context：`CUS（客户与服务关系）`、`PROJ（项目治理）`、`KNO（技术知识治理）`、`IMP（现场实施）`、`PLT（基础平台能力）`
> 适用基线：PRD V1.8及批准增量`CHG-PRD-2026-08-23-002`；SDS Phase 1/2/3 `BASELINE`
> Technical Plan：仅在本Feature晋级`BASELINE / READY`且实现仓库锁定新规格提交后生成

## 1. 目标

以租户内唯一设备序列号建立AST设备主档，提供按序列号检索和设备详情聚合，展示出厂信息、官网信息、在网版本、技术公告、维保基本信息和配置Log六类数据。平台保留每类数据的Owner、来源版本、最近成功时间和同步状态；外部来源不可用时继续展示最近成功副本，不以空响应覆盖有效事实。

本Feature同时冻结设备项目归属和客户归属的时态语义：一个设备在任一时点至多存在一个当前最具体项目直接归属和一个当前客户直接归属；历史、租用、共管及跨项目参与通过带类型和有效区间的关系表达，不复制为第二个当前直接归属。

## 2. Scope

### 2.1 包含

- 设备主档按`tenantId + serialNumber`唯一识别、精确查询和权限裁剪展示；
- 六类设备数据的统一详情外壳、分Tab展示、来源标识、来源版本、数据截止时间和同步异常标识；
- MES制造字段、ITR在网版本、KNO技术公告引用等已落本地副本的只读消费；
- 平台拥有的项目/客户关联、维保基本信息和配置Log引用聚合；
- 当前直接项目归属、项目归属历史和跨项目业务参与关系；
- 当前直接客户归属、客户归属历史和租用/共管等业务关系；
- 归属变更的版本校验、有效区间校验、冲突隔离、审计和`DeviceAssigned` Outbox事件；
- 配置Log元数据展示及逐次鉴权的限时下载入口；
- 序列号、来源映射和归属冲突的待处理展示，不在冲突未解决时改写有效事实；
- 真实数据库约束、授权负向、并发、来源降级和真实浏览器响应式验收。

### 2.2 外部同步拆分

F-AST-001消费外部系统已写入Owner本地副本后的稳定事实，不承接外部连接器和同步运行闭环。

| 数据切片 | 权威Owner | F-AST-001职责 | 拆出能力 |
|---|---|---|---|
| MES设备身份与出厂信息 | MES | 校验租户内序列号唯一性，读取并展示AST本地只读副本、来源版本和截止时间 | `EQP-04`负责MES协议适配、批次/增量同步、重试、补偿和对账 |
| ITR在网版本与版本历史 | ITR | 按唯一设备引用已同步版本事实，按事件发生时间展示当前版本与历史 | `INT-02`负责ITR传输、来源定位、旧版/重复/迟到事件处理、重试和对账 |
| ITR技术公告 | ITR；KNO持有平台只读镜像 | 通过KNO公开查询契约展示与设备匹配的公告引用 | `INT-04`负责公告同步、字典映射、隔离、重试和对账；F-AST-001不创建本地公告发布能力 |
| 官网公开信息 | KNO | 通过KNO公开查询契约按产品/设备映射展示已发布版本、来源URL和核验时间 | KNO授权人员受控人工维护，V1不建设自动爬取 |
| 配置Log | AST/EQP-02 | 展示元数据和受控下载入口，不拥有采集业务结果 | `EQP-02`管理原始文件、不可变解析版本、软删除规则和业务引用 |
| 设备安装位置 | AST | 展示AST当前地点和版本历史 | `EXE-02`保存安装事实并通过`AssetLocationApi.effectEquipmentLocation`使位置生效 |

拆出的同步Feature未完成时，F-AST-001可以使用受控测试种子或已核验本地副本验证查询与聚合，但不得将替身、手工数据库写入或预置数据声明为`EQP-04`、`INT-02`、`INT-04`完成证据。外部HTTP受理、批次启动或消息送达均不等于设备事实已生效。

### 2.3 不包含

- MES、ITR、官网的网络连接、认证、调度、游标、批次执行、重试、补偿和来源对账；
- `EQP-02`配置Log原始文件、解析版本、删除审批及实施采集结果接收；
- `EQP-03`七类全生命周期设备档案、备件/RMA、故障聚合和停产停维完整视图；
- `EQP-05`扫码入口、扫码历史和摄像头能力；
- `EQP-07`项目问题单页面；
- 续保记录、续保任务、续保经营对象、续保率和人工覆盖客观维保状态；
- 设备登录密码、私钥、Token或其他连接凭证的保存与展示；
- V3的`EQP-06`子公司序列号展示增强；
- Deployment、SIT、UAT、Release和历史数据迁移授权。

## 3. 业务规则

### BR-FAST001-001 设备身份

- 设备序列号在租户内唯一，查询、归属和外部映射均以稳定`deviceId`为内部标识，以序列号作业务唯一校验。
- 平台设备业务身份按`tenantId + serialNumber`幂等创建或更新；外部来源事件按`MES设备ID + sourceVersion/eventId`幂等消费。一个有效MES对象只能映射一个Device，一个Device最多一个当前MES主映射；序列号缺失、同租户重复或来源映射冲突时进入待处理区。
- 冲突记录不得创建第二个有效设备、合并相似序列号或覆盖既有设备主档。跨租户相同序列号互不形成可见关联。
- 人工补录必须标记`sourceSystem=PLATFORM_MANUAL`、原因、证据和待对账状态，不伪造MES/ITR来源ID或来源版本。

### BR-FAST001-002 字段Owner与聚合

- MES拥有序列号、产品编码、产品名称及制造/出厂字段；ITR拥有在网版本事实；KNO保存ITR技术公告只读镜像；AST拥有设备平台标识、项目/客户归属、维保基本信息、配置Log引用和设备当前位置。
- 业务角色不能直接编辑MES、ITR和KNO来源字段；外部来源同步不得覆盖AST平台字段。
- 设备详情按模块返回`sourceSystem/sourceKey/sourceVersion/dataAsOf/syncStatus`。来源失败保留最近成功值并显示数据截止时间；空响应、部分失败或旧来源版本不得清空当前有效值。
- 聚合查询允许某一外部来源切片延迟，但必须把该切片标记为`STALE/FAILED/PENDING_MAPPING`等已批准同步状态；不得把部分聚合发布为来源完整且最新。

### BR-FAST001-003 项目直接归属时态契约

- 同一`tenantId + deviceId`任一时点至多一个当前直接项目归属，目标必须是实际最具体项目节点，不向祖先项目复制归属行。
- 当前关系保存目标项目、归属类型、`assignedAt`和`assignmentVersion`；历史关系保存`effectiveFrom/effectiveTo`、原因、批次和操作者。当前历史区间的`effectiveTo`为空。
- 变更归属使用同一事务时间关闭旧历史区间并新增新区间，再更新当前关系。历史只追加，不覆盖、不删除；同一设备的有效区间不得重叠。
- 设备参与其他项目时建立带业务类型和有效区间的参与关系。参与关系不改变当前直接归属，不授予设备权限，也不使祖先项目形成第二个直接归属。
- 父级项目统计读取按`treeVersion + assignmentVersion`构建的祖先投影并按`deviceId`去重。投影延迟时设备详情返回当前真值，汇总返回水位和更新中标识。

### BR-FAST001-004 客户直接归属时态契约

- 同一`tenantId + deviceId`任一时点至多一个当前客户直接归属；客户必须由CUS公开契约确认存在、租户一致且调用者有权引用。
- 客户直接归属变更必须关闭上一有效区间并新增历史，不得原地覆盖客户ID。历史客户、租用、共管等关系保存关系类型、`effectiveFrom/effectiveTo`和来源。
- 项目直接归属变更不自动覆盖客户直接归属。项目当前客户与设备当前客户不一致时，保留双方Owner事实并创建待核对项，未经授权核对不得自行选择任一值覆盖另一方。
- 客户关系只影响设备聚合和授权判定输入，不把CUS客户主数据复制到AST作为第二权威副本。

### BR-FAST001-005 归属命令、并发与幂等

- 项目归属命令使用`POST /api/v1/pms/devices/{id}/actions/assign-project`，请求必须携带`If-Match`、目标项目和变更原因，成功返回新的`assignmentVersion`与祖先投影`operationId`。
- 归属写入以`tenantId + deviceId`当前关系和`assignmentVersion`为互斥边界。两个项目并发认领同一设备时最多一个成功，失败方收到`VERSION_CONFLICT`及当前最具体项目和最新版本。
- 同一幂等键和同一请求摘要重放返回首次结果，不重复生成历史、审计、Outbox或投影任务；同键不同摘要返回`IDEMPOTENCY_CONFLICT`。
- 目标项目不存在、跨租户、无管理范围、项目状态不允许接收、期望版本过期或历史区间重叠时，当前关系和历史均不得变化。
- 客户归属命令固定为`POST /api/v1/pms/devices/{id}/actions/assign-customer`，携带目标客户、关系类型、原因、`If-Match`和幂等键；AST维护当前唯一关系与统一时态关系。

### BR-FAST001-006 权限与数据范围

- 查询先校验租户，再按设备当前直接项目、有效项目参与关系、当前客户关系及调用者项目/组织授权裁剪；空项目或空设备范围返回空结果，不能省略条件扩大查询。
- 服务经理仅在所属组织和有效设备范围内维护AST平台字段及处理冲突；项目经理、工程师只读本人授权项目当前归属或有效参与设备。
- 项目归属变更需要设备归属管理功能权限、目标项目管理范围和服务端业务守卫同时通过。角色名称、前端按钮可见性或设备序列号本身均不授予操作权限。
- MES、ITR和KNO来源字段只允许对应集成服务身份按Owner契约写入；集成服务身份不能改变项目/客户归属、维保基本信息和设备位置。
- 配置Log下载必须同时通过设备查看权限和文件下载权限，每次重新鉴权并生成绑定当前用户和短有效期的链接；链接过期、转发或权限撤销后不可继续使用。

### BR-FAST001-007 事件、审计与来源证据

- 项目直接归属成功后，在同一事务写入不可变历史、幂等完成点、审计和`DeviceAssigned` Outbox。事件冻结`deviceId/oldProjectId/newProjectId/assignmentVersion/effectiveAt`及统一事件元数据。
- 事件消费者按`eventId`幂等；事件发送或祖先投影重建失败不回滚已经提交的归属真值，后台按同一`operationId`重试。
- 外部主数据副本成功更新后可发布`MasterDataSynchronized`或Owner定义的稳定事件；F-AST-001不以消息受理替代本地副本成功提交。
- 审计覆盖设备精确查询、来源字段变化摘要、同步状态变化、归属前后值、冲突创建与处置、配置Log下载授权和下载结果。日志不得记录配置正文、凭证明文、完整限时URL或敏感客户字段。

## 4. API契约

所有业务路径继承`/api/v1/pms`前缀。

| 接口 | 操作 | 当前契约 |
|---|---|---|
| `/devices` | `GET` | 按精确序列号、项目范围和已批准筛选条件分页查询；空权限范围返回空；返回设备标识、当前归属摘要、来源状态和版本 |
| `/devices/{id}` | `GET` | 返回设备主档和六类Tab的可见性/摘要；来源切片分别返回Owner、版本、截止时间和同步状态 |
| `/devices/{id}/archive` | `GET` | 返回EQP-01范围内的平台档案聚合；不得宣称EQP-03七类全生命周期档案完成 |
| `/devices/{id}/assignment-history` | `GET` | 分页返回项目直接归属历史、有效区间、原因和版本；按调用者范围裁剪敏感信息 |
| `/devices/{id}/actions/assign-project` | `POST` | `If-Match`、幂等键、目标项目和原因必填；成功返回`assignmentVersion/operationId` |
| `/devices/{id}/customer-relationships` | `GET` | 返回调用者有权查看的当前客户直接归属及历史/租用/共管关系；只返回CUS稳定引用和必要快照 |
| `/devices/{id}/configuration-logs` | `GET` | 仅返回EQP-02公开契约提供的可见元数据和下载能力标识 |
| `/devices/{id}/configuration-logs/{logId}/download-url` | `POST` | 每次校验设备查看与文件下载权限，返回绑定用户的短期链接；不得返回持久对象存储地址 |

正式契约已冻结：官网信息通过KNO公开查询契约；客户归属使用`assign-customer`动作；详情使用固定外壳和分Tab DTO；来源状态统一为`FRESH/STALE/FAILED/PENDING_MAPPING/NOT_AVAILABLE`；沿用现有资产权限并新增归属、冲突和下载高风险权限；下载链接默认5分钟可配置。

## 5. 数据与物理边界

- `Device`是AST聚合根和外部主数据副本载体；MES/ITR Owner字段必须保留来源键、来源版本和同步时间，AST平台字段与外部字段分列维护。
- 项目归属使用SDS已冻结的当前唯一关系、时态历史和可重建祖先投影：`ast_device_current_assignment`、`ast_device_assignment_history`、`ast_device_project_ancestor`。
- 当前关系唯一约束为`tenantId + deviceId`；历史区间不得重叠；祖先投影唯一表达`deviceId + ancestorProjectId`并携带`treeVersion/assignmentVersion`。
- `AssetSyncSnapshot`只追加保存来源版本、水位、校验摘要和字段差异，不覆盖项目/客户归属、位置或平台维保事实。
- 客户直接归属采用当前唯一表，历史、租用和共管采用统一时态关系表；Device主表与MES/ITR/KNO分来源表按SDS机器物理契约实现，不用万能JSON替代核心字段。序列号软删除后仍占用。
- 新查询必须使用场景化Query对象；简单单表条件使用类型安全查询，联表、动态集合和锁查询进入Mapper XML。禁止SQL注解、`${}`、`.last(...)`及空范围放大查询。
- 所有迁移使用前向Flyway版本，不修改已执行SQL；历史迁移和生产切换不由本Feature授权。

## 6. UI

- 提供设备列表、按序列号精确查询和设备详情。详情使用六个Tab：出厂信息、官网信息、在网版本、技术公告、维保信息、配置Log。
- 每个Tab固定展示来源、最近成功时间、数据截止时间和同步状态；来源异常时保留最近成功数据并显示异常，不用空白页冒充无数据。
- 设备摘要区展示当前最具体项目、当前客户、当前位置和待核对标识。项目/客户历史使用独立抽屉或页签，不把历史关系混入当前值。
- 归属操作只向通过服务端权限和状态检查的用户开放；提交前展示当前值、目标值、原因和版本，冲突后刷新当前真值，不覆盖其他操作者结果。
- 配置Log页签只展示有权元数据；无下载权限时不生成链接。链接过期后重新发起授权，不缓存持久URL。
- 320/768/1024/1440宽度不得出现页面级横向溢出；真实浏览器验证查询、Tab切换、来源降级、归属冲突、权限负向和刷新持久化。

## 7. 验收标准

- `AC-FAST001-001`：同租户设备序列号唯一；重复、缺失或来源映射冲突进入待处理且不覆盖既有设备，跨租户数据不可见。
- `AC-FAST001-002`：有权用户按序列号查询时看到六类Tab及各自Owner、来源版本、最近成功时间和同步状态；任一来源失败时其他Tab可用，最近成功值不被空响应覆盖。
- `AC-FAST001-003`：MES/ITR/KNO来源字段对业务角色只读，外部同步不能覆盖AST项目/客户归属、维保基本信息和位置；平台人工补录不冒充外部来源。
- `AC-FAST001-004`：设备任一时点最多一个当前最具体项目直接归属；变更以同一事务时间关闭旧区间并新增新区间，历史不可覆盖且区间不重叠。
- `AC-FAST001-005`：跨项目参与关系不形成第二个直接归属；父项目统计按设备去重并返回`treeVersion/assignmentVersion`水位，投影延迟不改变详情当前真值。
- `AC-FAST001-006`：设备任一时点最多一个当前客户直接归属；项目与客户归属不一致时进入待核对，不自动覆盖任一Owner事实；历史、租用和共管关系保留类型与有效区间。
- `AC-FAST001-007`：归属并发最多一个成功；旧`If-Match`、同键异请求、越权、跨租户、无效项目和重叠区间均拒绝且不产生历史、成功审计或事件副作用。
- `AC-FAST001-008`：同幂等键同请求重放不重复历史、Outbox和投影任务；`DeviceAssigned`冻结前后项目、版本和生效时间，消费者重复处理不产生第二次业务变化。
- `AC-FAST001-009`：配置Log元数据按设备权限展示；下载逐次鉴权并使用绑定用户的限时链接，过期、转发、撤权或无文件权限均不能下载。
- `AC-FAST001-010`：真实MySQL验证唯一键、时态区间、锁/CAS、幂等和事务无副作用；真实浏览器验证四档响应式、来源降级、权限负向和刷新后数据一致。
- `AC-FAST001-011`：F-AST-001完成不宣称`EQP-02`、`EQP-03`、`EQP-04`、`INT-02`、`INT-04`、外部系统联调、Deployment、SIT、UAT或Release完成。

## 8. 测试与证据

实现阶段至少需要以下证据：

- 设备身份、来源Owner和聚合服务单元测试；
- 项目/客户归属时态规则、区间重叠和不一致待核对测试；
- API契约、功能权限、项目/设备范围和跨租户负向测试；
- 真实MySQL唯一约束、行锁、乐观锁、幂等和Outbox事务测试；
- MES/ITR/KNO受控替身的旧版、重复、迟到、同版本冲突、部分失败和空响应测试；
- 祖先投影水位、项目树移动和归属并发测试；
- 配置Log下载实时授权、过期和转发负向测试；
- 真实浏览器六Tab、来源异常、归属冲突、刷新持久化和四档响应式闭环；
- 独立Feature Ready复审和代码评审。
