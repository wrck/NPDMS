# F-IMP-003 硬件安装与位置生效 Feature Spec

> 文档状态：`DRAFT`
> Feature Ready：`NOT_READY`
> Requirement：`EXE-02（V1/P0）`
> Requirement切片覆盖：`EXE-02@V1=FULL`
> Owner Context：`IMP（现场实施）`
> 前置Feature：`F-IMP-002`、`F-AST-001`
> AST支撑Task：`T-FIMP001-AST-01`

## 1. 业务目标与范围

按已签收设备保存安装、迁移或拆除记录、AST结构化位置/受控文本降级、安装人/时间和模板要求的照片；项目经理确认后通过AST命令使设备当前位置生效并保留历史。

## 2. 核心规则

- 对象必须已由F-IMP-002签收且当前直接归属本项目；未签、拒收或仅参与其他项目的设备不得确认安装。
- 每台设备同一时点一个当前有效安装记录；更换位置或纠正创建新版本，不覆盖证据。
- 有`siteId/siteLocationId`时结构化引用是权威位置；文本降级标记`UNRESOLVED`，不参与结构化权限或自动解析。
- 确认前不更新AST当前位置；AST位置命令失败时标记待重试且不计入完整里程碑。
- 已签且要求安装的设备全部有有效记录或具体设备豁免时才形成完成事实；新签设备加入范围后必须重验。

## 3. 公开事实契约

`InstallationCompletionFactApi.inspect/lockAndRevalidate`按项目、设备范围和期望版本返回`installationFactId`、`COMPLETED/NOT_COMPLETED`、`factVersion`、`scopeWatermark`、未满足设备、位置同步待重试项和`reopened`；不返回照片或位置敏感正文。

## 4. 数据、UI与验收

- Owner表：`imp_installation_record`、`imp_installation_item`、`imp_installation_evidence`；位置引用只通过AST公开契约。
- UI覆盖待安装列表、位置选择/待维护降级、照片、提交/确认/退回和历史版本。
- 验收覆盖未签/越权设备、照片或位置缺失、结构化/文本降级、AST同步失败补偿、范围重开、历史不覆盖、真实MySQL和浏览器。

## 5. Feature Ready Gate

`NOT_READY`：须锁定F-IMP-002签收事实、AST设备/地点/位置生效契约、旧安装记录映射和证据模板输入。

## 2026-10-09 FB-17 批准差量（旧功能范围）

本会话需求方确认安装人员自动取当前账号、安装时间自动取保存时间，位置由工程师填写，现场照片保存即完成。旧项目硬件安装工作台的新增批量保存沿用已存在的创建设备记录、开始与完成命令、设备范围校验及AST位置生效事务；只将新记录人员/时间收紧为服务端认证用户与保存时间，忽略客户端伪造取值，界面只读显示。既有单条旧接口、历史记录及完成状态不改写；本差量不把尚未就绪的新领域Feature标记Ready，不增加照片必填或其他节点完成规则。

## 2026-10-28 TF-040 批准差量（旧功能范围）

需求方明确按旧实现的分组过滤方式完成安装地址要求配置，不等待具体配件清单。仅复用旧 `ProductItemExampleBuilder` / `ProductItemConditionGroup` 的逻辑：组间 OR、组内 AND，条件在数据库执行；变量、类和参数均采用当前系统的产品命名。编码、型号、描述支持 LIKE、IN、NOT IN，并增加产品分类、类型的相同条件。类型值均由参数维护，不硬编码光模块、电源或其他产品类型。不照搬旧未知字段被静默忽略、描述列表未进入SQL及嵌套组引用错误。

- 系统参数 `pms.installation.address.product.filters`，通过既有参数配置维护 `{"productFilters":[...]}`；命中设备要求地址，不命中设备免填。缺少参数或空 `productFilters` 沿用全部必填。未知字段、空条件组、空筛选集合、无效JSON显式报错，不能因配置损坏扩大免填范围。参数保持既有500字符限制，复杂配置可使用型号/分类/类型条件压缩表达，不改变平台参数接口和存储。
- 组字段：`productCodeLike/In/NotIn`、`productModelLike/In/NotIn`、`productDescLike/In/NotIn`、`productCategoryLike/In/NotIn`、`productTypeLike/In/NotIn`；不保留旧item字段或别名。`alternativeGroups`沿旧分组意图：子组间 AND、每个子组内条件 OR，仅一层；顶层条件与子组共同 AND。比较、LIKE及NULL采用数据库原生语义，与旧SQL执行方式一致，不在Java重写通配符或匹配逻辑。
- 需求方追加要求：公共条件属于AST，不能限定为安装地址。AST通用项目设备筛选API及SQL片段直接在数据库过滤，仅返回ID；IMP消费NOT_MATCHING结果。主档仅按租户、编码及逻辑删除直接关联，不新增产品分组、MAX、COUNT、CAST等防御或把产品行全量读到Java。外部系统来源及产品状态不默认限制；来源主要用于追溯，只有明确业务需要时才作为Query可选参数，不写死CRM/ACTIVE等值。IMP不得跨模块访问产品表，原设备锁定DTO不因本次配置增加产品字段。
- 当前项目设备地址完成核对和安装结果形成使用相同过滤；免填设备仍在设备表展示，可维护地址和查历史。接口返回必填、已填、免填数量及免填设备ID，UI只展示服务端决定，不按名称猜测配件。全部免填且项目确有设备时地址要求满足；无设备仍不满足。业务结果仍要求真实完成安装记录作为原生结果标识，不伪造安装记录或状态。
- 配置变化在下一次读取/锁定完成核对生效，当前结果版本包括规则与数据库返回的免填ID集合；不逐设备序列化产品元数据，不改写旧完成任务、安装记录、地址或冻结历史。本轮不执行数据库迁移、初始化参数或业务数据写入。

- 2026-11-04 需求确认：设备列表增加安装状态筛选，默认全部；存在当前生效的已完成安装记录为已安装，否则为未安装。与地址要求筛选组合生效，切换时清除已选设备，不新增设备状态列或持久化状态。

- 2026-11-04 需求确认：安装地点候选包含本项目当前生效安装记录所引用的本租户启用站点及原项目客户启用站点；读取和提交保留项目权限，提交时重验候选。方案部署位置去重后只有一个地址时可供直接引用；多个地址时按所选产品编码取共同候选并由用户选择，不改变已填地址直到用户主动引用。
