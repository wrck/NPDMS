# F-CUT-001 割接统一配置版本与采集项基础 Feature Spec

> 规格状态：`IN_REVIEW / SCOPE_REOPENED_20260830`
> Feature Ready：`NOT_READY / REVALIDATION_REQUIRED`
> Requirement ID：`CUT-07（V1/P0）`、`CUT-09（V1/P0）`、`CUT-10（V1/P1）`
> Requirement切片覆盖：`CUT-07@V1=FULL；CUT-09@V1=FULL；CUT-10@V1=FULL`
> 前置Feature：无
> 后续Feature：CUT-01～CUT-04运行时消费
> Open Questions：`Q-FCUT001-001`、`Q-FCUT001-002`、`Q-FCUT001-003`均已关闭

## 1. 目标与业务结果

本Feature建立CUT领域唯一的后台配置版本真值，使割接-管理员能够在同一管理入口维护并发布割接维度、统一采集项、动态多维绑定关系和方案模板章节配置。配置采用`DRAFT -> PUBLISHED -> DISABLED`生命周期，已发布版本不可覆盖，后续任务、评估、清单和方案只冻结所消费版本，不被后台修改反向覆盖。

本Feature完成后表示CUT-07配置Owner、CUT-09风险配置视图和CUT-10调研配置视图共同形成可独立发布的V1首批配置基础；不表示CUT-01～CUT-06运行态、CUT-08 V2集成或任何割接业务实例已经完成。

## 2. 范围

### 2.1 包含

- 配置根版本：稳定配置编码、修订号、状态、生效区间、变更说明、字典及维度快照、发布与停用事实、乐观锁版本。
- 基础维度：割接类型、组网模式、设备类型、割接等级四个V1维度；类型、模式和设备值复用基础平台字典，不新增业务字典表。
- 扩展维度定义：维度编码、名称、数据类型、允许值来源、业务Owner、任务上下文取值路径和启用状态。
- 统一采集项：业务调研项、风险考察项、双机部署检查项共用一个版本模型，维护稳定项键、类型、名称、含义、界面格式、反馈格式、必填性、外部数据源配置、所属子表、状态和排序。
- 动态多维绑定：采集项版本与维度条件快照、优先级、规则版本和状态。
- 双机部署检查项：提供统一CRUD、所属子表约束和动态绑定能力；XLSX/HTML可作名称、字段与界面参考，但不参与业务裁决或发布数量门禁，不从旧表反推配置主数据。
- 风险矩阵视图：过滤风险考察项与双机部署检查项，支持批量多维绑定、必选覆盖校验、专属条件校验和逐项错误定位；五类双机检查基准为17/25/23/24/8，合计97项。
- 调研矩阵视图：过滤业务调研项，覆盖12类核心调研内容、绑定级必填性、割接背景条件显示Schema和批量多维绑定。
- 方案模板章节配置：按割接类型和等级维护版本化章节定义，保存于配置根`planTemplateSectionSnapshot`并随根版本不可变发布。
- 管理页面：配置修订、三类采集项分组、维度与绑定规则、方案模板章节、发布校验结果和历史版本只读查看。
- 租户隔离、维护/发布权限分离、操作审计、发布失败零半发布和并发冲突处理。

### 2.2 不包含

- CUT-01～CUT-06任务、评估、清单生成、方案实例、审批、执行、闭环或归档。
- CUT-03运行时匹配、输入快照、命中轨迹、重新匹配和CollectionTask下发。
- CUT-08备件集成及任何V2 KPI、导航、时效或自动化能力。
- 对`pms_cut_task`、`pms_cut_risk`、`pms_cut_plan`旧表、接口、页面或数据的改造、迁移和双写。

## 3. 领域边界与复用

- CUT拥有`CutoverConfigurationRevision`；基础平台拥有字典，CUT只冻结代码和显示名称快照。
- 三类采集项只有一套Owner主数据。CUT-09和CUT-10后续只提供过滤视图和专用校验，不建立第二套风险项或调研项表。
- `CutoverPlan`只承载CUT-04/05业务方案修订，不承载CUT-07后台配置主数据。
- 外部动态数据源只保存已批准的接口标识、参数映射、返回映射和人工降级规则；本Feature不调用外部业务接口证明CUT-03完成。
- 旧实现结论见`F-CUT-001-legacy-reuse-audit.md`。旧任务、风险和方案模型语义不兼容，只能复用Yudao通用编码、分页、租户和权限模式。

## 4. 状态与不变量

### 4.1 配置版本状态

```text
DRAFT --publish--> PUBLISHED --disable--> DISABLED
```

- 只有草稿可编辑或删除未被引用的草稿子项。
- 已发布版本及其采集项、绑定规则、维度、方案模板章节均不可覆盖；修改必须从已发布版本创建新修订。
- 发布在单事务内完成全量校验和状态切换。失败保持草稿，当前已发布版本继续有效。
- 同一租户、同一配置编码只允许一个当前已发布版本；并发发布最多一个成功。
- 停用只阻止新实例消费，历史版本及已有引用仍可读取。
- 稳定项键不得在后续修订中复用为不同业务含义。

### 4.2 采集项不变量

- 双机部署检查项必须且只能配置一个所属组网模式子表；其他类型不得配置所属子表。
- 外部数据源启用时，接口标识、参数映射、返回映射和人工降级标识必须完整。
- 发布项引用的字典值和绑定维度必须启用且可从任务上下文判定。
- 同一采集项不得存在条件相同但结果互斥的有效规则；完全相同的匹配条件不得有相同优先级的多个有效结果。
- 发布校验不把参考附件行数硬编码为业务门禁；双机检查项仍须满足类型、所属子表、稳定键、启用引用和绑定规则通用校验。
- 双机检查发布基准只取正式PRD：VSM双机17项、静默双机25项、DRP双机23项、普通双机24项、集群8项，合计97项；原124不参与发布或验收。
- 风险“所有情况必选”项必须显式覆盖全部启用割接类型、设备类型和A/B/C级；升级后版本公告只适用于版本升级，五类双机项不得跨所属组网模式绑定。
- 调研矩阵必须覆盖PRD的12类核心内容；割接背景条件字段引用必须存在，条件显示不能绕过处于显示条件的必填校验。

## 5. 权限与数据范围

| 动作 | 权限码 | 服务端守卫 |
|---|---|---|
| 查询配置与历史 | `pms:cutover-config:query` | 当前租户；历史引用只读 |
| 创建/编辑草稿 | `pms:cutover-config:manage` | 当前租户、DRAFT、If-Match版本一致 |
| 发布配置 | `pms:cutover-config:publish` | 当前租户、DRAFT、完整性校验、发布CAS |
| 停用配置 | `pms:cutover-config:disable` | 当前租户、PUBLISHED、停用CAS |

前端按钮只作展示，Controller和Service必须重复执行权限、租户、状态、版本和引用校验。配置权限不授予割接任务、客户、设备、采集结果或外部系统数据访问权。

## 6. API契约草案

统一前缀为`/api/v1/pms/cutover-config`，HTTP层沿用平台统一`CommonResult`和分页响应：

- `GET /revisions`：按配置编码、状态分页查询修订摘要。
- `POST /revisions`：创建空白草稿。
- `GET /revisions/{revisionId}`：读取修订详情及发布校验摘要。
- `PUT /revisions/{revisionId}`：按`If-Match`整体保存草稿聚合，原子替换根信息、维度、采集项、绑定规则和方案章节。
- `POST /revisions/{revisionId}/actions/copy`：按`If-Match`复制任一历史修订为同配置编码的新草稿修订。
- `POST /revisions/{revisionId}/actions/validate`：执行无副作用发布预检并返回逐项错误位置。
- `POST /revisions/{revisionId}/actions/publish`：按`If-Match`发布；成功返回已发布修订摘要。
- `POST /revisions/{revisionId}/actions/disable`：按`If-Match`停用。

所有列表分页并稳定排序；状态命令不接受客户端直接写`statusCode`。

## 7. 数据与迁移草案

已批准基础载体：

- `cut_cutover_configuration_revision`
- `cut_cutover_checklist_item_definition_revision`
- `cut_cutover_checklist_binding_rule_revision`

三张表均为`NONE_NEW / FEATURE_FORWARD_MIGRATION`，不从`pms_cut_plan`、`pms_cut_risk`或需求附件反推当前业务主数据。配置根增加`plan_template_section_snapshot`结构化JSON列。迁移仅允许新增前向Flyway，最终版本号在集成时确定；不得修改V12、V13或V50。

## 8. 管理界面草案

- 页面以配置修订为第一层，清晰展示草稿、已发布、已停用状态和版本号。
- 草稿详情使用“基本信息 / 维度 / 业务调研项 / 风险考察项 / 双机检查项 / 绑定规则 / 方案模板 / 发布校验”分区，不把三类采集项拆成三个Owner页面。
- 风险矩阵和调研矩阵作为同一配置聚合的专用投影视图；批量编辑仍按根版本`If-Match`保存，不能形成独立发布状态。
- 已发布和已停用版本全部字段只读；“新建修订”是唯一编辑入口。
- 发布前展示错误总数和逐项定位；错误不能只用颜色表示。
- 提供加载、空数据、失败和权限不足状态；支持键盘操作及320/768/1024/1440视口。

## 9. 验收标准

- AC-FCUT001-001：有维护权限的管理员可创建草稿，稳定编码在租户内唯一；跨租户不可见。
- AC-FCUT001-002：三类采集项使用同一数据结构；双机项所属子表规则和非双机禁填规则生效。
- AC-FCUT001-003：V1四个维度均可配置并通过值来源、Owner和上下文路径校验；不可判定维度阻止发布。
- AC-FCUT001-004：重复编码、失效字典引用、外部源定义不完整、冲突绑定均阻止发布并返回逐项位置。
- AC-FCUT001-005：发布成功后全部子项不可修改；复制为新修订后才可变更，历史版本保持可读。
- AC-FCUT001-006：同一草稿并发发布最多一个成功；失败请求不产生半发布版本或提前停用旧版本。
- AC-FCUT001-007：无发布权限、跨租户、错误If-Match和直接写状态均被服务端拒绝且无业务副作用。
- AC-FCUT001-008：双机检查项可按五类所属子表维护，参考附件内容不形成发布数量门禁或第二事实源。
- AC-FCUT001-009：方案模板章节随配置根草稿维护、发布后不可变，新修订可复制并修改，CUT-04后续按revision冻结消费。
- AC-FCUT001-010：真实MySQL迁移、后端自动化、前端组件测试和真实浏览器四档视口均通过，控制台无错误。
- AC-FCUT001-011：风险矩阵覆盖PRD正式风险类别，五类双机检查分别精确为17/25/23/24/8项；不足、超出或跨子表引用均阻止发布。
- AC-FCUT001-012：所有情况必选风险项覆盖全部启用割接类型、设备类型和A/B/C级；覆盖缺口、停用引用及同组合冲突逐项定位且保持旧发布版本有效。
- AC-FCUT001-013：调研矩阵覆盖12类核心内容，绑定级必填性、割接背景六字段及两组条件显示关系可维护并通过发布校验。
- AC-FCUT001-014：风险与调研专用视图只读写同一配置聚合，复制修订保留全部内容，任一部分校验失败不得部分发布。
- AC-FCUT001-015：参考XLSX/HTML只提供名称、说明、界面格式和排序参考，不产生数量、规则、不一致或完成结论。

## 10. Feature Ready Gate

当前结论：`NOT_READY / REVALIDATION_REQUIRED`。

原CUT-07基础实现和证据继续有效，但正式SDS要求同一Feature承接CUT-09/10首批配置基础，因此原Feature Ready只适用于已完成的CUT-07子范围。`CHG-PRD-2026-08-30-008`已关闭97项数量口径；本次扩展规格经用户书面复审后，方可重新形成Feature Ready结论并生成唯一新Technical Plan。
