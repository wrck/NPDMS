# F-CUS-001 客户主档与本地生命周期 Feature Spec

> 文档状态：`BASELINE`
> Feature Ready：`READY`
> Requirement：`CUS-03（V1）`
> 关联Requirement：`CUS-01`、`CUS-02`、`CUS-04`、`EQP-01`、`INT-03`；不宣称关联Requirement完成
> Owner Context：`CUS（客户与服务关系）`
> 目标实现载体：独立`pms-module-customer`与稳定`pms-module-customer-api`
> 外部协作Context：`PROJ（项目治理）`、`AST（资产管理）`、`PLT（基础平台能力）`、CRM Integration ACL
> 适用基线：PRD V1.8及批准增量`CHG-PRD-2026-08-23-002`；SDS Phase 1/2/3 `BASELINE`
> Technical Plan：仅在本Feature晋级`BASELINE / READY`且实现仓库锁定新规格提交后生成

## 1. 目标

建立由CUS拥有的客户主档，支持授权人员创建平台客户、组合查询、维护平台扩展字段、软删除和恢复，并保留字段变化、来源、外部映射和业务引用的完整审计。CRM权威字段与平台扩展字段分区保存；CRM不可用时允许创建显式标记的临时客户，但不得伪造CRM来源或自动覆盖来源冲突。

本Feature冻结客户与项目、设备、地点的跨域引用边界。CUS拥有客户身份和客户字段，不直接写PROJ项目、AST设备或AST地点业务表；项目与设备归属由各自Owner维护当前关系和时态历史，客户地点只保存AST Address/Site稳定引用。

## 2. Scope

### 2.1 包含

- 客户主档创建、精确查询、组合分页、详情和平台字段更新；
- 租户内客户编码唯一，CRM客户ID与平台客户稳定一对一映射；
- `CRM_SYNC/PLATFORM_CREATED/PLATFORM_TEMPORARY`等来源事实及来源状态；
- CRM权威字段只读和平台扩展字段独立维护；
- 平台临时客户创建、待匹配状态和人工确认所需差异展示；
- 客户启用、停用、软删除和恢复；
- 删除前通过公开引用守卫检查项目、设备、联系人、领域任务和外部问题记录；
- 客户对AST Address/Site的稳定引用、类型、来源版本和有效区间；
- 项目和设备归属摘要的公开查询，不复制PROJ/AST时态关系；
- 字段级权限、组织数据范围、联系方式脱敏、幂等、乐观锁和审计；
- 独立`pms-module-customer`目标边界及旧`pms-module-project`客户实现的迁移/退役要求；
- 真实MySQL约束、权限负向、并发和真实浏览器响应式验收。

### 2.2 CRM同步拆分

F-CUS-001定义CRM权威字段的本地承载、只读规则和稳定写入边界，不承接CRM连接器及同步运行闭环。

| 数据切片 | 权威Owner | F-CUS-001职责 | 拆出能力 |
|---|---|---|---|
| 客户编码、名称、等级、状态、归属销售及CRM联系方式 | CRM | 分列保存只读副本、来源键、来源版本、截止时间和同步状态 | `INT-03`负责认证、协议适配、事件/批次同步、乱序幂等、隔离、重试和对账 |
| 市场部、系统部、拓展部、子行业组合目录 | CRM；CUS保存本地目录副本 | 客户直接保存八个编码/名称字段，不保存`relationId` | `INT-03`同步`MarketRelation`目录和映射状态 |
| 平台标签、服务偏好和交付备注 | CUS | 由授权业务角色维护并独立版本化 | CRM同步不得覆盖或反向写回 |
| 客户服务等级 | CUS/CUS-02 | 只展示当前有效等级引用和来源版本 | `CUS-02`负责时态等级版本、策略和联动事件 |
| 客户地点 | AST拥有地点，CUS拥有引用 | 保存Address/Site稳定ID、引用类型、版本和有效区间 | AST通过`AssetLocationApi`维护地点实体和树 |

`INT-03`未完成时，本Feature可使用受控测试种子或已核验本地副本验证客户查询、字段Owner和降级展示，但不得将替身、手工写库或预置数据声明为CRM同步完成证据。

### 2.3 不包含

- CRM网络连接、认证、调度、游标、事件消费、批次、重试、补偿和对账；
- CRM字典映射工作台和V2扩展同步治理；
- `CUS-02`客户服务等级维护；
- `CUS-04`项目联系人管理；
- `CUS-01`用户资产库聚合视图；
- 项目或设备归属关系的写入、区间关闭和历史维护；
- Address、Site、SiteLocation实体或地点树维护；
- 自动合并未确认的临时客户和CRM客户；
- 把客户档案自动创建为基础平台用户账号；
- Deployment、SIT、UAT、Release和历史数据迁移授权。

## 3. 业务规则

### BR-FCUS001-001 客户身份与唯一性

- `customerId`是平台稳定内部标识；客户编码在租户内唯一，软删除后仍占用原编码，恢复沿用原ID。
- 一个CRM客户ID在租户内最多映射一个有效平台客户，一个平台客户最多存在一个当前CRM主映射；旧CRM ID、合并来源和历史映射不得删除。
- 创建前同时校验客户编码和外部映射。重复客户编码、同一CRM ID多映射或一个客户多当前CRM映射时拒绝写入并进入待处理。
- 不使用客户名称模糊匹配自动合并。名称相似、编码冲突或外部映射冲突只能由授权人员查看差异后受控处理。

### BR-FCUS001-002 字段Owner

- CRM拥有客户编码、名称、CRM等级、CRM状态、归属销售及正式映射确认的CRM联系方式等权威字段；建立CRM映射后，业务角色不能直接编辑这些字段。
- CUS拥有平台标签、服务偏好、交付备注、地点引用和其他已批准扩展字段。CRM写入命令不得覆盖平台字段。
- 客户和项目直接保存`marketCode/marketName/systemCode/systemName/expendCode/expendName/industryCode/industryName`八字段；`MarketRelation`仅是候选目录和对账副本，不作为持久化外键。
- 每个来源切片保存`sourceSystem/sourceKey/sourceVersion/dataAsOf/syncStatus`。来源失败保留最近成功值，空响应和旧版本不得清空当前有效值。

### BR-FCUS001-003 平台客户与临时客户

- CRM不可用或业务尚未取得CRM客户ID时，授权服务经理或项目经理可在各自数据范围内创建`PLATFORM_TEMPORARY`客户，必须填写客户编码、名称、创建原因和待对账标识。
- 平台临时客户不得填写伪造CRM客户ID、来源事件ID或CRM版本；页面明确显示临时来源和待匹配状态。
- CRM恢复后的匹配、冲突处理和受控合并由`INT-03`承接。F-CUS-001只提供稳定客户写接口、字段Owner守卫和引用迁移能力边界。
- 合并必须保留临时来源、字段差异决策、历史映射和业务引用迁移审计，不得覆盖后删除原历史。

### BR-FCUS001-004 更新、停用、删除与恢复

- 更新命令只允许修改调用者有权维护的平台字段；请求携带`If-Match`和幂等键，旧版本拒绝且不覆盖先成功结果。
- 停用客户不允许用于新项目、设备或联系人关系，但历史引用继续展示。停用不等于删除，不解除已有关系。
- 删除采用软删除。删除前调用PROJ、AST、CUS联系人及其他已登记Owner的公开引用守卫；任一守卫返回有效引用、未知、超时或不可用时拒绝删除。
- 删除成功保留客户、外部映射、字段历史和审计；默认查询不返回已删除客户。恢复沿用原ID、编码和映射，不得创建同编码新客户绕过守卫。
- 删除和恢复必须记录原因；同一客户的并发删除、恢复或更新最多一个基于当前版本成功。

### BR-FCUS001-005 跨域引用

- 项目当前客户和历史归属由PROJ拥有；设备当前客户、历史及租用/共管关系由AST拥有。CUS不得直接更新两域Repository或业务表。
- CUS详情通过PROJ/AST公开查询契约返回调用者有权查看的项目和设备摘要。来源不可用时该切片显示不可用，不把缓存数量当成完整真值。
- 客户地点只保存AST Address/Site稳定ID、引用类型、来源版本和有效区间。维护前通过`AssetLocationApi`校验存在、租户和版本；CUS不拥有地点树。
- 项目或设备归属与客户状态冲突时，由关系Owner阻止新关系生效或进入待核对；CUS不反向覆盖关系Owner事实。

### BR-FCUS001-006 权限与数据范围

- 查询先校验租户，再按组织客户范围、项目授权和字段权限裁剪；空组织、项目或客户集合返回空结果，不能省略条件扩大范围。
- 服务经理可在所属组织范围创建平台客户、维护平台扩展字段、软删除和恢复；项目经理可在本人负责或明确授权项目范围创建项目所需的平台客户、查看所属项目客户并维护项目使用的非权威扩展信息，但不得删除客户或修改CRM权威字段。
- CRM集成身份仅能调用正式CRM字段写入契约，不能维护平台扩展字段、删除客户或改变项目/设备关系。
- 联系电话、邮箱和其他个人信息按字段权限返回原值、脱敏值或不返回；列表、导出、详情和审计查询使用同一服务端规则。
- 前端按钮和字段禁用不代替服务端权限校验，角色名称不直接产生数据范围。

### BR-FCUS001-007 审计、历史与事件

- 客户创建、平台字段更新、CRM字段更新、停用、删除、恢复、地点引用和冲突处置均记录来源、前后值摘要、操作者、时间、operationId和traceId。
- 字段历史只追加，不覆盖；敏感联系方式在审计中使用字段名和摘要，不记录明文。
- 客户业务事实成功提交后可发布`CustomerUpdated` Outbox；事件冻结客户ID、动作、来源、版本和发生时间，不携带完整敏感联系方式。
- 通知、事件投递或下游投影失败不回滚已经提交的客户主档，消费者按`eventId`幂等重试。

## 4. API契约

所有业务路径继承`/api/v1/pms`前缀。

| 接口 | 操作 | 当前契约 |
|---|---|---|
| `/customers` | `GET` | 按客户编码、名称、行业、CRM级别、办事处、来源、状态和同步状态分页组合查询；空权限范围返回空 |
| `/customers` | `POST` | 创建平台或临时客户；幂等键必填；CRM来源字段不得由业务身份伪造 |
| `/customers/{id}` | `GET` | 返回字段Owner、来源版本、同步状态、平台扩展、地点引用及有权项目/设备摘要 |
| `/customers/{id}` | `PUT` | `If-Match`和幂等键必填；仅更新有权平台字段，CRM字段只读 |
| `/customers/{id}/actions/disable` | `POST` | 停用客户；要求原因、版本和幂等键，不删除历史关系 |
| `/customers/{id}/actions/delete` | `POST` | 软删除；要求原因、版本、幂等键并通过全部引用守卫 |
| `/customers/{id}/actions/restore` | `POST` | 恢复原客户ID、编码和映射；要求原因、版本和幂等键 |
| `/customers/{id}/locations` | `GET/POST/PUT` | 查询或维护AST地点稳定引用；写入前校验地点和版本，不创建地点实体 |
| `/customers/{id}/projects` | `GET` | 通过PROJ公开契约分页返回有权项目归属摘要和截止时间 |
| `/customers/{id}/devices` | `GET` | 通过AST公开契约分页返回当前直接归属和有权业务关联设备摘要 |

正式契约已冻结：INT-03只调用`CustomerMasterDataApi`；跨域删除守卫统一使用`CustomerReferenceGuardApi`并失败关闭；地点引用仅允许Address/Site并在写入前调用AST校验；权限拆分为查询、创建、更新、删除、恢复、敏感查看和导出；联系方式默认脱敏、特权明文；旧Owner以前向迁移一次性切换。

## 5. 数据与模块边界

- 新建独立`pms-module-customer`和稳定`pms-module-customer-api`；PROJ、AST与INT-03只依赖API模块。
- `Customer`是CUS聚合根；`MarketRelation`是CRM组合目录副本；`CustomerLocationReference`是AST地点时态引用；字段变化使用不可变历史或审计事实。
- 客户主表分列保存CRM权威字段、平台字段及来源元数据，不使用万能JSON替代已批准核心字段。
- 客户编码和当前CRM映射使用租户内稳定唯一约束；软删除不释放业务唯一键。
- 旧`pms-module-project`客户实现以前向迁移一次性退出，不设双写期；旧客户API立即退出，新路径固定为`/api/v1/pms/customers`。
- PROJ、AST和其他Context只保存客户逻辑ID及必要业务快照，不依赖CUS的Service、Mapper、Repository或业务表。
- 新查询遵守场景Query、类型安全单表查询和Mapper XML规则；所有迁移使用前向Flyway版本，不修改已执行SQL。

## 6. UI

- 提供客户列表、创建/编辑抽屉和客户详情。详情区分CRM权威字段、平台扩展字段、地点引用、项目摘要、设备摘要和变更历史。
- CRM字段使用只读视觉状态并展示来源、数据截止时间和同步异常；临时客户显示来源和待匹配状态，不伪装为CRM客户。
- 删除前展示服务端引用守卫结果；存在引用、未知或提供方不可用时不开放确认提交。
- 联系方式按当前字段权限脱敏。导出、复制和详情使用相同服务端权限，不在前端保存未脱敏缓存。
- 320/768/1024/1440宽度无页面级横向溢出；真实浏览器验证创建、更新、软删除、恢复、来源降级、权限负向和刷新持久化。

## 7. 验收标准

- `AC-FCUS001-001`：租户内客户编码唯一；重复编码和CRM映射冲突拒绝且不产生第二个有效客户，跨租户客户不可见。
- `AC-FCUS001-002`：授权服务经理可在组织范围创建平台客户，授权项目经理可在本人负责或明确授权项目范围创建项目所需的平台客户；两者创建的临时客户都必须保留原因和待对账状态，不能伪造CRM来源。
- `AC-FCUS001-003`：建立CRM映射后，CRM权威字段对业务角色只读；平台扩展字段可独立更新，任一来源更新不会覆盖另一Owner字段。
- `AC-FCUS001-004`：组合查询按租户、组织、项目和字段权限裁剪；空范围返回空，联系方式按权限原值、脱敏或隐藏。
- `AC-FCUS001-005`：停用客户不能用于新业务关系但历史可查；软删除在任一有效引用、未知或守卫不可用时拒绝，无引用时保留全部历史并从默认列表隐藏。
- `AC-FCUS001-006`：恢复沿用原客户ID、编码和外部映射；并发更新、删除和恢复只有基于当前版本的一个请求成功。
- `AC-FCUS001-007`：客户地点只保存AST稳定引用；无效、跨租户或旧版本地点拒绝，CUS不创建或更新AST地点实体。
- `AC-FCUS001-008`：客户详情中的项目和设备摘要来自Owner公开契约并按调用者权限裁剪；来源失败明确显示截止时间，不把不完整聚合标为完整。
- `AC-FCUS001-009`：同幂等键同请求重放不重复客户、历史、审计或事件；同键异请求、旧`If-Match`和权限失败无成功副作用。
- `AC-FCUS001-010`：旧project客户实现不会与新customer模块形成双写Owner；迁移或兼容路径具备自动化和真实MySQL证据。
- `AC-FCUS001-011`：真实MySQL验证唯一键、软删除保留、乐观锁、幂等和引用守卫无副作用；真实浏览器验证四档响应式和权限负向。
- `AC-FCUS001-012`：本Feature完成不宣称`INT-03`、`CUS-01`、`CUS-02`、`CUS-04`、项目/设备归属写入、Deployment、SIT、UAT或Release完成。

## 8. 测试与证据

实现阶段至少需要：

- 客户身份、字段Owner、临时来源和生命周期规则单元测试；
- 客户编码、CRM映射、软删除和恢复真实MySQL约束测试；
- PROJ、AST、联系人及其他引用守卫契约测试，覆盖有效引用、空引用、超时和未知；
- 功能权限、组织范围、项目范围、字段脱敏和跨租户负向测试；
- 乐观锁、幂等、并发删除/恢复和Outbox事务测试；
- CRM受控替身的最近成功值、空响应、旧版本和字段Owner隔离测试；
- 旧project客户实现迁移、兼容和禁止双写的架构测试；
- 真实浏览器创建、更新、停用、删除、恢复、来源异常和四档响应式闭环；
- 独立Feature Ready复审和代码评审。
