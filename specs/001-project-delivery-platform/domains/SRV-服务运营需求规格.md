## 1. 领域目标与边界

本领域只定义自身拥有的业务规则、数据、权限和验收标准；跨领域能力通过需求依赖、输入输出和事件协作，不复制其他领域Owner的业务事实。

## SRV-01 设备服务状态与停产停维提示

| 属性 | 内容 |
| ---- | ---- |
| 需求编号 | SRV-01 |
| 所属阶段 | 设备运行与持续服务 |
| 用户角色 | 服务经理、项目经理、客户、设备管理员 |
| 优先级 | P1 |
| 目标版本 | V2 |
| 复杂度 | 中 |
| 依赖条件 | 内部强前置：EQP-03设备档案库；集成依赖：CRM公告/服务数据、产品版本主数据 |
| 来源追溯 | FR-SRV-016 |

**业务场景与需求描述：**

在设备档案中展示在售、停产、停止服务等客观服务状态和生效日期，向受影响项目和设备责任人提示风险；不建设独立维保经营模块。

**核心业务规则：**

1. 服务状态、原因、通知级别和生效规则使用可配置字典；来源系统同步的数据保留来源版本和生效时间。
2. 停产不等于停止服务，停止服务状态只有在权威来源明确生效后才可展示；平台不得依据库存、领域任务或历史工单记录自行推断。
3. 提示按设备、项目和客户授权范围生成，可确认已读但不能修改权威状态。

**用户故事：**

作为服务经理，我希望在设备档案中及时看到停产停维风险，以便安排客户沟通或替换计划。

**验收标准：**

- **WHEN** CRM或产品主数据同步服务状态
- **THEN** 设备档案展示状态、来源、生效日期和影响说明
- **WHEN** 设备处于停止服务状态
- **THEN** 向授权责任人生成提示并可关联现有SRV服务提示/任务；ACC-05持续服务跟踪仅在V3启用后可作为进一步关联对象
- **WHEN** 来源状态被撤回或更正
- **THEN** 平台按新版本更新当前状态，历史状态和通知记录保留

**涉及数据字段：**

设备ID、产品线、服务状态、状态原因、来源系统、来源版本、生效日期、影响范围、提示级别、已读记录

**权限与数据范围：**

设备责任人、项目成员和服务经理按项目授权查看；客户只能查看其设备；状态维护仅限同步接口或主数据管理员。

**异常、降级及留痕要求：**

同步失败保留上次状态并标注数据时点，不生成虚假停维提示；记录来源报文、状态变更、提示发送和已读确认。

**依赖关系：**

- 前置依赖：EQP-03设备档案库、CRM/产品主数据
- 后续依赖：无
- 关联依赖：ACC-05持续服务跟踪（仅V3启用后可关联）；不依赖备件库存或独立续保模块
## INS-01 巡检任务管理

| 属性 | 内容 |
| ---- | ---- |
| 需求编号 | INS-01 |
| 所属阶段 | 巡检专项 |
| 用户角色 | 一线工程师 |
| 优先级 | P1 |
| 目标版本 | V2 |
| 复杂度 | 中 |
| 依赖条件 | 内部强前置：平台项目服务、客户档案、设备档案 |

**业务场景与需求描述：**

巡检任务是巡检流程主线的起点，提供统一入口与全生命周期管理能力，任务来源包含两类。当项目交付过程中达到巡检节点（如设备入网后定期巡检），或项目正常闭环后基于客户、项目和设备历史关系触发例行巡检时，平台应发布内部业务事件生成独立巡检任务，并关联项目编码、合同号、设备清单、客户信息等；项目闭环后的巡检任务拥有独立领域生命周期，不修改项目`current_stage`或`lifecycle_status`，触发规则由后台配置。当一线工程师根据现场实际情况自建任务时，系统应支持录入客户、项目、设备清单、巡检背景等基础信息，并选择巡检方式（在线/离线，详见INS-02）与适用巡检规则（详见INS-03）。

巡检任务创建后进入"待准备"状态，先完成INS-02.S1巡检方式选择和INS-03规则选择：选择在线巡检时，进入INS-04连通性预检，预检通过后进入INS-02.S2在线执行；选择离线巡检时，直接进入INS-02.S2离线脚本执行与结果上传；两条执行分支完成后统一进入INS-05报告生成、INS-06问题标注和INS-07闭环归档（INS-02.S1与INS-02.S2是同一需求内的两个业务步骤，不构成INS-02与INS-04之间的需求依赖循环）。任务支持查看任务详情、关联设备清单、关联项目档案、来源业务事件和状态流转历史等。

**核心业务规则：**

1. 内部事件按来源事件ID幂等生成任务；自建任务必须关联客户、项目、设备和巡检背景，设备须属于项目或有明确参与关系。
2. 任务状态受控为待准备、待预检、巡检中、待报告、待标注、待办跟踪中、已闭环、已归档、已取消，不能跳过报告、标注和跟踪门禁。
3. 创建时冻结设备清单，执行时冻结巡检方式和规则版本；变化形成新执行版本，不覆盖历史结果。

**用户故事：**

作为一线工程师，我希望项目达到巡检节点时平台通过内部业务事件自动生成巡检任务并预填客户、项目、设备等关键信息，同时支持根据现场情况手动创建巡检任务，以便统一巡检任务入口、避免重复录入并确保任务与项目数据可追溯关联。

**验收标准：**

- **WHEN** 平台发布有效巡检事件或工程师提交完整自建任务
- **THEN** 巡检服务生成唯一"待准备"任务，保存来源事件、客户、项目和设备清单快照
- **WHEN** 任务完成规则/方式选择并满足对应前置条件
- **THEN** 平台按在线或离线路径更新到待预检/巡检中，并记录状态流转和执行版本
- **WHEN** 来源事件重复、设备与项目不匹配、必填数据缺失或用户无项目权限
- **THEN** 平台返回既有任务或拒绝创建/流转，保持当前业务对象状态不变

**涉及数据字段：**

巡检任务编号、任务来源（项目模块内部触发/自建）、来源业务事件编号、客户编码、客户名称、项目编码、合同号、设备序列号清单、巡检背景描述、巡检方式（在线/离线，关联INS-02）、适用巡检规则清单（关联INS-03）、巡检计划时间、任务状态、创建人、创建时间、当前责任人、状态流转历史、关联项目档案标识

**权限与数据范围：**

工程师可创建和执行本人授权项目/设备任务，服务经理可分配、取消和查看授权项目任务；项目管理权不自动授予设备凭证使用权。跨项目、跨租户及未授权平级任务不可见。

**异常、降级及留痕要求：**

来源事件、设备校验或状态流转失败时任务保持原状态，可按事件/任务版本重试；部分设备失败逐台记录，不把任务标为全部成功。平台记录来源、设备/规则/方式版本、状态前后值、取消原因和失败。

**依赖关系：**

- 前置依赖：平台项目服务及内部业务事件（项目档案、设备清单、巡检节点）、客户档案（关联CUS-01用户资产库）、设备档案（关联EQP-01设备序列号档案）
- 后续依赖：INS-02双巡检方式（任务创建后选择巡检方式）、INS-03巡检规则管理（任务关联巡检规则）、INS-04巡检连通性预检（在线巡检任务需预检）、INS-05巡检报告生成（巡检执行后生成报告）、INS-07巡检闭环归档（归档至平台客户资产库）
- 关联依赖：NFR-03割接/巡检节点通知与内部事件（巡检Step1~5发布内部项目进度事件）、权限体系（一线工程师创建权限）

## INS-02 双巡检方式选择与执行

| 属性 | 内容 |
| ---- | ---- |
| 需求编号 | INS-02 |
| 所属阶段 | 巡检专项 |
| 用户角色 | 一线工程师 |
| 优先级 | P1 |
| 目标版本 | V2 |
| 复杂度 | 高 |
| 依赖条件 | 内部强前置：INS-01巡检任务、INS-03巡检规则；集成依赖：INT-12设备连接与采集平台集成及INS-04预检通过结果（在线分支执行门禁） |

**业务场景与需求描述：**

本需求为巡检服务的核心执行能力，提供在线巡检与离线巡检两种方式，灵活适配不同设备场景，包含两个顺序明确的内部步骤：INS-02.S1负责选择在线或离线方式；INS-02.S2负责执行对应分支。在线分支必须在S1选择后先完成INS-04预检，再返回S2通过INT-12复用现有采集平台执行；离线分支从S1直接进入S2下载脚本、现场执行并上传结果。平台只管理设备认证信息、任务下发、数据回调及巡检业务结果，不建设设备连接与采集执行引擎；UMC不参与INS-02执行，仅在INS-05作为可选的巡检结果解析与报告文件生成服务。

**在线巡检（SSH/TELNET）：**

1. **适用场景**：设备可达、网络连通且允许通过SSH/TELNET远程登录的场景，现有采集平台通过SSH或TELNET协议连接设备执行巡检命令，实时采集巡检结果。
2. **统一入口**：一线工程师从巡检任务内进入INT-12设备连接与采集中心，系统自动带入巡检任务、项目和设备上下文；V2启用巡检入口，复用V1已经稳定的公共契约。
3. **设备连接与认证**：设备IP、SSH/TELNET端口和序列号从设备档案带入或现场补充；工程师可选择本人有权使用的设备凭证，也可临时输入登录用户名、密码（临时连接信息）并按需显式保存为设备凭证。巡检任务保存认证方式：凭证模式保存凭证ID、版本和授权快照，临时模式保存登录用户名但不保存密码。
4. **执行流程**：选择在线巡检 → 选择设备凭证或临时输入认证 → 校验设备连接端点、巡检规则命令模板和对应权限/输入 → 通过INT-12下发INS-04预检任务 → 预检通过后下发在线巡检采集任务 → 现有采集平台连接设备执行命令并回调状态与结果 → SRV消费结果并流转至INS-05报告生成。
5. **UMC外部接口集成**：UMC外部接口可集成，用于巡检结果解析与报告文件生成；设备连接、凭证取用和原始采集执行统一通过INT-12，不在INS-02或UMC集成中重复维护凭证明文。
6. **超时控制**：巡检命令执行超时≤30秒（可配置，NFR-02），超时后自动终止并标记该命令执行失败。

**离线巡检（脚本下载/结果上传）：**

1. **适用场景**：设备不可达、网络隔离或安全策略禁止远程登录的场景，一线工程师现场使用离线脚本执行巡检。
2. **脚本下载**：平台根据巡检任务关联的巡检规则（INS-03）自动生成巡检脚本（包含所有勾选检测项的执行命令），一线工程师下载巡检脚本至本地或现场终端。
3. **现场执行**：一线工程师在现场设备上手动执行巡检脚本，脚本自动采集巡检结果并生成本地结果文件（含设备信息、执行命令、执行结果、执行时间等）。
4. **结果上传**：一线工程师将本地结果文件上传至平台，平台解析结果文件并流转至INS-05报告生成。
5. **结果文件格式**：结果文件采用标准化格式（如XML/JSON/CSV），确保平台可解析；结果文件包含设备序列号、检测项ID、执行命令、执行结果、严重级别、执行时间等字段。

**核心业务规则：**

1. 在线方式复用INT-12下发与回调，不自建设备连接引擎；离线方式生成规则版本对应脚本并接收结果文件，两者产出统一设备级结果。
2. 在线必须通过INS-04，使用有权设备凭证或临时连接信息；临时模式只保存登录用户名，密码不落库。离线结果必须关联脚本哈希和规则版本。
3. 在线失败可显式切换离线并创建新执行尝试，保留原失败证据，不把失败任务原地改成离线成功。

**用户故事：**

作为一线工程师，我希望根据设备场景灵活选择在线或离线巡检；在线巡检时可使用已保存的设备凭证，也可临时输入登录用户名、密码，常用账号可显式保存为加密凭证，以便兼顾临时连接效率与凭证复用，并确保密码不留存、执行结果可追溯。

**验收标准：**

- **WHEN** 一线工程师在巡检任务中选择"在线巡检"方式
- **THEN** 系统进入INT-12设备连接与采集中心并带入巡检任务、项目和设备上下文，展示本人有权使用的设备凭证、临时连接信息输入方式与INS-03已发布命令模板
- **AND** INS-04预检通过后创建在线巡检采集任务，现有采集平台连接设备执行命令并回调巡检结果与日志文件，SRV接收并流转至INS-05报告生成
- **AND** 临时输入模式只保存登录用户名，不保存密码；巡检任务、接口调用记录、回调、日志和导出内容均不得包含密码/密钥明文
- **WHEN** 在线巡检命令执行时间超过30秒（可配置）
- **THEN** 系统自动终止该命令执行并标记为"执行失败"，巡检结果中记录超时失败项
- **AND** 一线工程师可在巡检结果中查看超时失败项详情并决定是否重试
- **WHEN** 一线工程师在巡检任务中选择"离线巡检"方式
- **THEN** 平台根据巡检任务关联的巡检规则自动生成巡检脚本（包含所有勾选检测项的执行命令），一线工程师可下载脚本至本地或现场终端
- **AND** 脚本中包含设备序列号、检测项ID、执行命令、预期结果正则、超时时间等字段（关联INS-09配置字段，见11.4.2）
- **WHEN** 一线工程师现场执行巡检脚本后上传结果文件
- **THEN** 平台解析并保存标准化结果文件（如XML/JSON/CSV）的设备信息、检测项结果、严重级别和文件哈希
- **AND** 解析后的结果流转至INS-05报告生成环节，解析失败时提示一线工程师结果文件格式错误并支持重新上传
- **WHEN** 平台调用UMC解析结果或生成报告
- **THEN** 平台只发送不含凭证明文的结果引用和上下文，并保存UMC返回结果或失败记录
- **WHEN** 预检失败、凭证无权、下发/回调超时、离线文件不匹配或工程师切换方式
- **THEN** 平台保留本次执行为失败记录且任务不进入待报告；修正后可重试或创建新的离线执行尝试

**涉及数据字段：**

巡检任务编号、巡检方式（在线/离线）、INS-02内部步骤（S1方式选择/S2分支执行）、在线巡检协议（SSH/TELNET）、设备连接端点（IP/端口）、设备序列号、认证方式（设备凭证/临时连接信息）、设备凭证ID及版本、凭证授权快照、临时登录用户名、保存为凭证标识、INS-04预检结果引用、统一采集任务编号、外部任务号、外部状态原值、平台映射状态、采集结果引用、巡检脚本ID、巡检脚本下载时间、巡检脚本下载人、离线结果文件ID、离线结果文件上传时间、离线结果文件解析状态、巡检命令执行超时时间（默认30秒，可配置）、执行结果列表（检测项ID/命令模板ID及版本/执行结果/严重级别/执行时间/是否超时）；临时连接信息不保存密码

**权限与数据范围：**

## INS-03 巡检规则管理

| 属性 | 内容 |
| ---- | ---- |
| 需求编号 | INS-03 |
| 所属阶段 | 巡检专项 |
| 用户角色 | 一线工程师、管理员 |
| 优先级 | P1 |
| 目标版本 | V2 |
| 复杂度 | 中 |
| 依赖条件 | 内部强前置：巡检规则库（后台维护，字段定义见INS-09） |

**业务场景与需求描述：**

巡检规则库是巡检服务的标准化支撑能力，按10大检测分类组织巡检规则，每条规则关联检测ID、检测项目、巡检执行命令和严重级别，前端勾选后台自动关联命令。本需求为巡检模块重点需求，标准化巡检内容、降低个人经验依赖；每条规则的8个配置字段（规则名称/描述/命令列表/执行顺序/超时时间/预期结果正则/结果阈值/适用产品类型）由INS-09细化定义（见11.4.2）。

**巡检规则库10大检测分类：**

1. **①基础检测**：设备基本信息检测，包括设备型号、序列号、软件版本、硬件版本、运行时长、系统时间等基础信息采集与校验。
2. **②运行状态检测**：设备运行状态检测，包括CPU利用率、内存利用率、温度、风扇状态、电源状态、接口状态等运行关键指标检测。
3. **③日志检测**：设备日志检测，包括系统日志、告警日志、错误日志的采集与关键字匹配，识别异常日志模式。
4. **④业务状态检测**：业务运行状态检测，包括业务接口连通性、业务流量、业务响应时间、会话状态等业务关键指标检测。
5. **⑤冗余性检测**：设备冗余性检测，包括主备切换状态、双机热备状态、集群成员状态、冗余链路状态等冗余配置检测。
6. **⑥路由检测**：路由协议检测，包括路由表、邻居状态、路由收敛、路由策略等路由相关检测。
7. **⑦安全检测**：设备安全检测，包括ACL配置、安全策略、登录权限、证书状态、安全日志等安全相关检测。
8. **⑧转发通道检测**：转发通道检测，包括转发路径、隧道状态、MPLS、VPN通道等转发相关检测。
9. **⑨负载均衡设备专用**：负载均衡设备专用检测，包括VS状态、池成员状态、健康检查、会话保持、负载分配等负载均衡专属检测。
10. **⑩流量清洗设备专用**：流量清洗设备专用检测，包括清洗策略、清洗阈值、攻击防护、流量回注等流量清洗专属检测。

**规则字段关联：**

每条巡检规则关联以下核心字段：

- **检测ID**：规则的唯一标识，用于规则检索与结果关联。
- **检测项目**：规则的检测项目名称，如"CPU利用率检测"、"主备切换状态检测"等。
- **巡检执行命令**：规则对应的巡检执行命令（SSH/TELNET命令或脚本命令），由后台自动关联，一线工程师前端勾选检测项后无需手动编写命令。
- **严重级别**：规则对应的严重级别，分为**一般/严重/致命**三级：
  - **一般**：轻微异常或提示性信息，不影响业务运行，需关注但不紧急。
  - **严重**：明显异常或潜在风险，可能影响业务运行，需及时处理。
  - **致命**：严重故障或业务中断，需立即处理。

**前端勾选后台自动关联命令：**

一线工程师在巡检任务中按10大检测分类浏览规则库，勾选需要执行的检测项。系统后台自动关联每条勾选规则对应的已发布巡检命令模板，生成巡检命令清单（在线巡检通过INT-12下发至现有采集平台，离线巡检打包至巡检脚本）。一线工程师无需且默认不允许手动编写任意设备命令，降低个人经验依赖与命令错误风险。

**管理员后台维护：**

管理员在后台维护巡检规则库的内容定义（10大检测分类、规则字段、执行命令、严重级别、适用产品类型等，详见INS-09配置字段，见11.4.2）。一线工程师仅在前端勾选规则，不可修改规则内容。

**核心业务规则：**

1. 十类检测分类和严重级别使用基础平台字典；规则按草稿、已发布、已停用和版本管理，发布后不可原位覆盖。
2. 规则必须明确适用设备/版本、检测项、命令模板、判定逻辑和严重级别；任务创建时冻结规则版本，后台换版不改变历史任务。
3. 命令模板发布前执行安全审查，禁止未授权高风险或交互式命令；审核事实只追加，不覆盖或删除历史。
4. 同租户、同revision和同命令/正则内容摘要按审核时间与事实ID倒序选择最后结论，仅最后`PASSED`允许发布；停用规则禁止新选用但保留历史解释。

**用户故事：**

作为一线工程师，我希望在巡检任务中按10大检测分类浏览巡检规则库，勾选需要执行的检测项后系统后台自动关联对应的巡检执行命令，无需手动编写命令，以便标准化巡检内容、降低个人经验依赖、避免命令错误、确保巡检覆盖全面。

**验收标准：**

- **WHEN** 一线工程师在巡检任务中浏览巡检规则库
- **THEN** 系统按10大检测分类（①基础检测②运行状态检测③日志检测④业务状态检测⑤冗余性检测⑥路由检测⑦安全检测⑧转发通道检测⑨负载均衡设备专用⑩流量清洗设备专用）展示规则库
- **AND** 每条规则展示检测ID、检测项目、严重级别（一般/严重/致命）、适用产品类型等字段，支持按分类/严重级别/产品类型筛选
- **WHEN** 一线工程师勾选若干检测项并提交
- **THEN** 系统后台自动关联每条勾选规则对应的巡检执行命令，生成巡检命令清单
- **AND** 巡检命令清单作为INS-02双巡检方式的输入（在线巡检作为INT-12采集任务的已发布命令模板，离线巡检打包至巡检脚本）
- **WHEN** 管理员在后台维护巡检规则库
- **THEN** 系统支持新增/编辑/启用/停用/排序巡检规则，每条规则可配置检测ID/检测项目/巡检执行命令/严重级别/适用产品类型等字段（详见INS-09，见11.4.2）
- **AND** 发布形成新规则版本，新任务展示当前有效版本，历史任务继续关联原版本
- **WHEN** 规则命令未通过安全审核、适用范围冲突、规则已停用或用户无发布权限
- **THEN** 平台拒绝发布或选择，旧版本保持有效且任务不生成未授权命令清单

**涉及数据字段：**

检测ID、检测分类（10大分类之一）、检测项目名称、巡检执行命令、严重级别（一般/严重/致命）、适用产品类型、规则描述、启用状态、排序、维护人、维护时间、规则版本、安全审核权限码、授权类型、授权来源ID（可空）、关联INS-09配置字段（规则名称/描述/命令列表/执行顺序/超时时间/预期结果正则/结果阈值/适用产品类型）

**权限与数据范围：**

巡检-管理员可维护和发布本租户规则，工程师只能选择适用于授权设备的已发布规则。审批/任务角色组以`pms:inspection-rule:security-review`专用权限表达；目标租户上下文建立后，由System现有`PermissionApi.hasAnyPermissions`对当前审核人重新判定，显式角色—菜单授权或System超级管理员任一命中均可审核。租户访问`skipPermissionCheck`只服务上下文切换，不能单独形成审核结论。任务使用者不能修改规则定义，跨租户规则不可见。

**异常、降级及留痕要求：**

规则校验、命令审查或发布失败时旧版本继续有效，新版本保持草稿；同revision同摘要以最后审核事实为当前结论，内容变化或新revision必须重新审核。审核权限撤销不追溯改写历史事实，需要撤销当前结论时追加`REJECTED`。System布尔权限判定为`false`、上下文缺失或调用异常时失败关闭且不记录审核事实；布尔结果不提供授权贡献路径，`authorizationSourceId`保持为空，不伪造角色—菜单来源。任务匹配冲突时阻止执行并列出冲突。平台记录规则/命令前后值、审核事实、发布停用、任务引用、失败和修正人时间。

## INS-09 巡检规则配置字段

| 属性 | 内容 |
| ---- | ---- |
| 需求编号 | INS-09 |
| 所属阶段 | 巡检专项 |
| 用户角色 | 管理员 |
| 优先级 | P1 |
| 目标版本 | V2 |
| 复杂度 | 低 |
| 依赖条件 | 内部强前置：INS-03巡检规则管理（规则库为本需求的配置对象） |

**业务场景与需求描述：**

本需求提供巡检规则的字段化配置能力，作为INS-03巡检规则管理的细化补充（巡检核心配置），管理员在后台通过8个配置字段精细化配置每条巡检规则。8个配置字段属于INS-03同一规则主数据，不另建重复规则表。

**8个配置字段：**

1. **规则名称**：巡检规则的名称，用于规则检索与展示，如"CPU利用率检测"、"主备切换状态检测"等。规则名称需唯一，便于一线工程师前端识别。
2. **描述**：巡检规则的描述说明，含检测目的、检测范围、注意事项等，帮助一线工程师理解规则含义。
3. **命令列表**：巡检规则对应的执行命令列表，支持单条或多条命令。多条命令按"执行顺序"字段依次执行，命令输出作为检测结果判定的输入。命令格式需适配SSH/TELNET协议与设备型号。
4. **执行顺序**：命令列表中各命令的执行顺序，以数字标识（如1、2、3）。在线巡检时作为已发布命令模板按顺序通过INT-12下发，离线巡检时按顺序打包至巡检脚本。
5. **超时时间**：单条命令的执行超时时间（秒），默认30秒（关联NFR-02巡检命令执行超时≤30秒）。超时后自动终止该命令并标记为"执行失败"。不同命令可配置不同超时时间，如简单命令5秒、复杂命令30秒。
6. **预期结果正则**：命令输出的预期结果正则表达式，用于判定检测结果是否通过。命令输出匹配正则则判定为"通过"，不匹配则判定为"异常"。正则表达式需兼容主流正则语法（如PCRE）。
7. **结果阈值**：检测结果的阈值配置，用于数值类检测项的判定。如"CPU利用率≤80%"中80%为阈值。阈值支持比较运算符（>、<、≥、≤、=、≠）与数值组合，超出阈值则判定为"异常"。
8. **适用产品类型**：巡检规则适用的产品类型清单，关联产品类型库。一线工程师前端勾选规则时，系统按设备清单的产品类型自动筛选适用规则，避免不适用规则被误选。

**配置流程：**

管理员在后台巡检规则配置页面，按10大检测分类（INS-03）选择规则所属分类，填写8个配置字段后保存为草稿；通过校验与安全审核并发布后生成新规则版本，发布版本对新任务生效（一线工程师前端勾选按最新发布版本展示），历史版本保留可回溯。

**核心业务规则：**

1. 八个字段属于INS-03同一规则主数据，不另建重复规则表；规则名称在租户和版本内唯一，命令顺序连续且不得重复。
2. 超时默认30秒并受NFR-02上限约束；正则须通过语法和复杂度校验，阈值须包含数据类型、运算符和单位，设备适用范围必须明确。
3. 发布后字段冻结为规则版本；修改命令、正则、阈值或适用范围均生成新版本，历史任务按原版本解释。
4. 安全审核结论只允许`PASSED/REJECTED`；审核事实只追加且仅`DRAFT`可追加，同租户、同revision及同内容摘要按`reviewed_at DESC, id DESC`选择最后结论，仅最后`PASSED`允许发布。内容摘要变化或新revision必须重新审核，审核与发布共享聚合锁/CAS，发布后纠正只能形成新草稿revision。
5. 记录安全审核时，租户访问拦截器先完成目标租户上下文切换，再由Inspection使用当前审核人调用System现有`PermissionApi.hasAnyPermissions`重新判定`pms:inspection-rule:security-review`。普通显式授权和System超级管理员均按现有布尔语义允许；不得只依赖`SecurityFrameworkService`的租户访问`skip`。判定失败或异常不追加事实，`authorizationSourceId`保持为空。

**用户故事：**

作为管理员，我希望在后台通过8个配置字段（规则名称/描述/命令列表/执行顺序/超时时间/预期结果正则/结果阈值/适用产品类型）精细化配置每条巡检规则，以便标准化规则定义、确保规则可配置可维护、支撑一线工程师前端勾选与后台自动关联命令。

**验收标准：**

- **WHEN** 管理员在后台巡检规则配置页面新增或编辑巡检规则
- **THEN** 系统提供8个配置字段（规则名称/描述/命令列表/执行顺序/超时时间/预期结果正则/结果阈值/适用产品类型）的录入界面
- **AND** 每个字段含输入校验（如规则名称必填且唯一、超时时间为正整数≤30、预期结果正则为合法正则表达式、适用产品类型关联产品类型库）
- **WHEN** 管理员配置命令列表与执行顺序
- **THEN** 系统支持单条或多条命令配置，多条命令按执行顺序依次执行
- **AND** 命令格式校验通过并发布后保存版本，INS-02在线巡检时按顺序通过INT-12下发、离线巡检时按顺序打包至巡检脚本
- **WHEN** 管理员配置预期结果正则与结果阈值
- **THEN** 系统校验正则表达式合法性，校验阈值格式（比较运算符+数值）
- **AND** INS-02巡检执行后按正则与阈值判定检测结果（通过/异常），异常项按严重级别（INS-03）标注
- **WHEN** 管理员配置适用产品类型
- **THEN** 一线工程师前端勾选规则时，平台按设备清单的产品类型筛选并展示适用规则
- **AND** 不适用规则在前端置灰或隐藏，避免误选
- **WHEN** 管理员保存规则配置
- **THEN** 平台保存草稿；仅当同revision同当前摘要的最后安全审核事实为`PASSED`且其他发布校验通过时生成新规则版本，历史版本和审核事实保留可回溯
- **AND** INS-03规则库展示最新配置，INS-08误报反馈机制可基于误报分析优化这8个字段
- **WHEN** 正则存在语法/超时风险、阈值单位冲突、命令顺序重复、适用产品缺失或用户无发布权限
- **THEN** 平台拒绝发布并保持旧版本有效，返回字段级错误供管理员修正后重新校验

**涉及数据字段：**

规则ID、规则名称、规则描述、命令列表（命令ID/命令内容/执行顺序）、执行顺序、超时时间（秒）、预期结果正则、结果阈值（比较运算符/数值）、适用产品类型清单、规则所属检测分类（10大分类之一）、严重级别（一般/严重/致命，关联INS-03）、启用状态、规则版本、维护人、维护时间、历史版本记录

**权限与数据范围：**

巡检-管理员可维护草稿，审批/任务角色组通过专用权限批准命令/正则后发布；目标租户普通授权用户和System超级管理员均按现有`PermissionApi`布尔结果获得审核资格，维护权或发布权本身不自动替代专用权限。工程师只读选择适用规则。命令可能含敏感参数时按字段权限脱敏，跨租户规则不可见。

**异常、降级及留痕要求：**

正则超时风险、阈值单位冲突、命令顺序缺失或最后安全审核事实非`PASSED`时禁止发布，旧版本继续有效；同摘要追加`PASSED -> REJECTED`后阻断，追加`REJECTED -> PASSED`后恢复发布资格，`reviewed_at`相同按更大事实ID裁决。System权限判定为`false`或异常时不记录审核；审核权限撤销不改写历史。平台记录八字段前后值、校验/审核、发布停用、任务引用和失败原因，布尔权限结果的授权来源ID保持为空。

## INS-04 巡检连通性预检

| 属性 | 内容 |
| ---- | ---- |
| 需求编号 | INS-04 |
| 所属阶段 | 巡检专项 |
| 用户角色 | 一线工程师 |
| 优先级 | P1 |
| 目标版本 | V2 |
| 复杂度 | 中 |
| 依赖条件 | 集成依赖：INT-12设备连接与采集平台集成 |

**业务场景与需求描述：**

本需求为在线巡检的前置验证环节，在执行巡检命令前通过INT-12下发预检任务，由现有采集平台校验设备连通性与账号有效性。本需求为在线巡检（INS-02）的前置依赖环节，离线巡检无需预检；本平台不直接连接设备。

**预检内容：**

1. **TELNET/SSH端口连通性**：校验设备IP地址的TELNET（默认端口23）或SSH（默认端口22）端口是否可达，端口可配置。端口不可达时提示一线工程师检查设备网络或端口配置。
2. **账号有效性**：工程师可选择本人有权使用的设备凭证，也可临时输入登录用户名、密码。现有采集平台在当次任务执行期间使用所选认证信息尝试登录设备，校验账号、密码/密钥和巡检所需权限是否有效。平台仅展示预检结论，不展示密码或密钥明文；临时模式只保存登录用户名，不保存密码。

**预检流程：**

一线工程师在巡检任务中选择在线巡检方式、设备及认证方式后，系统通过INT-12创建预检采集任务。预检通过后流转至INS-02在线巡检执行环节；预检失败时提示不泄露密码/密钥明文的失败原因（端口不可达/账号无效/凭证错误/权限不足等），工程师可修正连接端点、选择其他有权使用的凭证，或重新输入临时连接信息后再次预检。

**核心业务规则：**

1. 预检是INT-12下发的独立采集任务，按巡检任务、设备、端点和认证快照幂等；仅校验连通、认证和所需权限，不执行正式巡检命令。
2. 通过结果绑定设备、端点、认证方式和有效期；任一项变化或结果过期必须重新预检，旧结果不能复用。
3. 失败原因仅显示端口不可达、认证失败、权限不足等分类，不回显密码、密钥或采集端敏感原文。

**用户故事：**

作为一线工程师，我希望在执行在线巡检命令前，系统自动校验TELNET/SSH端口连通性与账号有效性，避免因连通性问题导致巡检命令执行失败，以便提前发现问题、节省巡检时间、确保巡检执行顺利。

**验收标准：**

- **WHEN** 一线工程师在巡检任务中选择在线巡检方式和目标设备，并选择本人有权使用的设备凭证或临时输入登录用户名、密码
- **THEN** 系统按认证方式完成权限或输入校验后通过INT-12下发预检任务，由现有采集平台校验TELNET/SSH端口连通性与账号有效性
- **AND** 预检结果实时展示（通过/失败），失败时提示具体原因（端口不可达/账号无效/密码错误/权限不足等）
- **WHEN** 连通性预检通过
- **THEN** 平台把预检状态更新为"通过"并流转至INS-02在线巡检执行环节，通过INT-12下发巡检采集任务
- **AND** 预检通过状态记录至巡检任务，预检时间与预检人完整记录
- **WHEN** 连通性预检失败
- **THEN** 巡检任务保持"待预检"并保存失败分类，一线工程师修正连接端点或认证后可重新预检
- **AND** 预检失败记录（含失败原因、失败时间、设备连接信息）保存至任务历史，便于追溯
- **WHEN** 预检结果已过期、端点/认证已变化、回调验签失败或用户无凭证权限
- **THEN** 平台拒绝进入在线巡检并要求重新预检，不复用旧通过结果且不展示密码/密钥明文

**涉及数据字段：**

巡检任务编号、预检ID、统一采集任务编号、设备IP地址、预检协议（SSH/TELNET）、预检端口、认证方式（设备凭证/临时连接信息）、设备凭证ID及版本、授权快照、临时登录用户名、保存为凭证标识、预检结果（通过/失败）、预检失败原因（端口不可达/账号无效/凭证错误/权限不足）、预检时间、预检人、重试来源任务号、设备连接端点修正记录；临时连接信息不保存密码

**权限与数据范围：**

工程师只能对本人巡检任务和授权设备发起预检，并使用本人创建或显式授权凭证/临时认证；管理员只能查看脱敏状态，不能取用凭证或绕过任务范围。

**异常、降级及留痕要求：**

下发超时、回调验签失败或凭证失效时预检保持失败/待核对，不允许进入在线执行；工程师可修正端点、更换有权凭证或重新输入临时连接信息后重试。平台记录任务、端点、认证方式、结论、失败与重试，排除明文。

**依赖关系：**

- 前置依赖：INS-01巡检任务管理（业务上下文来源）、设备档案（设备连接端点来源，关联EQP-01）、INT-12设备连接与采集平台集成
- 后续依赖：INS-02.S2在线巡检执行（预检通过后方可创建在线巡检采集任务）
- 关联依赖：NFR-02设备凭证及巡检非功能需求、权限体系（一线工程师预检与凭证使用权限）

## INS-05 巡检报告生成

| 属性 | 内容 |
| ---- | ---- |
| 需求编号 | INS-05 |
| 所属阶段 | 巡检专项 |
| 用户角色 | 一线工程师 |
| 优先级 | P1 |
| 目标版本 | V2 |
| 复杂度 | 中 |
| 依赖条件 | 内部强前置：INS-02巡检结果；集成依赖：UMC接口（可选的巡检结果解析与报告文件生成服务） |

**业务场景与需求描述：**

本需求提供巡检报告业务对象的标准化生成、管理、下载与归档能力。SRV是巡检报告业务对象、报告状态、模板选择和归档关系的唯一Owner；UMC是可选的巡检结果解析与报告文件生成服务，其输出作为平台报告的输入和证据，不取得报告业务对象所有权。平台允许的报告格式集合为PDF/DOC/XML：UMC或平台基础模板生成时提供三种格式，人工上传时至少提供其中一种格式并仅展示实际已上传格式，便于归档、分享与后续问题处理。

**报告生成流程：**

1. **结果汇总**：INS-02巡检执行完成后，SRV汇总所有检测项的执行结果（含检测项ID、检测项目、执行命令、执行结果、严重级别、执行时间、是否超时等）。
2. **生成方式选择**：正常情况下调用UMC解析结果并生成报告文件；UMC不可用或生成失败时，具备权限的工程师可选择平台基础模板生成或人工上传报告。三种方式均由SRV创建并维护同一报告业务对象。
3. **生成结果归档**：SRV保存生成方式、模板版本、外部调用记录或人工上传记录、报告文件列表和失败原因。人工上传仅替代报告文件生成，至少上传一份PDF、DOC或XML格式文件，不要求补齐另外两种格式，也不触发平台格式转换；人工文件不得修改或覆盖原始巡检结果、UMC失败证据。
4. **报告下载**：报告生成后，一线工程师可下载报告业务对象实际具备的格式文件。UMC或平台基础模板生成路径提供PDF/DOC/XML三种格式；人工上传路径仅展示实际上传的允许格式：
   - **PDF格式**：适用于归档与正式分享，格式固定不可编辑。
   - **DOC格式**：适用于二次编辑，一线工程师可在下载后补充分析与建议。
   - **XML格式**：适用于系统间数据交换与二次解析，保留结构化数据。

**报告内容：**

- **设备信息**：设备序列号、设备型号、软件版本、客户名称、项目编码等基础信息。
- **巡检概览**：巡检任务编号、巡检方式、巡检时间、巡检人、检测项总数、通过数、异常数、致命/严重/一般问题分布。
- **检测项明细**：按10大检测分类展示每条检测项的执行命令、执行结果、严重级别、预期结果、实际结果、是否通过。
- **问题清单**：检出异常的检测项汇总，含问题描述、严重级别、建议处理方式。
- **严重级别统计**：按一般/严重/致命三级统计问题分布，可视化展示。

**核心业务规则：**

1. 平台是报告业务对象、状态、版本与归档关系Owner；UMC仅提供解析/文件生成，人工上传只替代文件生成，不改写原巡检结果。
2. 报告绑定巡检任务和执行结果版本；生成方式、模板版本、输入哈希和文件哈希冻结。重生成形成新版本，旧报告不可覆盖。
3. UMC/基础模板路径应产出PDF、DOC、XML，人工上传至少一种允许格式；只有文件安全校验和结果完整性通过才标记"可用"。

**用户故事：**

作为一线工程师，我希望巡检执行完成后由平台统一管理报告，并可通过UMC、平台基础模板或受控人工上传形成报告，支持PDF/DOC/XML三种格式下载，以便外部生成服务异常时仍能完成巡检闭环，同时保证原始结果和失败证据可追溯。

**验收标准：**

- **WHEN** INS-02巡检执行完成并汇总所有检测项结果
- **THEN** SRV创建唯一巡检报告业务对象，记录报告状态、生成方式和输入结果引用，并在正常路径调用UMC解析结果、生成结构化报告文件
- **AND** 报告包含设备信息、巡检概览、检测项明细、问题清单、严重级别统计等章节；UMC返回结果作为报告输入和证据，不直接控制报告业务状态
- **WHEN** UMC或平台基础模板完成报告生成
- **THEN** 平台保存PDF/DOC/XML文件版本和哈希，一线工程师可下载三种格式的报告
- **AND** PDF格式适用于归档与正式分享，DOC格式适用于二次编辑，XML格式适用于系统间数据交换
- **WHEN** UMC接口解析失败或报告生成失败
- **THEN** SRV记录失败原因和调用证据并支持受控重试，一线工程师可在任务详情中查看失败原因
- **AND** 具备报告生成权限的工程师可选择平台基础模板生成或人工上传报告；人工上传需记录文件、上传人、上传时间和说明，且不得覆盖UMC失败证据或原始巡检结果
- **AND** 人工上传至少包含一份PDF、DOC或XML格式文件，系统仅展示实际上传格式且不要求自动转换为其他格式
- **AND** 任一生成方式完成必填校验并形成有效报告后，SRV将报告状态更新为"已生成"，巡检任务流转至INS-06问题标注环节；未形成有效报告时停留在"待报告"
- **WHEN** 输入结果不完整、文件安全校验失败、用户无报告权限或生成服务超时
- **THEN** 报告保持"生成失败/不可用"，巡检任务停留"待报告"，不得进入问题标注并支持受控重试

**涉及数据字段：**

巡检任务编号、报告ID、报告Owner（SRV）、报告生成方式（UMC/平台基础模板/人工上传）、报告模板ID及版本、输入巡检结果引用、UMC接口调用记录（调用时间/调用参数摘要/返回结果引用）、UMC失败原因、报告文件列表（文件ID/格式/路径/来源）、人工上传人、人工上传时间、人工上传说明、报告生成时间、报告生成状态（待报告/生成中/已生成/失败）、可下载格式集合、设备信息（序列号/型号/版本/客户/项目）、巡检概览（任务编号/巡检方式/巡检时间/巡检人/检测项总数/通过数/异常数）、检测项明细列表（检测项ID/检测项目/执行命令/执行结果/严重级别/预期结果/实际结果/是否通过）、问题清单（问题描述/严重级别/建议处理方式）、严重级别统计（致命数/严重数/一般数）

**权限与数据范围：**

工程师可为本人任务生成、重试或上传报告，服务经理可审核和下载授权项目报告；UMC服务账号只能读取任务授权输入并回传文件。报告下载须执行项目、设备和敏感文件权限校验。

**异常、降级及留痕要求：**

UMC不可用或生成失败时可选基础模板或人工上传，原失败证据保留；文件存储/校验失败时报告保持"生成失败/不可用"，不进入标注。平台记录输入/模板/文件版本、生成方式、下载、失败和重试。

**依赖关系：**

- 前置依赖：INS-01巡检任务管理、INS-02双巡检方式（巡检结果作为报告输入）、INS-03巡检规则管理（检测项明细来源）；UMC接口为可选结果解析和文件生成服务
- 后续依赖：INS-06巡检问题标注（报告中的问题清单进入标注环节）、INS-07巡检闭环归档（报告作为归档内容之一）
- 关联依赖：基础平台附件能力（报告文件存储）、NFR-01平台性能、安全与兼容基线（文件上传≤50MB）、权限体系（一线工程师下载权限）；INT-11仅为V3可选企业归档增强

## INS-06 巡检问题标注

| 属性 | 内容 |
| ---- | ---- |
| 需求编号 | INS-06 |
| 所属阶段 | 巡检专项 |
| 用户角色 | 一线工程师 |
| 优先级 | P1 |
| 目标版本 | V2 |
| 复杂度 | 中 |
| 依赖条件 | 内部强前置：INS-01巡检任务管理、INS-05巡检报告生成；关联能力：权限体系、待办管理 |

**业务场景与需求描述：**

本需求提供巡检检出问题的标注处理能力。当INS-05报告生成并展示问题清单后，一线工程师应对每个检出问题进行分类标注，标注类型包括误报/不关注/确认跟踪三类，确认跟踪的问题进入待办跟踪环节。

**标注类型：**

1. **误报**：检出问题实际不存在或检测结果错误，一线工程师标注为"误报"。误报项进入INS-08误报反馈机制，导出分析后反向优化巡检规则。
2. **不关注**：检出问题实际存在但无需处理（如已知的非关键告警、不影响业务的轻微异常），一线工程师标注为"不关注"。不关注项不进入待办，但在报告中保留记录。
3. **确认跟踪**：检出问题实际存在且需要处理，一线工程师标注为"确认跟踪"。确认跟踪项进入待办跟踪环节（INS-07），分配责任人跟踪处理直至闭环。

**标注流程：**

一线工程师在巡检报告的问题清单中逐项标注每个检出问题。标注完成后，确认跟踪的问题自动生成待办项（含问题描述、严重级别、责任人、计划解决时间等），流转至INS-07闭环归档环节。误报项汇总至INS-08误报反馈机制。不关注项仅记录不进入待办。

**核心业务规则：**

1. 每个报告检出项必须且只能标注误报、不关注或确认跟踪之一；类型使用字典，提交后形成标注版本，修改须保留前后值和原因。
2. 误报必须填写误报原因并进入INS-08；不关注必须填写业务依据；确认跟踪必须指定责任人、计划时间并幂等创建一条待办。
3. 报告所有检出项均完成有效标注后任务才可离开待标注；规则或报告换版不追溯改写历史标注。

**用户故事：**

作为一线工程师，我希望对巡检检出的每个问题进行分类标注（误报/不关注/确认跟踪），确认跟踪的问题自动进入待办跟踪，以便区分问题真伪、聚焦真正需要处理的问题、确保确认跟踪的问题不被遗漏。

**验收标准：**

- **WHEN** 巡检报告生成完成并展示问题清单
- **THEN** 平台为每个检出项提供误报/不关注/确认跟踪标注并保存标注状态
- **AND** 标注时支持填写标注说明（如误报原因、不关注理由、确认跟踪的处理建议）
- **WHEN** 一线工程师将检出问题标注为"确认跟踪"并提交
- **THEN** 系统自动生成待办项（含问题描述、严重级别、责任人、计划解决时间），流转至INS-07闭环归档环节
- **AND** 待办项关联巡检任务编号与检出问题ID，支持从待办项跳转至巡检报告详情
- **WHEN** 一线工程师将检出问题标注为"误报"
- **THEN** 误报项汇总至INS-08误报反馈机制，支持导出分析
- **AND** 误报项在报告中保留记录但标记为"误报"，不进入待办
- **WHEN** 一线工程师将检出问题标注为"不关注"
- **THEN** 不关注项在报告中保留记录但标记为"不关注"，不进入待办
- **AND** 不关注项不进入INS-08误报反馈机制
- **WHEN** 任一检出项未标注、理由缺失、责任人无权或待办/误报联动失败
- **THEN** 巡检任务保持"待标注/联动失败"，平台阻止完成标注并允许修正后幂等重试

**涉及数据字段：**

巡检任务编号、检出问题ID、检测项ID、问题描述、严重级别（一般/严重/致命）、标注类型（误报/不关注/确认跟踪）、标注说明、标注人、标注时间、待办项ID（确认跟踪时生成）、待办项责任人、待办项计划解决时间、待办项状态、误报反馈关联ID（误报时关联INS-08）

**权限与数据范围：**

执行工程师可标注本人任务，服务经理可复核不关注及重大误报，待办责任人只能查看授权问题和证据。巡检-管理员可看脱敏误报数据，不能修改任务标注。

**异常、降级及留痕要求：**

待办或误报反馈创建失败时标注保持"联动失败"，任务不能完成标注；按检出项和标注版本幂等重试。责任人无权/失效时拒绝提交并要求重新分配。平台记录标注、理由、责任人、联动和失败。

**依赖关系：**

- 前置依赖：INS-01巡检任务管理、INS-05巡检报告生成（问题清单来源）
- 后续依赖：INS-07巡检闭环归档（确认跟踪项进入待办跟踪）、INS-08误报反馈机制（误报项进入反馈优化）
- 关联依赖：权限体系（一线工程师标注权限）、待办管理（确认跟踪项生成待办）

## INS-07 巡检闭环归档

| 属性 | 内容 |
| ---- | ---- |
| 需求编号 | INS-07 |
| 所属阶段 | 巡检专项 |
| 用户角色 | 一线工程师 |
| 优先级 | P1 |
| 目标版本 | V2 |
| 复杂度 | 中 |
| 依赖条件 | 内部强前置：平台客户资产服务（CUS-01） |

**业务场景与需求描述：**

本需求提供巡检待办的跟踪闭环与归档能力。INS-06确认跟踪的问题进入待办后，由责任人跟踪处理直至闭环，闭环后通过内部客户资产服务将巡检结果归档至CUS-01。

**闭环流程：**

1. **待办跟踪**：INS-06确认跟踪的问题生成待办项后，分配至责任人跟踪处理。责任人处理待办时记录处理过程、处理结果、处理时间等，支持多次跟进记录直至问题解决。
2. **闭环确认**：问题解决后，责任人提交闭环申请，一线工程师或服务经理确认闭环。闭环确认后待办状态变更为"已闭环"。
3. **归档平台客户资产库**：巡检任务中所有确认跟踪问题均已闭环后，巡检任务可归档。归档时通过内部客户资产服务关联巡检结果（含巡检报告、问题清单、处理记录等）至CUS-01，作为客户资产的历史巡检记录。

**归档内容：**

- 巡检任务基础信息（任务编号、客户、项目、设备、巡检时间、巡检人等）
- 巡检报告（INS-05生成的PDF/DOC/XML报告）
- 问题清单与标注记录（INS-06的标注结果）
- 待办处理记录（确认跟踪问题的处理过程与结果）
- 闭环确认记录（闭环人、闭环时间、闭环说明）

**核心业务规则：**

1. 每个确认跟踪项独立记录处理、证据和闭环申请；责任人提交、工程师或服务经理确认后才为已闭环，不能由任务状态批量覆盖。
2. 只有全部确认跟踪项已闭环、报告可用且标注完成，巡检任务才可归档；无跟踪项时仍须完成报告和标注确认。
3. 归档通过内部客户资产服务建立原任务、报告、问题和处理记录引用，不复制成失去来源的数据；归档后任务只读，修订形成新版本。

**用户故事：**

作为一线工程师，我希望确认跟踪的问题进入待办后由责任人跟踪处理直至闭环，闭环后巡检结果归档至平台客户资产库，以便确保巡检发现的问题不被遗漏、问题处理可追溯、客户资产库积累历史巡检记录便于后续查阅与分析。

**验收标准：**

- **WHEN** INS-06确认跟踪的问题生成待办项并分配至责任人
- **THEN** 责任人收到待办通知，可记录处理过程、处理结果、处理时间等跟进记录
- **AND** 待办项支持多次跟进记录，每次跟进记录含跟进人、跟进时间、跟进内容
- **WHEN** 责任人提交闭环申请
- **THEN** 一线工程师或服务经理确认闭环，闭环确认后待办状态变更为"已闭环"
- **AND** 闭环确认记录（闭环人、闭环时间、闭环说明）保存至待办详情
- **WHEN** 巡检任务中所有确认跟踪问题均已闭环
- **THEN** 巡检任务可归档，归档时通过内部客户资产服务将巡检结果关联至CUS-01
- **AND** 归档内容包含巡检任务基础信息、巡检报告、问题清单与标注记录、待办处理记录、闭环确认记录
- **WHEN** 巡检任务归档完成
- **THEN** 任务状态变更为"已归档"，归档时间与归档人完整记录
- **AND** 平台客户资产库中可查看该客户的历次巡检记录
- **WHEN** 存在未闭环跟踪项、报告不可用、标注未完成、资产引用失败或用户无归档权限
- **THEN** 平台拒绝归档并保持"待办跟踪中/归档失败"，列出阻断项且不在CUS-01展示为已归档

**涉及数据字段：**

巡检任务编号、待办项ID、待办项责任人、待办项状态（待处理/处理中/待闭环/已闭环）、跟进记录列表（跟进人/跟进时间/跟进内容）、闭环申请人、闭环申请时间、闭环确认人、闭环确认时间、闭环说明、归档标识、归档时间、归档人、平台客户资产库归档记录（归档ID/归档内容/归档时间）、关联CUS-01用户资产库标识

**权限与数据范围：**

待办责任人处理本人问题，工程师或服务经理按项目权限确认闭环，服务经理执行归档；CUS-01仅按原项目/客户权限展示引用。跨租户和未授权问题不可见。

**异常、降级及留痕要求：**

存在未闭环待办、证据缺失或资产引用失败时任务保持"待办跟踪中/归档失败"，不得标记已归档；修正后按任务版本重试。平台记录每次跟进、闭环确认、归档清单、引用结果、失败和重试。

**依赖关系：**

- 前置依赖：INS-01巡检任务管理、INS-06巡检问题标注（确认跟踪项生成待办）、平台客户资产服务（关联CUS-01，归档目标）
- 后续依赖：CUS-01用户资产库（归档后客户资产库积累历史巡检记录）
- 关联依赖：待办管理（待办跟踪机制）、INT-10短信/邮件平台集成（待办通知推送）、NFR-03割接/巡检节点通知与内部事件（巡检Step1~5发布内部项目进度事件）、权限体系（一线工程师归档权限、责任人处理权限）

## INS-08 误报反馈机制

| 属性 | 内容 |
| ---- | ---- |
| 需求编号 | INS-08 |
| 所属阶段 | 巡检专项 |
| 用户角色 | 管理员 |
| 优先级 | P1 |
| 目标版本 | V2 |
| 复杂度 | 中 |
| 依赖条件 | 内部强前置：INS-03巡检规则管理、INS-06巡检问题标注；关联能力：权限体系、报表统计 |

**业务场景与需求描述：**

本需求提供误报反馈的导出分析与巡检规则优化能力，将一线工程师标注的误报项（INS-06）导出分析，反向优化巡检规则库（INS-03），形成"巡检→标注→反馈→优化"的闭环改进机制，持续提升巡检规则准确率。

**误报反馈流程：**

1. **误报项汇总**：INS-06中标注为"误报"的检出问题自动汇总至误报反馈库，含检测项ID、检测项目、执行命令、执行结果、误报原因、标注人、标注时间、所属巡检任务等字段。
2. **导出分析**：管理员在后台查看误报反馈库，支持按检测分类、严重级别、设备型号、时间范围等维度筛选与统计。支持导出误报清单（Excel/CSV格式）进行离线分析。
3. **规则优化**：管理员基于误报分析结果优化巡检规则：
   - **调整预期结果正则**：误报原因为正则匹配过宽或过严时，调整INS-09中的"预期结果正则"字段。
   - **调整结果阈值**：误报原因为阈值设置不合理时，调整INS-09中的"结果阈值"字段。
   - **修改执行命令**：误报原因为命令输出不准确时，修改INS-09中的"命令列表"字段。
   - **停用规则**：误报率过高且无法优化时，停用该规则。
4. **优化效果跟踪**：规则优化后，系统跟踪该规则的误报率变化，验证优化效果。

**核心业务规则：**

1. 误报库按检出项和标注版本幂等收集，保留规则版本、设备型号、原始结果摘要、原因和标注人；取消误报形成状态变化，不删除历史。
2. 误报率分子为经巡检-管理员确认有效的误报数，分母为同规则版本实际检出数；必须展示样本数和统计期，不能跨规则版本直接合并解释。
3. 分析结论只能创建INS-03/INS-09规则修订草稿，须按规则发布流程生效；不得直接修改已发布规则或历史任务结果。

**用户故事：**

作为管理员，我希望将一线工程师标注的误报项导出分析，基于分析结果优化巡检规则（调整正则/阈值/命令/停用），并跟踪优化后的误报率变化，以便持续提升巡检规则准确率、减少无效告警、降低一线工程师标注负担。

**验收标准：**

- **WHEN** 一线工程师在INS-06中将检出问题标注为"误报"
- **THEN** 误报项自动汇总至误报反馈库，含检测项ID、检测项目、执行命令、执行结果、误报原因、标注人、标注时间、所属巡检任务等字段
- **AND** 误报反馈库支持按检测分类、严重级别、设备型号、时间范围等维度筛选与统计
- **WHEN** 管理员在后台查看误报反馈库并导出误报清单
- **THEN** 平台生成Excel/CSV导出记录和文件，保存筛选条件、样本数、数据截止时间及下载权限
- **AND** 导出的误报清单支持离线分析，便于管理员识别高频误报规则
- **WHEN** 管理员基于误报分析结果优化巡检规则（调整正则/阈值/命令/停用）
- **THEN** 系统支持在后台修改INS-09配置字段（预期结果正则/结果阈值/命令列表等），修改形成规则修订并按INS-03发布流程生效，规则版本更新
- **AND** 规则优化后系统跟踪该规则的误报率变化，展示优化前后误报率对比
- **WHEN** 管理员停用某条巡检规则
- **THEN** 该规则在INS-03规则库中标记为"停用"，一线工程师前端不再展示该规则
- **AND** 历史巡检任务中已执行该规则的结果保留不变
- **WHEN** 误报统计不完整、规则修订发布失败、用户无规则权限或导出超时
- **THEN** 平台保持当前发布规则不变，标记统计/导出失败并允许修正后重试，不改写历史任务结果

**涉及数据字段：**

误报反馈ID、检测项ID、检测项目、检测分类、执行命令、执行结果、误报原因、标注人、标注时间、所属巡检任务编号、设备序列号、设备型号、严重级别、误报反馈时间、导出记录（导出人/导出时间/导出格式/导出范围）、规则优化记录（优化前字段值/优化后字段值/优化人/优化时间/优化原因）、规则版本、误报率统计（优化前误报率/优化后误报率/统计周期）

**权限与数据范围：**

巡检-管理员查看本租户脱敏误报汇总、导出和创建修订草稿，工程师查看本人标注；原始配置和设备信息按字段权限控制，未授权项目与跨租户数据不可见。

**异常、降级及留痕要求：**

汇总或导出失败时展示最近成功截止时间且不发布不完整误报率；恢复后按标注ID重算。规则修订创建失败不改变当前规则。平台记录样本口径、导出、修订来源、发布关系、失败和重试。

**依赖关系：**

- 前置依赖：INS-03巡检规则管理（规则库优化对象）、INS-06巡检问题标注（误报项来源）
- 后续依赖：INS-03巡检规则管理（规则优化后反作用于规则库）、INS-09巡检规则配置字段（字段优化对象，见11.4.2）
- 关联依赖：权限体系（管理员分析与优化权限）、报表统计（误报率统计）
