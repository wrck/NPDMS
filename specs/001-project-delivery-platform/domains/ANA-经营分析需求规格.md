## RPT-02 项目状态统计

| 属性 | 内容 |
| ---- | ---- |
| 需求编号 | RPT-02 |
| 所属阶段 | 全局 |
| 用户角色 | 管理层、服务经理 |
| 优先级 | P1 |
| 目标版本 | V2 |
| 复杂度 | 中 |
| 依赖条件 | 内部强前置：项目数据（项目档案、当前阶段、生命周期状态、指派状态、所属办事处）、项目状态模型与阶段实例；关联能力：CLO-02、PM-10终态事实及PLN-03超期结果 |

**业务场景与需求描述：**

提供项目全状态分布、阶段分布、超期态势与分类闭环率统计能力，支撑管理层和服务经理按办事处及其他授权维度监控项目全集场景。RPT-02是项目状态统计的完整业务表达，不只统计闭环终态，也不得因新增终态分类而删减进行中阶段、图表下钻、时间筛选或导出能力。主要功能包含以下5部分：

1. **项目全状态统计**：按办事处及授权维度统计项目派生展示状态的数量分布。展示状态由`current_stage`、`lifecycle_status`、`assignment_status`、领域任务事实和超期事实共同派生，例如S0待指派/立项处理中、S1工前准备、S2施工计划、S3实施方案、S4实施部署、割接中、S5验收交维、S6闭环处理中、正常闭环、不予跟踪闭环、异常关闭；“维护中”不作为项目主生命周期状态。
2. **阶段与超期统计**：按冻结模板中的真实阶段实例统计S0～S6阶段项目数量、阶段完成情况和超期情况。模板未配置的阶段不生成缺失项；割接中等专项状态作为派生展示，不改写项目阶段或生命周期状态。
3. **分类闭环统计**：分别统计`NORMAL_CLOSED`、`NO_TRACKING_CLOSED`和`EXCEPTION_CLOSED`的数量、占比及明细，并提供正常交付闭环率和业务闭环率。不得使用单一“已关闭”指标掩盖三类退出结果。
4. **多维筛选与时间口径**：支持按时间范围、办事处、项目模板、签约方式、项目类别、实施方式、重大项目级别、当前阶段、生命周期状态和项目统计粒度筛选。办事处按部门主数据`department_code/department_name`承载，不引入独立办事处编码。
5. **图表下钻与导出**：状态分布、阶段分布、超期和闭环指标可使用柱状图、饼图、仪表盘等形式展示；任一数据点均可点击跳转到保留同一筛选条件和统计口径的项目列表，并可在权限范围内导出Excel。

**核心业务规则：**

1. 每个正式项目在同一统计时点只能形成一个当前`display_status`。`display_status`只读派生，不得反写`current_stage`、`lifecycle_status`或领域任务状态；同一项目可以同时具有超期、风险等附加标记，但不能因此重复计入项目总数。
2. 进行中项目按其真实`current_stage`和指派/领域事实派生展示；模板未配置的阶段不计为缺失、未完成或超期。闭环项目保留最后真实`current_stage`，并按`closed_from_stage`展示实际收口位置，不得伪造S5、S6或其他阶段完成数量。
3. **正常交付闭环率**=`NORMAL_CLOSED`项目数/筛选范围内正式项目总数×100%。`NO_TRACKING_CLOSED`不表示实施或验收成功，不进入正常交付闭环率分子。
4. **业务闭环率**=（`NORMAL_CLOSED`+`NO_TRACKING_CLOSED`）项目数/筛选范围内正式项目总数×100%，并必须同时展示两类分项数量；`EXCEPTION_CLOSED`单列统计，不进入正常交付闭环率或业务闭环率分子。
5. 分子、分母、阶段数量、超期数量和各终态数量均按项目ID去重。父子项目按用户选择的统计粒度计算：根项目口径只计根项目，项目节点口径各节点各计一次，不得混用两个粒度导致重复。
6. 时间筛选以项目创建时间、统计时点状态快照及所选口径执行；历史快照保存指标口径版本、状态版本和数据截止时间。项目范围、阶段或终态后续通过受控事实更正时，只刷新后续快照，不覆盖已发布历史快照。
7. 图表、下钻列表和导出必须复用完全相同的筛选条件、统计粒度、数据截止时间和项目权限。无权项目既不进入数量，也不在下钻或导出中泄露名称、状态或敏感字段。
8. 状态快照或统计批次部分失败时，该批指标标记“数据不完整/待重算”，展示最近一次成功数据截止时间和异常数量，不得把未知值计为0或发布为完整正式指标。

**用户故事：**

作为管理层，我希望按办事处及项目业务维度查看从S0到S6、专项进行态、超期和三类终态的完整项目状态分布，并从任一指标下钻到同口径项目明细，以便全面监控项目交付态势、阶段瓶颈和真实闭环质量。

作为服务经理，我希望区分正常交付闭环、不予跟踪闭环和异常关闭，并查看项目实际从哪个阶段收口，以便闭环率不被代理商自服或异常项目虚高，同时不丢失进行中项目的阶段统计。

**验收标准：**

- **WHEN** 用户选择时间范围、办事处、项目业务维度和项目统计粒度
- **THEN** 平台返回项目总数、全状态分布、S0～S6真实阶段分布、超期数量、三类终态数量、正常交付闭环率、业务闭环率及数据截止时间
- **AND** 每个项目在项目总数和当前状态分布中只计一次，超期等附加标记单独展示
- **WHEN** 查询闭环统计
- **THEN** 平台分别返回`NORMAL_CLOSED`、`NO_TRACKING_CLOSED`和`EXCEPTION_CLOSED`数量、占比及项目明细
- **AND** 正常交付闭环率只使用`NORMAL_CLOSED`作为分子，业务闭环率使用`NORMAL_CLOSED + NO_TRACKING_CLOSED`作为分子，异常关闭始终单列
- **WHEN** 模板不含S5/S6的项目从S4正常闭环
- **THEN** 全状态统计显示其为正常闭环，阶段收口分布显示`closed_from_stage=S4`，不得计为S5或S6阶段完成实例
- **WHEN** 用户点击任一状态、阶段、超期或闭环图表数据点
- **THEN** 平台跳转到保留相同筛选条件、统计粒度、口径版本和数据截止时间的项目列表，列表数量与图表一致
- **WHEN** 用户导出项目状态统计
- **THEN** 平台按当前筛选和权限生成Excel，包含口径说明、数据截止时间、分子分母及有权项目明细，并记录导出审计
- **WHEN** 当前阶段/生命周期状态缺失导致展示状态无法计算、统计批次部分失败、根/节点粒度未选择或用户无办事处权限
- **THEN** 平台标记待核对/数据不完整并拒绝混合口径，不显示无权项目数量与明细，也不得将未知状态计入正常项目或任一闭环分子

**涉及数据字段：**

办事处部门ID/编码/名称（`department_id/department_code/department_name`）、项目ID、项目模板及版本、签约方式、项目类别、项目实施方式、重大项目级别、当前阶段、阶段实例状态、生命周期状态、指派状态、派生统计展示状态、闭环类型、闭环来源阶段、超期标记/超期天数、项目数量、正常交付闭环数量及闭环率、业务闭环数量及闭环率、不予跟踪闭环数量、异常关闭数量、统计粒度、统计周期、口径版本、状态版本、数据截止时间、图表类型、跳转目标及筛选条件、导出文件及审计记录

**权限与数据范围：**

管理层按组织授权查看汇总和明细；服务经理仅查看本人责任项目、所属办事处项目及授权后代。图表、下钻和导出使用相同项目、组织、字段和文件权限；未授权平级项目、跨租户项目及敏感字段不进入统计或导出。闭环汇总权限不自动产生交付件、审批正文或客户敏感数据访问权。

**异常、降级及留痕要求：**

状态快照生成失败、下钻数量与图表不一致或导出数据版本漂移时，暂停发布该批正式指标，保留最近一次成功快照并显示数据截止时间；恢复后按项目ID和状态版本重算对账。平台记录统计条件、统计粒度、口径版本、状态版本、三类终态分子、正式项目分母、权限范围摘要、批次结果、下钻、导出、失败和重算时间。

**依赖关系：**

- 前置依赖：项目数据（项目档案、当前阶段、生命周期状态、指派状态、所属办事处）、项目状态模型、阶段实例和PLN-03超期结果
- 后续依赖：管理看板与项目组合分析
- 关联依赖：CLO-02正常/不予跟踪闭环事实、PM-10异常关闭事实、权限体系（管理层/服务经理数据范围）
## ANA-01 项目组合经营看板

| 属性 | 内容 |
| ---- | ---- |
| 需求编号 | ANA-01 |
| 所属阶段 | 全生命周期 |
| 用户角色 | 管理层、区域负责人、工程管理部 |
| 优先级 | P1 |
| 目标版本 | V2 |
| 复杂度 | 中 |
| 依赖条件 | 内部强前置：PROJ-12项目组合管理、项目指标；关联能力：数据快照 |
| 来源追溯 | FR-ANA-001 |

**业务场景与需求描述：**

提供组合、区域、客户及项目四维业务属性（签约方式、项目类别、项目实施方式、CRM重大项目级别）维度的经营看板，展示进度、风险、资源投入、合同履约和验收状态，并支持从指标下钻到项目证据。

**核心业务规则：**

1. 指标口径、刷新频率、异常阈值和维度均采用可配置字典或指标定义，不允许页面自行计算另一套口径。
2. 看板只读，不直接修改业务数据；指标必须标注统计时点、数据完整性和快照版本。
3. 下钻结果继承用户项目和组织权限，导出内容按字段脱敏规则处理。

**用户故事：**

作为管理层，我希望从组合健康度异常直接定位到项目、任务和风险证据，以便及时决策。

**验收标准：**

- **WHEN** 用户选择组合、区域、客户、签约方式、项目类别、实施方式或重大项目级别筛选条件
- **THEN** 看板按统一指标口径刷新并展示统计时点
- **WHEN** 用户点击异常指标
- **THEN** 系统下钻到授权范围内的项目、任务或风险清单
- **WHEN** 数据刷新失败
- **THEN** 页面提示数据时点并保留最近一次成功快照，不显示为最新数据

**涉及数据字段：**

指标编码、指标值、统计口径、统计时点、快照版本、维度值、异常阈值、数据质量标记、下钻对象ID

**权限与数据范围：**

按组合、组织和项目权限控制；管理层可看汇总，项目角色只能看本人授权项目；导出继承同一过滤条件。

**异常、降级及留痕要求：**

指标计算超时采用异步快照；数据源缺失标记"部分数据"；记录筛选条件、查看人、导出和下钻行为。

**依赖关系：**

- 前置依赖：PROJ-12项目组合管理、项目主数据、任务、风险、合同和验收数据
- 后续依赖：无
- 关联依赖：数据快照能力

## 6. 领域验收门禁

- 本领域正式需求全部直接来源于PRD需求块，业务验收标准以PRD为准。
- V1/V2需求不得以V3方向替代；V3不进入当前开发与验收。
- 领域状态必须遵循“初始化可扩展状态定义+受控状态机”；扩展状态不得绕过权限、责任、审批或证据门禁。
- 跨领域写入必须通过应用服务、接口或事件完成，不直接修改其他领域业务事实。
- 权限拒绝、版本冲突、重复提交、外部失败和人工降级必须保留可追溯记录。
