## RPT-01 工时多维统计

| 属性 | 内容 |
| ---- | ---- |
| 需求编号 | RPT-01 |
| 所属阶段 | 全局 |
| 用户角色 | 管理层、服务经理 |
| 优先级 | P1 |
| 目标版本 | V2 |
| 复杂度 | 中 |
| 依赖条件 | WO-01工单数据 |

**业务场景与需求描述：**

提供工时多维统计与图表展示能力，支撑工时分析决策。平台基于WO-01工单数据（含打卡工单与手动创建工单的工时申报明细），按5个维度进行工时统计：

1. **客户维度**：按客户统计工时，展示各客户工时占比、Top客户工时排行等。
2. **项目维度**：按项目统计工时，展示各项目工时占比、Top项目工时排行等。
3. **销售维度**：按销售统计工时，展示各销售工时占比、Top销售工时排行等。
4. **办事处维度**：按办事处统计工时，展示各办事处工时占比、Top办事处工时排行等。
5. **个人维度**：按工程师个人统计工时，展示各工程师工时占比、Top工程师工时排行等。

统计结果以柱状图、饼图、折线图、热力图等图表形式展示，支持时间范围筛选（如本月、本季度、本年、自定义时间范围）与多维度交叉分析（如"客户×办事处"交叉统计）。统计结果支持导出Excel。本需求依赖WO-01工单数据积累后建设，属P1需求。

**核心业务规则：**

1. 正式工时仅取WO-01/WO-04最终“已通过且可计入”的工时明细，草稿、驳回、撤回和同步失败未确认记录不进入统计。
2. 时间口径为工时发生日期，按平台业务时区；客户、项目、销售、办事处、个人维度取申报生效时快照，后续组织调整不无痕重算历史。
3. 同一工时明细ID只计一次；父项目汇总授权后代时按明细ID去重，总工时等于可下钻明细时数之和。看板显示数据截止时间和待同步数量。

**用户故事：**

作为管理层，我希望使用“工时多维统计”能力完成本条定义的业务活动，以便获得业务场景中明确的处理结果并能够追溯处理过程。

**业务验收标准：**

- **WHEN** 用户按时间和任一维度查询工时
- **THEN** 平台汇总权限范围内已通过明细，展示总工时、占比、排行、样本数和截止时间，并可下钻到同口径明细
- **WHEN** 工时待审批/驳回、维度缺失、批次部分失败或用户无项目/个人权限
- **THEN** 平台不计入无效明细，标记待映射/数据延迟，且不返回无权明细或虚假完整汇总

**涉及数据字段：**

统计维度（客户/项目/销售/办事处/个人）、统计周期（起始日期/结束日期）、客户编码、客户名称、项目编码、项目名称、销售ID、销售姓名、办事处编码、办事处名称、工程师ID、工程师姓名、工时数、工时类型、工时占比、Top排行、图表类型（柱状图/饼图/折线图/热力图）、导出文件、交叉分析维度组合

**权限与数据范围：**

管理层按组织范围查看汇总，服务经理查看本人项目及授权后代，个人只看本人明细；个人排行和导出执行人员字段权限。跨租户、未授权平级项目不参与分子分母。

**异常、降级及留痕要求：**

统计批次失败或明细对账不一致时展示最近成功结果、截止时间和异常数，暂停正式导出；恢复后按明细ID重算。平台记录口径版本、批次、样本/总时数、权限摘要、失败和重算时间。

**依赖关系：**

- 前置依赖：WO-01打卡工单同步（工时数据来源）、WO-04工时审批（审批通过后的工时数据计入统计）
- 后续依赖：无
- 关联依赖：权限体系（管理层/服务经理数据查看权限、数据范围权限）；WO-09仅为V3可选标签分析增强，不构成当前报表前置或验收条件
## RPT-02 项目状态统计

| 属性 | 内容 |
| ---- | ---- |
| 需求编号 | RPT-02 |
| 所属阶段 | 全局 |
| 用户角色 | 管理层、服务经理 |
| 优先级 | P1 |
| 目标版本 | V2 |
| 复杂度 | 中 |
| 依赖条件 | 项目数据 |

**业务场景与需求描述：**

提供项目全状态统计与闭环率统计能力，支撑项目态势监控。平台基于项目档案数据，按办事处统计项目全状态分布与闭环率，主要功能包含3部分：

1. **项目全状态统计**：按办事处统计项目在各状态（如立项中/实施中/割接中/维护中/已闭环等）的数量分布，以柱状图或饼图展示，便于掌握各办事处项目态势。
2. **闭环率统计**：按办事处统计项目闭环率（已闭环项目数/总项目数×100%），以仪表盘或柱状图展示，便于评估各办事处项目交付效率。
3. **点击跳转**：统计图表中各状态或各办事处的数据点支持点击跳转，跳转至对应的项目列表页面（保留筛选条件），便于管理层与服务经理下钻查看具体项目明细。

统计结果支持时间范围筛选与导出Excel。本需求为P1需求，依赖项目数据积累。

**核心业务规则：**

1. 状态分布按统计时点每个正式项目唯一有效状态计数；草稿/测试项目不进入，PM-10异常关闭单列且不计为“已闭环”。
2. 闭环率=筛选范围内已按CLO-02闭环项目数/正式项目总数×100%，分子分母均按项目ID去重并展示数量；时间筛选以项目创建时间和统计时点状态快照为准。
3. 父子项目按所选统计粒度分别计算；选择根项目口径时只计根项目，选择项目节点口径时各节点各计一次，不混用导致重复。图表下钻必须复用同一筛选和权限。

**用户故事：**

作为管理层，我希望使用“项目状态统计”能力完成本条定义的业务活动，以便获得业务场景中明确的处理结果并能够追溯处理过程。

**业务验收标准：**

- **WHEN** 用户选择时间、办事处和项目统计粒度
- **THEN** 平台返回状态分布、闭环分子/分母/比率和截止时间，点击数据点进入保留同一条件的项目列表
- **WHEN** 项目状态缺失、批次部分失败、根/节点粒度未选择或用户无办事处权限
- **THEN** 平台标记待核对/数据不完整并拒绝混合口径，且不显示无权项目数量与明细

**涉及数据字段：**

办事处编码、办事处名称、项目状态（立项中/实施中/割接中/维护中/已闭环等）、项目数量、闭环率、统计周期、图表类型（柱状图/饼图/仪表盘）、跳转目标URL、跳转筛选条件、导出文件

**权限与数据范围：**

管理层按组织范围查看，服务经理仅查看本人责任项目及授权后代；图表、下钻、导出使用相同项目权限，未授权平级项目和跨租户数据不进入统计。

**异常、降级及留痕要求：**

状态快照生成失败或下钻数量不一致时暂停发布该批正式指标，展示最近成功截止时间；恢复后按项目ID重算对账。平台记录统计粒度、状态版本、分子分母、权限摘要、批次、失败和重算时间。

**依赖关系：**

- 前置依赖：项目数据（项目档案、项目状态、所属办事处）
- 后续依赖：无
- 关联依赖：CLO-02闭环审批流程（闭环状态判定）、权限体系（管理层/服务经理数据查看权限、办事处数据范围权限）
## RPT-04 人效分析

| 属性 | 内容 |
| ---- | ---- |
| 需求编号 | RPT-04 |
| 所属阶段 | 全局 |
| 用户角色 | 管理层 |
| 优先级 | P1 |
| 目标版本 | V2 |
| 复杂度 | 中 |
| 依赖条件 | 工时数据 |

**业务场景与需求描述：**

提供行业人效统计能力，支撑人效评估。平台基于工时数据（关联RPT-01工时多维统计的工时数据来源），按行业维度统计多维度产品实施维护工时，评估人效。主要功能包含3部分：

1. **行业维度统计**：按行业（如金融、政府、能源、制造业等）统计实施维护工时总量、人均工时、人均项目数等指标。
2. **多维度产品统计**：按产品维度（如网络产品、存储产品、服务器产品等）统计实施维护工时，识别不同产品的人效差异。
3. **人效指标计算**：基于工时数据与项目数据，计算人效指标（如人均工时产出、人均项目交付数、人均闭环率等），以图表形式展示。

统计结果支持时间范围筛选、多维度交叉分析与导出Excel。本需求属P1需求，依赖工时数据积累。

**核心业务规则：**

1. 数据只取RPT-01已通过工时和正式项目；行业以客户在统计期内快照、产品以项目设备/产品关系映射，未知值单列不得强行归入其他。
2. 人均工时=范围内已通过工时/范围内有工时人员数；人均项目交付数=统计期闭环项目数/参与人员数；人均闭环率同时展示闭环项目分子、参与项目分母和人员数，不把工时量直接等同“产出”。
3. 同一项目多人参与时按人员参与关系计个人项目数，组织级项目总数仍按项目ID去重；跨行业/产品项目采用明确映射或分摊规则版本并展示口径。
4. 看板展示统计期、截止时间、样本人数、未知分类数和口径版本，样本不足时标记而不作无依据排名。

**用户故事：**

作为管理层，我希望使用“人效分析”能力完成本条定义的业务活动，以便获得业务场景中明确的处理结果并能够追溯处理过程。

**业务验收标准：**

- **WHEN** 管理层选择时间、组织、行业和产品范围
- **THEN** 平台按已通过工时与正式项目计算指标，展示公式分子分母、样本人数、未知分类和数据截止时间
- **WHEN** 行业/产品映射缺失、样本不足、批次失败或用户无组织权限
- **THEN** 平台单列未知/标记样本不足或数据延迟，不生成误导排名且不返回无权人员明细

**涉及数据字段：**

行业编码、行业名称、产品编码、产品名称、工时总量、人均工时、人均项目数、人均工时产出、人均项目交付数、人均闭环率、统计周期、图表类型、交叉分析维度组合、导出文件

**权限与数据范围：**

管理层按组织数据范围查看汇总，人员明细、排行和导出需人力数据权限；服务经理若获授权仅查看本人组织汇总。跨租户和无权组织不参与指标。

**异常、降级及留痕要求：**

工时/项目/人员口径对账失败时显示最近成功结果和截止时间，暂停正式导出与排名；映射修正后按口径版本重算并支持失败批次重试。平台记录公式、分子分母、样本、映射版本、权限摘要、失败、重试和重算时间。

**依赖关系：**

- 前置依赖：工时数据（WO-01工单数据、WO-04工时审批数据）、项目数据（项目档案、所属行业、关联产品）
- 后续依赖：无
- 关联依赖：RPT-01工时多维统计（工时数据来源共享）、CUS-03客户信息管理CURD（客户行业字段来源）、权限体系（管理层数据查看权限）
## ANA-01 项目组合经营看板

| 属性 | 内容 |
| ---- | ---- |
| 需求编号 | ANA-01 |
| 所属阶段 | 全生命周期 |
| 用户角色 | 管理层、区域负责人、工程管理部 |
| 优先级 | P1 |
| 目标版本 | V2 |
| 复杂度 | 中 |
| 依赖条件 | PROJ-12、项目指标、数据快照 |
| 来源追溯 | FR-ANA-001 |

**业务场景与需求描述：**提供组合、区域、客户和项目类型维度的经营看板，展示进度、风险、资源投入、合同履约和验收状态，并支持从指标下钻到项目证据。

**核心业务规则：**
1. 指标口径、刷新频率、异常阈值和维度均采用可配置字典或指标定义，不允许页面自行计算另一套口径。
2. 看板只读，不直接修改业务数据；指标必须标注统计时点、数据完整性和快照版本。
3. 下钻结果继承用户项目和组织权限，导出内容按字段脱敏规则处理。

**用户故事：**作为管理层，我希望从组合健康度异常直接定位到项目、任务和风险证据，以便及时决策。

**业务验收标准：**
- **WHEN** 用户选择组合、区域、客户或项目类型筛选条件
- **THEN** 看板按统一指标口径刷新并展示统计时点
- **WHEN** 用户点击异常指标
- **THEN** 系统下钻到授权范围内的项目、任务或风险清单
- **WHEN** 数据刷新失败
- **THEN** 页面提示数据时点并保留最近一次成功快照，不显示为最新数据

**涉及数据字段：**指标编码、指标值、统计口径、统计时点、快照版本、维度值、异常阈值、数据质量标记、下钻对象ID。

**权限与数据范围：**按组合、组织和项目权限控制；管理层可看汇总，项目角色只能看本人授权项目；导出继承同一过滤条件。

**异常、降级及留痕要求：**指标计算超时采用异步快照；数据源缺失标记“部分数据”；记录筛选条件、查看人、导出和下钻行为。

**依赖关系：**依赖PROJ-12、项目主数据、任务、风险、合同和验收数据。

## 6. 领域验收门禁

- 本领域正式需求全部直接来源于PRD需求块，业务验收标准以PRD为准。
- V1/V2需求不得以V3方向替代；V3不进入当前开发与验收。
- 领域状态必须遵循“初始化可扩展状态定义+受控状态机”；扩展状态不得绕过权限、责任、审批或证据门禁。
- 跨领域写入必须通过应用服务、接口或事件完成，不直接修改其他领域业务事实。
- 权限拒绝、版本冲突、重复提交、外部失败和人工降级必须保留可追溯记录。
