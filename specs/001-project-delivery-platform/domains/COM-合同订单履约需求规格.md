## 1. 领域目标与边界

ERP合同、订单及订单行权威引用与平台项目交付范围分配；平台不接管ERP商务事实。

本领域只定义自身拥有的业务规则、数据、权限和验收标准；跨领域能力通过需求依赖、输入输出和事件协作，不复制其他领域Owner的业务事实。

## 3. 详细需求

## COM-01 合同订单关联与范围分配

| 属性 | 内容 |
| ---- | ---- |
| 需求编号 | COM-01 |
| 所属阶段 | S0-S1 |
| 用户角色 | 工程管理部、合同管理员、项目经理 |
| 优先级 | P0 |
| 目标版本 | V1 |
| 复杂度 | 中 |
| 依赖条件 | 集成依赖：ERP合同订单数据；内部强前置：项目和设备对象 |
| 来源追溯 | FR-PROJ-011 |

**业务场景与需求描述：**
项目建立后关联ERP合同、销售订单及订单行，明确交付范围、数量、地点和项目分摊。ERP拥有合同、销售订单、订单行及数量/金额等商务事实，平台拥有项目范围分配记录；CRM仅提供项目、客户和销售执行上下文。

**核心业务规则：**
1. 合同、销售订单和订单行以ERP来源业务键幂等关联；合同业务身份按"所属公司+合同编号"确定。一个项目可关联多个订单，一个订单可按订单行拆分到多个项目，但每个订单行的已分配数量不得超过ERP有效订单数量。
2. 范围分配必须记录项目、订单行、产品/设备类型、数量、地点和生效时间；已进入验收的范围不可静默减少。
3. ERP合同、订单、订单行、产品、数量和金额等权威字段在平台只读；平台仅维护项目分配数量、实施地点、生效区间和分配状态等交付范围事实，CRM字段不得作为合同订单权威值覆盖ERP。
4. COM交付范围地点唯一冻结分配发生时目标项目所属办事处部门的稳定ID、编码、名称和版本；项目或组织后续变化不得覆盖历史快照。AST结构化站点、位置与文本降级仅由IMP/AST实施地点能力维护，COM不得保存或推导第二套地点真值。
5. 经授权人工补录仅形成`PENDING_AUTHORITY`候选及不可变依据，必须按稳定业务键与后续ERP事实对账；人工候选不得改写、伪造或晋级为ERP权威事实。
6. 每个项目维护单调递增的交付范围版本。当前已分配范围查询返回稳定范围版本；分配、调整、释放、冲突冻结和冲突处置每次只递增一次，重复请求不得重复推进版本。
7. 项目进入其设定验收阶段时，必须把该项目全部当前有效范围的精确版本与不可变阶段快照绑定；项目已处于验收阶段时，新生效范围版本必须同步绑定。普通减量或释放不得绕过已绑定范围守卫。

**用户故事：**
作为项目经理，我希望明确本项目承接的合同订单范围，以便避免多项目交付和验收边界不清。

**验收标准：**
- **WHEN** ERP合同、销售订单或订单行数据可用（接口同步或经授权人工补录待核对）
- **THEN** 平台按ERP来源业务键关联项目并展示权威字段及来源状态
- **AND** 接口不可用不阻断项目内部流程，但未取得ERP权威数量前不得将待核对数量视为最终可分配量
- **WHEN** 项目经理分配订单行到项目
- **THEN** 系统校验数量、目标项目办事处快照、范围版本和权限，生成可追溯的范围分配记录
- **WHEN** 分配数量超过可用数量
- **THEN** 系统拒绝保存并提示已分配明细

**涉及数据字段：**
合同号、订单号、订单行号、产品编码、数量、已分配数量、项目ID、目标项目办事处部门快照（ID/编码/名称/版本）、项目范围版本、来源版本、生效时间；实施站点和位置由IMP/AST独立维护

**权限与数据范围：**
合同管理员维护关联；项目经理只能维护授权项目的范围分配；ERP权威合同订单字段不可由平台业务角色修改，CRM销售上下文也不得覆盖ERP商务事实。

**异常、降级及留痕要求：**
ERP接口失败时保留最近一次有效ERP快照或进入"合同订单待核对"，平台项目内部流程可继续，但涉及最终可分配数量、验收范围锁定等动作必须使用已确认的ERP权威事实；订单取消、减量或变更时冻结受影响分配并通知项目经理；记录ERP来源版本、人工补录依据、分配前后数量及审批意见。

**依赖关系：**
- 前置依赖：INT-01及项目、产品、设备主数据；SYSTEM办事处部门事实
- 后续依赖：IMP/AST实施地点、ACC验收范围使用

- V1/V2需求不得以V3方向替代；V3不进入当前开发与验收。
- 领域状态必须遵循“初始化可扩展状态定义+受控状态机”；扩展状态不得绕过权限、责任、审批或证据门禁。
- 跨领域写入必须通过应用服务、接口或事件完成，不直接修改其他领域业务事实。
- 权限拒绝、版本冲突、重复提交、外部失败和人工降级必须保留可追溯记录。
