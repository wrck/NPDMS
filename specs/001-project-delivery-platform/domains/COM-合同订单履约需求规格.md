## 3. 详细需求

## COM-01 合同订单关联与范围分配

| 属性 | 内容 |
| ---- | ---- |
| 需求编号 | COM-01 |
| 所属阶段 | S0-S1 |
| 用户角色 | 工程管理部、合同管理员、项目经理 |
| 优先级 | P0 |
| 目标版本 | V1 |
| 复杂度 | 中 |
| 依赖条件 | CRM合同订单接口、项目和设备对象 |
| 来源追溯 | FR-PROJ-011 |

**业务场景与需求描述：**项目建立后关联CRM合同、销售订单及订单行，明确交付范围、数量、地点和项目分摊，作为设备、任务和验收范围的权威来源。

**核心业务规则：**
1. 合同/订单以CRM同步编号幂等关联；一个项目可关联多个订单，一个订单可按订单行拆分到多个项目，但每个订单行的已分配数量不得超过订单数量。
2. 范围分配必须记录项目、订单行、产品/设备类型、数量、地点和生效时间；已进入验收的范围不可静默减少。
3. CRM权威字段只读，平台补充的项目分配字段通过变更流程维护。

**用户故事：**作为项目经理，我希望明确本项目承接的合同订单范围，避免多项目交付和验收边界不清。

**业务验收标准：**
- **WHEN** CRM合同或订单行同步成功
- **THEN** 平台可按来源编号关联项目并展示权威字段
- **WHEN** 项目经理分配订单行到项目
- **THEN** 系统校验数量、地点和权限，生成可追溯的范围分配记录
- **WHEN** 分配数量超过可用数量
- **THEN** 系统拒绝保存并提示已分配明细

**涉及数据字段：**合同号、订单号、订单行号、产品编码、数量、已分配数量、项目ID、实施地点、来源版本、生效时间。

**权限与数据范围：**合同管理员维护关联；项目经理只能维护授权项目的分配；CRM同步字段不可由平台角色修改。

**异常、降级及留痕要求：**接口失败进入补偿；订单取消或变更时冻结受影响分配并通知项目经理；记录来源报文、分配前后数量及审批意见。

**依赖关系：**依赖INT-01及项目、产品、设备主数据，供AST、IMP和ACC验收范围使用。
## COM-02 合同订单履约回写与对账

| 属性 | 内容 |
| ---- | ---- |
| 需求编号 | COM-02 |
| 所属阶段 | S1-S5 |
| 用户角色 | 项目经理、合同管理员、财务/经营人员 |
| 优先级 | P2 |
| 目标版本 | V2 |
| 复杂度 | 中 |
| 依赖条件 | COM-01、CRM回写接口、验收与设备数据 |
| 来源追溯 | FR-RES-011 |

**业务场景与需求描述：**将项目实施、设备交付、阶段验收和最终验收结果按合同订单行回写CRM，并提供平台与CRM数量、状态和日期的对账结果。

**核心业务规则：**
1. 只有达到对应验收门禁的交付事实才可回写；回写按来源编号和版本幂等，禁止用失败回写覆盖成功结果。
2. 对账区分数量、状态、日期和金额口径；差异必须由责任人确认后关闭。
3. 平台保留回写报文和CRM回执，CRM仍是合同经营状态的权威系统。

**用户故事：**作为合同管理员，我希望看到平台交付事实与CRM履约状态的差异并能追踪处理。

**业务验收标准：**
- **WHEN** 设备或验收事实达到回写门禁
- **THEN** 系统生成按订单行聚合的回写报文并记录回执
- **WHEN** CRM返回失败或拒绝
- **THEN** 事实保持原状态，平台生成重试/人工处理待办，不重复记账
- **WHEN** 执行对账
- **THEN** 系统列出差异字段、来源时点、责任人和关闭结果

**涉及数据字段：**回写批次、订单行、履约数量、验收状态、验收日期、CRM回执、对账差异、确认人、关闭时间。

**权限与数据范围：**合同管理员和经营人员可看授权合同对账；项目角色只能查看本项目相关结果；回写密钥和报文内容按集成权限隔离。

**异常、降级及留痕要求：**CRM不可用时进入可靠队列；超过重试阈值转人工待办；保存请求摘要、响应码、重试次数、人工确认和最终结果。

**依赖关系：**依赖COM-01、ACC验收和AST设备交付数据，以及CRM接口契约。

## 6. 领域验收门禁

- 本领域正式需求全部直接来源于PRD需求块，业务验收标准以PRD为准。
- V1/V2需求不得以V3方向替代；V3不进入当前开发与验收。
- 领域状态必须遵循“初始化可扩展状态定义+受控状态机”；扩展状态不得绕过权限、责任、审批或证据门禁。
- 跨领域写入必须通过应用服务、接口或事件完成，不直接修改其他领域业务事实。
- 权限拒绝、版本冲突、重复提交、外部失败和人工降级必须保留可追溯记录。
