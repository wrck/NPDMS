## 3. 详细需求

## CUS-03 客户信息管理CURD

| 属性 | 内容 |
| ---- | ---- |
| 需求编号 | CUS-03 |
| 所属阶段 | 全局 |
| 用户角色 | 服务经理、项目经理 |
| 优先级 | P0 |
| 目标版本 | V1 |
| 复杂度 | 中 |
| 依赖条件 | 集成依赖：CRM接口（INT-03 CRM客户同步，可降级）；关联能力：《数据元.xlsx》数据元定义（字段映射参考） |

**业务场景与需求描述：**

作为平台V1基础能力与集成前置依赖，平台须先实现完整的客户CURD（创建/查询/更新/删除）功能，再承接CRM同步与项目/设备双向映射。核心能力包含4部分：

1. **客户CURD基础能力（V1必须建设）**：
   - 创建：服务经理或项目经理录入客户基本信息（客户编码、客户名称、行业、级别、联系方式、所属办事处等），客户编码唯一，重复录入时校验提示；字段映射参考《数据元.xlsx》核心实体的数据元定义（共151个数据元，建模以151数据元为基础，补充关联类实体设计）。
   - 查询：支持按客户编码、客户名称、行业、级别、所属办事处、服务等级等多条件组合查询，查询结果以列表展示，支持分页与排序。
   - 更新：支持客户基本信息字段更新，更新操作留存变更历史（含变更人、变更时间、变更字段、变更前值、变更后值），便于审计。
   - 删除：采用软删除（标记"已删除"状态，不物理删除）；删除前校验是否存在关联项目、设备、联系人、领域任务或外部问题记录等业务引用，存在有效引用时禁止删除并提示。
2. **CRM同步**：通过CRM接口（INT-03 CRM客户同步）将CRM系统中的客户信息同步至平台客户档案，同步字段包含客户编码、客户名称、行业、级别、联系方式、所属办事处等，支持增量同步（按客户编码匹配，已存在则更新，不存在则创建）。CRM同步数据与平台本地CURD数据并存：CRM字段以CRM数据为准（只读），平台扩展字段（如自定义标签）由平台维护。
3. **客户与项目双向映射**：一个客户可关联多个项目，一个项目任一时点仅归属一个客户；客户档案展示该客户关联的所有项目列表，项目档案展示所属客户信息。映射关系在项目创建时建立（项目创建时选择所属客户），支持变更所属客户并留存变更历史。
4. **客户与设备双向映射**：采用"当前直接归属+带类型业务关联"模型——同一时点一个设备仅直接归属一个客户；设备所属项目或客户变更后，以生效起止时间保留历史归属；租用、共管等场景可手工补充带关联类型和有效期的业务关联，但不得形成第二个当前直接归属。客户档案展示直接归属及授权可见的业务关联设备，设备档案展示当前客户、历史客户和关联类型；映射可通过项目自动建立，也可在权限校验后手工补充。

地点与组织承载口径（修订002）：客户地址不作为CUS自有物理地点字段，客户档案仅保存对AST拥有的Address/Site的稳定引用，CUS不拥有物理地点实体；所属办事处为对部门主数据（`system_dept.code`）的引用，跨模块关系和快照统一使用`department_id/department_code/department_name`。

**核心业务规则：**

1. 客户编码在租户内唯一，是平台客户主键；CRM客户ID作为外部来源键唯一映射一个平台客户。CRM同步、人工创建和后续匹配均不得产生两个有效客户档案指向同一CRM客户。
2. CRM是客户核心主数据的权威来源。已建立CRM映射后，客户编码、名称、行业、级别、联系方式和所属办事处等CRM权威字段在平台只读；自定义标签、服务等级及其他平台扩展字段由平台维护，CRM同步不得覆盖平台字段。
3. CRM暂不可用时，授权人员可创建来源为"平台临时"的客户以支撑项目建立。恢复后按客户编码和人工确认结果与CRM客户受控匹配；合并保留原临时客户标识、字段冲突处理结果和业务引用，不以覆盖方式丢失历史。
4. 客户删除一律软删除。存在有效项目、设备、联系人、领域任务、外部问题记录或其他业务引用时禁止删除；恢复客户沿用原客户ID和映射关系，不得新建同编码档案规避关联校验。
5. 一个项目任一时点只能有一个当前所属客户，变更所属客户必须设置生效时间并保留历史。一个设备任一时点只能有一个当前直接所属客户；租用、共管等关系以关联类型和有效期表达，不得形成第二个当前直接归属。
6. 客户行业、级别、来源、状态、业务关联类型等可能变化的字段使用基础平台可配置字典；停用字典值不得用于新建数据，但历史档案仍按原值展示。
7. 客户地址按修订002为客户档案对AST Address/Site的稳定引用，CUS不拥有物理地点实体；所属办事处按部门主数据引用承载，不引入独立办事处编码。

**用户故事：**

作为服务经理，我希望平台提供完整的客户CURD能力并通过CRM接口同步客户信息（CRM字段以CRM为准、平台扩展字段由平台维护），同时客户档案与项目档案、设备档案建立双向映射（客户档案展示关联项目与设备列表，项目档案与设备档案展示所属客户信息），字段映射参考《数据元.xlsx》151个数据元定义，以便在平台V1阶段建立客户管理基础能力，作为后续客户资产库、领域任务关联、项目关联、设备关联等业务场景的集成前置依赖，确保客户数据在平台内可独立维护并与CRM保持一致。

**验收标准：**

- **WHEN** 服务经理在平台客户管理页面点击"创建客户"按钮，录入客户基本信息（客户编码、客户名称、行业、级别、联系方式、所属办事处等），客户编码已存在
- **THEN** 平台校验客户编码唯一性失败，提示"客户编码已存在"，禁止创建
- **AND** 客户编码校验通过后，平台保存客户档案，客户状态为"启用"，同时记录创建人、创建时间
- **WHEN** 平台通过CRM接口（INT-03）执行客户信息同步任务且未发生来源键冲突
- **THEN** 平台按客户编码匹配CRM客户数据：已存在则更新CRM字段（客户名称、行业、级别、联系方式等以CRM为准），不存在则创建新客户档案
- **AND** 平台扩展字段（如自定义标签、服务等级）保持平台本地值不变，CRM同步数据与本地数据并存，同步任务执行结果（成功/失败/新增/更新数量）记录至同步日志
- **WHEN** 服务经理在客户档案页面查看客户详情
- **THEN** 页面展示客户基本信息、关联项目列表（项目编码/项目名称/派生展示状态/当前阶段/负责人）、关联设备列表（设备序列号/设备型号/在网状态），列表支持分页与排序
- **AND** 在项目档案页面可查看所属客户信息，在设备序列号档案（EQP-01）页面可查看所属客户信息，实现客户与项目、客户与设备的双向映射
- **WHEN** 服务经理对客户档案执行删除操作，且该客户存在关联项目、设备、联系人、领域任务或外部问题记录等业务数据
- **THEN** 平台校验存在关联业务数据，提示"客户存在关联业务数据，禁止删除"，删除操作被拦截
- **AND** 若客户无关联业务数据，平台执行软删除（标记为"已删除"状态），客户在客户列表中不再展示，但数据保留备查，支持有权限角色恢复

**涉及数据字段：**

客户ID、客户编码（租户内唯一）、CRM客户ID、客户名称、客户简称、行业、客户级别、服务等级（关联CUS-02）、所属办事处（部门主数据引用，修订002）、联系人列表（关联CUS-04）、客户地址（对AST Address/Site的引用，修订002）、联系电话、邮箱、客户来源（CRM同步/平台创建/平台临时）、权威字段来源、CRM同步时间、CRM同步状态、字段冲突状态、自定义标签、关联项目列表及归属有效期（关联PM项目档案）、关联设备列表及关联类型/有效期（关联EQP-01设备序列号档案）、创建人、创建时间、更新人、更新时间、变更历史（变更人/变更时间/变更字段/变更前值/变更后值）、客户状态（启用/停用/已删除）、删除人、删除时间

**权限与数据范围：**

服务经理可在所属组织数据范围内创建平台客户、维护平台扩展字段、处理CRM匹配冲突和执行满足条件的软删除/恢复；项目经理可查看所属项目的客户档案、维护项目使用的非权威扩展信息并发起项目客户归属变更，但无权修改客户全局核心字段或删除客户。CRM权威字段对业务角色只读，仅集成服务账号可按字段映射写入。设备和项目映射的查看范围同时受客户、项目和设备数据权限约束，父项目只汇总授权后代数据，跨租户客户及联系方式不可见。

**异常、降级及留痕要求：**

CRM接口不可用时继续展示最近一次成功同步的数据及同步时间，任务保持失败状态并支持重试；业务急需可创建"平台临时"客户，但不得伪造CRM来源。客户编码或CRM客户ID冲突时禁止自动覆盖，进入待匹配队列并保留双方字段差异。项目或设备归属有效期重叠时禁止生效并保留原归属；存在业务引用的删除请求必须被拦截。客户创建、字段变更、CRM同步、冲突处理、临时客户合并、归属变更、删除和恢复均记录操作者、来源、时间、前后值及影响对象。

**依赖关系：**

- 前置依赖：CRM接口（INT-03 CRM客户同步，集成前置依赖）、《数据元.xlsx》数据元定义（字段映射参考）
- 后续依赖：CUS-01用户资产库（客户基础数据来源）、CUS-04项目联系人管理（联系人关联客户）、EQP-01设备序列号档案（设备档案展示所属客户）
- 关联依赖：INT-03 CRM客户同步（CRM数据来源）、权限体系（服务经理/项目经理客户管理权限、CRM同步任务执行权限）
## CUS-04 项目联系人管理

| 属性 | 内容 |
| ---- | ---- |
| 需求编号 | CUS-04 |
| 所属阶段 | S1 |
| 用户角色 | 项目经理 |
| 优先级 | P0 |
| 目标版本 | V1 |
| 复杂度 | 低 |
| 依赖条件 | 内部强前置：项目档案（联系人所属项目）、CUS-03客户信息管理CURD（所属客户单位字段来源） |

**业务场景与需求描述：**

提供项目联系人的维护能力，保障项目沟通联络顺畅。当项目经理在项目中维护联系人时，系统应支持：每个项目维护多个联系人，其中主联系人唯一（一个项目仅一个主联系人），主联系人在项目页面以显著标识展示，便于快速联络；其他联系人支持增删改操作。联系人信息包含姓名、职务、联系电话、邮箱、所属客户单位等字段。

主联系人变更需先取消原主联系人主标识，再设置新主联系人，主联系人字段同步至项目档案首页展示。联系人信息变更留存变更历史。本需求属S1阶段P0需求，须与CUS-03客户信息管理CURD协同建设。

**核心业务规则：**

1. 联系人记录必须归属于一个明确项目，并关联该项目当前所属客户或经授权使用的客户单位；同一联系人可在不同项目建立独立记录，项目记录的修改不自动改写客户全局联系人档案。
2. 一个项目任一时点最多存在一个"启用"状态的主联系人。设置新主联系人前必须取消原主标识；主联系人切换按同一次业务操作校验，发生并发更新时只能有一项成功，禁止出现两个当前主联系人。
3. 姓名和至少一种有效联系方式为启用联系人的必填条件；联系电话、邮箱按基础格式校验。职务、联系人角色、状态等可变化字段使用基础平台可配置字典。
4. 联系人删除采用软删除。删除当前主联系人前必须先指定新主联系人，或由项目经理明确确认项目暂不设置主联系人；被交付、割接或通知记录引用的联系人快照不随档案删除而消失。
5. 项目首页只展示当前启用的主联系人；其他业务选择联系人时仅列出当前项目下的启用联系人，并在业务记录提交时保存联系人姓名和联系方式快照，避免后续修改影响历史事实。

**用户故事：**

作为项目经理，我希望在项目档案中维护多个项目联系人（含姓名、职务、联系电话、邮箱、所属客户单位等字段）并设置其中一人为唯一主联系人（主联系人在项目页面以显著标识展示），其他联系人可随时增删改，主联系人变更时先取消原主标识再设置新主标识，以便项目团队在沟通联络时快速定位主联系人，同时保留所有相关联系人信息应对不同场景的联络需求。

**验收标准：**

- **WHEN** 项目经理在项目档案页面点击"新增联系人"按钮，录入联系人信息（姓名、职务、联系电话、邮箱、所属客户单位等），并勾选"设为主联系人"，而该项目已存在主联系人
- **THEN** 平台校验主联系人唯一性失败，提示"项目已存在主联系人，请先取消原主联系人主标识"，新增操作被拦截
- **AND** 项目经理取消原主联系人主标识后，可设置新联系人为项目主联系人，主联系人字段同步至项目档案首页以显著标识展示
- **WHEN** 项目经理对项目其他联系人执行修改或删除操作
- **THEN** 平台保存修改或执行删除（联系人状态变更为"已删除"，数据保留备查），变更操作留存变更历史（含变更人、变更时间、变更字段、变更前值、变更后值）
- **AND** 主联系人不受批量删除影响，删除主联系人时需先指定其他联系人为主联系人或确认项目暂无主联系人
- **WHEN** 两名项目经理并发设置主联系人发生数据版本冲突
- **THEN** 平台保留先成功的唯一主联系人并拒绝后提交操作，提示后提交者刷新联系人列表后重试

**涉及数据字段：**

项目编码、联系人ID、客户ID、姓名、职务、联系人角色、联系电话、邮箱、所属客户单位（关联CUS-03客户档案）、是否主联系人（是/否）、主联系人设置时间、创建人、创建时间、更新人、更新时间、数据版本号、变更历史、联系人状态（启用/停用/已删除）、删除人、删除时间

**权限与数据范围：**

项目经理仅可维护本人负责或明确授权项目的联系人，并只能从该项目当前所属客户或授权客户单位中选择；项目成员可查看本项目启用联系人，但无权修改、删除或切换主联系人。服务经理可在组织数据范围内查看联系人用于服务协同，不因可查看客户档案而自动取得联系人维护权。联系电话、邮箱按个人信息数据范围展示，跨项目、跨客户和跨租户默认不可见；联系人记录不得自动创建基础平台登录账号。

**异常、降级及留痕要求：**

所属客户与项目当前客户不一致、联系方式格式无效或目标联系人已停用时，禁止启用或设为主联系人。并发设置主联系人发生版本冲突时，后提交者刷新当前主联系人后重新操作，不覆盖先成功结果。项目首页同步失败时保留联系人变更成功事实并标记"展示待刷新"，恢复后重试刷新。新增、修改、主联系人取消/设置、停用、删除、恢复及被业务单据引用均记录操作人、时间、前后值和关联项目。

**依赖关系：**

- 前置依赖：项目档案（联系人所属项目）、CUS-03客户信息管理CURD（所属客户单位字段来源）
- 后续依赖：CUS-01用户资产库（联系人列表展示）、CUT-01割接任务管理（割接联络人来源）
- 关联依赖：权限体系（项目经理联系人维护权限）
## CUS-01 用户资产库

| 属性 | 内容 |
| ---- | ---- |
| 需求编号 | CUS-01 |
| 所属阶段 | 全局 |
| 用户角色 | 服务经理、项目经理 |
| 优先级 | P1 |
| 目标版本 | V2 |
| 复杂度 | 高 |
| 依赖条件 | 内部强前置：CUS-03客户信息管理CURD、EQP-01设备序列号档案 |

**业务场景与需求描述：**

提供客户资产全貌视图能力，将客户单位、联系人、项目、设备、故障、服务记录等分散数据聚合为统一的可视化资产库。当服务经理或项目经理通过客户编码或客户名称进入用户资产库页面后，平台聚合展示该客户的6类资产信息：

1. **用户单位信息**：客户基本信息、服务等级（关联CUS-02）、行业、级别等。
2. **联系人信息**：客户联系人列表，含主联系人与其他联系人（关联CUS-04）。
3. **项目信息**：客户关联的所有项目列表，含项目派生展示状态、当前阶段、负责人等。
4. **设备信息**：客户关联的所有设备序列号列表，关联EQP-01设备序列号档案。
5. **故障信息**：客户关联的所有故障记录，关联EQP-07项目问题单页面数据。
6. **服务记录**：客户关联的领域服务任务、ITR问题记录、巡检报告、割接记录等。

可视化展示支持列表视图与图表视图切换，便于快速浏览与深度分析。本需求依赖CUS-03客户信息管理CURD（客户基础数据来源）与EQP-01设备序列号档案（设备数据来源），价值高但可在V2阶段建设。

地点承载口径（修订002）：用户单位信息中的客户地址、站点信息为客户档案对AST拥有的Address/Site的稳定引用，CUS-01仅经引用解析展示、不拥有物理地点实体；设备信息中的设备位置（如展示）以EXE-02安装记录确认的当前位置为权威事实。

**核心业务规则：**

1. 客户资产库以经CRM客户ID映射的平台客户编码定位客户、聚合只读全景；平台临时客户入库并标记来源（无CRM映射）；不创建新的客户、项目、设备、故障或服务记录副本；各卡片显示来源系统/模块和数据截止时间。
2. 项目按项目ID、设备按序列号、问题按ITR问题单号去重；设备同一时点唯一直接项目归属，客户/父项目汇总不得因多项目参与关系重复计数。
3. 维保开始/结束、类型、服务商、合同仅作为设备基本信息展示；本需求不得生成设备基本信息以外的独立经营对象，详细排除范围统一引用第十三章`OUT_OF_SCOPE`清单。
4. 各类数据先按用户项目、客户和字段权限过滤再聚合；无权卡片不显示数量或名称，不能通过全景页扩大权限。
5. 客户地址与站点信息按修订002经客户档案对AST Address/Site的引用展示；设备当前位置以EXE-02安装记录为权威事实，CUS-01不直接维护地点数据。

**用户故事：**

作为服务经理，我希望通过客户编码或客户名称进入用户资产库，一站式查看该客户的单位信息、联系人、项目、设备、故障和服务记录并支持列表/图表视图切换，以便快速掌握客户资产全貌并支撑服务决策。

**验收标准：**

- **WHEN** 有权用户打开客户资产库
- **THEN** 平台按客户返回权限过滤后的单位、联系人、项目、设备、故障和服务记录，展示各卡片数量、来源和截止时间
- **WHEN** 同一设备被父子项目引用、部分来源异常或用户无某项目/敏感字段权限
- **THEN** 平台按序列号去重，异常卡片标记数据延迟，无权数据不参与数量且不显示明细

**涉及数据字段：**

客户编码、客户名称、服务等级、行业、客户级别、联系人列表（姓名/职务/联系方式/是否主联系人）、项目列表（项目编码/项目名称/派生展示状态/当前阶段/负责人）、设备列表（设备序列号/设备型号/在网状态）、故障列表（问题单号/工单状态/主题/级别/根因）、服务记录列表（业务单号/服务类型/服务时间/服务人）、视图类型（列表/图表）

**权限与数据范围：**

服务经理查看本人客户/项目范围全景，项目经理只查看本人项目关联客户数据，管理层按组织范围查看脱敏汇总；联系人、故障正文、配置Log和维保合同字段需专项权限。跨租户及未授权平级项目不可见。

**异常、降级及留痕要求：**

来源查询失败时保留其他卡片，失败卡片显示最近成功截止时间和"更新异常"，不以0替代未知；恢复后按客户重算。权限服务异常时默认拒绝敏感卡片。平台记录客户查询、权限范围摘要、来源批次、去重数量、失败与重算时间，不记录敏感明文。

**依赖关系：**

- 前置依赖：CUS-03客户信息管理CURD（客户基础数据来源）、CUS-04项目联系人管理（联系人数据来源）、EQP-01设备序列号档案（设备数据来源）、EQP-07项目问题单页面（故障数据来源）
- 后续依赖：无
- 关联依赖：CUS-02服务等级管理（服务等级字段来源）、权限体系（服务经理/项目经理数据查看权限）
## CUS-02 服务等级管理

| 属性 | 内容 |
| ---- | ---- |
| 需求编号 | CUS-02 |
| 所属阶段 | 全局 |
| 用户角色 | 服务经理、管理层 |
| 优先级 | P1 |
| 目标版本 | V2 |
| 复杂度 | 中 |
| 依赖条件 | 无 |

**业务场景与需求描述：**

提供客户服务等级的划分与管理能力，支撑差异化服务策略。客户服务等级分为3级：

1. **一级重点**：重点客户，享受最高优先级服务，可作为重大项目立项和重要割接保障的策略输入；主动服务计划仅由V3的SRV-V3-01消费，本需求在V1/V2不创建主动服务任务。
2. **二级区域**：区域级客户，享受标准服务，按区域服务策略保障。
3. **三级普通**：普通客户，享受基础服务，按通用服务策略推进。

服务等级由管理层或服务经理维护，等级标识同步至客户档案（关联CUS-03客户信息管理CURD）。在V1/V2范围内，服务等级作为重大项目立项、重要割接保障（关联CUT-01割接任务管理）等已确认能力的差异化策略输入；主动服务仅作为V3 SRV-V3-01的后续消费方向，不由本需求在V1/V2生成主动服务任务。服务等级变更需留存变更历史，便于追溯。

**核心业务规则：**

1. 一级重点、二级区域、三级普通为初始服务等级字典值；等级必须配置生效期和对应服务行为，如项目升级提示、割接保障级别建议；主动服务提醒仅作为V3消费方向，不在V1/V2由本需求触发。
2. 同一客户同一时点只有一个有效服务等级；变更形成新生效区间并保留原因、依据和批准人，不追溯改写历史项目判断快照。
3. 业务动作在触发时保存等级快照和命中的策略版本；等级变化只影响新触发动作，不自动改变已批准割接或项目级别。

**用户故事：**

作为服务经理，我希望为客户划分并维护服务等级（一级重点/二级区域/三级普通）且等级变更留存历史，以便对重大项目立项、重要割接保障等业务执行差异化服务策略并追溯等级变化依据。

**验收标准：**

- **WHEN** 有权人员为客户设置有效等级、依据、生效时间和服务策略
- **THEN** 平台结束原等级区间并生成新版本，后续项目/割接/服务动作保存命中等级与策略快照
- **WHEN** 等级区间重叠、策略缺失、客户不存在或用户无客户管理权限
- **THEN** 平台拒绝生效并保持原有效等级和既有业务动作不变

**涉及数据字段：**

客户编码、客户名称、服务等级（一级重点/二级区域/三级普通）、等级生效时间、等级失效时间、变更历史（变更人/变更时间/变更前等级/变更后等级/变更原因）、关联重大项目清单、关联重要割接清单；V3如启用主动服务时仅通过服务等级版本引用消费，不在V1/V2新增主动服务字段或任务状态

**权限与数据范围：**

服务经理可维护授权客户等级，管理层按组织范围批准策略，服务经理可查看本人客户等级和执行提示但不能修改策略字典。跨组织/租户客户不可见。

**异常、降级及留痕要求：**

客户同步或策略加载失败时不生成新等级，沿用原有效等级并标记待处理；业务联动失败保留等级变更且生成待重试事件，不伪造已执行策略。平台记录等级/策略版本、生效区间、依据、联动结果、失败和操作人时间。

**依赖关系：**

- 前置依赖：无
- 后续依赖：CUS-01用户资产库（服务等级字段展示）、CUS-03客户信息管理CURD（服务等级同步至客户档案）
- 关联依赖：CUT-01割接任务管理（重要割接按服务等级判定）、权限体系（管理层/服务经理等级维护权限）
## INT-03 CRM客户同步

| 属性 | 内容 |
| ---- | ---- |
| 需求编号 | INT-03 |
| 所属阶段 | 全局 |
| 用户角色 | 管理员 |
| 优先级 | P1 |
| 目标版本 | V1 |
| 复杂度 | 中 |
| 依赖条件 | 集成依赖：CRM接口 |

**业务场景与需求描述：**

平台从CRM入向同步客户权威核心字段和产品信息，支撑客户数据准确。CRM核心字段在平台只读，发生来源冲突时不得由平台直接覆盖；平台扩展标签和交付服务字段由平台独立维护，不反向覆盖CRM自定义标签。换货、单机风险和售前测试反馈按各自业务需求向CRM发送业务结果，不改变客户主数据Owner。停产停维信息按T+1同步并用于EQP-03设备档案技术风险标记。当CRM接口不可用时，允许维护平台扩展字段，CRM权威字段沿用最近一次成功同步值并标记同步状态；核心信息反向写回不纳入V1。

**核心业务规则：**

1. CRM是客户编码、客户名称、客户等级、客户状态、归属销售及CRM产品信息的Owner；平台按CRM客户ID建立映射并只读展示这些权威字段，不允许业务人员在平台直接覆盖。
2. 平台是交付联系人、服务偏好、交付标签、项目服务备注等平台扩展字段的Owner；扩展字段与CRM字段分区保存，平台扩展值不得反向覆盖CRM客户主数据或CRM自定义标签。
3. V1执行客户核心字段入向同步、停产停维信息T+1同步，以及本节已定义的幂等、映射冲突、失败重试和批次对账；换货、单机风险、售前测试等出向结果由对应业务需求发起并携带业务单号，不构成客户主数据双向同步。未定义的扩展同步治理工作台不形成V2切片，仅作为V3跨需求演进方向重新评审。
4. 客户同步以CRM客户ID和来源事件ID幂等；事件乱序时按CRM数据版本或更新时间处理，旧事件不得覆盖新值。客户合并/停用必须保留旧ID映射和历史项目引用，不级联删除平台项目与设备档案。
5. 客户等级、状态、产品类别等可变含义字段保存CRM源值及平台映射字典版本；未知源值进入待映射，不得强行映射为"其他"后当作正常数据。
6. T+1任务完成后生成应同步数、成功数、失败数和数据截止时间；存在失败时该批次为"部分成功"，不得以任务进程结束表示全量成功。

**用户故事：**

作为数据管理员，我希望平台清楚区分CRM权威客户字段与平台交付扩展字段，并能按来源版本幂等同步和对账，以便客户资料准确且不会发生双向覆盖。

**验收标准：**

- **WHEN** 平台收到包含CRM客户ID、数据版本和核心字段的新增或更新事件
- **THEN** 平台按CRM客户ID新增或更新只读权威字段，保存来源版本、同步时间和映射状态，同时保留平台交付扩展字段不变
- **WHEN** 客户管理员维护交付联系人、服务偏好或交付标签
- **THEN** 平台只更新扩展字段及其版本，不生成CRM客户主数据更新请求，也不修改CRM同步字段
- **WHEN** 收到重复/旧版本事件、未知字典值、CRM客户合并停用，或T+1批次部分记录失败
- **THEN** 平台分别执行幂等忽略、进入待映射、保留旧ID历史映射，或把批次标记为"部分成功"；不得覆盖新值、删除历史项目或宣称全量成功
- **WHEN** CRM接口不可用且业务人员查看客户资料
- **THEN** 平台展示最近一次成功值、数据截止时间和"同步异常"标识，允许维护平台扩展字段但禁止编辑CRM权威字段

**涉及数据字段：**

CRM客户ID、原CRM客户ID、客户编码、客户名称、客户等级、客户状态、归属销售、CRM产品编码/名称、源数据版本、源更新时间、来源事件ID、平台交付联系人、服务偏好、交付标签、项目服务备注、字典映射状态、同步状态、同步批次号、数据截止时间、失败原因、创建/更新时间

**权限与数据范围：**

集成管理员可配置CRM接口、查看同步批次、重试失败记录和维护字典映射，但不能修改CRM权威业务值；客户管理员可在本人组织与项目授权范围内维护平台交付扩展字段，不能编辑CRM只读字段。项目成员按项目数据范围查看关联客户必要信息，客户敏感联系方式按字段权限脱敏；跨租户、未授权客户及平级项目关联信息不可见。

**异常、降级及留痕要求：**

CRM超时、验签失败、字段缺失或字典未映射时，失败记录进入隔离/待处理队列，客户沿用最近一次成功权威值并显示数据截止时间；平台扩展字段继续可用。恢复后按CRM客户ID、事件ID和源版本幂等重试，并对批次总数与CRM侧结果对账。平台记录请求批次、来源事件、字段变更摘要、旧事件忽略、映射处理、失败原因、重试和人工处置，日志不得记录敏感联系方式明文。

**依赖关系：**

- 前置依赖：CRM接口
- 后续依赖：CUS-03客户信息管理CURD（CRM同步前置）、EQP-03设备档案库（停产停维T+1同步）
