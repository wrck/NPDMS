## 3. 详细需求

## EXE-01 到货签收

| 属性 | 内容 |
| ---- | ---- |
| 需求编号 | EXE-01 |
| 所属阶段 | S4 |
| 用户角色 | 项目经理 |
| 优先级 | P0 |
| 目标版本 | V1 |
| 复杂度 | 低 |
| 依赖条件 | 无（里程碑节点） |

**业务场景与需求描述：**
作为S4实施部署阶段的起始里程碑节点，支持项目经理上传到货签收单（含签收单扫描件/照片），系统记录到货签收时间并同步至交付件页面（ACC-04交付件归档管理）。签收单内容包含设备清单、签收人、签收时间、物流单号等关键信息。到货签收完成后里程碑节点标记为"已签收"，方可进入EXE-02硬件安装环节。

**核心业务规则：**

1. 到货签收按项目设备范围和到货批次记录，支持同一项目多批到货、部分签收、补签、差异和拒收；每个批次必须关联物流单号、签收人、签收时间、设备明细和签收证据。
2. 设备明细按序列号或可识别的订单/型号数量核对，状态至少包括未到货、已签收、差异待处理、已拒收。短少、破损、型号不符等差异类型使用基础平台字典，并保存差异数量、原因、照片及后续处理结果。
3. 单台设备或数量只有在对应明细“已签收”后才可进入EXE-02安装；部分签收只开放已签收设备，不得将整批或整个项目提前标记完成。
4. 项目到货里程碑只有在全部应到设备已签收，或剩余明细取得针对具体设备/数量的有效豁免后才变为“已签收”。豁免必须有原因、风险、批准人和有效范围，不能用于掩盖未知差异。
5. 已提交签收记录不得直接覆盖；补签、差异关闭和签收信息纠正形成后续记录并关联原批次。签收证据同步ACC-04作为交付件引用，业务明细Owner仍为现场实施到货记录。

**用户故事：**
作为项目经理，我希望能够在设备到货后上传到货签收单并记录签收时间，签收信息自动同步至交付件页面归档，以便到货环节可追溯、里程碑节点可管控，并作为后续硬件安装环节的准入条件。

**验收标准：**
- **WHEN** 项目经理在S4阶段进入到货签收环节
- **THEN** 系统提供到货签收单上传页面，支持上传签收单扫描件/照片，并填写设备清单、签收人、签收时间、物流单号等关键信息
- **AND** 系统记录到货签收时间，签收单数据同步至ACC-04交付件归档管理页面
- **WHEN** 某批设备仅部分到货或存在短少、破损、型号不符等差异
- **THEN** 系统分别保存已签收和差异明细，仅将已签收设备开放给EXE-02，项目到货里程碑保持“进行中”
- **AND** 差异关闭或补签后更新对应明细，不覆盖原批次证据
- **WHEN** 全部应到设备均已签收，或剩余设备已取得有效豁免
- **THEN** 系统标记到货签收里程碑为“已签收”，保存完成时间和豁免范围，并准入EXE-02处理已签收设备

**涉及数据字段：**
项目编码、签收单附件、设备清单（序列号/型号/数量）、签收人、签收时间、物流单号、签收状态、里程碑节点状态、同步交付件标识

**权限与数据范围：**

项目经理可在本人负责项目创建到货批次、录入签收/拒收结果、提交差异处理和补签记录；获授权现场工程师可上传签收证据和录入本人参与批次，但最终提交由项目经理确认。豁免审批人只能审批授权项目的具体设备/数量。客户签收人仅作为业务证据记录，不自动获得平台访问权。上级项目角色按授权查看后代项目到货汇总和证据，不能修改子项目批次；平级项目与跨租户数据不可见。

**异常、降级及留痕要求：**

签收附件上传失败、设备不在项目应到范围、序列号重复或签收数量超过未签数量时阻止提交，批次保持草稿；项目经理修正或补传后重新提交。ACC-04引用失败不回滚已确认签收，但标记“归档待重试”且不得伪报已归档。差异未关闭或豁免过期时里程碑保持进行中。平台保存批次、设备明细前后状态、数量、差异证据、补签/拒收/豁免链路、归档重试和所有操作人时间。

**依赖关系：**
- 前置依赖：S3方案阶段审核通过（S4阶段准入）
- 后续依赖：EXE-02硬件安装记录（到货签收作为硬件安装准入）、ACC-04交付件归档管理（签收单归档）
- 关联依赖：PM-03项目模板（里程碑节点配置）
## EXE-02 硬件安装记录

| 属性 | 内容 |
| ---- | ---- |
| 需求编号 | EXE-02 |
| 所属阶段 | S4 |
| 用户角色 | 项目经理、工程师 |
| 优先级 | P0 |
| 目标版本 | V1 |
| 复杂度 | 中 |
| 依赖条件 | EQP-01设备序列号档案 |

**业务场景与需求描述：**
针对硬件安装场景，支持安装位置填写与安装照片上传，确保安装过程可追溯。安装位置字段同步至EQP-01设备序列号详情，作为设备档案的位置信息更新来源。安装记录按序列号维度管理，每个设备对应一条安装记录，记录安装位置（机房/机柜/U位）、安装人、安装时间、安装照片（前/后/侧等多角度）。安装照片支持时间戳与地理位置水印（如设备支持）。安装完成后数据同步至设备档案库与项目档案。

**核心业务规则：**

1. 安装对象必须是EXE-01已签收且当前直接归属本项目节点的设备；未签收、已拒收或仅属于其他项目的设备不得创建本项目安装完成记录。
2. 安装按设备序列号管理，每台设备同一时点只有一条当前安装记录，至少包含机房、机柜、U位、安装人、安装时间和模板要求的照片；安装位置类型和照片类别使用基础平台配置，但不能省略项目规定的必填证据。
3. 提交安装记录后同步更新EQP-01设备位置，并保留安装记录为位置来源；更换位置或纠正信息必须形成新版本，记录原位置和新位置，不覆盖历史安装证据。
4. 项目硬件安装里程碑以当前安装范围为准：全部已签收且要求安装的设备均有有效安装记录，或取得具体设备豁免后才可完成。新签收设备加入范围后，里程碑重新校验。
5. 安装照片的时间和地理水印在终端支持时采集；设备不支持地理位置时记录“无定位能力”，不得伪造水印，也不因此取消项目模板规定的其他照片证据。

**用户故事：**
作为项目经理/工程师，我希望能够按设备序列号填写安装位置（机房/机柜/U位）并上传多角度安装照片，安装位置数据自动同步至设备序列号详情，以便硬件安装过程可追溯、设备档案位置信息实时更新，并为后续配置调试环节提供设备位置参考。

**验收标准：**
- **WHEN** 项目进入EXE-02硬件安装环节（EXE-01到货签收已完成）
- **THEN** 系统按EQP-01设备序列号清单展示待安装设备列表，支持逐台填写安装位置（机房/机柜/U位）、安装人、安装时间
- **AND** 每台设备支持上传多角度安装照片（前/后/侧等），照片自动添加时间戳与地理位置水印（如设备支持）
- **WHEN** 工程师完成单台设备安装位置填写与照片上传并提交
- **THEN** 系统将该设备的安装位置数据同步至EQP-01设备序列号详情的位置字段
- **AND** 安装记录归档至项目档案，支持按序列号/安装人/安装时间查询
- **WHEN** 项目所有设备安装记录全部填写完成
- **THEN** 系统标记硬件安装里程碑节点为"已完成"，准入EXE-03配置调试环节
- **WHEN** 设备尚未签收、不属于当前项目安装范围，或安装位置/必需照片缺失
- **THEN** 安装记录保持草稿或未完成状态，不更新设备当前位置，也不计入项目安装里程碑完成数量

**涉及数据字段：**
项目编码、设备序列号、设备型号、安装位置（机房/机柜/U位）、安装人、安装时间、安装照片（多角度/含水印）、安装备注、同步设备档案标识、里程碑节点状态

**权限与数据范围：**

被分配到项目和设备的工程师可创建、编辑本人未提交的安装记录并上传照片；项目经理可查看全项目安装范围、确认记录、退回补充及发起设备豁免。已确认记录的更正必须由项目经理创建新版本，工程师不能删除历史照片。设备位置和照片只对设备所属项目授权人员可见；上级项目角色按授权查看后代汇总，平级项目、其他项目关联人员及跨租户用户不得查看具体安装位置。

**异常、降级及留痕要求：**

设备范围校验失败、照片上传失败或位置字段缺失时不提交安装完成记录；工程师可保存草稿并在修正后重试。EQP-01位置同步失败时安装记录标记“位置同步待重试”，里程碑不得把该设备视为完整归档；恢复后按安装记录版本补偿更新。平台保存设备范围快照、安装前后位置、照片版本与水印能力、提交/退回/豁免、同步失败及重试的操作人和时间。

**依赖关系：**
- 前置依赖：EXE-01到货签收（硬件安装准入）、EQP-01设备序列号档案（设备清单与位置同步来源）
- 后续依赖：EXE-03配置Log采集解析（硬件安装完成作为配置调试准入）
- 关联依赖：EQP-01设备序列号档案（安装位置信息同步）
## EXE-03 配置Log采集解析

| 属性 | 内容 |
| ---- | ---- |
| 需求编号 | EXE-03 |
| 所属阶段 | S4 |
| 用户角色 | 项目经理、工程师 |
| 优先级 | P0 |
| 目标版本 | V1 |
| 复杂度 | 高 |
| 依赖条件 | INT-12设备连接与采集平台集成、设备档案 |

**业务场景与需求描述：**
针对配置调试场景，实现配置Log的采集、解析、按序列号拆分存储与展示，作为设备版本追溯与配置归档的核心环节。EXE-03保留实施业务页面入口，通过INT-12创建统一采集任务并复用现有采集平台；平台侧支持选择已保存设备凭证或临时输入登录用户名、密码，并实现权限校验、任务下发、回调接收、Log管理、解析存储和按序列号拆分展示，不建设设备连接和原始数据采集引擎。

**采集方式：** 工程师可选择在线采集或手动上传Log文件。在线采集时，工程师选择设备、SCH-03已发布配置脚本以及认证方式：可引用本人有权使用的设备凭证，也可临时输入登录用户名、密码；临时输入时可显式选择保存为设备凭证。平台创建统一采集任务并向现有采集平台下发设备连接端点、认证信息、脚本版本和项目上下文。EXE-03任务和业务记录保存认证方式；凭证模式保存凭证ID、版本及授权快照，临时模式保存登录用户名但不保存密码。

**解析存储：** IMP实施领域对回调日志文件进行解析，按序列号拆分存储至"配置Log"库。框式产品支持存储整机Log（不拆分到线卡）。每次采集操作生成一条新记录，关联统一采集任务，保留操作人、操作时间、采集方式、设备连接端点、认证方式、凭证引用或临时登录用户名和配置脚本版本等元数据，但不保存临时密码。

**展示与管理：** 平台实现Log管理界面，支持按项目/序列号/操作时间/操作人维度查询与检索配置Log。每条记录展示原始日志、解析结果、关联设备、关联配置脚本、操作人、操作时间。支持日志下载、对比（同序列号不同版本对比）、按关键字检索。配置Log由EQP-02统一管理，在EQP-01设备序列号档案的配置Log页签展示，并由EQP-03设备档案的版本历史关联，作为设备配置版本追溯依据。

**核心业务规则：**

1. 只有EXE-02安装完成且属于当前项目配置范围的设备，才能发起在线采集或建立手动Log记录；在线采集必须引用已发布的SCH-03脚本版本，任务创建后脚本和设备范围冻结。
2. 在线采集统一通过INT-12下发给现有采集平台执行，本平台拥有采集任务业务状态、项目/设备上下文、回调消费和配置Log；现有采集平台拥有设备连接、命令执行和原始采集过程，本平台不重复建设执行引擎。
3. 已保存凭证模式必须校验当前用户对凭证、设备和项目的权限，并保存凭证ID、版本和授权快照；临时模式只保存登录用户名，不保存密码。用户显式选择“保存为凭证”后才创建加密凭证，新凭证默认仅创建人可用。
4. 每次在线尝试或手动上传均生成独立记录并关联设备、脚本版本和采集任务；回调按任务编号和结果标识幂等处理。原始文件不可覆盖，解析结果形成版本；框式设备可按整机保存，不强制拆分到线卡。
5. 配置调试里程碑只统计每台目标设备的有效配置Log。失败任务、解析失败文件或没有设备归属的文件不得计入；人工上传可作为有效来源，但必须标记来源、上传人和与失败任务的关联。

**用户故事：**
作为项目经理/工程师，我希望能够通过设置Log路径自动获取或手动上传的方式采集设备配置Log，系统按序列号拆分存储并展示，每次操作生成新记录保留操作人与时间，以便设备配置可追溯、版本变更可对比，支撑设备版本追溯与配置归档的核心闭环。

**验收标准：**
- **WHEN** 项目进入EXE-03配置调试环节（EXE-02硬件安装已完成）且工程师选择在线采集
- **THEN** 页面进入INT-12统一采集能力，工程师选择目标设备、SCH-03已发布配置脚本及认证方式，可选择本人有权使用的设备凭证或临时输入登录用户名、密码
- **AND** 系统完成业务权限、设备权限和命令模板权限校验；凭证模式追加凭证权限校验，临时模式按INT-12规则不保存密码，校验通过后创建采集任务并下发项目与设备上下文
- **AND** 现有采集平台连接设备执行采集并通过INT-12回调日志文件或结果引用；任务、接口日志和回调均不得包含凭证明文
- **WHEN** 工程师选择手动上传Log
- **THEN** 平台直接接收Log文件并按手动上传方式建立配置Log记录，不调用采集子应用
- **WHEN** 平台接收到日志文件
- **THEN** 系统对日志文件进行解析，按序列号拆分存储至"配置Log"库；框式产品支持存储整机Log不拆分到线卡
- **AND** 每次操作生成一条新记录，保留操作人、操作时间、采集方式（在线采集/手动上传）、设备连接端点、认证方式、凭证引用或临时登录用户名、统一采集任务编号和关联配置脚本版本等元数据，但不保存临时密码
- **AND** 平台Log管理界面按项目/序列号/操作时间/操作人维度展示配置Log记录，支持日志下载、版本对比、关键字检索
- **WHEN** 配置Log存储完成
- **THEN** 系统将配置Log交由EQP-02管理，在EQP-01配置Log页签展示并由EQP-03版本历史关联，作为设备配置版本追溯依据
- **AND** 配置调试里程碑节点在所有目标设备均有至少一条配置Log记录后标记为"已完成"，准入EXE-04业务联调环节

- **AND** 现有采集平台执行show tech采集并通过INT-12回调状态和结果；或工程师选择手动上传Log文件
- **AND** 采集结果按设备维度归档至业务联调记录，记录设备序列号、采集时间、操作人、采集方式

- **THEN** 联调任务保持失败或待补充状态，不计入里程碑；工程师可重试或关联原任务人工上传结果，补齐基线后重新生成对比

**涉及数据字段：**

## EXE-05 单机风险标记

| 属性 | 内容 |

| 用户角色 | 项目经理、CRM销售 |
| 优先级 | P1 |

| 复杂度 | 低 |

**业务场景与需求描述：**
针对实施过程中识别的单机风险（如设备故障隐患、配置不匹配、性能不达标等），支持项目经理选定设备并描述风险详情后推送至CRM销售跟进。风险记录包含设备序列号、风险类型、风险描述、风险等级、推送状态、CRM销售跟进结果回传等信息。推送后CRM销售在CRM侧跟进并将跟进结果回传至平台，形成风险跟踪闭环。

**核心业务规则：**

1. 平台是单机风险记录、当前状态和关闭结论的Owner；CRM承载销售协同跟进，CRM回传不能直接删除风险或把平台风险自动置为已关闭。
2. 风险必须关联项目和设备序列号，风险类型、等级、状态使用基础平台字典。状态至少包括草稿、待推送、跟进中、待确认、已关闭、已取消；同一设备可存在多条不同风险，但相同来源事件只能幂等生成一条。
3. 推送CRM前必须具备风险类型、等级、描述、设备及项目责任人；CRM成功返回风险单号后才转为“跟进中”，请求已发送但未获业务单号不视为受理成功。
4. CRM回传跟进结果后风险转为“待确认”，由项目经理核对证据并选择关闭、继续跟进或取消。关闭必须记录结论和关闭人，未解除的高风险可作为后续实施/验收提示，但不新增PRD未定义的自动阻断。
5. 设备换绑或项目层级调整不改写风险历史归属；当前统计按风险记录关联项目及授权项目子树汇总，按风险ID去重。

**用户故事：**

作为项目经理，我希望把现场发现的设备风险登记到平台并协同CRM销售跟进，在核实CRM处理结果后由平台完成关闭，以便风险责任和结论可追溯。

**业务验收标准：**

- **WHEN** 项目经理为授权项目内设备填写完整风险信息并提交CRM协同
- **THEN** 平台保存风险记录并发起推送；CRM返回唯一风险单号后状态更新为“跟进中”，同时保留请求与响应关联
- **WHEN** CRM回传处理结果和证据
- **THEN** 平台把风险更新为“待确认”，项目经理确认风险解除后才生成关闭结论并转为“已关闭”
- **WHEN** 设备不属于授权项目、风险关键字段缺失、CRM请求超时或重复回传同一事件
- **THEN** 平台拒绝无权提交；推送失败保持“待推送/推送失败”并可重试；重复事件不新增风险或重复状态记录

**涉及数据字段：**
项目编码、设备序列号、风险类型、风险描述、风险等级、推送人、推送时间、CRM销售负责人、CRM风险单号、推送状态、跟进结果回传、回传时间

**权限与数据范围：**

项目经理可在本人负责项目内创建、推送、确认和关闭单机风险；CRM销售仅通过集成处理其CRM业务单并回传跟进结果，不能直接修改平台风险描述、等级或关闭结论。服务经理可查看和督办授权项目子树风险。设备、附件和风险明细按项目授权过滤，未授权平级项目和跨租户数据不可见。

**异常、降级及留痕要求：**

CRM不可用、请求超时或回调验签失败时，风险保留在平台并标记具体推送状态，不把消息发送记录当作CRM受理；恢复后按风险ID幂等重试或人工录入经核验的CRM单号。回传设备与原风险不一致时进入待核对队列，不覆盖原记录。平台记录风险前后状态、项目与设备、推送批次、CRM单号、回调内容摘要、人工确认、失败原因和操作人时间。

**依赖关系：**
- 前置依赖：EXE-02硬件安装记录（设备序列号来源）、CRM接口
- 关联依赖：INT-03 CRM客户信息同步、CRM风险跟进流程接口
## EXE-06 割接上线门禁

| 属性 | 内容 |
| ---- | ---- |
| 需求编号 | EXE-06 |
| 所属阶段 | S4 |
| 用户角色 | 项目经理 |
| 优先级 | P0 |
| 目标版本 | V1 |
| 复杂度 | 低 |
| 依赖条件 | CUT割接模块 |

**业务场景与需求描述：**
作为S4实施部署阶段的收口环节，对前序里程碑节点（到货签收→硬件安装→配置调试→业务联调）进行门禁校验，全部完成后方可发起割接流程。割接管理是本平台内部业务模块，与项目交付模块通过内部服务和业务事件衔接，不进行跨系统跳转或复制项目数据。

前序门禁校验规则：EXE-01到货签收里程碑“已签收”、EXE-02硬件安装里程碑“已完成”、EXE-03配置调试里程碑“已完成”、EXE-04业务联调里程碑“已完成”，四项全部满足方可发起割接。割接发起后，平台内嵌割接管理模块接管割接流程（割接方案/割接执行/割接验证/割接回退），割接结果通过内部业务事件更新项目档案，作为S4阶段完成与S5验收阶段准入的依据。

**核心业务规则：**

1. 发起割接前必须实时校验EXE-01到货、EXE-02安装、EXE-03配置Log和EXE-04联调四个里程碑均完成，并保存校验快照；任一里程碑只部分完成、被重新打开或存在未处理阻断项时不得发起。
2. 割接是同一平台内的CUT业务模块，直接引用同一项目ID、设备范围、批准方案和配置Log；项目模块不复制CUT任务数据，也不把CUT作为外部系统建立同步副本。
3. 对同一项目和设备范围，同一时点只能有一个进行中的割接任务；再次发起必须在前一任务结束后创建新任务并关联前次任务，不能复用已结束流程实例或覆盖历史结果。
4. CUT任务创建后，项目只消费受控业务事件更新割接状态。只有CUT-06执行完成、验证通过并满足稳定观察要求时，S4才标记完成并准入S5；停止、失败、回退或观察未通过均不得完成S4。
5. 割接执行前若批准方案、设备范围或四个前序里程碑发生变化，CUT必须重新校验并阻止继续；变更按方案/项目变更流程处理，不允许项目经理手工改写门禁结果。

**用户故事：**
作为项目经理，我希望在S4前序里程碑（到货签收/硬件安装/配置调试/业务联调）全部完成后发起割接流程，且割接流程在统一平台内通过界面接口深度集成方式衔接（非跳转、数据互通），以便S4实施部署阶段流程衔接顺畅、割接数据自动回传项目档案，避免多平台切换与数据孤岛。

**验收标准：**
- **WHEN** 项目经理在S4阶段进入EXE-06割接上线环节
- **THEN** 系统对前序里程碑节点进行门禁校验：EXE-01到货签收"已签收"、EXE-02硬件安装"已完成"、EXE-03配置调试"已完成"、EXE-04业务联调"已完成"四项全部满足
- **AND** 门禁校验通过后允许发起割接流程；任一前序里程碑未完成则禁止发起割接，并提示未完成节点
- **WHEN** 门禁校验通过且项目经理发起割接
- **THEN** 系统在统一平台内调起内嵌割接管理模块（CUT），通过界面接口深度集成方式衔接，非独立部署、非简单跳转
- **AND** 割接流程直接引用平台项目编码、设备清单、配置Log和方案信息，无需跨系统传递或重复录入
- **WHEN** 割接流程完成（割接验证通过）
- **THEN** 割接结果通过内部业务事件更新项目档案，S4实施部署阶段标记为“已完成”
- **AND** S4阶段完成后准入S5验收阶段，割接记录归档至交付件页面（ACC-04）
- **WHEN** 任一前序里程碑未完成、批准方案或设备范围在校验后变化，或同一范围已有进行中的割接任务
- **THEN** 系统阻止创建或继续割接任务，项目S4保持原状态，并返回未通过门禁和冲突任务编号
- **WHEN** 割接停止、执行失败、完成回退或稳定观察未通过
- **THEN** 项目记录对应CUT结果但S4不标记完成，不准入S5；项目经理按CUT流程处理后才能重新发起关联任务

**涉及数据字段：**
项目编码、前序里程碑状态（EXE-01/02/03/04）、门禁校验结果、割接发起人、割接发起时间、割接流程实例ID、割接模块集成方式（深度集成）、数据互通字段（项目编码/设备清单/配置Log/方案信息）、割接结果、割接完成时间、S4阶段完成状态、S5准入标识

**权限与数据范围：**

项目经理可对本人负责项目查看门禁明细并发起割接任务，但无权修改四个前序里程碑结果、CUT审批或执行结果。CUT模块内的评估、审批、执行和验证由CUT-01～06定义的授权角色处理。项目成员只读查看与本人项目相关的割接状态；上级项目角色按授权查看后代汇总，平级项目和跨租户任务不可见。设备凭证和采集结果继续按INT-12/CUT-06权限控制，项目经理不能因发起权限获得凭证明文。

**异常、降级及留痕要求：**

CUT模块暂不可用或任务创建失败时，门禁快照可保留但项目不得进入“割接中”，项目经理恢复后按同一幂等请求重试。内部事件重复或乱序时按流程实例和事件版本幂等处理；事件缺失时项目保持原状态并进入对账，不得人工标记S4完成。割接停止、失败、回退和观察未通过必须保留CUT原始结果。平台记录每次门禁快照、发起请求、流程实例、关联前次任务、内部事件、状态前后值、归档重试和操作人时间。

**依赖关系：**
- 前置依赖：EXE-01到货签收、EXE-02硬件安装记录、EXE-03配置Log采集解析、EXE-04业务联调配置收集（前序门禁）、CUT割接模块（统一平台内嵌）
- 后续依赖：S5验收阶段（S4完成作为S5准入）、ACC-04交付件归档管理（割接记录归档）
- 关联依赖：SCH-01实施方案在线编审（割接引用部署方案）、EXE-03配置Log库（割接引用配置数据）
