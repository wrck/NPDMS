## 3. 详细需求

## INT-04 ITR技术公告同步

| 属性 | 内容 |
| ---- | ---- |
| 需求编号 | INT-04 |
| 所属阶段 | 全局 |
| 用户角色 | 工程师、管理员 |
| 优先级 | P1 |
| 目标版本 | V2 |
| 复杂度 | 低 |
| 依赖条件 | ITR接口 |

**业务场景与需求描述：**

技术公告在ITR与平台知识域间互通，平台保存公告标题、公告编号、公告来源、外部编号、适用产品、适用版本、公告级别、正文、发布时间、生效时间和同步状态。同步频率为实时；接口不可用时公告降级为邮件/钉钉人工转发并支持恢复后补录。

**核心业务规则：**

1. ITR是公告编号、正文、适用产品/版本、级别和生效状态Owner，平台以ITR公告ID建立只读镜像并保存源版本。
2. 实时事件按事件ID和源更新时间幂等，旧事件不得覆盖新值；撤回/失效只更新状态，不删除历史项目引用。
3. 产品、版本和公告级别映射使用字典，未知值进入待映射；邮件/钉钉人工转发仅是通知兜底，不自动成为权威公告。

**用户故事：**

作为工程师，我希望使用“ITR技术公告同步”能力完成本条定义的业务活动，以便获得业务场景中明确的处理结果并能够追溯处理过程。

**业务验收标准：**

- **WHEN** 平台收到合法且版本较新的ITR公告事件
- **THEN** 平台按ITR公告ID新增或更新只读公告，保存源版本、同步时间和产品/版本映射状态
- **WHEN** 事件重复乱序、字典未映射、ITR不可用或用户无公告范围权限
- **THEN** 平台忽略旧事件或标记待映射/同步异常，沿用最近成功值且不返回无权正文

**涉及数据：**

ITR公告ID、公告编号、标题、正文、公告级别、适用产品、适用版本、发布时间、生效时间、失效状态、源版本、来源事件ID、映射状态、同步状态、数据截止时间、失败原因

**权限与数据范围：**

工程师按授权产品/项目查看公告，集成管理员查看批次、重试和维护映射但不能编辑ITR权威内容；公告敏感附件按字段权限，跨租户不可见。

**异常、降级及留痕要求：**

ITR超时、验签失败或字典未映射时沿用最近成功公告并显示截止时间，事件进入隔离/待映射；恢复后按公告ID和源版本重试。平台记录事件、字段变更摘要、通知补录、失败和处理人时间。

**依赖关系：** 前置依赖ITR接口（与INT-02共用）；后续依赖EQP-01设备序列号档案（技术公告集中展示）。

## 6. 领域验收门禁

- 本领域正式需求全部直接来源于PRD需求块，业务验收标准以PRD为准。
- V1/V2需求不得以V3方向替代；V3不进入当前开发与验收。
- 领域状态必须遵循“初始化可扩展状态定义+受控状态机”；扩展状态不得绕过权限、责任、审批或证据门禁。
- 跨领域写入必须通过应用服务、接口或事件完成，不直接修改其他领域业务事实。
- 权限拒绝、版本冲突、重复提交、外部失败和人工降级必须保留可追溯记录。
