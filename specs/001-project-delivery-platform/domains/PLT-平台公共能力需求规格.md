## INT-05 钉钉/HR/OA集成

| 属性 | 内容 |
| ---- | ---- |
| 需求编号 | INT-05 |
| 所属阶段 | 全局 |
| 用户角色 | 工程师、服务经理 |
| 优先级 | P0 |
| 目标版本 | V1钉钉/HR组织与通知协作；V2 OA扩展 |
| 复杂度 | 中 |
| 依赖条件 | 钉钉/HR/OA接口 |

**业务场景与需求描述：**

作为协同办公与人员数据的集成能力，集成钉钉、HR、OA三系统。V1由HR同步必要的人员、组织与在离职主数据，并通过钉钉触达平台待办和审批通知；V2扩展OA领料、外采及转包待办链接。打卡、通用工单和工时统计已退出V1/V2，不得借本集成需求恢复。

1. **HR必要主数据同步**：V1由HR提供人员、工号、组织、岗位和在离职状态，为人员身份映射、候选人解析及权限回收提供依据；平台保存业务所需快照，不要求每次使用时实时调用HR。
2. **OA领料/外采流程**：V2调用OA发起领料流程、外采事前审批流程并接收状态结果；V1不以OA能力作为割接或项目闭环前提。
3. **钉钉审批通知推送**：平台审批节点触发钉钉待办/通知并携带平台审批链接。审批仍在平台完成，钉钉不拥有审批状态，钉钉回执仅用于送达状态，不得改变平台审批结果。
4. **OA转包代办链接推送**：转包流程（SUB-01~05）为平台内独立审批引擎，OA仅接收代办链接通知，不在OA内审批。
5. **同步频率**：人员主数据采用事件/增量同步与定期对账，审批通知和OA流程状态采用实时事件或回调。

**核心业务规则：**

1. HR是人员工号、姓名、组织、岗位和在离职状态Owner；平台拥有人员与项目关系、项目角色、候选人解析结果和所有平台业务审批状态。来源字段不得被平台业务用户改写。
2. HR人员按HR人员ID/工号幂等，平台通知按“业务对象ID+审批实例ID+节点ID+接收人”幂等；重复同步或通知重试不得生成重复人员、角色关系或待办。
3. 人员必须先完成HR身份映射才能被自动解析为流程候选人。无法唯一匹配的人员或组织进入待映射，不自动绑定同名人员；离职状态触发新任务禁选和待办转交检查，但不删除历史项目角色、审批及操作记录。
4. V1同步HR必要主数据，并通过钉钉/站内消息发送平台审批通知；审批操作和结果只在平台生效。转包等平台内审批向OA/钉钉发送的均是待办链接，不在外部系统复制审批流。
5. V2增加OA领料/外采的流程发起和结果回填，按OA流程实例ID幂等；OA流程状态只更新对应物料申请，不改变无关项目或平台审批实例。
6. 同步采用来源事件/回调优先、增量游标任务兜底并执行日对账；通知失败使用站内消息兜底。任务频率、游标、送达状态、重试次数和对账结果必须可查询。
7. 人员状态、考勤异常类型、通知通道、送达状态和OA流程状态等可变化字段使用基础平台可配置字典并保留来源值映射版本。

**用户故事：**

作为工程师/服务经理，我希望平台能够同步必要的HR人员与组织主数据、调用OA发起领料/外采流程，并通过钉钉推送平台待办链接，以便候选人解析准确、物料流程在线化且审批能够及时触达。

**验收标准：**

- **WHEN** HR人员、组织、岗位或在离职状态发生变化
- **THEN** 平台按来源业务键幂等同步必要主数据并更新身份映射；既有审批和操作历史保持可追溯
- **WHEN** V2工程师/服务经理在平台发起领料或外采事前审批
- **THEN** 平台调用OA接口创建对应流程并保存OA流程实例ID，平台页面展示OA办理链接
- **AND** OA流程状态实时同步，流程完成后结果回填对应物料申请
- **WHEN** 平台审批节点触发（割接审批/变更审批/转包审批等）
- **THEN** 平台通过钉钉推送审批通知，通知含审批标题、申请人、审批人、审批链接、截止时间
- **AND** 审批人在平台链接内完成审批，钉钉只回传通知送达/阅读状态，不得更新平台审批结果
- **WHEN** 转包流程（SUB-01~05）发起
- **THEN** 平台在平台内独立审批，OA仅接收代办链接通知（不在OA内审批）
- **WHEN** 钉钉/HR/OA接口不可用
- **THEN** 平台继续使用最近一次成功同步的人员组织快照，OA流程降级为线下审批后补录，审批通知降级为站内消息；不得把通知失败判为业务失败或审批成功
- **WHEN** 同一人员事件或通知请求重复到达、HR人员无法唯一匹配，或钉钉回调试图携带审批结果
- **THEN** 平台对重复请求返回既有记录；人员保持待映射且不进入候选人列表；忽略外部审批结果字段并记录协议异常，不改变平台审批状态

**涉及数据字段：**

HR人员ID、工号、姓名、部门、岗位、在离职状态、人员映射状态、来源更新时间；通知业务对象ID、审批实例ID、节点ID、接收人、审批标题/链接/截止时间、通知通道、送达/阅读状态、重试次数；V2 OA流程实例ID、流程类型、物料明细/数量/金额/事由/状态/办理链接；同步任务/游标/批次/时间/状态/失败原因、对账结果

**权限与数据范围：**

HR、钉钉和OA集成服务账号仅可写入各自来源字段、送达状态和同步日志；集成管理员可配置任务、重试和对账但不能改写HR来源事实或代替审批人审批。工程师只能访问分配给本人的待办链接；服务经理只在组织/项目授权范围审批并查看必要证据。人员信息按组织、项目角色和字段权限控制，跨租户不可见。

**异常、降级及留痕要求：**

HR同步失败时批次保持失败/部分失败，按来源键重试且不重复生成人员映射；映射不唯一时进入待处理而非丢弃。钉钉通知失败立即生成站内消息并保留外部重试任务，通知失败不改变审批节点。V2 OA创建请求失败时物料申请保持“外部流程未创建”，不得生成虚假流程号；回调乱序按流程版本处理。平台记录来源事件、幂等、映射、通知送达/重试、OA发起/回调及协议异常，不记录接口密钥。

**依赖关系：**

- 前置依赖：钉钉接口、HR接口、OA接口
- 后续依赖：CUT-05割接分级审批（钉钉审批通知）、CHG-01变更申请电子流（钉钉审批通知）、SUB-01~05转包流程（OA代办链接推送）
- 关联依赖：权限体系（工程师/服务经理集成权限）

## INT-09 LDAP/AD集成

| 属性 | 内容 |
| ---- | ---- |
| 需求编号 | INT-09 |
| 所属阶段 | 全局 |
| 用户角色 | 管理员、全员 |
| 优先级 | P0 |
| 目标版本 | V1 |
| 复杂度 | 中 |
| 依赖条件 | LDAP/AD接口 |

**业务场景与需求描述：**

作为平台统一身份认证的基础能力，集成LDAP/AD目录服务，实现账号与组织架构信息获取、单点登录（SSO），支撑NFR-01/NFR-02的LDAP/AD单点登录要求。本需求为P0核心需求（评分50.0），SSO基础能力，须首批建设。

1. **账号目录服务**：平台通过LDAP/AD接口入向同步账号信息，包含账号、姓名、工号、邮箱、部门、岗位、状态（在职/离职）等。账号信息作为平台用户主数据源头，平台按账号建立用户档案并与LDAP/AD保持一致。
2. **组织架构信息获取**：平台通过LDAP/AD接口同步组织架构信息，包含部门层级、部门负责人、部门成员等。组织架构信息支撑数据权限（如上级按授权范围查看后代项目、平级项目默认互不可见）与角色权限配置。
3. **单点登录（SSO）**：平台集成LDAP/AD实现SSO，用户通过企业账号一次登录即可访问平台及关联系统，无需重复登录。SSO支持Kerberos/NTLM/SAML等标准协议，与企业现有身份认证体系对接。
4. **账号生命周期同步**：LDAP/AD中账号新增、变更、禁用、离职等状态变更实时同步至平台，平台自动同步用户状态（如离职账号自动禁用）。
5. **同步频率**：实时同步，LDAP/AD账号/组织架构变更后平台实时同步。

**核心业务规则：**

1. LDAP/AD是企业账号、姓名、工号、邮箱、组织、岗位和启停状态的身份Owner；平台拥有应用角色、项目授权、数据范围和业务职责。目录同步不得按部门名称自动授予项目权限，也不得覆盖平台显式授权。
2. 用户按LDAP/AD不可变对象标识幂等，组织按目录对象标识幂等；账号名、邮箱或部门名称变更只能更新同一用户/组织。不可变标识缺失、重复或一个目录账号匹配多个平台用户时进入待映射，禁止自动合并。
3. 部署时从企业已选定的Kerberos、NTLM或SAML协议中启用受支持方案，不要求单次登录同时执行多种协议。SSO成功后平台创建自身会话并重新计算当前角色和数据范围，外部身份通过不等于拥有任意项目权限。
4. 账号禁用或离职事件同步后立即禁止新登录，并撤销或标记失效现有平台会话、设备凭证任务授权和未使用的委托授权；历史业务记录保留原用户标识，不转移给同名新账号。
5. 同步采用目录变更事件/增量查询优先、全量对账兜底；保存目录游标、计划频率、处理数量和对账结果。组织变更只更新组织主数据，权限变化按平台授权规则重新计算并留痕。
6. SSO或目录暂不可用时，普通用户不得降级为可自助设置的本地密码。仅预先建立、独立保管、默认禁用且受控启用的应急管理员账号可用于恢复服务；应急账号不参与日常业务，启用、登录和停用必须告警与审计。
7. 账号状态、岗位、组织类型、同步状态和SSO协议等可变化字段使用基础平台可配置字典或受控配置；来源原值和映射版本必须保留。

**用户故事：**

作为管理员/全员用户，我希望平台能够通过LDAP/AD实现账号目录服务、组织架构信息获取、单点登录（SSO），以便我用企业账号一次登录即可访问平台、账号与组织架构信息自动同步无需重复维护、账号生命周期（入职/离职）自动同步至平台保障安全。

**验收标准：**

- **WHEN** 用户通过企业账号登录平台
- **THEN** 平台校验LDAP/AD单点登录断言后创建平台会话，记录用户ID、登录时间和认证协议并加载当前角色/数据范围
- **AND** SSO支持Kerberos/NTLM/SAML等标准协议，与企业现有身份认证体系对接
- **WHEN** LDAP/AD中账号信息新增或变更（账号/姓名/工号/邮箱/部门/岗位）
- **THEN** 平台实时同步账号信息至用户档案，保持与LDAP/AD一致
- **WHEN** LDAP/AD中组织架构信息变更（部门层级/部门负责人/部门成员）
- **THEN** 平台实时同步组织架构信息，支撑数据权限与角色权限配置
- **WHEN** LDAP/AD中账号状态变更（如离职禁用）
- **THEN** 平台自动同步用户状态，离职账号自动禁用，无法登录平台
- **WHEN** LDAP/AD接口不可用
- **THEN** 普通用户登录保持失败并展示统一认证不可用状态，平台仅允许按受控流程启用预置应急管理员账号，组织架构以最近一次成功同步版本只读展示
- **AND** 接口恢复后自动批量补录同步账号与组织架构变更
- **WHEN** 目录不可变标识缺失/重复、账号映射冲突，或已离职账号携带未失效平台会话
- **THEN** 平台将同步记录标记“待映射”且不创建重复用户；对禁用/离职账号拒绝新请求并撤销现有会话和未使用任务授权

**涉及数据字段：**

LDAP/AD用户对象ID、账号、姓名、工号、邮箱、部门对象ID、岗位、账号状态（在职/离职/禁用）、组织对象ID/父组织ID/层级/负责人/成员、平台用户ID、账号映射状态、来源游标/批次/时间/状态、对账结果、SSO协议/外部会话标识/平台会话ID、登录时间/IP/结果、会话撤销时间/原因、应急账号启用申请/启用人/有效期/登录/停用/告警记录

**权限与数据范围：**

LDAP/AD集成服务账号只可写入目录Owner字段和同步日志；身份管理员可配置同步、处理映射冲突和查看对账结果，但不能借此授予项目业务权限。普通用户只能通过企业SSO访问本人的平台会话和授权数据，无权查看目录同步日志。应急管理员账号仅由受控运维责任人按审批启用，不得用于日常项目操作；其每次操作均按最高审计级别记录。租户之间账号、组织、会话和授权完全隔离。

**异常、降级及留痕要求：**

目录查询、SSO验签或同步任务失败时不把用户标记为同步成功，保留最近成功组织版本和失败原因并按游标重试。映射冲突不自动创建或合并用户；离职/禁用事件处理失败列为高优先级安全告警并持续重试会话撤销。应急账号启用超期后自动停用，失败时触发告警。平台记录目录事件摘要、映射、SSO成功/失败、角色与数据范围计算、会话撤销、应急启停和对账过程，不记录票据、令牌或密码正文。

**依赖关系：**

- 前置依赖：LDAP/AD接口
- 后续依赖：NFR-01割接平台非功能需求（LDAP/AD单点登录要求）、NFR-02设备凭证及巡检非功能需求（LDAP/AD单点登录要求）、权限体系（账号与组织架构为权限基础）、数据权限（组织架构支撑上级按授权范围查看后代项目等数据权限规则）
- 关联依赖：无

## INT-12 设备连接与采集平台集成

| 属性 | 内容 |
| ---- | ---- |
| 需求编号 | INT-12 |
| 所属阶段 | 全局公共能力 |
| 用户角色 | 项目经理、实施工程师、割接一线工程师、巡检一线工程师、系统管理员 |
| 优先级 | P0 |
| 复杂度 | 高 |
| 目标版本 | V1实施/割接公共能力；V2巡检入口 |
| 依赖条件 | 现有采集平台、INT-09统一身份认证、设备档案、业务命令模板 |

**业务场景与需求描述：**

现有采集平台已具备设备连接、命令执行和原始数据采集能力。本平台将其作为统一的“设备连接与采集”业务模块引入，技术上优先采用子应用集成，提供统一登录、菜单、导航和权限体验，不采用外部系统简单跳转。本平台建设设备认证信息管理（已保存凭证或临时输入）、统一采集任务下发和数据回调三类核心能力，以及实施、割接、巡检和独立中心的业务入口，不重复建设SSH/TELNET连接、命令执行或采集执行引擎。

**1. 统一功能入口：**

- V1提供独立“设备连接与采集中心”、EXE-03/04实施采集入口和CUT-06割接任务入口。
- V2在INS-02/04巡检任务中启用在线连接、预检和采集入口，直接复用V1公共契约。
- 业务页面进入时自动带入业务类型、业务单号、项目和设备上下文；独立中心发起任务时至少选择项目、设备、用途和已发布命令模板。
- 独立中心是统一工作台，不是新的命令治理域；默认禁止直接输入任意设备命令。

**2. 设备认证信息与凭证管理：**

- 发起在线任务时，用户可在“使用已保存凭证”和“临时输入账号密码”两种认证方式中选择一种。
- 平台加密保存设备账号、密码或密钥，密钥材料与业务数据分离管理。
- 凭证默认仅创建人可使用；项目成员、任务参与人、服务经理或管理员身份均不自动取得使用权。
- 扩大用户使用范围必须显式授权，授权至少绑定被授权用户、凭证、设备范围、连接协议、命令模板范围和有效期。
- 选择“临时输入账号密码”时，任务可保存登录用户名用于审计，但不得保存密码；密码不得进入浏览器持久化存储、数据库、缓存、异步消息、日志、回调或导出，页面刷新、任务重试或再次执行均须重新输入。
- 临时输入页面提供“保存为设备凭证”的显式选项。用户选择后，平台按设备凭证规则保存用户名并加密保存密码，创建的新凭证默认仅当前用户可用；本次任务改为引用该凭证。未选择时不得以任何形式自动沉淀密码或创建凭证。
- 采集执行服务不作为永久凭证使用主体。用户发起任务并通过业务、设备、模板以及与认证方式对应的凭证权限或临时输入校验后，平台才为该任务签发短期、任务绑定且不可复用的执行授权；任务结束、失败、超时、撤销或到期后立即失效。
- 用户只能选择或引用有权使用的凭证，任何用户均不得查看、复制或导出密码/密钥明文。
- 凭证轮换、授权、取用、撤销和停用均记录审计，但审计内容不得包含明文。

**3. 命令模板治理：**

- 实施方案模块的SCH-03需求拥有配置脚本内容及其发布版本，IMP拥有EXE-04实施联调/show tech命令模板，CUT拥有割接命令模板，SRV拥有巡检规则及巡检命令模板。
- 采集任务只能引用已发布模板及其确定版本，保存模板Owner和版本快照，避免模板变更影响历史任务。
- 独立中心创建任务时也必须选择上述业务域拥有的已发布模板；默认不提供任意命令输入框。

**4. 采集任务下发：**

- 平台创建统一采集任务，记录来源入口、业务上下文、项目、设备、连接协议、命令模板、认证方式、凭证引用或临时登录用户名、授权快照和幂等键；临时密码不属于任务数据字段。
- 平台完成业务权限、设备数据权限和命令模板权限校验；使用已保存凭证时追加凭证权限校验，临时输入时校验必填项但不要求预先存在凭证。校验通过后，为采集执行服务签发任务绑定的短期执行授权，向现有采集平台下发任务并保存外部任务号和受理结果。
- 一个批量任务可包含多台设备，但每台设备执行独立记录状态、认证方式、凭证引用或临时登录用户名及结果，支持部分设备成功或失败的准确追溯；临时密码按设备执行单次使用且不得复用。
- 重试必须基于原任务创建新的受控重试任务，不覆盖原任务、原始下发报文摘要和原始回调证据；原任务采用临时输入时，重试必须重新输入密码，不得从原任务恢复。

**5. 数据回调：**

- 现有采集平台回调外部任务状态、设备级执行结果、日志文件或结果引用及错误信息。
- 平台执行调用方认证、验签、幂等校验、回调顺序校验和状态映射，同时保留外部状态原值和原始回调证据哈希。
- PLT拥有通用采集任务状态和结果引用；SCH-03负责配置脚本内容与版本；EXE-03/04负责形成实施配置Log与联调业务结果并解释采集结果，EQP-02统一管理配置Log原始文件、解析版本与设备关联；CUT负责割接结果解释与证据关联，SRV负责巡检结果、报告业务对象和问题闭环。
- 未关联具体IMP/CUT/SRV业务单据的独立任务，结果保留在设备连接与采集中心，并可按项目、设备、创建人、时间和状态查询。

**6. 密码/密钥明文使用边界：**

- 使用已保存凭证时，设备认证允许在经认证且获得本次任务授权的采集执行进程内，短暂将凭证解密为设备协议所需明文；临时输入模式下，密码只能从当次提交请求通过受保护链路传入同一可信执行边界。
- 已保存凭证优先通过一次性取密令牌或凭证引用按任务取用；若现有接口必须接收密码字段，已保存凭证与临时密码均只可通过端到端加密且双方身份受控的同步接口传递。
- 含明文的同步请求体必须绕过网关、代理、客户端和服务端正文日志；明文不得写入数据库、异步消息、持久化队列、业务日志、回调报文、异常堆栈或导出文件。
- 临时密码不得写入浏览器本地存储、会话存储或自动填充数据；页面刷新、任务重试或再次执行必须由用户重新输入。
- 采集执行结束、失败、超时或会话关闭后，执行进程必须清除内存中的密码或密钥明文。

**7. 授权撤销与异常收敛：**

- 授权在取密或建立连接前撤销时，任务立即终止，不得再取用凭证。
- 已建立连接时撤销授权，平台通知采集子应用停止后续命令、取消当前执行、关闭会话并清除内存凭证。
- 若设备协议或执行端无法安全中断已经发出的当前命令，可等待该命令返回或超时后关闭，但必须标记“授权执行中撤销”、记录实际停止点，并禁止新连接、重试和剩余命令继续执行。
- 任务下发超时、重复下发、子应用不可用、回调重复或乱序、设备级部分失败、凭证失效等异常必须保留可追溯状态，不能覆盖原始证据。

**8. 集成形态演进：**

- V1优先采用子应用方式复用现有采集平台，保持其独立执行和发布边界。
- 只有在技术栈、依赖版本、租户模型、权限模型、发布周期和安全边界兼容后，才评估将其源代码直接合并为基础平台内部模块；该评估不作为V1交付前提。

**核心业务规则：**

1. 平台拥有设备凭证元数据、使用授权、通用采集任务、业务上下文和结果引用；现有采集平台拥有连接会话、命令执行和原始采集执行。IMP/CUT/SRV分别解释实施、割接和巡检结果，INT-12不得代替业务域直接判定实施完成、割接成功或巡检问题闭环。
2. 任务必须关联业务入口/用途、项目、设备、已发布命令模板及版本和认证方式。业务权限、设备数据权限、模板权限任一不满足时禁止下发；使用已保存凭证时还必须校验凭证对用户、设备、协议、模板和有效期的显式授权。
3. 凭证默认仅创建人可用，授权扩大必须显式记录范围和有效期。临时认证只持久化用户名，不保存密码；只有用户显式勾选“保存为设备凭证”才加密创建凭证，且新凭证仍默认仅创建人可用。
4. 每次通过校验的任务签发短期、任务绑定、不可复用的执行授权；授权在任务结束、失败、超时、撤销或到期时失效。采集执行服务不能以系统身份绕过用户和任务授权永久取用凭证。
5. 采集任务按平台任务幂等键创建，外部下发按平台任务ID幂等；批量任务按设备生成独立执行记录。重试必须创建引用原任务的新任务，保留原证据；临时密码必须重新输入。
6. 回调必须通过调用方认证、验签、任务匹配、事件幂等和序号/状态迁移校验。重复回调返回既有结果，乱序回调不得使终态回退；平台保存外部原状态和证据哈希，再通知对应业务域消费。
7. 密码/密钥明文仅可在受保护同步链路和已获本次任务授权的可信执行进程内存中短暂存在；数据库、缓存、消息、持久队列、网关/应用正文日志、回调、异常堆栈、浏览器存储和导出均不得出现明文，执行结束后清除。
8. 授权撤销发生在连接前时立即终止；连接中撤销时停止后续命令并关闭会话，无法安全中断的当前命令只可等待返回/超时，随后禁止新连接、重试和剩余命令，并记录实际停止点。
9. 子应用不可用、下发失败或业务窗口内无结果时，实施和割接按各自需求关联原失败任务上传人工证据；V2巡检可切换离线方式。人工结果不能删除、覆盖或改写在线失败任务。
10. V1启用独立中心、EXE-03/04和CUT-06入口；V2巡检复用同一凭证、任务和回调契约。集成形态可从子应用演进为内部模块，但不得改变上述Owner、授权和明文边界。

**用户故事：**

作为实施、割接或巡检工程师，我希望从当前业务任务或独立设备连接与采集中心选择设备和已发布命令模板，并可选择本人有权使用的凭证或临时输入登录用户名、密码后发起采集；如后续需要复用，我可显式将输入信息保存为加密设备凭证，以便兼顾临时设备快速连接与常用设备凭证复用，并保证密码不泄露、任务和结果全程可追溯。

**验收标准：**

- **WHEN** 用户从EXE-03/04、CUT-06或独立中心发起V1采集任务
- **THEN** 系统自动或人工确定项目、设备、用途和业务上下文，展示用户有权使用的凭证、临时账号密码输入方式和已发布命令模板
- **AND** 权限校验通过后创建统一采集任务，向现有采集平台下发并保存外部任务号和受理结果
- **WHEN** V2用户从INS-02/04发起在线巡检或预检
- **THEN** 系统复用同一认证方式、任务下发和回调契约，不新增巡检专用凭证副本或采集执行引擎
- **WHEN** 用户选择“临时输入账号密码”并直接发起任务
- **THEN** 采集任务保存认证方式和登录用户名用于审计，密码仅经受保护同步链路传至已认证采集执行进程，不写入任何持久化介质
- **AND** 页面刷新、任务重试或再次执行时，系统不得自动回填原密码，必须要求用户重新输入
- **WHEN** 用户在临时输入模式显式选择“保存为设备凭证”
- **THEN** 系统按凭证规则保存用户名并加密保存密码，创建默认仅当前用户可用的新凭证，本次任务记录该凭证ID及授权快照
- **AND** 未选择“保存为设备凭证”时，系统不得自动创建凭证或以缓存、草稿、历史参数等形式保留密码
- **WHEN** 非创建人未获得显式凭证授权，或用户缺少业务、设备、模板任一权限
- **THEN** 对已保存凭证禁止下发任务；临时输入模式仍须校验业务、设备和模板权限，并记录不含密码/密钥明文的拒绝原因和审计记录
- **WHEN** 现有采集平台返回任务状态、日志文件或结果引用
- **THEN** 系统完成调用方认证、验签、幂等和顺序校验，保留外部状态原值和原始证据，并按业务上下文通知IMP/CUT/SRV消费
- **AND** 重复回调不得生成重复业务结果，乱序回调不得使已完成任务回退到非终态
- **WHEN** 独立中心任务未关联具体IMP/CUT/SRV业务单据且收到有效终态回调
- **THEN** PLT按状态映射将通用任务更新为相应终态，保存设备级结果、结果文件引用和原始证据，并在独立中心按项目、设备、创建人、时间和状态可查询
- **WHEN** 用户通过页面、查询接口、导出、审计日志或异常信息访问设备凭证
- **THEN** 系统仅返回凭证ID、账号脱敏值和授权状态，阻止查看、复制或导出密码/密钥明文并记录访问结果
- **WHEN** 现有采集接口必须接收已保存凭证解密值或临时输入密码字段
- **THEN** 明文仅通过受保护同步链路进入已认证采集执行进程，相关请求体不记录正文日志，执行结束后清除内存中的密码或密钥
- **WHEN** 凭证授权在任务执行前或执行中撤销
- **THEN** 系统按本需求第7项规则终止或收敛执行，记录实际停止点，撤销后不得发起新连接、重试或继续剩余命令
- **WHEN** 子应用不可用、下发超时、设备级部分失败或回调异常
- **THEN** 系统保留原任务和原始证据，展示设备级结果并允许基于原任务创建新的受控重试任务
- **AND** 实施场景可按EXE-03/04手动上传Log，割接场景可按CUT-06关联原失败任务人工上传结果，巡检场景可按INS-02切换离线方式；任何降级结果均不得覆盖原任务失败证据

**涉及数据字段：**

设备凭证ID、凭证名称、凭证类型、登录账号、凭证密文、密钥版本、创建人、授权用户、允许设备范围、允许协议、允许命令模板范围、有效期、授权状态、撤销信息；采集任务编号、来源入口、用途、业务类型、业务单号、项目编码、设备序列号、连接协议、命令模板ID及版本、模板Owner、认证方式（已保存凭证/临时输入）、凭证ID及版本（临时输入时为空）、授权快照（临时输入时为空）、临时登录用户名、保存为凭证标识、任务执行授权标识、执行服务身份、执行授权签发时间与失效时间、幂等键、外部任务号、下发结果、外部状态原值、平台映射状态、设备级执行结果、结果文件引用、回调序号、验签结果、回调证据哈希、失败原因、重试来源任务号、授权撤销标记、实际停止点。临时密码不是持久化数据字段；所有业务查询、日志和回调均不得保存密码或密钥明文。

**权限与数据范围：**

项目经理可查看授权项目的采集任务状态和脱敏结果引用，但不能因项目管理权使用设备凭证；实施、割接、巡检工程师只能在对应业务任务和设备范围内发起任务，使用本人创建或显式授权的凭证，或临时输入认证。凭证创建人可管理本人凭证，授权管理员可审批/撤销指定范围但任何人都不能查看、复制或导出密码/密钥明文。集成管理员可配置子应用、重试和回调对账，无权绕过业务/设备/模板/凭证授权发起任务。结果和文件按项目、设备、业务单据及文件权限隔离，跨租户不可见。

**异常、降级及留痕要求：**

子应用不可用、下发超时或部分设备失败时保留原任务、设备级状态、请求摘要和失败证据，允许创建受控重试或走业务人工证据路径；不得把未受理任务标记成功。回调验签失败进入隔离队列并告警，重复/乱序按事件ID和序号处理。凭证失效或授权撤销立即执行本条收敛规则，无法确认执行端已清除明文时任务标记安全异常并阻止重试。临时密码不得用于异步补偿。平台记录凭证创建/轮换/授权/取用/撤销、任务校验/下发/回调/重试/停止、人工降级和业务消费结果，所有留痕均排除明文。

**依赖关系：**

- 前置依赖：现有采集平台可用接口或子应用、INT-09 LDAP/AD集成（统一身份）、EQP-01设备档案（设备与连接端点）、各业务域已发布命令模板
- 后续依赖：EXE-03配置Log采集解析、EXE-04业务联调配置收集、CUT-06割接执行闭环、INS-02双巡检方式、INS-04巡检连通性预检
- 关联依赖：NFR-02设备凭证及巡检非功能需求、平台权限与审计能力、UMC结果解析和报告能力

## NFR-01 平台性能、安全与兼容基线

| 属性 | 内容 |
| ---- | ---- |
| 需求编号 | NFR-01 |
| 所属阶段 | 全局公共基线 |
| 用户角色 | 管理员、全员 |
| 优先级 | P0 |
| 目标版本 | V1 |
| 复杂度 | 中 |
| 依赖条件 | INT-09（LDAP/AD集成） |

**业务场景与需求描述：**

作为平台公共性能安全保障（P0核心需求，评分62.5），定义项目交付、割接、巡检及公共工作台须满足的性能、安全、兼容性基线指标，为平台V1基础保障须首批满足。量化指标如下：

1. **页面响应**：页面加载与交互响应时间≤2秒（P95），覆盖项目与任务树查询、项目交付、割接任务管理、分级评估、方案编审、审批、执行等核心页面。
2. **文件上传**：单文件上传大小≤50MB，覆盖割接方案、承诺书、采集清单、执行结果等文件上传场景。
3. **并发能力**：支持并发用户≥50人，满足割接高峰期多办事处多项目并行操作需求。
4. **单点登录**：支持LDAP/AD单点登录（依赖INT-09），用户企业账号一次登录访问平台。
5. **权限控制**：基于RBAC（基于角色的访问控制）实现权限控制，支持灵活角色设置+模块权限，覆盖原厂/外协/驻场/渠道/客户多级标识。
6. **数据隔离**：实现数据隔离，项目上级按授权范围查看全部后代项目、同一父项目下的平级项目默认互不可见；外协仅授权项目；付款后自动移除代理商；服务经理精确搜索查全国；项目经理查本办事处；外协查指派项目。
7. **操作审计日志**：记录全量操作审计日志，含操作人、操作时间、操作类型、操作对象、操作前后值等，支持审计查询与追溯。
8. **浏览器支持**：支持Chrome/Edge/Firefox主流浏览器，确保跨浏览器兼容性。
9. **数据库/存储规范**：遵循数据库设计与存储规范，确保数据一致性、完整性、可扩展性。
10. **非固定层级规模**：项目规模取实际迁移项目量两倍与20万项目的较大值，任务规模取实际迁移任务量两倍与200万任务的较大值；覆盖单项目树1万个节点、单任务树5万个节点、单节点直接子节点2000个、测试深度30。测试深度不是业务层级上限。

**核心业务规则：**

1. 性能验收使用接近生产的独立环境、生产同版本构建和本条规定的数据规模；测试前记录应用/数据库/缓存节点规格、网络时延、数据量、浏览器版本和构建号，结果不能以开发机空库测试替代。
2. 核心页面/接口在50个并发登录用户持续30分钟、累计不少于10000次有效业务请求的稳态测试中，服务端错误率不高于0.5%，页面加载和主要交互P95不超过2秒；冷启动、文件传输和外部系统自身耗时单独统计，不混入后掩盖平台性能。
3. 50MB文件必须完整上传并能按文件哈希下载校验一致；超过50MB的文件在传输前或受控接收阶段明确拒绝，不产生可被业务引用的残缺附件。上传失败可重试且不得产生重复有效文件版本。
4. 项目/任务层级不设业务深度上限。性能基线按项目量max(迁移量×2,20万)、任务量max(迁移量×2,200万)，并覆盖单项目树1万节点、单任务树5万节点、单节点2000直接子节点和深度30；深度30仅为基准样本，超过时仍须保证关系、路径、权限和汇总正确并按需加载。
5. 权限验收同时覆盖允许与拒绝用例：跨租户、未授权平级项目、越级设备/文件和已撤销授权请求必须100%拒绝且不返回对象存在性之外的敏感信息；父项目仅在明确授权的后代范围内去重汇总。
6. 审计必须覆盖登录、权限/角色、项目层级、审批、设备凭证、文件、集成补偿和关键状态变更，保存主体、对象、动作、结果、时间、来源和必要前后值；审计查询本身受权且不可由业务用户修改或删除。
7. V1采用响应式Web布局，在1920×1080、1440×900、1366×768和1024×768视口完成核心流程；除明确允许横向滚动的数据表外不得出现页面级横向溢出，导航、表单和操作区应在窄视口重排。桌面客户端等多端后续复用业务接口，不作为V1门禁。
8. Chrome、Edge、Firefox以验收时记录的当前稳定版执行同一核心用例，功能、权限和业务结果一致；样式差异不得遮挡关键字段、操作或错误提示。
9. 类型、指标场景和告警级别等可变化含义字段使用基础平台可配置字典；性能阈值、安全边界和数据隔离规则不得由普通业务配置降低。

**用户故事：**

作为管理员/全员用户，我希望项目实施交付管理平台能够满足页面响应≤2秒、文件上传≤50MB、并发≥50人、LDAP/AD单点登录、RBAC权限控制、数据隔离、操作审计日志、主流浏览器支持、数据库/存储规范等性能安全基线，以便平台在割接高峰期稳定运行、权限与数据安全可控、操作可审计追溯、跨浏览器体验一致。

- **THEN** 平台在50并发基线内保持错误率≤0.5%且页面响应≤2秒（P95），资源监控无内存溢出或持续不可恢复增长

- **WHEN** 用户通过企业账号登录

## NFR-02 设备凭证及巡检非功能需求

| 属性 | 内容 |
| ---- | ---- |
| 需求编号 | NFR-02 |
| 所属阶段 | 全局公共安全基线/巡检专项 |
| 用户角色 | 管理员、全员 |
| 优先级 | P0 |
| 复杂度 | 中 |
| 目标版本 | V1设备凭证与采集安全基线；V2巡检专项 |
| 依赖条件 | INT-09（LDAP/AD集成）、INT-12（设备连接与采集平台集成） |

**业务场景与需求描述：**

作为设备连接与采集公共能力及巡检平台的性能安全基础保障，在NFR-01全部指标基础上增加设备认证信息和巡检专项指标。已保存凭证与临时账号密码的安全基线随INT-12在V1首批建设，巡检命令超时等专项能力随V2巡检业务启用。

1. **V1基础指标（同NFR-01）**：设备连接与采集公共页面响应≤2秒、文件上传≤50MB、并发≥50人、LDAP/AD单点登录、RBAC权限控制、数据隔离、操作审计日志、浏览器支持（Chrome/Edge/Firefox）、数据库/存储规范。
2. **V2巡检命令执行超时**：巡检命令执行超时≤30秒（可配置），超时后自动终止并标记该命令执行失败。超时时间由管理员后台配置，适应不同设备与命令场景；本项不作为V1发布门禁。
3. **V1设备凭证密文存储**：设备密码或密钥采用AES-256或不低于同等强度的算法加密存储，密钥材料与业务数据分离，支持密钥版本和轮换；不得保存可查询的明文副本。
4. **V1最小授权**：凭证默认仅创建人可使用，扩大用户范围必须显式授权并绑定用户、设备、协议、命令模板和有效期；“可使用”不授予明文查看、复制或导出权限。采集执行服务仅可获得由已授权用户任务派生的短期、任务绑定且不可复用的执行授权，不具有永久凭证使用权。
5. **V1受保护传输与临时明文**：优先使用一次性取密令牌或凭证引用。若现有采集接口必须接收密码字段，仅允许通过端到端加密且双方身份受控的同步链路传递，明文只在获本次任务授权的采集执行进程内存中短暂存在，执行结束后清除。
6. **V1明文防泄露**：页面、查询接口、导出、数据库、异步消息、持久化队列、网关/代理/应用正文日志、回调报文、异常堆栈和审计记录均不得包含密码或密钥明文。
7. **V1凭证审计**：凭证创建、授权、取用、轮换、撤销、停用和任务引用必须可审计，审计记录只保存凭证标识、版本、授权主体、作用范围、时间和结果。
8. **V1临时输入安全**：临时连接任务允许保存登录用户名和认证方式用于审计，但密码不得持久化或写入浏览器本地存储、会话存储和自动填充数据；刷新、重试或再次执行必须重新输入。只有用户显式选择“保存为设备凭证”时，平台才可按第3、4、7项规则加密保存并纳入凭证授权管理。

**核心业务规则：**

1. V1设备凭证与采集公共基线是EXE-03/04、CUT-06和独立采集中心的发布门禁；V2巡检超时指标只在在线巡检启用时成为门禁，不反向阻塞V1发布。
2. 已保存密码/密钥采用AES-256或同等强度的经批准算法加密，数据密文、主密钥/密钥加密密钥分离存放；凭证记录保存算法和密钥版本，不存在可通过业务查询获得的明文副本。
3. 凭证默认仅创建人可用；授权必须同时限制用户、设备、协议、命令模板和有效期。项目经理、管理员、任务参与人等身份不构成隐式凭证授权，“可使用”永远不包含查看、复制或导出明文。
4. 任务执行授权必须绑定单一采集任务和授权快照，其有效期不超过任务执行窗口；任务结束、失败、超时、撤销或到期后取密请求必须拒绝。授权撤销按INT-12停止连接和剩余命令。
5. 临时认证只持久化用户名、认证方式和任务审计，密码不得进入浏览器存储/自动填充、数据库、缓存、消息、持久队列、日志、回调、异常堆栈或导出；刷新、重试和再次执行必须重新输入。

## NFR-03 割接/巡检推送节点

| 属性 | 内容 |
| ---- | ---- |
| 需求编号 | NFR-03 |
| 所属阶段 | 割接/巡检专项 |
| 用户角色 | 一线工程师、服务经理 |
| 优先级 | P1 |
| 目标版本 | V2 |
| 复杂度 | 低 |
| 依赖条件 | INT-10（短信/邮件平台集成） |

**业务场景与需求描述：**

定义割接与巡检流程各节点的通知推送及平台内部项目进度事件要求，确保流程节点通知触达并使项目进度与专项任务状态一致。平台项目是本系统核心数据，不建设外部项目同步接口。量化指标如下：

1. **割接Step1~5各节点通知推送**：割接流程5个关键节点（任务创建/分级评估、方案编审、分级审批、执行闭环、归档）均触发短信/邮件通知推送，通知接收人含一线工程师、服务经理、二线/研发等节点相关方。
2. **巡检Step1~5内部项目进度事件**：巡检流程5个关键节点（任务创建、连通性预检、报告生成、问题标注、闭环归档）均发布内部业务事件，由项目模块幂等消费并更新项目进度。

测试方法为推送到达率测试与内部事件消费一致性测试，要求推送到达率≥99%，项目进度内部更新时间≤1分钟；重复事件不得重复推进，失败事件可重试并可追溯。

**核心业务规则：**

1. 割接五节点生成外部通知事件，巡检五节点同时生成通知和平台内部项目进度事件；每个事件包含业务对象ID、节点、状态版本和发生时间。
2. 通知到达率以渠道“已送达”数/有效发送数计算，测试样本覆盖五节点和各渠道且目标≥99%；项目进度从事件产生到项目读取新状态≤1分钟。
3. 事件按业务对象、节点和状态版本幂等，重复/乱序不得重复推进或回退项目；外部通知失败不回滚已成功的业务节点。

**用户故事：**

作为一线工程师，我希望使用“割接/巡检推送节点”能力完成本条定义的业务活动，以便获得业务场景中明确的处理结果并能够追溯处理过程。

**业务验收标准：**

- **WHEN** 测试覆盖割接/巡检各五个节点和全部启用渠道的有效通知样本
- **THEN** 渠道已送达数除以有效发送数达到99%以上，并可按节点下钻到发送与回执记录
- **WHEN** 巡检节点产生项目进度事件
- **THEN** 项目在1分钟内读取对应状态版本，重复事件不重复推进，乱序旧事件不回退进度
- **WHEN** 渠道或内部事件消费失败、接收人无权或消息重复
- **THEN** 平台保留站内兜底/进度待同步状态并支持补偿重试，不改变已成功业务节点

**涉及数据：**

业务事件ID、专项任务ID、项目ID、节点编码、状态版本、事件时间、通知ID、渠道、有效发送数、已送达数、到达率、消费时间、进度更新时间、延迟秒数、重试次数、失败原因

**权限与数据范围：**

工程师和服务经理按本人任务/项目查看通知与进度，通知管理员查看脱敏送达统计，项目内部服务仅更新授权业务对象；未授权项目和跨租户事件不可见。

**异常、降级及留痕要求：**

外部渠道失败时站内消息兜底并按INT-10重试；内部事件失败进入重试/对账队列，项目显示“进度待同步”而不伪造成功。平台记录事件版本、消费结果、延迟、渠道送达和补偿时间。

**依赖关系：** 前置依赖INT-10短信/邮件平台集成、平台内部事件能力；后续依赖CUT-01~06割接流程（节点通知推送）、INS-01~07巡检流程（内部项目进度事件）。

## AUT-01 授权申请管理

| ---- | ---- |

| 用户角色 | 工程师、管理员 |
| 优先级 | P1 |
| 目标版本 | V2 |
| 复杂度 | 中 |
| 依赖条件 | OA接口 |

**业务场景与需求描述：**

提供设备临时授权申请管理能力，规范临时授权流程。工程师或管理员通过设备序列号发起临时授权申请，授权申请规则如下：

1. **售前首次免审批**：售前场景下首次针对某设备序列号发起临时授权申请时，免审批直接生效，提升售前响应效率。
2. **再次需OA审批**：再次针对同一设备序列号发起临时授权申请时，需通过OA审批流程审批，审批通过后授权生效。
3. **OA审批集成**：再次申请触发OA审批流程（依赖INT-05 OA集成），审批结果实时回传平台，平台同步更新授权状态。

**核心业务规则：**

1. 临时授权申请必须关联申请人、项目、设备序列号、用途、权限范围和有效期；售前首次免审批按申请人业务、设备和授权类型共同判定，只能使用一次。
2. 再次申请提交OA审批，平台拥有申请状态，OA回调只更新对应审批实例；审批通过后由授权系统返回授权ID/状态才生效。
3. 申请页面和日志只展示授权类型、范围、期限、掩码授权标识，任何用户不得查看或导出设备密码、密钥或完整License明文。

**用户故事：**

作为工程师，我希望使用“授权申请管理”能力完成本条定义的业务活动，以便获得业务场景中明确的处理结果并能够追溯处理过程。

**业务验收标准：**

- **WHEN** 售前人员对授权项目设备首次申请同类型临时授权且资格校验通过
- **THEN** 平台生成免审批申请并向授权系统下发，返回授权ID后标记生效且记录首次资格已使用
- **WHEN** 同一资格再次申请
- **THEN** 平台冻结申请并生成OA审批实例，全部通过且授权系统返回结果后才标记生效
- **WHEN** 设备/项目不匹配、申请人无权、OA/授权系统失败或请求重复
- **THEN** 平台拒绝或保持待审批/待下发，幂等返回既有申请且不展示任何密码、密钥或完整License

**涉及数据：**

申请ID、申请人ID、项目ID、设备ID/序列号、业务场景、授权类型、权限范围、有效期、首次资格键、是否免审批、OA审批单号/状态、授权ID掩码、授权状态、来源版本、失败原因、申请/生效时间

**权限与数据范围：**

工程师可为本人授权项目/设备申请，售前首次资格由平台校验；OA指定审批人处理再次申请，授权管理员处理失败映射但不能代审批或查看秘密。跨项目、跨租户申请禁止。

**异常、降级及留痕要求：**

OA或授权系统不可用时申请保持“待审批/待下发”，不得消耗首次资格后又无有效授权；恢复后按申请/审批ID重试。平台记录首次判定、审批、授权ID掩码、状态前后值、失败和操作人时间，不含秘密明文。

**依赖关系：** 前置依赖OA接口（INT-05）；后续依赖INT-06备件/授权/UMC集成（授权系统关联）。

工程师按本人项目/设备查询掩码信息，授权管理员可处理找回和映射冲突但不能查看设备密码/密钥；合同和授权字段按专项权限，跨项目/租户不可见。

**异常、降级及留痕要求：**

授权接口超时展示最近成功状态和截止时间，不把未知当有效；找回证据不足或多授权冲突时保持“待核对”，修正后重试。平台记录查询条件摘要、掩码结果、映射前后值、找回证据、失败和操作人时间。

**依赖关系：** 前置依赖授权系统接口（INT-06）；后续依赖无。

## CHG-01 项目变更申请电子流

| 属性 | 内容 |
| ---- | ---- |
| 需求编号 | CHG-01 |
| 所属阶段 | 全局 |
| 用户角色 | 一线工程师、服务经理、二线/研发 |
| 优先级 | P1 |
| 目标版本 | V2 |
| 复杂度 | 中 |
| 依赖条件 | 审批引擎 |

**业务场景与需求描述：**

作为变更管控必备能力（P1需求，评分16.0），支持在项目实施、割接或独立售后服务任务执行期间发起变更申请电子流，规范变更审批流程。本需求为变更管控规范化基础，含变更内容、影响范围、回退方案三大要素；售后服务任务中的变更不得反向修改已正常闭环项目的生命周期终态。

1. **变更申请发起**：一线工程师在项目实施、割接或独立售后服务任务执行期间，针对需变更的事项（如割接方案变更、设备配置变更、实施计划调整等）发起变更申请电子流，录入变更内容、影响范围、回退方案等要素；项目已正常闭环时，变更对象仅限对应售后领域任务及其业务数据，不得将项目重新写入实施阶段或“维护阶段”。
2. **审批链路**：变更申请按"一线工程师→服务经理→二线→研发"四级链路逐级审批，每级审批人可同意、驳回或要求补充信息。审批通过后进入下一级，全部通过后变更生效。
3. **变更内容**：详细描述变更事项的具体内容，包含变更对象、变更前状态、变更后状态、变更原因等。
4. **影响范围**：评估变更对项目进度、设备运行、客户业务、关联系统等的影响范围，含受影响设备清单、受影响业务清单、风险等级等。
5. **回退方案**：制定变更失败时的回退方案，含回退步骤、回退条件、回退验证方法、回退责任人等，确保变更失败时可快速回退。
6. **审批通知**：审批节点触发钉钉审批通知推送（依赖INT-05），通知含审批标题、申请人、审批人、审批链接、截止时间等。
7. **变更记录归档**：变更申请全流程记录归档，含申请内容、审批意见、变更结果、回退记录等，支持审计追溯。

**核心业务规则：**

1. 变更必须关联明确对象及当前批准基线版本，冻结变更前值、目标值、原因、影响项目/设备/业务、风险和可执行回退方案。
2. 状态为草稿、审批中、补充中、已驳回、已批准、执行中、已完成、已回退、已撤回；审批通过只形成可执行批准版本，不代表执行成功。
3. 四级链路按申请时组织/角色解析并冻结；修改变更对象、目标值、影响范围或回退方案必须形成新版本重新审批。
4. 执行逐项记录实际结果；失败达到回退条件时按批准方案回退并验证。全部影响对象完成或回退验证后才可关闭变更。

**用户故事：**

作为一线工程师，我希望使用“项目变更申请电子流”能力完成本条定义的业务活动，以便获得业务场景中明确的处理结果并能够追溯处理过程。

**业务验收标准：**

- **WHEN** 工程师基于当前批准基线提交完整变更、影响分析和可验证回退方案
- **THEN** 平台冻结申请版本并按四级链路生成审批；全部通过后状态为“已批准/待执行”，原基线仍保持有效
- **WHEN** 执行结果全部通过验证或触发回退并验证成功
- **THEN** 平台分别生成新生效基线并标记已完成，或保留原基线并标记已回退，记录逐项结果
- **WHEN** 批准基线已变化、审批驳回/撤回、影响项缺失、执行失败或回退失败
- **THEN** 平台阻止执行/关闭并保持待补充、已驳回、已撤回或待人工处置状态，不把失败变更标记完成

**涉及数据：**

变更申请ID/版本、项目ID、变更对象类型/ID、批准基线ID/版本、变更前值、目标值、变更原因、影响项目/设备/业务、风险等级、回退条件/步骤/验证/责任人、审批实例/节点/意见、执行结果、回退结果、状态、生效时间、失败原因

**权限与数据范围：**

一线工程师可对本人任务/设备发起并执行批准变更，服务经理、二线、研发仅审批路由分配且在授权范围的实例；申请人不能代审批。敏感配置和回退附件按项目/设备字段权限，跨租户不可见。

**异常、降级及留痕要求：**

审批通知失败保留平台待办，批准基线已变化则阻止执行并要求重新评估；执行失败保持“执行失败/待回退”，回退失败升级人工处置且不得标完成。平台记录每版申请、审批、基线校验、执行步骤、回退验证、撤回和失败证据。

**依赖关系：**

- 前置依赖：审批引擎（平台内独立审批）
- 后续依赖：无
- 关联依赖：INT-05钉钉/HR/OA集成（审批通知推送）、权限体系（一线/服务经理/二线/研发各级审批权限）

## PLT-01 统一待办接入与状态一致性

| 属性 | 内容 |
| ---- | ---- |
| 需求编号 | PLT-01 |
| 所属阶段 | 全生命周期 |
| 用户角色 | 项目经理、工程管理部、审批人 |
| 优先级 | P0 |
| 目标版本 | V1 |
| 复杂度 | 中 |
| 依赖条件 | 基础平台待办、权限模型、领域事件 |
| 来源追溯 | FR-PLT-007 |

**业务场景与需求描述：**各领域产生的审批、补录、整改、回调失败和待处理事项统一进入平台待办中心；待办打开后必须定位到原业务对象和当前节点，处理结果回写原业务状态。

**核心业务规则：**
1. 待办由业务事件幂等生成，必须带业务对象、来源模块、当前状态、处理人和截止提醒时间；重复事件更新原待办，不重复创建。
2. 只有当前责任人、被授权代理人或项目权限范围内的管理角色可以处理待办；处理动作必须经过原业务模块的状态机校验。
3. 待办完成、转派、退回和挂起使用基础平台字典，业务状态以领域对象为准，待办状态不得单独形成第二套事实。

**用户故事：**作为项目经理，我希望在一个待办列表中处理各领域事项并直接回到业务上下文，以免遗漏审批和整改任务。

**业务验收标准：**
- **WHEN** 业务模块发布待处理事件
- **THEN** 平台按幂等键生成待办并展示来源对象、当前节点、责任人和操作入口
- **WHEN** 责任人完成或转派待办
- **THEN** 原业务对象状态同步更新并写入操作人、时间、前后状态及意见
- **WHEN** 原业务状态已被其他操作改变
- **THEN** 平台拒绝过期待办动作并提示刷新，保留冲突记录

**涉及数据字段：**待办编号、业务类型、业务对象ID、来源模块、节点编码、处理人、代理人、状态、优先级、提醒时间、幂等键、处理意见、完成时间。

**权限与数据范围：**按租户、组织、项目和角色授权过滤；管理角色可查看授权范围内汇总，普通人员仅查看本人待办及被授权代理待办，不得跨项目搜索业务详情。

**异常、降级及留痕要求：**事件消费失败进入重试队列并告警；待办服务不可用时原业务状态不回退，恢复后补生成；记录事件ID、重试次数、处理结果和人工补偿。

**依赖关系：**前置依赖基础平台用户、组织、权限和事件总线；后续被各领域审批、整改和回调流程调用。
## PLT-02 统一文件身份与版本管理

| 属性 | 内容 |
| ---- | ---- |
| 需求编号 | PLT-02 |
| 所属阶段 | 全生命周期 |
| 用户角色 | 项目成员、审批人、工程管理部 |
| 优先级 | P0 |
| 目标版本 | V1 |
| 复杂度 | 中 |
| 依赖条件 | 基础平台文件服务、对象存储、权限模型 |
| 来源追溯 | FR-PLT-008 |

**业务场景与需求描述：**方案、检查表、测试记录、验收资料和回调附件统一使用文件身份、版本和关联关系管理，确保同一业务对象下可查到当前有效文件及历史版本。

**核心业务规则：**
1. 文件身份与文件版本分离；上传新内容生成新版本，不能覆盖已引用或已审批版本。
2. 文件必须关联业务对象、文件类型字典、上传人和来源；审批引用固定版本，删除只允许逻辑删除未被引用的草稿。
3. 下载、预览、替换、归档和失效均校验项目及文件权限，外部回调文件需校验来源签名或幂等键。
4. 文件病毒扫描由部署配置统一控制并默认关闭。关闭时仍校验大小、摘要、扩展名、MIME、内容类型和文件策略，成功版本真实记录`SKIPPED`且不得表示为扫描通过；开启时只有Provider返回`PASSED`才允许入库，Provider缺失、异常或拒绝均失败关闭。

**用户故事：**作为审批人，我希望审批时看到的是锁定版本，后续修改不会改变已作出的判断。

**业务验收标准：**
- **WHEN** 用户上传同一业务对象的新文件
- **THEN** 平台生成新版本并保留旧版本、校验摘要和版本说明
- **WHEN** 审批单引用文件
- **THEN** 审批记录保存文件版本ID，文件后续更新不影响历史审批
- **WHEN** 无权用户访问文件
- **THEN** 平台拒绝下载并记录拒绝原因
- **WHEN** 部署未启用文件病毒扫描且其他文件校验全部通过
- **THEN** 平台不调用扫描Provider，生成新版本并记录`SKIPPED`及空Provider事实，不表示为扫描通过
- **WHEN** 部署启用病毒扫描但Provider不可用、异常或未通过
- **THEN** 平台拒绝入库且不得自动降级为`SKIPPED`

**涉及数据字段：**文件ID、版本号、业务对象类型/ID、文件类型、文件名、摘要、存储地址、来源系统、上传人、上传时间、审批引用、归档状态。

**权限与数据范围：**继承业务对象项目权限；密级和文件类型使用可配置字典；外部系统回调仅可写入约定对象和目录。

**异常、降级及留痕要求：**对象存储上传成功而元数据失败时进入补偿；安全扫描开启时病毒或Provider异常、摘要校验失败均拒绝入库且不得降级；扫描关闭时跳过病毒校验并真实记录`SKIPPED`，不得伪造`PASSED`；记录上传、扫描配置与结果、预览、下载、替换、删除和回调结果。

**依赖关系：**依赖基础平台文件服务和对象存储，供方案、实施、割接、验收和分析模块复用。
