## 3. 详细需求

## CUT-01 割接任务管理

| 属性   | 内容                          |
| ---- | --------------------------- |
| 需求编号 | CUT-01                      |
| 所属阶段 | 割接专项P1～P6                   |
| 用户角色 | 割接-一线工程师、服务经理、项目只读角色、集成服务账号 |
| 优先级  | P0                          |
| 目标版本 | V1任务闭环；V2首页KPI              |
| 复杂度  | 中                           |
| 依赖条件 | ITR接口、平台项目服务、基础平台工作流        |

**业务场景与需求描述：**

当割接任务创建时，系统应以唯一CutoverTask承载一次割接从P1任务接入、P2等级确认、P3调研及风险考察、P4割接方案、P5割接审批到P6跟踪闭环和归档的全过程；它不是通用工单，也不派生独立的割接保障工单。P1统一接收三类来源：ITR接口触发、平台项目模块内部事件触发和割接-一线工程师自建；来源上下文进入同一个CutoverTask，后续问卷、采集、方案、审批和闭环记录均关联该任务。项目工作区中的割接ProjectTask保留通用任务基础信息，并通过WorkBinding在同一任务详情工作台装载CutoverTask业务执行区。

首页提供待办列表、办理入口和一线自建入口：ITR来源任务保存来源工单及背景引用；项目来源任务直接引用平台核心项目、客户和设备数据；自建任务由割接-一线工程师输入设备序列号后通过平台项目服务查询可用上下文。V2在当前用户数据范围内增加待办、已归档、审批中和驳回待修改统计。

**核心业务规则：**

1. 每个割接任务使用唯一任务编号。ITR来源按"来源系统+来源业务单号"幂等，项目内部触发按业务事件ID幂等；重复请求返回既有任务，不覆盖历史。
2. CutoverTask拥有P1～P6流程阶段、当前状态及各阶段业务记录；客户、项目、合同和设备仍由其所属领域拥有，CUT只保存业务引用和必要快照。
3. 割接-一线工程师可办理本人有权项目的来源任务或创建自建任务；自建时必须关联一个可访问项目节点及至少一台授权设备。存在多个有效业务关联时由割接-一线工程师在授权范围内选择，不改变设备当前直接归属。
4. 任务状态以P1～P6阶段为边界，至少包括待办理、等级确认中、调研中、方案编制中、审批中、驳回待修改、闭环中和已归档。状态只能由对应阶段业务结果推进，不建立派单、接管、转单、挂起、责任区间等通用工单状态。
5. D级任务在P2完成后跳过P3进入P4；A/B/C级进入P3。P5驳回返回P4并保留原审批版本，全部节点通过后进入P6；P6提交即归档并结束本次割接流程。
6. CUT-01不提供当前通用取消、暂停、转派或平台通用时效流程；若后续需要这些动作，必须独立完成业务评审和状态机变更。
7. 任务来源、阶段状态、割接类型和组网模式等可变化值优先使用基础平台可配置字典；停用字典值不得改变历史任务解释。
8. P1是任务接入入口；任务详情中的五步工作台按P2～P6展示当前步骤、可访问历史步骤和允许操作。该界面映射不得删除、合并或重编号P1～P6业务阶段，也不得把P3采集执行拆成独立业务阶段。

**用户故事：**

作为割接-一线工程师，我希望从统一待办办理ITR或项目来源的割接任务，也能在本人有权项目下自建割接任务，并沿P1～P6查看完整进度，以便来源数据不重复录入且全过程可追溯。

**验收标准：**

- **WHEN** 割接-一线工程师进入割接首页并办理ITR或平台项目来源任务

- **THEN** 平台展示来源、项目、设备和负责人上下文，进入P2等级确认，并保存来源业务键和创建留痕

- **WHEN** 割接-一线工程师输入设备序列号创建自建割接任务

- **THEN** 平台只展示本人有权项目和设备，确认后生成唯一CutoverTask并进入P2，不创建通用工单

- **WHEN** D级任务完成P2，或A/B/C级任务完成P2

- **THEN** D级直接进入P4，A/B/C级进入P3；任务详情五步工作台展示P2～P6当前步骤及历史完成步骤，P1接入事实在任务上下文中只读展示

- **WHEN** 相同来源业务键被重复提交、用户无项目权限或设备上下文无法确认

- **THEN** 重复请求返回既有任务；无权或上下文不完整的请求不创建任务，并记录拒绝原因和操作时间

**涉及数据字段：**

割接任务编号、任务来源、来源系统、来源业务单号、来源业务事件ID、项目ID及编码、客户ID及编码、设备ID及序列号清单、割接背景、割接类型、组网模式、计划时间、当前阶段、任务状态、当前负责人、创建人、创建时间、归档时间、状态版本号、流程历史、上下文快照、V2阶段统计

**权限与数据范围：**

割接-一线工程师只能办理或创建本人参与、负责或明确授权项目的割接任务；服务经理按组织和项目范围查看任务并在P5执行审批，不因审批权限取得P1创建、指派或取消权。集成服务账号只能按契约写入来源字段。上级项目角色仅查看获授权后代项目，平级项目和跨租户任务不可见；CUT任务权限不授予设备凭证明文权限。

**异常、降级及留痕要求：**

ITR不可用不影响平台项目内部触发和一线自建；失败请求按来源幂等键重试。项目或设备查询失败时不得用空上下文创建任务，恢复后可重新查询。并发阶段推进仅首个符合状态版本的请求成功。平台记录来源摘要、幂等结果、项目设备快照、阶段前后值、拒绝原因、操作者和时间。

**依赖关系：**

* 前置依赖：INT-02 ITR接口、平台项目服务、客户与设备档案

* 后续依赖：CUT-02～CUT-06割接P2～P6业务流程

* 关联依赖：CUT-07统一采集项配置、基础平台工作流和权限体系
## CUT-02 割接分级评估

| 属性   | 内容                    |
| ---- | --------------------- |
| 需求编号 | CUT-02                |
| 所属阶段 | P2等级确认                |
| 用户角色 | 割接-一线工程师、服务经理         |
| 优先级  | P0                    |
| 目标版本 | V1人工判级；V3系统建议等级       |
| 复杂度  | 中                     |
| 依赖条件 | CUT-01、平台项目上下文、基础平台字典 |

**业务场景与需求描述：**

当割接任务进入P2等级确认时，系统应以问卷形式采集割接等级判断信息：平台项目数据提供项目、客户、设备和客户服务等级等输入上下文，割接-一线工程师填写问卷并人工选择最终割接等级（割接A/B/C/D级之一）；服务经理不在P2新增独立确认节点，而是在P5审批时复核问卷和最终等级。D级进入简易流程并跳过P3，A/B/C级进入P3。系统自动建议等级仅作为V3候选，不构成V1/V2提交条件。

问卷至少覆盖业务重要等级、操作复杂度等级、隐患风险等级、备件是否申请、客户服务等级等判断维度；字段呈现及选项使用基础平台可配置字典。问卷维度用于形成判级上下文，当前不配置评分分值、等级区间或自动计算门禁。

**核心业务规则：**

1. 只有CUT-01处于等级确认阶段且割接-一线工程师具有任务权限时可以填写问卷。平台项目数据作为输入上下文展示，不要求用户重复录入已有权威数据。
2. 割接-一线工程师提交问卷和人工等级；问卷必填项或最终等级缺失时不得提交。提交后保存问卷答案、上下文快照、最终等级、提交人和提交时间。
3. 服务经理在P5审批中复核问卷、人工等级和割接方案，不增加P2审批节点，也不在P2修改割接-一线工程师已提交答案；如认为等级或答案不合理，按P5不通过规则驳回P4/P2相关内容修正后重新提交。
4. A/B/C级进入P3并展示割接信息采集表；D级跳过P3直接进入P4，只编制简易操作和回退方案，P5仍按D级路由审批。
5. 已提交问卷发生项目、设备范围或关键上下文实质变化时，原结果标记失效并由割接-一线工程师重新填写，历史答案和等级不得覆盖。
6. V1/V2不要求评分规则、分值或等级区间。V3可另行评估系统建议等级，但建议结果不得替代人工等级和P5审批责任。

**用户故事：**

作为割接-一线工程师，我希望结合平台项目上下文填写割接等级问卷并人工确定割接A/B/C/D级，以便系统按风险等级进入标准或简易流程；服务经理在P5统一复核，避免P2重复增加审批节点。

**验收标准：**

- **WHEN** 割接-一线工程师打开处于P2的割接任务

- **THEN** 平台展示项目上下文和等级问卷，允许填写问卷答案并选择最终割接等级（A/B/C/D级）

- **WHEN** 割接-一线工程师提交完整问卷和人工等级

- **THEN** 平台保存答案、上下文快照、最终等级和提交留痕；A/B/C级进入P3，D级直接进入P4

- **WHEN** 服务经理在P5发现问卷或最终等级不合理并将相应评审项判定为不通过

- **THEN** 当前审批节点驳回并填写原因，任务按驳回流程返回修改，不在P2生成第二个审批节点

- **WHEN** 问卷必填项、最终等级缺失，用户无权，或项目设备上下文版本已失效

- **THEN** 平台阻止提交并保持P2状态，展示缺失或失效原因，不生成自动建议等级作为替代

**涉及数据字段：**

割接任务编号、评估ID、评估版本、问卷模板标识、问卷答案、项目上下文快照、客户服务等级上下文、人工最终等级、是否简易流程、提交人、提交时间、失效原因、状态版本号、P5复核结果引用

**权限与数据范围：**

割接-一线工程师填写、暂存和提交本人负责割接任务的问卷及人工等级；服务经理只在本人有权项目的P5节点复核，不在P2代填或修改答案。项目只读角色仅查看已提交等级和授权范围内依据；跨项目、平级项目和跨租户问卷不可见。

**异常、降级及留痕要求：**

平台项目上下文暂不可用时问卷可暂存但不得提交，恢复后按项目和设备引用重试。重复提交按评估ID和版本幂等；并发提交只接受首个有效版本。上下文变化使原评估失效但不删除历史。平台记录答案、人工等级、上下文版本、提交/失效人、时间和P5驳回原因。

**依赖关系：**

* 前置依赖：CUT-01割接任务、平台项目/客户/设备上下文、基础平台字典

* 后续依赖：CUT-03（A/B/C）、CUT-04（D级或P3完成后）、CUT-05分级审批

* 后置演进：V3系统建议等级算法
## CUT-03 割接采集清单动态多维绑定生成

| 属性   | 内容                             |
| ---- | ------------------------------ |
| 需求编号 | CUT-03                         |
| 所属阶段 | P3调研及风险考察                      |
| 用户角色 | 割接-一线工程师、割接-管理员                |
| 优先级  | P0                             |
| 目标版本 | V1清单管理；V2导出与流程跳转               |
| 复杂度  | 非常高                            |
| 依赖条件 | 割接类型库、组网模式库、设备类型库、后台配置、外部数据源接口 |

**业务场景与需求描述：**

当割接任务等级为A/B/C级并进入P3调研及风险考察时，系统应通过动态多维绑定机制动态生成割接采集清单，包含风险考察项（25+项，关联CUT-09）和业务调研项（扩展，关联CUT-10）两大类，标准化割接采集内容、降低个人经验依赖。匹配、填写、设备采集发起和结果回填在同一个P3任务工作台内完成：普通采集项直接渲染业务控件，需要设备采集的项目通过INT-12创建CollectionTask并在原采集项位置展示任务状态和结果。该合并是同一阶段内的交互整合，不新增采集阶段、独立通用任务或采集结果中转页面。**割接信息采集表仅在A/B/C级展示，D级不展示**（D级走简易流程，跳过P3直接跳转至P4割接方案环节）。

**动态多维绑定机制（替代原三维联动）：**

采集清单生成采用动态多维绑定（已知4维：割接类型×组网模式×设备类型×割接等级，管理员可扩展新增维度），替代原"割接类型×组网模式×产品类型"三维联动机制：

1. **多维规则匹配**：系统根据"割接类型∩组网模式∩设备类型∩割接等级"（已知4维，可扩展）的多维规则组合，从统一采集项主数据（按采集项类型区分）中匹配并动态渲染对应的采集清单，界面按采集项类型分块显示（业务调研项区块/风险考察项区块/双机部署检查项区块）。
2. **维度扩展能力**：割接-管理员可在后台新增/编辑/删除关联维度，规则引擎支持动态多维组合匹配，避免硬编码，优先支撑已知4维组合匹配。
3. **设备类型主字典**：设备类型为主字典数据，由系统管理员维护，支持扩展新增（已知示例FW/SW/ADX，非穷举）。
4. **高可靠性组网模式特殊处理**：当组网模式为5类高可靠性组网模式（VSM双机/静默双机/DRP双机/普通双机/集群）之一时，触发双机部署规范性检查表展示。

**割接信息采集表字段：**

割接信息采集表包含割接类型、组网模式、设备类型、当前版本、升级后版本（仅"版本升级"割接类型时显示）等字段，仅在A/B/C级展示。

**统一工作台填写与采集方式：**

* 采集项按已发布"界面格式"直接渲染文本、单选/多选、表格、文件、业务引用等控件；条件变化时在当前P3草稿内重新匹配并切换适用控件，不要求用户进入另一页面。

* 配置为设备采集的项目显示"发起采集"入口，调用INT-12创建与当前割接任务、清单版本、采集项和设备绑定的CollectionTask；回调后在原项目位置展示采集状态、结果摘要和证据引用，由割接-一线工程师按采集项业务规则确认或补充，不把技术回调成功直接解释为风险项通过。

* 同一项目不得同时以"直接填写结果"和"自动采集成功"伪造两个当前结果；人工降级必须标记来源并保留自动下发失败证据。凭证选择、临时账号密码与保存为凭证仍遵循INT-12权限和秘密保护规则。

**割接背景数据模块：**

新增割接背景子表，含字段：是否解决网上问题、问题工单号、工单处理人、是否二次割接、首次割接保障人、割接背景表述等，支持条件显示（如"是否解决网上问题"选"是"时展示问题工单号/工单处理人，"是否二次割接"选"是"时展示首次割接保障人）。

**双机部署检查项区块（采集项类型=双机部署检查项，5类组网模式124行）：**

作为统一采集项主数据中采集项类型=双机部署检查项的区块，仅当组网模式为5类高可靠性组网模式（VSM双机/静默双机/DRP双机/普通双机/集群）之一时才显示对应的双机部署检查表，按所选组网模式动态展示对应1类检查表（否则不显示）：

* VSM双机部署规范性检查表（17项）

* 静默双机部署规范性检查表（25项）

* DRP双机部署规范性检查表（23项）

* 普通双机部署规范性检查表（24项）

* 集群部署规范性检查表（8项）

每项检查结果反馈：是否已执行（下拉）+特殊情况备注。

**外部数据源接入能力：**

风险考察项支持从配置的外部数据源加载已知情况数据。外部数据源加载展示条件——以技术公告检查项为例：

* **所有情况必选加载当前版本外部数据**：加载当前版本对应的技术公告列表，每条数据项显示编号/主题/描述/解决方案，补充本次是否涉及+采取措施。

* **版本升级时同时加载当前版本和升级后版本外部数据**：当割接类型为"版本升级"时，同时加载当前版本和升级后版本的技术公告外部数据。

外部数据源接口为统一采集项的配置属性之一（所有采集项类型均可配置，实际应用中风险考察项使用较多），可配置数据来源接口（传入上下文信息调接口获取数据），支持动态数据查询。**接口预留，V1实现优先级最低，不可用时通过手动查询外部数据源+手动录入采集项结果替代。**

采集清单来源于统一采集项主数据，界面按采集项类型分块显示为三大区块（双机部署检查项区块仅当组网模式为5类之一时显示对应检查表，详见上文）：

* **双机部署检查项区块（采集项类型=双机部署检查项，5类组网模式124行）**：详见上文"双机部署检查项区块"说明，按所选组网模式动态展示对应1类检查表（VSM双机17项/静默双机25项/DRP双机23项/普通双机24项/集群8项）。

**割接-一线工程师扩展能力：**

支持割接-一线工程师在已生成清单基础上自定义新增调研项和风险项（自定义项标记来源，禁止删除系统预置必选项；提交前可删除本人新增且未被引用的自定义项，见核心业务规则5）。

**清单操作能力：**

* 暂存（V1）：保存按钮临时保存当前进度（来源R014，P0）。

* 导出（V2子功能）：下载按钮导出清单（风险考察项+业务调研项）。**本子功能为V2规划能力（来源R013，P1），V1不支持清单导出，V2实现下载按钮导出。**

* 流程跳转（V2子功能，基础跳转V1内置）：下一步跳转至P4割接方案环节。**V1内置基础跳转能力（采集清单保存后通过任务状态流转自动进入P4），独立流程跳转优化需求（来源R015，P1）为V2规划能力，V2支持更灵活的流程跳转配置。**

**割接-管理员后台维护（动态多维配置）：**

割接-管理员在后台维护统一采集项（按采集项类型区分业务调研项/风险考察项/双机部署检查项）的内容定义及动态多维绑定关系（已知4维：割接类型×组网模式×设备类型×割接等级，可扩展新增维度，详见CUT-07、CUT-09、CUT-10）。统一采集项表格支持后台维护编辑（增、删、改、查及添加动态多维关联关系），各字段的界面格式与内容用于采集信息分析与结果页面的填写说明。割接-一线工程师仅在前端按动态多维绑定结果填写，不可修改绑定关系。

**核心业务规则：**

1. 只有CUT-02最终等级为A/B/C且评估版本有效的任务可生成采集清单；D级任务必须跳过P3，平台不得为其生成或提交采集清单实例。
2. 清单生成以任务的割接类型、组网模式、设备类型、最终等级及已启用扩展维度值为输入，匹配CUT-07/CUT-09/CUT-10当前适用的已发布配置。生成时保存输入快照、采集项版本和绑定规则版本，后台配置后续变更不增删已生成清单内容。
3. 同一采集项命中多条有效绑定时按采集项ID去重，"必填"优先于"选填"；若命中定义互相冲突，平台列出冲突规则并要求选择有效配置。没有任何适用项时，允许一线补充自定义项并标记配置缺口，不直接阻断割接主流程；系统预置必填项仍须完成。
4. 高可靠组网只展示与当前组网模式对应的一类双机部署检查表。版本升级任务同时带入当前版本和升级后版本；非版本升级任务不得要求填写升级后版本，也不得加载升级后版本公告。
5. 系统预置必填项不可删除、改名或改为选填；割接-一线工程师可新增任务级自定义项，并可在提交前删除本人新增且未被引用的自定义项。提交后清单内容和答案锁定，修改必须生成新清单版本并使下游未审批方案失效。
6. 外部数据加载结果必须记录来源、查询条件、查询时间和成功状态。接口不可用时允许工程师附上人工查询证据并手工录入，记录来源为"人工"，不得把加载失败标记为"无风险"。
7. 所有必填项完成后方可提交；风险考察结果为"否/未通过"时必须填写事实说明，并作为CUT-04预估风险及应对措施的输入。暂存不触发流程推进。
8. V1支持生成、填写、暂存、提交和提交后进入P4；V2增加导出与流程跳转配置，不改变清单版本、必填校验和D级跳过规则。
9. 采集项界面格式、条件显示和工作方式来自已发布采集项版本；前端不得按采集项名称硬编码控件或采集动作。条件值变化时系统在当前草稿中重新匹配，展示新增、移除和保持项差异；稳定采集项ID未变化的有效答案可保留，移出适用范围的旧答案只保留在版本/审计记录中，不进入本次提交。
10. 设备采集项必须通过INT-12创建CollectionTask，并保存任务、清单版本、采集项、设备和结果引用关系。设备连接与采集中心（DAC）只负责授权、任务下发和回调，CUT负责采集项业务解释与提交门禁；任何回调不得直接把采集项判定为通过。
11. CollectionTask执行中、失败或回调待处理时，P3工作台展示真实技术状态。失败时可按规则重试或采用人工证据降级，原失败任务和失败原因不可覆盖；清单提交只读取当前被选择且满足业务规则的结果版本。

**用户故事：**

作为割接-一线工程师，我希望在A/B/C级割接任务中按割接类型、组网模式、设备类型、割接等级动态多维绑定生成风险考察项和业务调研项清单，组网模式为5类高可靠性组网模式之一时自动展示对应的双机部署规范性检查表，风险考察项支持从配置的外部数据源加载已知情况数据，并支持自定义新增项和暂存（V2后续补充导出与流程跳转优化），以便无需依赖个人经验判断采集内容、避免遗漏关键风险点或业务调研点。

**验收标准：**

- **WHEN** 割接任务等级为A/B/C级（非简易流程），割接-一线工程师进入P3调研及风险考察页面

- **THEN** 页面展示割接信息采集表（含割接类型、组网模式、设备类型、当前版本、升级后版本字段），项目信息表和割接等级表在当前页面固定展示

- **AND** 升级后版本字段仅当割接类型为"版本升级"时显示

- **WHEN** 割接-一线工程师在割接信息采集表中选择割接类型、组网模式、设备类型

- **THEN** 系统根据动态多维绑定（割接类型×组网模式×设备类型×割接等级，可扩展）从统一采集项主数据（按采集项类型区分）中匹配并动态渲染对应的采集清单，界面按采集项类型分块显示（业务调研项区块/风险考察项区块/双机部署检查项区块）

- **AND** 清单中每项展示采集项名称、描述、检查结果/反馈结果、是否必填等字段，必填项以标识区分

- **AND** 文本、选择、表格、文件、业务引用和设备采集项在同一P3工作台按已发布界面格式显示；条件变化时自动重新匹配并显示项目差异，不跳转独立采集阶段

- **THEN** 系统按所选组网模式动态展示对应的双机部署规范性检查表（VSM双机17项/静默双机25项/DRP双机23项/普通双机24项/集群8项）

- **AND** 每项检查结果反馈"是否已执行"（下拉）+特殊情况备注

- **WHEN** 统一采集项中风险考察项配置了外部数据源接口（如技术公告检查项）

- **THEN** 所有情况必选加载当前版本外部数据（如技术公告列表，每条数据项显示编号/主题/描述/解决方案，补充本次是否涉及+采取措施）

- **AND** 若割接类型为版本升级，同时加载当前版本和升级后版本外部数据

- **WHEN** 割接-一线工程师在已生成清单基础上自定义新增或删除调研项和风险项

- **THEN** 系统允许新增自定义项（标记来源），禁止删除系统预置必选项

- **WHEN** 割接-一线工程师点击保存按钮

- **THEN** 系统保存清单草稿、当前已填内容和填写进度，清单保持未提交状态（V1能力）

- **AND** V1不支持导出清单（导出为V2子功能，来源R013），V2实现下载按钮导出清单（风险考察项+业务调研项）

- **AND** V1内置基础跳转能力（采集清单保存后通过任务状态流转自动进入P4），独立流程跳转优化为V2子功能（来源R015）

- **WHEN** A/B/C级任务没有命中适用规则，或命中规则存在定义冲突

- **THEN** 平台展示配置缺口或冲突：没有命中适用规则时允许一线补充任务级自定义项并标记配置缺口后继续，命中规则存在定义冲突时平台列出冲突规则并由人工选择有效配置；系统预置必填项缺失时仍阻止提交，D级任务按CUT-02直接进入P4

- **WHEN** 外部数据源加载失败或超时

- **THEN** 平台标记对应采集项"外部数据加载失败"，保存失败记录，并允许工程师上传人工查询证据后以"人工"来源填写结果

- **WHEN** 割接-一线工程师在设备采集项发起采集，或DAC返回执行结果

- **THEN** 平台创建并展示与任务、清单版本、采集项和设备绑定的CollectionTask；回调结果在原采集项位置回填状态、摘要和证据引用，仍由CUT规则判断是否满足该项

- **WHEN** 采集平台不可用、授权失败或回调超时

- **THEN** 原项目保留下发失败状态和证据，允许重试或按权限采用手工填写/上传证据，不新增独立采集页面、不将失败任务改写为成功

**业务场景与需求描述：**

当割接任务进入P4割接方案环节时，系统应提供割接方案的模板化编审能力，支撑标准流程与简易流程两条线，确保方案标准化。方案编审以CUT-03采集清单为输入，输出可执行的割接方案；业务调研录入结果+风险考察录入结果+割接项目+用户资产库等信息字段可被割接方案环节引用和带入。

**方案来源分支（是否已有割接方案）：**

1. **选"是"→直接导入上传完整方案**：割接-一线工程师已有完整割接方案时，直接上传完整方案文件，跳过模板填写环节。
2. **选"否"→展示方案模板填写**：割接-一线工程师无现成方案时，基于方案模板在线填写各章节内容。

**风险考察结果展示：**

风险考察结果从上一步P3调研及风险考察流程带入展示，作为方案编审的输入依据。

**方案章节细化：**

方案分为两大章节：

1. **割接概述**：含项目割接描述（从割接任务带入）、计划表、割接前拓扑上传、割接后拓扑上传、设备清单（带入）、组网配置上传、割接保障人员安排表等子章节。
2. **执行操作**：含预估风险及应对措施、割接前操作清单、执行操作清单、收尾收集清单、后业务测试表、回退方案说明、回退步骤、割接后保障等子章节。

**割接保障人员安排表：**

角色预置为四类：客户、迪普一线工程师、迪普二线工程师、迪普研发，每类角色含字段：姓名、任务描述、联系电话、到位时间。（该四类角色为保障人员安排表的预置业务角色枚举，非平台RBAC角色。）

**预估风险及应对措施：**

风险项来源于割接信息采集表（CUT-03）中所有选"否"的选项（即未通过规范性检查的风险项），割接-一线工程师针对每个风险项填写应对措施。

**操作按钮：**

* 保存：临时保存方案。

* 下载割接初稿：下载当前编写的方案初稿。

* 上传完整方案：上传完整方案文件（对应"是否已有割接方案"选"是"分支）。

* 返回：返回上一步。

* 下一步：提交方案流转至CUT-05分级审批环节。

**标准流程与简易流程差异：**

* **标准流程（A/B/C级）**：方案需完整填写所有章节（割接概述+执行操作），包含详细割接步骤、操作清单、回退方案、保障人员安排、预估风险及应对措施等。

* **简易流程（D级）**：仅弹出割接各阶段操作步骤填写窗口，填写每割接阶段操作步骤+回退步骤，简化编审流程，提升效率。

**方案编审流程：**

割接-一线工程师提交方案后，流转至CUT-05分级审批环节。服务经理/二线/研发按级别审批方案，审批通过后方案锁定，作为CUT-06执行闭环的执行依据。审批驳回则退回割接-一线工程师修改。

**核心业务规则：**

1. A/B/C级任务必须引用一份有效且已提交的CUT-03清单后才能创建方案；D级任务引用已确认的CUT-02评估并创建简易方案，不得要求补建CUT-03清单。
2. 每次创建方案均绑定任务、评估版本、采集清单版本和方案模板版本，并保存引用数据快照。项目、设备、用户资产或风险清单后续变化不静默改写已提交方案；影响执行范围的变化使方案失效并要求创建新版本。
3. "上传完整方案"和"模板填写"是两种编辑方式。上传分支校验文件有效性、安全性、方案归属和人工确认，不强制解析或补齐在线模板字段；在线填写分支按当前等级校验模板必填内容。
4. CUT-03中所有"否/未通过"风险项必须逐项关联应对措施。保障人员安排属于方案从属信息；审批通过后仍允许修改保障人员安排中的联系人、联系方式和到位时间并记录前后值、操作人、时间和原因，不触发重新审批。
5. 草稿可反复保存和下载初稿；提交时形成不可修改的方案版本并进入CUT-05。审批驳回后原版本状态保持"已驳回"，工程师基于该版本创建新版本修改，不得覆盖审批所见内容。
6. CUT-05全部审批通过后方案正文版本锁定并作为P6引用依据。保障人员角色或任务职责变化必须创建新方案版本，并按原割接等级重新执行P5；其他方案正文或附件变化同样创建新版本，不覆盖原审批版本。
7. 方案编辑方式、章节类型、人员角色、方案状态和风险处置状态等可变化字段使用基础平台可配置字典；模板停用不影响历史方案解释。

**用户故事：**

作为割接-一线工程师，我希望在方案编审环节选择"是否已有割接方案"（选是→直接上传完整方案，选否→模板填写），风险考察结果从上一步带入展示，业务调研与风险考察录入结果、割接项目、用户资产库等信息字段可被引用带入，按割接概述和执行操作两大章节编制方案，D级简易流程仅填写各阶段操作步骤+回退步骤，以便标准化方案编审、减少重复录入、提升D级割接的编审效率。

**验收标准：**

- **WHEN** 割接-一线工程师在割接任务中发起方案编审

- **THEN** 页面展示"是否已有割接方案"选项，风险考察结果从上一步P3流程带入展示，业务调研录入结果+风险考察录入结果+割接项目+用户资产库等信息字段可被引用和带入

- **WHEN** 割接-一线工程师选择"是否已有割接方案"为"是"

- **THEN** 系统提供"上传完整方案"按钮，直接上传完整方案文件，跳过模板填写环节

- **AND** 平台校验文件有效性、安全性、方案归属和人工确认，不强制解析或补齐在线模板字段；校验通过后形成方案版本并流转至CUT-05

- **WHEN** 割接-一线工程师选择"是否已有割接方案"为"否"

- **THEN** 系统展示方案模板，方案分为割接概述和执行操作两大章节

- **AND** 割接概述含项目割接描述（带入）、计划表、割接前拓扑上传、割接后拓扑上传、设备清单（带入）、组网配置上传、割接保障人员安排表等子章节

- **AND** 执行操作含预估风险及应对措施、割接前操作清单、执行操作清单、收尾收集清单、后业务测试表、回退方案说明、回退步骤、割接后保障等子章节

- **WHEN** 割接-一线工程师填写割接保障人员安排表

- **THEN** 系统展示客户/迪普一线工程师/迪普二线工程师/迪普研发四类角色，并保存每类角色的姓名、任务描述、联系电话和到位时间

- **WHEN** 割接-一线工程师填写预估风险及应对措施

- **THEN** 系统加载CUT-03中所有结果为"否"的风险项，保存每个风险项与应对措施的一一关联及未填写状态

- **WHEN** 割接-一线工程师点击"下载割接初稿"按钮

- **THEN** 系统生成并返回当前方案版本的初稿文件，记录下载人、下载时间和方案版本

- **WHEN** 割接任务等级为D级（简易流程）

- **THEN** 系统仅展示割接各阶段操作步骤与回退步骤填写窗口，不加载A/B/C级完整方案章节

- **AND** 割接-一线工程师填写完毕提交后，方案按D级简易审批层级（发起人→服务经理）流转至CUT-05分级审批

- **WHEN** 割接-一线工程师填写完毕点击"下一步"

- **THEN** 系统将方案状态更新为"待审批"，保存提交版本并创建CUT-05分级审批实例

- **WHEN** A/B/C级方案缺少必需章节、存在未填写应对措施的风险项、上传文件校验失败或引用的采集清单版本已失效

- **THEN** 平台阻止提交并保持方案草稿状态，展示缺失章节、未处置风险、文件错误或失效来源，不创建CUT-05审批实例

**权限与数据范围：**

割接-一线工程师只能创建、编辑和提交本人负责割接任务的方案草稿，可读取该任务已授权的项目、设备、清单和用户资产信息；提交后无权修改该版本。服务经理可查看所属组织或授权项目方案、退回草稿或参与CUT-05审批，但不能在审批中代替工程师改写方案。项目只读成员仅查看已锁定方案的非敏感章节；联系方式、配置附件和拓扑按字段与文件权限控制，平级项目和跨租户不可见。下载初稿和完整方案均需重新鉴权并记录下载人。

**异常、降级及留痕要求：**

## CUT-05 割接分级审批

**业务场景与需求描述：**

当割接方案提交后进入P5割接审批时，系统应按割接等级实施分级审批管控，不同等级对应不同审批层级与串行级数，确保高级别割接获得更严格的审批把关。审批对象为CUT-04提交的割接方案（含采集清单）。审批页面汇总引用前序页面数据，并提供5项合理性评审表单与提前时间合规判断（提前时间合规判断为V2子功能，V1仅展示割接操作时间字段不启用自动合规判断），驳回跳转至P4割接方案修改，通过跳转至P6割接跟踪与闭环。

| 割接等级 | 审批路由                 | 串行级数 |
| ---- | -------------------- | ---- |
| A级   | 发起人 → 服务经理 → 二线 → 研发 | 4级串行 |
| B级   | 发起人 → 服务经理 → 二线      | 3级串行 |
| C级   | 发起人 → 服务经理           | 2级串行 |
| D级   | 发起人 → 服务经理           | 2级串行 |

**审批页面数据汇总引用：**

审批页面以引用方式汇总展示前序页面数据，确保审批人全面掌握方案上下文：

1. **项目信息**：11字段项目信息表（来源P2割接等级确认固定展示）。
2. **采集信息分析**：含割接类型、组网模式、割接操作时间、是否未按规定提前时间提交（V2子功能，系统判断带出；V1仅展示割接操作时间）。
3. **风险考察项展示**：风险项1-4等关键风险考察项填写结果。
4. **业务调研项展示**：调研项1-4等关键业务调研项填写结果。
5. **割接等级展示**：5个评估维度（业务重要等级/操作复杂度等级/隐患风险等级/备件是否申请/客户服务等级）取值与最终等级。
6. **割接方案展示**：CUT-04方案内容（割接概述+执行操作）。

**提前时间合规判断（V2子功能，仅A/B级启用）：**

* **启用条件**：仅关联割接等级为A/B级启用，C/D级不判断。

* **计算方式**：按自然日计算割接操作时间与方案提交时间差。

**审批动作流转：**

* 审批节点按级别自动生成，每个节点支持通过/驳回操作。

* **驳回→跳转至P4割接方案修改**：方案退回割接-一线工程师修改，方案状态变更为"已驳回"，修改后重新提交从首节点开始审批。

* **待办任务推送通知**：待办任务发送推送通知至下一审批人（来源R037）。V1通过站内消息通知；V2短信/邮件通过INT-10发送，钉钉通过INT-05发送。除上述已编号通道外不包含通用IM；外部通道不可用时回退站内消息。

* 审批意见、审批人、审批时间完整记录，支持审批历史追溯。

**核心业务规则：**

1. 每个审批实例必须绑定一份已提交且有效的CUT-04方案版本、最终割接等级和对应评估/清单版本；审批开始后引用快照固定，任何来源变更不得静默更新审批页面。
2. 审批路由以提交时最终等级生成并保存快照：A级为发起人→服务经理→二线→研发，B级为发起人→服务经理→二线，C/D级为发起人→服务经理，全部串行。不得由发起人删减节点或临时降低审批级别。
3. 当前节点仅能由节点快照中指定且具备该项目数据权限的审批人处理；非当前节点、已处理节点或代理授权已失效时禁止审批。通过和驳回都必须填写反馈意见，5项合理性评审必须全部作答。
4. 任一项为“否”必须填写不合理原因并驳回，不允许流向下一节点；全部节点通过后锁定方案正文版本并将任务置为"闭环中"。专项提前时间判断结果只作为审批信息展示，不自动替代5项评审结论。
5. 任一节点驳回即终止当前审批实例，方案版本状态为"已驳回"。工程师基于被驳回版本创建新方案版本，修改后从首节点重新发起新审批实例；原审批意见和快照只读保留。
6. V1仅展示割接操作时间，不执行自动提前时间判断。V2只对A/B级按割接类型匹配专项提前时间规则，以自然日计算"割接操作时间-方案提交时间"；结果作为审批参考，不新增平台通用时效审批，也不阻断C/D级流程。规则版本随审批实例保存。
7. 下一节点通知优先使用站内消息；V2增加INT-10短信/邮件和INT-05钉钉，不包含其他未编号IM通道。通知失败不回滚已完成审批动作，但必须按通道标记失败并支持重发，待办仍可在平台内查询。

**用户故事：**

作为服务经理/二线/研发审批人，我希望系统按割接等级自动生成对应审批节点（A级4级串行：发起人→服务经理→二线→研发；B级3级串行：发起人→服务经理→二线；C/D级2级串行：发起人→服务经理），在汇总引用前序页面数据（项目信息、采集信息分析、风险考察项、业务调研项、割接等级5个评估维度、割接方案）的审批页面上通过5项合理性评审表单进行评审，驳回跳转至P4修改、通过跳转至P6跟踪与闭环，驳回或通过均填写反馈意见，待办推送通知至下一审批人（V1站内消息，V2短信/邮件多通道接口预留），以便高级别割接获得更严格的多层级把关、低级别割接快速通过、审批管控与风险等级匹配。

**验收标准：**

- **WHEN** 割接-一线工程师提交割接方案（含采集清单）至审批环节

- **THEN** 系统按割接等级自动生成对应审批节点（A级4级串行：发起人→服务经理→二线→研发；B级3级串行：发起人→服务经理→二线；C/D级2级串行：发起人→服务经理）

- **AND** 审批页面汇总引用项目信息（11字段）、采集信息分析、风险考察项（风险项1-4）、业务调研项（调研项1-4）、割接等级（5个评估维度）、割接方案等前序页面数据

- **AND** 首节点审批人收到审批待办，并通过推送通知收到提醒（V1通过站内消息；V2短信/邮件通过INT-10、钉钉通过INT-05发送，不包含其他IM，外部通道不可用时回退站内消息）

- **AND** V2系统启用提前时间合规判断，按割接类型匹配提前时间阈值（10类规则表），计算割接操作时间与方案提交时间差，自动判断"是否未按规定提前时间提交"并在采集信息分析中带出结果（是/否）

- **WHEN** 割接等级为C/D级

- **THEN** 系统不启用提前时间合规判断，"是否未按规定提前时间提交"字段不展示或置空（V1/V2均不启用）

- **WHEN** 当前审批节点审批人查看评审表单

- **THEN** 页面展示5项合理性评审项（割接前准备工作是否合理/业务测试内容是否合理/割接执行步骤是否合理/割接回退步骤是否合理/其他是否合理），每项单选是/否，选"否"时展示不合理原因输入框

- **WHEN** 当前审批节点审批人执行通过操作并填写反馈意见

- **THEN** 流转至下一审批节点（若有），全部节点通过后方案状态变更为"已锁定"，跳转至P6割接跟踪与闭环（CUT-06执行闭环）

- **AND** 审批意见、审批人、审批时间完整记录，审批历史可追溯

- **WHEN** 当前审批节点审批人执行驳回操作并填写反馈意见（必填）

- **THEN** 方案退回割接-一线工程师修改，方案状态变更为"已驳回"，跳转至P4割接方案修改

- **AND** 割接-一线工程师修改后重新提交，从首节点开始重新审批

- **WHEN** 审批人无当前节点权限、方案或采集清单版本已失效、评审项缺失，或任一合理性评审为"否"却选择通过

- **THEN** 平台阻止审批并保持当前节点状态，展示权限、版本或评审校验失败原因，不锁定方案且不创建下一节点待办

**涉及数据字段：**

**权限与数据范围：**

发起人可提交本人方案并查看本审批实例进度，但不能代替服务经理、二线或研发审批；服务经理、二线和研发仅可处理分配给本人且处于当前节点的待办，并须同时具备任务所属项目数据权限。审批管理员可处理人员离职等节点改派，但不能代审批，改派必须保留原审批人和原因。只读项目成员仅查看最终结果；方案配置、拓扑、联系方式等内容继续受原字段/文件权限约束，平级项目和跨租户不可见。

**依赖关系：**

## CUT-06 割接跟踪与闭环

| 属性   | 内容                                  |
| ---- | ----------------------------------- |
| 需求编号 | CUT-06                              |
| 所属阶段 | P6跟踪与闭环                             |
| 用户角色 | 割接-一线工程师                            |
| 优先级  | P0                                  |
| 目标版本 | V1基础闭环；多角色填写仅为V3演进方向                |
| 复杂度  | 高                                   |
| 依赖条件 | CUT-05、INT-12、基础平台附件能力、平台项目服务、ITR接口 |

**业务场景与需求描述：**

当割接任务进入P6时，系统应支持记录现场割接结果并完成归档回流；P6不是平台驱动的逐步骤执行引擎。P4中的操作、验证和回退清单是已审批方案内容，P6引用方案并记录割接前检查、割接执行、割接测试、是否发生回退、详细说明、附件、遗留项文本以及最终成功/失败结果。提交后形成归档闭环事实并结束本次割接流程。

CUT-06通过INT-12提供设备凭证选择、临时账号密码输入、采集任务下发和数据回调入口，现有采集平台负责连接、命令执行和数据采集。本平台保存下发、失败、回调及人工上传证据，但这些证据不创造逐步骤执行状态机或稳定观察阶段。

**核心业务规则：**

1. CUT-05全部审批通过后任务进入P6；P6引用批准方案、设备范围和采集清单，不把方案步骤转换为可逐项开始、完成或失败的业务状态。
2. 割接-一线工程师统一填写割接前、执行、测试和回退结果。V1/V2正式范围不按二线、研发、服务经理拆分闭环字段；多角色填写只保留为V3跨需求演进方向，启动前必须重新确认字段Owner、角色权限、提交顺序、冲突规则和最终归档责任。
3. INT-12支持已保存凭证或临时账号密码。临时密码不保存；用户明确选择保存为凭证时才创建加密凭证。下发与回调按任务ID和回调事件ID幂等，回调只作为闭环证据。
4. 在线采集失败时允许授权工程师上传人工结果，必须关联原失败任务、设备、采集阶段和证据来源；失败记录不得被人工结果覆盖或删除。
5. 闭环单记录割接前/执行/测试是否正常、是否发生回退及说明、割接后信息采集清单、实施承诺书、遗留项文本和最终成功/失败。遗留项是本次闭环记录，不产生独立CUT任务、状态、责任区间或归档门禁。
6. 割接-一线工程师提交闭环单后，提交即形成归档闭环事实并结束本次割接流程；不存在"先已闭环、待遗留项全部处理后再归档"的第二阶段。
7. 成功结果发布项目阶段/进度业务事件并刷新客户资产，不得直接改写项目生命周期状态；失败结果同样归档。对ITR来源任务的已归档结果或按契约生成故障单，由INT-02@V2负责出向回传；外部接口失败进入重试、对账或人工补偿，不回滚本地归档事实。
8. CUT-06不建立逐步骤执行状态机、停止/回退条件引擎或稳定观察窗口；若未来需要现场编排，须作为独立增强需求重新评审。

**用户故事：**

作为割接-一线工程师，我希望在割接完成后记录检查、执行、测试、回退、附件、遗留项和最终结果，并引用设备采集证据提交归档，以便平台形成可信闭环但不替代现场操作指挥。

**验收标准：**

- **WHEN** CUT-05全部节点通过，割接-一线工程师进入P6

- **THEN** 平台展示批准方案引用、四类结果字段、附件、遗留项和INT-12连接/采集入口，不生成逐步骤执行或稳定观察任务

- **WHEN** 割接-一线工程师通过INT-12下发采集任务并收到成功或失败回调

- **THEN** 平台按任务ID和事件ID保存证据；失败时允许关联原任务上传人工结果，且保留原失败事实

- **WHEN** 割接-一线工程师填写闭环结果并点击提交

- **THEN** 平台保存闭环单和归档时间，任务直接进入已归档并结束流程；遗留项随闭环快照保存但不阻止归档

- **WHEN** 最终结果为失败，或ITR出方向接口暂不可用

- **THEN** 失败闭环仍归档；平台保留ITR待回传/待建单状态和重试记录，不把通知或HTTP成功当作业务完成

**涉及数据字段：**

割接任务编号、闭环单ID、批准方案ID及版本、设备范围引用、四项结果及详细说明、回退结果及原因、割接后信息采集清单附件、割接实施承诺书附件、遗留项文本、割接结果、统一采集任务编号、回调事件ID、认证方式、设备凭证ID及版本、临时登录用户名、保存为凭证标识、采集阶段、采集结果引用、原失败任务编号、人工上传人及时间、ITR回传状态及故障单号、项目阶段/进度刷新时间、客户资产刷新状态、提交人、提交时间、归档时间、状态版本号

**权限与数据范围：**

割接-一线工程师可填写和提交本人负责割接任务的P6闭环内容；V1其他角色只在授权范围查看，不代填角色化字段。设备凭证选择、临时输入、采集结果和附件下载分别执行INT-12及项目数据权限；未明确授权的凭证仅创建人可用，跨项目和跨租户不可见。

**异常、降级及留痕要求：**

采集平台不可用时保留下发失败记录并允许人工上传证据；附件上传失败时闭环单保持草稿，修复后重试。ITR回传失败不回滚已归档闭环，进入对账和人工补偿。重复提交返回既有归档结果，并发提交只接受首个状态版本。平台记录方案引用、闭环字段、采集失败及人工替代、附件、结果、回传、操作者和时间。

**依赖关系：**

* 前置依赖：CUT-05分级审批、INT-12设备连接与采集、基础平台附件能力

* 后续依赖：项目阶段/进度事实和客户资产刷新；INT-02@V2 ITR结果回传/失败建单

* 不依赖：后置工单领域候选不构成CUT-06当前交付或归档前提

**业务场景与需求描述：**

当割接-管理员维护割接模块配置时，系统应提供割接管理模块的可配置化能力，统一维护割接类型、组网模式、设备类型、统一采集项定义（按采集项类型区分业务调研项/风险考察项/双机部署检查项）及动态多维绑定关系，确保平台可配置、可扩展，避免硬编码。统一采集项表格支持后台维护编辑（增、删、改、查及添加动态多维关联关系），各字段的界面格式与内容用于采集信息分析与结果页面的填写说明（来源"3.调研及风险考察"sheet行52、行90）。

* 割接类型（外键，来源于CUT-07割接类型10类）

* 组网模式（外键，来源于CUT-07组网模式5类）

* 设备类型（外键，来源于CUT-07设备类型主字典）

* 割接等级（外键，A/B/C/D级）

* 其他维度（可扩展新增）

* 绑定关系ID（主键，唯一标识一条绑定关系）

* 是否必填（在该绑定关系下该项调研项是否必填）

* 是否启用（启用/停用）

* 维护人、维护时间

**核心业务规则：**

1. CUT-10不新建第二套调研项主数据，只提供CUT-07统一采集项中"采集项类型=业务调研项"的筛选视图和关联矩阵；调研项ID在两处必须一致。
2. 已知绑定维度为割接类型、组网模式、设备类型、割接等级；维度定义、选项和组合关系均配置化。新增维度须定义数据类型、取值来源、是否必填和匹配方式，不改变既有维度语义。
3. 一条有效绑定关系由调研项、维度组合、有效期唯一确定；相同有效期内禁止重复或互相冲突的绑定。具体组合优先于通配组合，优先级相同且结果冲突时平台列出冲突规则并由人工选择有效配置。
4. 矩阵变更对新生成的CUT-03清单生效；已生成或执行中的割接清单保留配置版本快照，不因后台变更静默增删采集项。需要采用新矩阵时必须显式重新生成并展示差异。
5. 系统预置必选调研项不得被一线删除；一线只能在具体割接任务新增自定义项并标记来源。条件显示只控制界面展示，处于显示条件且标记必填的字段仍参与提交校验。
6. 外部动态数据查询只负责候选值或已知数据加载，查询失败不得自动跳过必填项；人工填写须标记数据来源。

**用户故事：**

作为割接-管理员，我希望在后台维护业务调研项（含割接背景子表、涉及业务简述、影响范围、业务连续性要求、拓扑图、设备部署位置规划、接口互联规划、IP地址与vlan规划、并发/新建连接数、CPU/内存使用率、连通性测试、友商配置翻译检查等）的内容定义及动态多维绑定关系（已知4维可扩展），以便CUT-03采集清单按绑定关系联动展示对应业务调研项、确保关键业务调研点强制采集、降低个人经验依赖。

**验收标准：**

- **WHEN** 割接-管理员在后台维护业务调研项的内容定义

- **THEN** 系统支持配置调研项ID、调研项名称（项命名-调研项）、调研含义（项含义）、界面格式（支持多种数据类型）、界面格式动态数据查询、反馈结果内容、操作（新增/编辑/保存/删除）

- **AND** 此表格支持后台维护编辑，各字段的界面格式与内容用于采集信息分析与结果页面的填写说明

- **WHEN** 割接-管理员在后台配置业务调研项的动态多维绑定关系

- **THEN** 系统支持为每项调研项配置"割接类型×组网模式×设备类型×割接等级"（已知4维，可扩展）的绑定关系，配置界面以矩阵形式展示

- **AND** 绑定关系新版本发布后由新生成的CUT-03清单使用，已生成清单继续按原绑定版本展示（原文"绑定关系配置变更实时生效"与核心业务规则4冲突，已按规则4口径统一）

- **WHEN** 割接-管理员在后台配置调研项的必填项标识

- **THEN** 平台保存每项调研项在特定绑定关系下的必填/选填标识，并在生成清单时展示和校验该标识

- **WHEN** 割接-管理员在后台配置割接背景子表

- **THEN** 系统支持配置割接背景子表字段（是否解决网上问题/问题工单号/工单处理人/是否二次割接/首次割接保障人/割接背景表述）及条件显示逻辑

- **AND** "是否解决网上问题"选"是"时展示问题工单号/工单处理人，"是否二次割接"选"是"时展示首次割接保障人

- **WHEN** 相同调研项和有效期存在重复绑定、同优先级规则冲突或外部动态数据查询失败

- **THEN** 平台拒绝发布冲突矩阵；运行时同优先级规则冲突时列出冲突规则并由人工选择有效配置，外部动态数据查询失败时把清单标记为"生成失败/待处理"，不生成缺少必填项的正式割接清单

- **WHEN** 割接-管理员发布新矩阵版本而已有割接清单正在执行

- **THEN** 既有清单继续关联原配置快照；重新生成时平台展示新增、删除、必填变化差异并由有权人员确认

调研项ID、调研项名称（项命名-调研项）、调研含义（项含义）、界面格式（支持多种数据类型）、界面格式动态数据查询、反馈结果内容、绑定关系ID、割接类型（10类）、组网模式（5类）、设备类型（主字典，支持扩展）、割接等级（A/B/C/D级）、其他维度（可扩展）、是否必填、是否启用、割接背景子表（是否解决网上问题/问题工单号/工单处理人/是否二次割接/首次割接保障人/割接背景表述+条件显示规则）、维护人、维护时间

**权限与数据范围：**

**异常、降级及留痕要求：**

CUT-07主数据不可用、维度选项失效或矩阵冲突时禁止发布新版本，当前已发布版本继续有效；CUT-03生成失败时保留输入组合和命中轨迹，修正规则后可按原输入重试。外部数据源超时允许授权工程师人工填写但不得跳过必填校验。平台记录矩阵版本、调研项及维度前后值、发布人时间、命中规则、清单快照、冲突详情、人工来源和重试结果。
