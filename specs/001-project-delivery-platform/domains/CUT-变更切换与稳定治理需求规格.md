## CUT-01 割接任务管理

| 属性 | 内容 |
| ---- | ---- |
| 需求编号 | CUT-01 |
| 所属阶段 | 割接专项 |
| 用户角色 | 一线工程师、服务经理 |
| 优先级 | P0 |
| 目标版本 | V1任务闭环；V2首页KPI |
| 复杂度 | 中 |
| 依赖条件 | INT-12设备连接与采集平台集成、ITR接口 |

**业务场景与需求描述：**

提供割接任务的统一入口与全生命周期管理能力，作为割接流程主线的起点（P1首页任务接入）。首页包含两个模块：

1. **割接任务待办模块**：展示由ITR接口或平台项目模块内部触发的待办割接任务列表，列表字段含项目名称、负责人、割接来源（ITR/项目模块）、办事处、任务生成时间等，每条任务提供“办理”按钮入口。
2. **自建割接任务模块**：提供"新增"按钮入口，供一线工程师或服务经理根据现场实际情况手动创建割接任务。

**办理/新增按钮跳转逻辑：**

- **办理按钮**：ITR来源任务通过接口带入故障/变更背景，项目模块内部补充客户、项目和设备上下文；项目模块来源任务直接引用平台核心项目数据，跳转至P2割接等级确认环节。
- **新增按钮**：一线工程师人工输入设备序列号，平台项目服务查询并代填客户、项目和设备清单等内部数据，跳转至P2割接等级确认环节。

**任务来源三类：**

1. **ITR自动同步**：当ITR系统中产生与割接相关的故障/变更工单且满足割接触发条件时，通过ITR接口自动同步生成割接任务，预填客户信息、设备序列号、故障/变更背景等字段。
2. **项目模块内部触发**：项目交付达到割接节点（如实施阶段设备入网、版本升级等）时，项目模块发布内部业务事件生成割接任务并关联项目编码、合同号和设备清单。
3. **自建**：一线工程师或服务经理通过“新增”按钮手动创建割接任务，录入序列号后由平台项目服务代填其他字段。

**各阶段数据统计KPI（V2子功能）：**

首页顶部展示各阶段数据统计KPI看板：待办割接任务数、已完成割接任务数、审批中任务数、驳回待修改任务数，支撑一线工程师与管理员快速掌握任务分布。**本子功能为V2规划能力（来源R054，P1），V1首页仅展示待办任务列表与自建入口，不包含KPI统计看板。**

**流程状态导航可视化：**

全流程页面顶部展示流程状态导航条，以颜色标记各阶段状态：绿色表示已完成、红色表示未完成、当前阶段以强调样式区分展示，便于一线工程师直观掌握进度。

割接任务创建后进入“待评估”状态，流转至CUT-02分级评估环节。任务支持查看任务详情、关联设备清单、关联项目档案、ITR来源工单或内部来源业务事件、状态流转历史等。任务状态包含待评估、评估中、待方案、待审批、待执行、执行中、待闭环、已闭环、已归档、已取消等。

**核心业务规则：**

1. 每个割接任务在平台内使用唯一任务编号。ITR来源按“来源系统+来源业务单号”幂等，项目内部触发按“业务事件ID”幂等；重复推送或重试只能更新同一任务的来源同步信息，不得生成重复割接任务。
2. 平台割接任务是割接流程状态、评估、方案、审批和执行结果的Owner；客户、项目、合同和设备信息引用平台核心数据并在任务创建时保存必要快照，不复制形成另一套项目或设备主数据。来源系统只拥有来源工单及背景字段。
3. 新建任务必须关联唯一客户、一个具体项目节点和至少一台授权设备。自建任务以设备序列号反查当前直接归属项目；存在多个有效业务关联时由创建人在本人授权范围内选择，但不得把设备归入无有效归属或关联的项目。
4. 任务创建成功后进入“待评估”，后续状态只能按CUT-02～06的业务结果推进。进入审批后不得直接修改已提交方案；执行中不得取消，须按CUT-06停止或回退；已闭环任务满足归档条件后才可归档，任何角色不得手工跳过中间状态。
5. 取消仅适用于尚未执行的任务，必须填写原因并保留已形成的评估、方案和审批记录；来源任务取消不反向删除ITR工单或项目业务事件。
6. V1提供待办列表、自建入口、来源关联和完整状态导航；V2增加首页KPI，KPI按当前用户数据范围和任务当前状态实时统计。平台不在CUT-01设置通用割接时效门禁。
7. 任务来源、状态、割接类型、组网模式和取消原因等可变化字段使用基础平台可配置字典，停用值仅影响新任务，历史任务按创建时值解释。

**用户故事：**

作为一线工程师，我希望在首页查看由ITR接口、平台项目模块内部触发或人工创建的割接任务，办理时自动引用平台核心项目、客户和设备数据，并能查看流程状态导航颜色标记（V2补充各阶段KPI看板），以便统一割接任务入口、避免重复录入并保证ITR来源任务与平台项目数据可追溯关联。

**验收标准：**

- **WHEN** 一线工程师进入首页
- **THEN** 页面展示"割接任务待办"模块（列表含项目名称、负责人、割接来源、办事处、任务生成时间）与"自建割接任务"模块（新增按钮）
- **AND** V1首页不展示KPI统计看板（KPI看板为V2子功能），V2版本在首页顶部展示各阶段数据统计KPI看板（待办割接任务数/已完成割接任务数/审批中任务数/驳回待修改任务数）
- **WHEN** 一线工程师点击待办列表中的"办理"按钮
- **THEN** ITR接口提供来源业务信息，平台项目服务提供项目、客户和设备上下文，跳转至P2割接等级确认环节
- **AND** 任务详情中预填客户信息、设备序列号、故障/变更背景等字段；ITR来源任务建立ITR工单关联，项目模块来源任务保存内部来源业务标识
- **WHEN** 一线工程师点击"新增"按钮创建割接任务
- **THEN** 平台项目服务按输入的设备序列号查询并展示唯一匹配的项目、客户和设备信息，将确认结果保存至任务上下文
- **AND** 跳转至P2割接等级确认环节，任务自动关联项目档案，状态流转历史完整记录（含创建人、创建时间、来源类型）
- **WHEN** 割接任务来源为项目模块内部业务事件
- **THEN** 任务直接关联平台项目编码、合同号和设备清单
- **AND** 项目详情可查看关联割接任务，割接状态通过内部事件更新项目进度且不得形成项目数据副本
- **WHEN** 一线工程师在流程任一阶段查看页面
- **THEN** 页面顶部展示流程状态导航条，以颜色标记各阶段状态（绿色已完成、红色未完成、当前阶段强调展示）
- **WHEN** 同一ITR来源业务单号或同一项目业务事件被重复推送，或设备序列号无法匹配唯一授权项目
- **THEN** 平台对重复来源返回原割接任务编号且不创建新任务；对无法匹配项目的自建请求阻止提交并展示待核对的设备归属信息

**涉及数据字段：**

割接任务编号、任务来源（ITR接口/项目模块内部触发/自建）、来源系统、来源业务单号、来源业务事件ID、来源同步状态、客户ID/编码/名称快照、项目ID/编码、合同号快照、设备ID及序列号清单、设备归属核对状态、割接背景描述、割接类型（关联CUT-07）、组网模式（关联CUT-07）、割接计划时间、发起申请时间、任务生成时间、任务状态、状态版本号、创建人、创建时间、当前责任人、取消原因、状态流转历史、关联项目档案标识、流程状态导航颜色标记（绿色已完成/红色未完成/当前强调）、各阶段数据统计KPI（V2子功能：待办割接任务数/已完成割接任务数/审批中任务数/驳回待修改任务数）

**权限与数据范围：**

一线工程师可查看本人参与或被指派项目的割接任务、办理待办及创建自建任务，只能选择其有权访问的项目和设备；服务经理可在所属组织或明确授权项目范围内创建、指派、取消未执行任务并查看全流程。集成服务账号只能按接口契约创建或更新来源字段，无权执行评估、审批、割接或取消。上级项目角色仅查看获授权后代项目的任务与去重KPI，平级项目和跨租户任务不可见；任务创建权限不授予设备凭证明文或采集结果下载权限。

**异常、降级及留痕要求：**

ITR接口不可用时不影响项目内部触发和自建任务，失败批次保留来源请求、错误原因并按幂等键重试；不得以自建方式重复录入已有ITR任务。项目、客户或设备查询失败时任务保持未创建或“来源待核对”，不使用空值进入评估。重复来源返回既有任务；来源键冲突、设备归属冲突或并发状态修改时拒绝覆盖并提示人工核对。平台记录来源报文摘要、幂等结果、上下文快照、创建/指派/取消、状态前后值、操作者和时间。

**依赖关系：**

- 前置依赖：ITR接口（INT-02）、平台项目服务（项目档案与设备清单）、客户档案（CUS-03）
- 后续依赖：CUT-02割接分级评估（任务创建后流转评估）、WO-06割接保障工单（割接任务关联割接保障工单）
- 关联依赖：CUT-07割接后台配置（割接类型、组网模式字段来源）、权限体系（一线工程师创建权限、服务经理管理权限）

## CUT-02 割接分级评估

| 属性 | 内容 |
| ---- | ---- |
| 需求编号 | CUT-02 |
| 所属阶段 | 割接专项 |
| 用户角色 | 一线工程师、服务经理 |
| 优先级 | P0 |
| 目标版本 | V1 |
| 复杂度 | 中 |
| 依赖条件 | 问卷配置 |

**业务场景与需求描述：**

作为割接分级风控的核心环节，对割接任务进行等级评估，输出A/B/C/D四级评估结果，驱动后续差异化的采集清单、方案要求与审批层级。评估采用"问卷评估+人工确认"双机制，确保评估结果兼顾客观规则与人工经验。本页面项目信息表和割接等级表在当前页面固定展示，割接信息采集表仅在A/B/C级展示、D级不展示。

**评估维度（5个）：**

1. **业务重要等级**：评估割接涉及业务的关键程度，取值低/中/高。高对应核心业务系统、影响客户主流程；中对应重要业务系统、影响部分业务功能；低对应辅助业务系统、影响范围有限。
2. **操作复杂度等级**：评估割接操作的复杂程度，取值低/中/高。高对应多设备协同、跨系统联动、步骤繁多；中对应中等复杂度、单设备多步骤；低对应简单操作、单设备少步骤。
3. **隐患风险等级**：评估割接可能带来的风险程度，取值低/中/高。高对应高风险（如核心设备替换、网络结构调整等可能引发业务中断）；中对应中等风险；低对应低风险（如版本补丁、特征库升级等）。
4. **备件是否申请**：评估割接是否需要申请备件，取值是/否/不涉及。是对应需要申请备件保障，V1支持手动记录备件信息，V2实现备件系统跳转集成（接口预留，关联CUT-08备件集成）；否对应不需要申请备件；不涉及对应无备件概念（如配置变更、网络结构调整等）。
5. **客户服务等级**：评估客户服务关系与潜在隐患程度，取值低/中/高。高对应战略客户、有重大隐患或历史投诉；中对应一般客户、有潜在隐患；低对应普通客户、无明显隐患。

**评估流程：**

1. **问卷评估**：一线工程师在割接任务详情中发起评估，按5个维度逐项选择问卷选项，系统根据预设评分规则自动计算初步等级（A/B/C/D）。
2. **人工确认**：服务经理对问卷评估结果进行人工确认，可调整维度选项（需填写调整原因），系统重新计算等级；服务经理确认后等级锁定。
3. **等级判定规则**：基于5维度综合判定，A对应最高风险（多个维度为高），B对应较高风险，C对应中等风险，D对应最低风险（多个维度为低且备件不涉及或否）。具体评分规则由管理员后台配置。
4. **割接信息采集表展示规则**：项目信息表和割接等级表在当前页面固定展示；割接信息采集表仅在A/B/C级（非简易流程）时展示，D级不展示。
5. **D级简易流程**：D级确认后跳过P3调研及风险考察，直接跳转至P4割接方案环节，后续CUT-04方案编审使用方案编辑模块输出操作清单，仅填操作步骤+回退步骤，CUT-05审批按D级简易审批层级（发起人→用服经理）执行。
6. **割接评定算法（V2/V3能力）**：后续支持定义割接评定算法，问卷完成后系统自动推送建议等级，降低人工判断负担。

**核心业务规则：**

1. 评估只能针对“待评估/评估中”的CUT-01任务发起，必须完整回答业务重要等级、操作复杂度、隐患风险、备件是否申请和客户服务等级5个维度；缺少任一维度或没有适用的已发布评分规则版本时不得提交。
2. 初步等级由CUT-07当前适用的已发布评分规则计算，并保存问卷答案、规则版本、计算分值和A/B/C/D结果快照。规则后续变更不重算已确认评估，也不得覆盖历史解释。
3. 一线工程师负责填写和提交问卷；服务经理负责最终确认，可调整维度答案，但必须填写调整原因，平台按原规则版本重新计算并同时保存系统建议等级与最终等级。服务经理不得直接输入一个与维度答案不一致的等级。
4. 等级确认后评估版本锁定。割接类型、组网模式、设备范围、计划窗口或5个评估维度的来源事实发生实质变化时，原评估标记失效，任务退回“待评估”并创建新评估版本；历史版本只读保留。
5. A/B/C级确认后进入CUT-03并展示割接信息采集表；D级标记“简易流程”，跳过P3直接进入CUT-04，仅编写操作步骤和回退步骤，并按CUT-05的D级审批链执行。D级不得手工进入CUT-03形成另一条流程。
6. V1按已发布规则自动计算建议等级并由服务经理确认；后续智能算法只可作为建议来源，不改变人工确认责任和等级驱动规则。
7. 维度选项、等级和备件标记使用基础平台可配置字典；评分区间、等级边界和适用范围由CUT-07版本化配置，区间不得重叠或留空。

**用户故事：**

作为一线工程师，我希望通过问卷方式按5个评估维度（业务重要等级、操作复杂度等级、隐患风险等级、备件是否申请、客户服务等级）对割接任务进行评估，系统自动计算A/B/C/D等级，再由服务经理人工确认（可调整并填写原因），D级确认后直接跳转至P4割接方案环节（跳过P3），以便实现割接分级风控、避免完全依赖个人经验、确保高级别割接获得更严格的采集/方案/审批管控、并简化D级流程提升效率。

**验收标准：**

- **WHEN** 一线工程师在割接任务详情中发起评估并按5个维度逐项选择问卷选项
- **THEN** 系统根据预设评分规则自动计算初步等级（A/B/C/D），评估结果页面展示各维度选项与计算后的等级
- **AND** 评估结果进入"待确认"状态，等待服务经理人工确认
- **WHEN** 服务经理对问卷评估结果进行人工确认并提交（含或不含维度调整）
- **THEN** 系统记录最终等级、确认人、确认时间，若服务经理调整了维度选项则同步记录调整原因
- **AND** 等级锁定后任务按等级驱动后续采集深度、方案要求与审批层级
- **WHEN** 割接任务评估结果为A/B/C级（非简易流程）
- **THEN** 任务流转至CUT-03采集清单动态多维绑定生成环节，割接信息采集表正常展示
- **AND** 项目信息表和割接等级表在当前页面固定展示
- **WHEN** 割接任务评估结果为D级
- **THEN** 任务自动标记为"简易流程"，跳过P3调研及风险考察，直接跳转至P4割接方案环节
- **AND** 割接信息采集表不展示（项目信息表和割接等级表仍固定展示），后续CUT-04方案编审使用方案编辑模块输出操作清单，仅填操作步骤+回退步骤，CUT-05审批按D级简易审批层级（发起人→用服经理）执行
- **WHEN** 任一评估维度缺失、评分规则未发布或两名服务经理并发确认发生版本冲突
- **THEN** 平台阻止确认并保持任务原状态，展示缺失项、规则异常或版本冲突信息，不生成最终等级或后续流程实例

**涉及数据字段：**

割接任务编号、评估ID、评估版本、评估状态、评估维度1（业务重要等级：低/中/高）、评估维度2（操作复杂度等级：低/中/高）、评估维度3（隐患风险等级：低/中/高）、评估维度4（备件是否申请：是/否/不涉及）、评估维度5（客户服务等级：低/中/高）、问卷计算分值、问卷评估建议等级、人工确认最终等级（A/B/C/D）、是否简易流程（D级为是）、割接信息采集表展示标识（A/B/C级展示、D级不展示）、评估人、评估时间、确认人、确认时间、维度调整记录（维度名/原值/新值/调整原因）、评分规则配置ID及版本、失效原因、状态版本号

**权限与数据范围：**

一线工程师只能填写、保存和提交本人负责割接任务的评估问卷，提交后不能确认或改写评分结果；服务经理只能确认所属组织或明确授权项目的评估，可调整维度并填写原因，但无权修改评分规则。系统管理员可维护CUT-07规则，不参与具体任务确认。项目只读成员可查看已确认等级及非敏感依据；未授权项目、平级项目和跨租户的问卷答案、客户服务等级与调整原因不可见。

**异常、降级及留痕要求：**

评分规则缺失、未发布、适用范围冲突或区间不完整时，评估保持草稿并禁止确认，不允许人工绕过计算直接填写等级。问卷保存失败可基于同一评估ID重试，重复提交返回既有版本；并发确认时仅首个符合版本号的请求成功。确认后上游范围发生变化时自动失效而不删除历史，并通知责任人重新评估。平台记录每次答案、规则版本、计算结果、人工调整前后值及原因、确认/失效人和时间。

**依赖关系：**

- 前置依赖：CUT-01割接任务管理（评估对象为割接任务）、问卷配置（评分规则后台维护，关联CUT-07）
- 后续依赖：CUT-03割接采集清单动态多维绑定生成（按等级驱动采集深度，D级跳过本环节）、CUT-04割接方案编审（D级走简易方案，跳转至P4割接方案环节）、CUT-05割接分级审批（按等级驱动审批层级）、CUT-08割接备件集成（备件维度为"是"时标记为需要备件保障，V1支持手动记录备件信息，V2实现备件系统跳转集成（接口预留））
- 关联依赖：CUT-07割接后台配置（评分规则、维度选项配置）、权限体系（一线工程师评估权限、服务经理确认权限）

## CUT-03 割接采集清单动态多维绑定生成

| 属性 | 内容 |
| ---- | ---- |
| 需求编号 | CUT-03 |
| 所属阶段 | 割接专项 |
| 用户角色 | 一线工程师、管理员 |
| 优先级 | P0 |
| 目标版本 | V1清单管理；V2导出与流程跳转 |
| 复杂度 | 非常高 |
| 依赖条件 | 割接类型库、组网模式库、设备类型库、后台配置、外部数据源接口 |

**业务场景与需求描述：**

作为割接核心能力（P3调研及风险考察阶段），通过动态多维绑定机制动态生成割接采集清单，包含风险考察项（25+项，关联CUT-09）和业务调研项（扩展，关联CUT-10）两大类，标准化割接采集内容、降低个人经验依赖。是本模块的重点细化需求。**割接信息采集表仅在A/B/C级展示，D级不展示**（D级走简易流程，跳过P3直接跳转至P4割接方案环节）。

**动态多维绑定机制（替代原三维联动）：**

采集清单生成采用动态多维绑定（已知4维：割接类型×组网模式×设备类型×割接等级，管理员可扩展新增维度），替代原"割接类型×组网模式×产品类型"三维联动机制：

1. **多维规则匹配**：系统根据"割接类型∩组网模式∩设备类型∩割接等级"（已知4维，可扩展）的多维规则组合，从统一采集项主数据（按采集项类型区分）中匹配并动态渲染对应的采集清单，界面按采集项类型分块显示（业务调研项区块/风险考察项区块/双机部署检查项区块）。
2. **维度扩展能力**：管理员可在后台新增/编辑/删除关联维度，规则引擎支持动态多维组合匹配，避免硬编码，优先支撑已知4维组合匹配。
3. **设备类型主字典**：设备类型为主字典数据，由系统管理员维护，支持扩展新增（已知示例FW/SW/ADX，非穷举）。
4. **高可靠性组网模式特殊处理**：当组网模式为5类高可靠性组网模式（VSM双机/静默双机/DRP双机/普通双机/集群）之一时，触发双机部署规范性检查表展示。

**割接信息采集表字段：**

割接信息采集表包含割接类型、组网模式、设备类型、当前版本、升级后版本（仅"版本升级"割接类型时显示）等字段，仅在A/B/C级展示。

**割接背景数据模块（新增）：**

新增割接背景子表，含字段：是否解决网上问题、问题工单号、工单处理人、是否二次割接、首次割接保障人、割接背景表述等，支持条件显示（如"是否解决网上问题"选"是"时展示问题工单号/工单处理人，"是否二次割接"选"是"时展示首次割接保障人）。

**双机部署检查项区块（采集项类型=双机部署检查项，5类组网模式124行）：**

作为统一采集项主数据中采集项类型=双机部署检查项的区块，仅当组网模式为5类高可靠性组网模式（VSM双机/静默双机/DRP双机/普通双机/集群）之一时才显示对应的双机部署检查表，按所选组网模式动态展示对应1类检查表（否则不显示）：

- VSM双机部署规范性检查表（17项）
- 静默双机部署规范性检查表（25项）
- DRP双机部署规范性检查表（23项）
- 普通双机部署规范性检查表（24项）
- 集群部署规范性检查表（8项）

每项检查结果反馈：是否已执行（下拉）+特殊情况备注。

**外部数据源接入能力（新增）：**

风险考察项支持从配置的外部数据源加载已知情况数据。外部数据源加载展示条件——以技术公告检查项为例：

- **所有情况必选加载当前版本外部数据**：加载当前版本对应的技术公告列表，每条数据项显示编号/主题/描述/解决方案，补充本次是否涉及+采取措施。
- **版本升级时同时加载当前版本和升级后版本外部数据**：当割接类型为"版本升级"时，同时加载当前版本和升级后版本的技术公告外部数据。

外部数据源接口为统一采集项的配置属性之一（所有采集项类型均可配置，实际应用中风险考察项使用较多），可配置数据来源接口（传入上下文信息调接口获取数据），支持动态数据查询。**接口预留，V1实现优先级最低，不可用时通过手动查询外部数据源+手动录入采集项结果替代。**

**采集清单内容（统一采集项主数据按采集项类型分块显示）：**

采集清单来源于统一采集项主数据，界面按采集项类型分块显示为三大区块：业务调研项区块、风险考察项区块、双机部署检查项区块（双机部署检查项区块仅当组网模式为5类之一时显示对应检查表）。

- **风险考察项区块（采集项类型=风险考察项，25+项，详见CUT-09关联矩阵）**：覆盖割接前、割接中、割接后各阶段的风险点，含双机部署规范性检查（5类124行）、技术公告检查项（当前版本/升级后版本）、备份检查（版本备份/热补丁备份/license备份/配置备份）、系统日志/诊断日志告警检查、双机必要配置一致、包过滤NATQOS编译数、会话同步、框式双主控版本、MD5、重大备件、动态表项采集、MTU&超大帧、百G口FEC、长连接、二次过设备、STP、F5/adware、机房操作承诺书等，每项包含采集项ID、项命名、项含义、界面格式、反馈结果内容、动态多维关联关系等字段。
- **业务调研项区块（采集项类型=业务调研项，扩展，详见CUT-10关联矩阵）**：覆盖业务现状、业务影响、业务约束等维度，含割接背景、涉及业务、影响范围、业务连续性要求、中断次数、拓扑图、设备部署位置规划、接口互联、IP&VLAN、并发连接、新建连接、CPU、内存、连通性测试、友商配置翻译等，每项包含采集项ID、项命名、项含义、界面格式、反馈结果内容、动态多维关联关系等字段。
- **双机部署检查项区块（采集项类型=双机部署检查项，5类组网模式124行）**：详见上文"双机部署检查项区块"说明，按所选组网模式动态展示对应1类检查表（VSM双机17项/静默双机25项/DRP双机23项/普通双机24项/集群8项）。

**一线工程师扩展能力：**

支持一线工程师在已生成清单基础上自定义新增/删除调研项和风险项（自定义仅允许"新增"，禁止删除系统预置必选项，自定义项标记来源）。

**清单操作能力：**

- 暂存（V1）：保存按钮临时保存当前进度（来源R014，P0）。
- 导出（V2子功能）：下载按钮导出清单（风险考察项+业务调研项）。**本子功能为V2规划能力（来源R013，P1），V1不支持清单导出，V2实现下载按钮导出。**
- 流程跳转（V2子功能，基础跳转V1内置）：下一步跳转至P4割接方案环节。**V1内置基础跳转能力（采集清单保存后通过任务状态流转自动进入P4），独立流程跳转优化需求（来源R015，P1）为V2规划能力，V2支持更灵活的流程跳转配置。**

**管理员后台维护（动态多维配置）：**

管理员在后台维护统一采集项（按采集项类型区分业务调研项/风险考察项/双机部署检查项）的内容定义及动态多维绑定关系（已知4维：割接类型×组网模式×设备类型×割接等级，可扩展新增维度，详见CUT-07、CUT-09、CUT-10）。统一采集项表格支持后台维护编辑（增、删、改、查及添加动态多维关联关系），各字段的界面格式与内容用于采集信息分析与结果页面的填写说明。一线工程师仅在前端按动态多维绑定结果填写，不可修改绑定关系。

**核心业务规则：**

1. 只有CUT-02最终等级为A/B/C且评估版本有效的任务可生成采集清单；D级任务必须跳过P3，平台不得为其生成或提交采集清单实例。
2. 清单生成以任务的割接类型、组网模式、设备类型、最终等级及已启用扩展维度值为输入，匹配CUT-07/CUT-09/CUT-10当前适用的已发布配置。生成时保存输入快照、采集项版本和绑定规则版本，后台配置后续变更不增删已生成清单内容。
3. 同一采集项命中多条有效绑定时按采集项ID去重，“必填”优先于“选填”；若命中定义的界面格式、数据来源或所属区块互相冲突，平台阻止生成并列出冲突规则，不得随机选择。没有任何适用项时同样禁止进入CUT-04，须由管理员补充并发布配置。
4. 高可靠组网只展示与当前组网模式对应的一类双机部署检查表。版本升级任务同时带入当前版本和升级后版本；非版本升级任务不得要求填写升级后版本，也不得加载升级后版本公告。
5. 系统预置必填项不可删除、改名或改为选填；一线工程师可新增任务级自定义项，并可在提交前删除本人新增且未被引用的自定义项。提交后清单内容和答案锁定，修改必须生成新清单版本并使下游未审批方案失效。
6. 外部数据加载结果必须记录来源、查询条件、查询时间和成功状态。接口不可用时允许工程师附上人工查询证据并手工录入，记录来源为“人工”，不得把加载失败标记为“无风险”。
7. 所有必填项完成后方可提交；风险考察结果为“否/未通过”时必须填写事实说明，并作为CUT-04预估风险及应对措施的输入。暂存不触发流程推进。
8. V1支持生成、填写、暂存、提交和提交后进入P4；V2增加导出与流程跳转配置，不改变清单版本、必填校验和D级跳过规则。

**用户故事：**

作为一线工程师，我希望在割接任务（A/B/C级）中根据割接类型、组网模式、设备类型、割接等级动态多维绑定生成对应的风险考察项和业务调研项清单，当组网模式为5类高可靠性组网模式时自动展示对应的双机部署规范性检查表（124行），风险考察项支持从配置的外部数据源（如技术公告系统）加载已知情况数据，同时支持我自定义新增/删除调研项和风险项、暂存清单（V2后续补充导出清单与流程跳转优化），以便我无需依赖个人经验判断需要采集哪些项、确保采集内容标准化与全面性、避免遗漏关键风险点或业务调研点、并实时获取外部已知风险数据。

**验收标准：**

- **WHEN** 割接任务等级为A/B/C级（非简易流程），一线工程师进入P3调研及风险考察页面
- **THEN** 页面展示割接信息采集表（含割接类型、组网模式、设备类型、当前版本、升级后版本字段），项目信息表和割接等级表在当前页面固定展示
- **AND** 升级后版本字段仅当割接类型为"版本升级"时显示
- **WHEN** 一线工程师在割接信息采集表中选择割接类型、组网模式、设备类型
- **THEN** 系统根据动态多维绑定（割接类型×组网模式×设备类型×割接等级，可扩展）从统一采集项主数据（按采集项类型区分）中匹配并动态渲染对应的采集清单，界面按采集项类型分块显示（业务调研项区块/风险考察项区块/双机部署检查项区块）
- **AND** 清单中每项展示采集项名称、描述、检查结果/反馈结果、是否必填等字段，必填项以标识区分
- **WHEN** 一线工程师选择组网模式为5类高可靠性组网模式之一（如VSM双机/静默双机/DRP双机/普通双机/集群）
- **THEN** 系统按所选组网模式动态展示对应的双机部署规范性检查表（VSM双机17项/静默双机25项/DRP双机23项/普通双机24项/集群8项）
- **AND** 每项检查结果反馈"是否已执行"（下拉）+特殊情况备注
- **WHEN** 统一采集项中风险考察项配置了外部数据源接口（如技术公告检查项）
- **THEN** 所有情况必选加载当前版本外部数据（如技术公告列表，每条数据项显示编号/主题/描述/解决方案，补充本次是否涉及+采取措施）
- **AND** 若割接类型为版本升级，同时加载当前版本和升级后版本外部数据
- **WHEN** 一线工程师在已生成清单基础上自定义新增或删除调研项和风险项
- **THEN** 系统允许新增自定义项（标记来源），禁止删除系统预置必选项
- **WHEN** 一线工程师点击保存按钮
- **THEN** 系统保存清单草稿、当前已填内容和填写进度，清单保持未提交状态（V1能力）
- **AND** V1不支持导出清单（导出为V2子功能，来源R013），V2实现下载按钮导出清单（风险考察项+业务调研项）
- **AND** V1内置基础跳转能力（采集清单保存后通过任务状态流转自动进入P4），独立流程跳转优化为V2子功能（来源R015）
- **WHEN** 任务为D级、没有命中已发布绑定规则、命中规则发生定义冲突或必填采集项缺失
- **THEN** 平台阻止生成或提交清单并保持任务原状态，展示跳过原因、未命中维度或冲突/缺失项；D级任务直接按CUT-02进入P4
- **WHEN** 外部数据源加载失败或超时
- **THEN** 平台标记对应采集项“外部数据加载失败”，保存失败记录，并允许工程师上传人工查询证据后以“人工”来源填写结果

**涉及数据字段：**

割接任务编号、采集清单ID、清单版本、清单状态、割接评估ID及版本、割接等级（A/B/C/D，D级不生成采集表）、割接类型（关联CUT-07）、组网模式（关联CUT-07）、设备类型（主字典，支持扩展）、扩展维度及取值快照、当前版本、升级后版本（仅版本升级显示）、割接背景子表（是否解决网上问题/问题工单号/工单处理人/是否二次割接/首次割接保障人/割接背景表述）、动态多维绑定生成的统一采集项列表（采集项ID/版本/类型/项命名/项含义/界面格式/反馈结果内容/是否必填/匹配规则ID/外部数据源加载结果）、双机部署检查表类型及项目、自定义新增项列表（含创建人和来源标记）、采集项填写内容、未通过事实说明、外部数据来源/查询条件/查询时间/失败原因、人工查询证据、填写人、填写时间、提交人、提交时间、绑定配置ID及版本、输入快照、失效原因

**权限与数据范围：**

**异常、降级及留痕要求：**

配置未发布、无规则命中、规则冲突或任务维度缺失时不得生成空清单；管理员修正并发布后按同一任务重新生成。外部接口失败时保留请求摘要和失败状态，允许人工证据降级但不伪造自动加载结果。暂存失败可按清单ID和版本重试；并发编辑发生版本冲突时拒绝后提交者覆盖。清单提交后若评估、设备范围或配置输入发生受控变更，原清单标记失效并阻止旧版本进入方案。平台记录生成依据、配置版本、项目级增删项、答案前后值、外部加载/人工降级、提交和失效过程。

## CUT-04 割接方案编审

| 属性 | 内容 |
| ---- | ---- |
| 需求编号 | CUT-04 |
| 所属阶段 | 割接专项 |
| 用户角色 | 一线工程师、服务经理 |
| 优先级 | P0 |
| 目标版本 | V1 |
| 复杂度 | 中 |
| 依赖条件 | 模板管理 |

**业务场景与需求描述：**

提供割接方案的模板化编审能力，支撑标准流程与简易流程两条线，确保方案标准化。方案编审以CUT-03采集清单为输入，输出可执行的割接方案。业务调研录入结果+风险考察录入结果+割接项目+用户资产库等信息字段可被割接方案环节引用和带入。

**方案来源分支（是否已有割接方案）：**

1. **选"是"→直接导入上传完整方案**：一线工程师已有完整割接方案时，直接上传完整方案文件，跳过模板填写环节。
2. **选"否"→展示方案模板填写**：一线工程师无现成方案时，基于方案模板在线填写各章节内容。

**风险考察结果展示：**

风险考察结果从上一步P3调研及风险考察流程带入展示，作为方案编审的输入依据。

**方案章节细化：**

方案分为两大章节：

1. **割接概述**：含项目割接描述（从割接任务带入）、计划表、割接前拓扑上传、割接后拓扑上传、设备清单（带入）、组网配置上传、割接保障人员安排表等子章节。
2. **执行操作**：含预估风险及应对措施、割接前操作清单、执行操作清单、收尾收集清单、后业务测试表、回退方案说明、回退步骤、割接后保障等子章节。

**割接保障人员安排表（新增）：**

角色预置为四类：客户、迪普一线工程师、迪普二线工程师、迪普研发，每类角色含字段：姓名、任务描述、联系电话、到位时间。

**预估风险及应对措施（新增）：**

风险项来源于割接信息采集表（CUT-03）中所有选"否"的选项（即未通过规范性检查的风险项），一线工程师针对每个风险项填写应对措施。

**操作按钮：**

- 保存：临时保存方案。
- 下载割接初稿：下载当前编写的方案初稿。
- 上传完整方案：上传完整方案文件（对应"是否已有割接方案"选"是"分支）。
- 返回：返回上一步。
- 下一步：提交方案流转至CUT-05分级审批环节。

**标准流程与简易流程差异：**

- **标准流程（A/B/C级）**：方案需完整填写所有章节（割接概述+执行操作），包含详细割接步骤、操作清单、回退方案、保障人员安排、预估风险及应对措施等。
- **简易流程（D级）**：仅弹出割接各阶段操作步骤填写窗口，填写每割接阶段操作步骤+回退步骤，简化编审流程，提升效率。

**方案编审流程：**

一线工程师提交方案后，流转至CUT-05分级审批环节。服务经理/二线/研发按级别审批方案，审批通过后方案锁定，作为CUT-06执行闭环的执行依据。审批驳回则退回一线工程师修改。

**核心业务规则：**

1. A/B/C级任务必须引用一份有效且已提交的CUT-03清单后才能创建方案；D级任务引用已确认的CUT-02评估并创建简易方案，不得要求补建CUT-03清单。
2. 每次创建方案均绑定任务、评估版本、采集清单版本和方案模板版本，并保存引用数据快照。项目、设备、用户资产或风险清单后续变化不静默改写已提交方案；影响执行范围的变化使方案失效并要求创建新版本。
3. “上传完整方案”和“模板填写”是两种编辑方式，但验收门槛一致：A/B/C级必须具备割接范围、设备清单、操作步骤、验证步骤、风险与应对措施、回退条件和回退步骤；D级至少具备逐阶段操作步骤、验证结果判定和回退步骤。上传文件不能因存在附件而跳过完整性校验。
4. CUT-03中所有“否/未通过”风险项必须逐项关联一条应对措施，未处置风险不得提交。保障人员安排至少明确现场负责人、客户联系人和回退决策人；人员角色可配置，历史方案保存当时人员快照。
5. 草稿可反复保存和下载初稿；提交时形成不可修改的方案版本并进入CUT-05。审批驳回后原版本状态保持“已驳回”，工程师基于该版本创建新版本修改，不得覆盖审批所见内容。
6. CUT-05全部审批通过后方案状态为“已锁定”，只有该锁定版本可作为CUT-06执行依据。已锁定方案不得直接编辑、替换附件或切换编辑方式；确需变更时重新发起方案版本并重新审批。
7. 方案编辑方式、章节类型、人员角色、方案状态和风险处置状态等可变化字段使用基础平台可配置字典；模板停用不影响历史方案解释。

**用户故事：**

作为一线工程师，我希望在割接方案编审环节选择"是否已有割接方案"（选是→直接上传完整方案，选否→展示方案模板填写），风险考察结果从上一步流程带入展示，业务调研录入结果+风险考察录入结果+割接项目+用户资产库等信息字段可被方案环节引用和带入，方案分为割接概述（含项目割接描述带入+计划表+割接前/后拓扑上传+设备清单带入+组网配置上传+保障人员安排表）和执行操作（含预估风险及应对措施/割接前操作清单/执行操作清单/收尾收集清单/后业务测试表/回退方案说明/回退步骤/割接后保障）两大章节，保障人员安排表角色预置为客户/迪普一线工程师/迪普二线工程师/迪普研发，预估风险项来源于割接信息采集表中所有选"否"的选项，支持下载割接初稿和上传完整方案按钮，D级简易流程仅弹出割接各阶段操作步骤填写窗口填写每割接阶段操作步骤+回退步骤，以便标准化方案编审、减少重复录入、提升D级割接的编审效率。

**验收标准：**

- **WHEN** 一线工程师在割接任务中发起方案编审
- **THEN** 页面展示"是否已有割接方案"选项，风险考察结果从上一步P3流程带入展示，业务调研录入结果+风险考察录入结果+割接项目+用户资产库等信息字段可被引用和带入
- **WHEN** 一线工程师选择"是否已有割接方案"为"是"
- **THEN** 系统提供"上传完整方案"按钮，一线工程师直接上传完整方案文件，跳过模板填写环节
- **AND** 上传文件通过完整性校验并提交后，方案形成版本并流转至CUT-05分级审批环节
- **WHEN** 一线工程师选择"是否已有割接方案"为"否"
- **THEN** 系统展示方案模板，方案分为割接概述和执行操作两大章节
- **AND** 割接概述含项目割接描述（带入）、计划表、割接前拓扑上传、割接后拓扑上传、设备清单（带入）、组网配置上传、割接保障人员安排表等子章节
- **AND** 执行操作含预估风险及应对措施、割接前操作清单、执行操作清单、收尾收集清单、后业务测试表、回退方案说明、回退步骤、割接后保障等子章节
- **WHEN** 一线工程师填写割接保障人员安排表
- **THEN** 系统展示客户/迪普一线工程师/迪普二线工程师/迪普研发四类角色，并保存每类角色的姓名、任务描述、联系电话和到位时间
- **WHEN** 一线工程师填写预估风险及应对措施
- **THEN** 系统加载CUT-03中所有结果为“否”的风险项，保存每个风险项与应对措施的一一关联及未填写状态
- **WHEN** 一线工程师点击"下载割接初稿"按钮
- **THEN** 系统生成并返回当前方案版本的初稿文件，记录下载人、下载时间和方案版本
- **WHEN** 割接任务等级为D级（简易流程）
- **THEN** 系统仅展示割接各阶段操作步骤与回退步骤填写窗口，不加载A/B/C级完整方案章节
- **AND** 一线工程师填写完毕提交后，方案按D级简易审批层级（发起人→用服经理）流转至CUT-05分级审批
- **WHEN** 一线工程师填写完毕点击"下一步"
- **THEN** 系统将方案状态更新为“待审批”，保存提交版本并创建CUT-05分级审批实例
- **WHEN** A/B/C级方案缺少必需章节、存在未填写应对措施的风险项、上传文件校验失败或引用的采集清单版本已失效
- **THEN** 平台阻止提交并保持方案草稿状态，展示缺失章节、未处置风险、文件错误或失效来源，不创建CUT-05审批实例

**涉及数据字段：**

割接任务编号、方案ID、方案版本、来源方案版本、是否已有割接方案（是/否）、方案编辑方式（上传完整方案/模板填写）、割接等级（A/B/C/D）、是否简易流程、方案模板ID及版本、评估ID及版本、采集清单ID及版本、引用数据快照、风险考察结果、风险项与应对措施映射、业务调研录入结果、割接项目信息、用户资产信息、方案章节-割接概述（项目割接描述/计划表/割接前拓扑/割接后拓扑/设备清单/组网配置/割接保障人员安排表）、割接保障人员安排表（角色/姓名/任务描述/联系电话/到位时间/是否回退决策人）、方案章节-执行操作（预估风险及应对措施/割接前操作清单/执行操作清单/验证步骤/收尾收集清单/后业务测试表/回退触发条件/回退方案说明/回退步骤/割接后保障）、上传文件ID/文件哈希/校验结果、原方案编号、编写人、编写时间、提交人、提交时间、方案状态（草稿/待审批/已驳回/已锁定/已失效）、驳回来源、失效原因、状态版本号、操作记录

**权限与数据范围：**

一线工程师只能创建、编辑和提交本人负责割接任务的方案草稿，可读取该任务已授权的项目、设备、清单和用户资产信息；提交后无权修改该版本。服务经理可查看所属组织或授权项目方案、退回草稿或参与CUT-05审批，但不能在审批中代替工程师改写方案。项目只读成员仅查看已锁定方案的非敏感章节；联系方式、配置附件和拓扑按字段与文件权限控制，平级项目和跨租户不可见。下载初稿和完整方案均需重新鉴权并记录下载人。

**异常、降级及留痕要求：**

模板加载失败时可暂存已输入内容但不得提交空白模板；上传失败、文件损坏或安全校验不通过时保留草稿并允许替换文件。引用的评估/清单/设备范围失效时方案标记“来源已失效”，未创建审批则阻止提交，已在审批中则暂停CUT-05并通知责任人。重复提交按方案版本幂等，不重复创建审批；并发编辑发生版本冲突时拒绝覆盖。平台记录模板与来源版本、文件哈希、字段前后值、风险处置、提交、驳回派生、锁定、失效和下载行为。

**依赖关系：**

**业务场景与需求描述：**

**审批动作流转：**

- 审批节点按级别自动生成，每个节点支持通过/驳回操作。
- **驳回→跳转至P4割接方案修改**：方案退回一线工程师修改，方案状态变更为"已驳回"，修改后重新提交从首节点开始审批。
- **通过→跳转至P6割接跟踪与闭环**：全部节点通过后方案锁定，流转至CUT-06执行闭环。
- **反馈意见必填**：驳回或通过均需填写反馈意见（来源R039）。
- **待办任务推送通知**：待办任务发送推送通知至下一审批人（来源R037，支持站内+邮件+IM多通道）。**接口预留（INT-10），V1实现优先级最低，不可用时通过站内消息替代（V1通过站内消息通知，V2实现短信/邮件推送（接口预留））。**
- 审批意见、审批人、审批时间完整记录，支持审批历史追溯。

**核心业务规则：**

1. 每个审批实例必须绑定一份已提交且有效的CUT-04方案版本、最终割接等级和对应评估/清单版本；审批开始后引用快照固定，任何来源变更不得静默更新审批页面。
2. 审批路由以提交时最终等级生成并保存快照：A级为发起人→用服经理→二线→研发，B级为发起人→用服经理→二线，C/D级为发起人→用服经理，全部串行。不得由发起人删减节点或临时降低审批级别。
3. 当前节点仅能由节点快照中指定且具备该项目数据权限的审批人处理；非当前节点、已处理节点或代理授权已失效时禁止审批。通过和驳回都必须填写反馈意见，5项合理性评审必须全部作答。
4. 节点通过要求5项合理性均为“是”；任一项为“否”必须填写不合理原因并执行驳回，不允许带未处置的不合理项流向下一节点。全部节点通过后锁定方案版本并将任务置为“待执行”。
5. 任一节点驳回即终止当前审批实例，方案版本状态为“已驳回”。工程师基于被驳回版本创建新方案版本，修改后从首节点重新发起新审批实例；原审批意见和快照只读保留。
6. V1仅展示割接操作时间，不执行自动提前时间判断。V2只对A/B级按割接类型匹配专项提前时间规则，以自然日计算“割接操作时间-方案提交时间”；结果作为审批参考，不新增平台通用时效审批，也不阻断C/D级流程。规则版本随审批实例保存。
7. 下一节点通知优先使用站内消息；V2可增加短信/邮件/IM。通知失败不回滚已完成审批动作，但必须标记失败并支持重发，待办仍可在平台内查询。

**用户故事：**

作为用服经理/二线/研发审批人，我希望系统按割接等级自动生成对应审批节点（A级4级串行：发起人→用服经理→二线→研发；B级3级串行：发起人→用服经理→二线；C/D级2级串行：发起人→用服经理），审批页面汇总引用项目信息（11字段）、采集信息分析（含割接类型/组网模式/割接操作时间；V2后续补充"是否未按规定提前时间提交"自动合规判断）、风险考察项（风险项1-4）、业务调研项（调研项1-4）、割接等级（5个评估维度）、割接方案等内容，我可通过5项合理性评审表单（割接前准备/业务测试/割接执行步骤/割接回退步骤/其他，每项单选是/否，选否展示不合理原因）进行评审，驳回跳转至P4割接方案修改、通过跳转至P6割接跟踪与闭环，驳回或通过均需填写反馈意见，待办任务推送通知至下一审批人（V1通过站内消息通知，V2实现短信/邮件推送（接口预留，实现优先级最低）），以便高级别割接获得更严格的多层级把关、低级别割接快速通过、确保审批管控与风险等级匹配（V2后续补充合规性问题自动暴露能力）。

**验收标准：**

- **WHEN** 一线工程师提交割接方案（含采集清单）至审批环节

- **THEN** 页面展示5项合理性评审项（割接前准备工作是否合理/业务测试内容是否合理/割接执行步骤是否合理/割接回退步骤是否合理/其他是否合理），每项单选是/否，选"否"时展示不合理原因输入框
- **WHEN** 当前审批节点审批人执行通过操作并填写反馈意见
- **THEN** 流转至下一审批节点（若有），全部节点通过后方案状态变更为"已锁定"，跳转至P6割接跟踪与闭环（CUT-06执行闭环）
- **AND** 审批意见、审批人、审批时间完整记录，审批历史可追溯
- **WHEN** 当前审批节点审批人执行驳回操作并填写反馈意见（必填）
- **THEN** 方案退回一线工程师修改，方案状态变更为"已驳回"，跳转至P4割接方案修改
- **AND** 一线工程师修改后重新提交，从首节点开始重新审批
- **WHEN** 审批人无当前节点权限、方案或采集清单版本已失效、评审项缺失，或任一合理性评审为“否”却选择通过
- **THEN** 平台阻止审批并保持当前节点状态，展示权限、版本或评审校验失败原因，不锁定方案且不创建下一节点待办

## CUT-06 割接执行闭环

| 属性 | 内容 |

| 用户角色 | 一线工程师、二线、研发、用服经理 |

**业务场景与需求描述：**

对割接执行过程进行跟踪闭环（P6割接跟踪与闭环阶段），确保割接按方案执行、问题可追溯、结果可回传。闭环内容含设备连接与采集、4项正常判定、附件上传（割接后信息采集清单+割接实施承诺书）、割接遗留项记录、割接结果（成功/失败）回流，提交按钮结束流程。V1暂不区分各角色具体填写字段，统一填写闭环内容；V2再按角色拆分（来源R055）。

**设备连接与采集入口：**

P6页面提供“设备连接与采集”入口并携带割接任务、项目和设备上下文。工程师选择目标设备、CUT已发布命令模板以及认证方式，可引用本人有权使用的设备凭证，也可临时输入登录用户名、密码并按需显式保存为设备凭证；临时任务保存登录用户名但不保存密码。系统通过INT-12下发统一采集任务，由现有采集平台负责实际连接、命令执行和数据采集，平台接收回调并将结果关联为割接前、割接中或割接后执行证据。入口默认禁止直接输入任意设备命令，密码/密钥明文不可见。现有采集平台不可用或未能在割接窗口内返回必要结果时，具备权限的工程师可人工采集并上传结果；平台必须保留原下发失败任务及证据，将人工结果关联原任务并标明来源，执行证据齐备且经责任人确认后方可继续闭环。

**4项正常判定（每项单选是/否，选否展示详细说明）：**

| 序号 | 判定项 | 选项 | 选"否"时展示 |
| ---- | ---- | ---- | ---- |
| 1 | 割接前检查是否正常 | 是/否 | 详细说明 |
| 2 | 割接执行是否正常 | 是/否 | 详细说明 |
| 3 | 割接测试是否正常 | 是/否 | 详细说明 |
| 4 | 割接是否无回退操作 | 是/否 | 回退结果及原因（详细说明） |

> 来源R040（割接前/执行/测试是否正常+详细说明）、R041（割接回退操作+回退结果及原因）。第4项统一定义为“割接是否无回退操作”：选“是”表示未发生回退；选“否”表示发生回退，并展示回退结果及原因详细说明，避免字段名称与取值语义相反。

**附件上传（文件上传）：**

1. **割接后信息采集清单上传**：割接完成后上传割接后信息采集清单文件（来源R042）。
2. **割接实施承诺书上传**：上传割接实施承诺书文件（来源R042）。

**割接遗留项记录：**

割接过程中产生但未当场解决的问题记录为遗留项（输入框填写，含问题描述、责任人、计划解决时间），遗留项进入待办跟踪，闭环后方可归档（来源R043）。

**割接结果回流（成功/失败）：**

割接执行完成后，根据割接结果进行差异化回流（来源R044，**接口预留，V1实现优先级最低，不可用时通过手动操作回传结果**）：

- **成功**：通过平台内部服务更新项目割接节点状态并刷新客户资产库；ITR来源任务将割接结果回传ITR。
- **失败**：通过平台内部服务更新项目割接节点状态；ITR接口可用时自动生成故障单并关联割接任务。

**提交按钮结束流程：**

一线工程师点击"提交"按钮结束流程，割接任务状态变更为"已闭环"，遗留项进入待办跟踪，全部遗留项闭环后方可归档（来源R045）。

**多角色闭环分工（V1暂不区分）：**

V1暂不区分各角色具体填写字段，统一填写闭环内容；V2再按角色拆分（来源R055，已确认事项）。

**核心业务规则：**

1. 只有CUT-05全部审批通过、方案版本已锁定、执行设备范围与锁定方案一致、必需保障人员和V1人工确认的备件已就位时，任务才可从“待执行”进入“执行中”；任一门禁失败均不得记录已开始。
2. 执行步骤来自唯一锁定方案版本，按步骤序号记录开始、完成、结果、执行人和证据。前一步未成功或未经授权确认例外时不能进入下一步；执行中不得替换方案、设备范围、回退步骤或命令模板版本。
3. 本平台拥有割接业务步骤、状态和结果，现有采集平台只负责设备连接、命令执行与数据采集。平台通过INT-12下发任务并按任务ID+回调事件ID幂等接收状态/结果；回调不能直接把割接任务改为成功，须由CUT-06按业务门禁判定。
4. 认证支持已保存凭证和临时账号密码两种方式。已保存凭证必须校验当前用户、项目/设备范围和短期任务授权；临时模式只保存登录用户名，不保存密码。用户显式选择“保存为凭证”时才创建加密凭证，默认仅创建人可用，后续授权按INT-12执行。
5. 发现执行异常、验证失败、方案定义的停止条件或回退条件命中时，执行人必须停止后续步骤并记录触发事实；选择回退时只能按锁定方案的回退步骤执行，逐步记录结果。停止、失败或已回退均不得作为成功割接完成。
6. 全部执行步骤完成后进入稳定观察，观察时长、验证项和通过标准取锁定方案；平台记录开始/结束时间、采集证据和业务测试结果。观察未结束、任一验证项为否或必需证据缺失时不得判定成功。
7. 在线采集失败允许授权工程师上传人工结果，但必须关联原失败任务、设备、采集阶段、命令模板版本和证据来源，经责任人确认后才能替代该阶段的“证据齐备”判断；人工结果不得覆盖或删除在线失败记录。
8. 成功要求执行、验证、观察和必传附件全部通过；失败或回退必须记录结果、原因和故障处理。任务提交后可进入“已闭环”，未关闭遗留项继续形成待办并阻止“已归档”；不得把未解决遗留项隐藏或删除。
9. 项目状态和客户资产通过平台内部服务更新；ITR回传失败只把回传状态置为“待重试”，不回滚平台已确认的闭环事实。V1角色共用闭环界面，V2角色字段拆分不得改变执行Owner、证据和成功判定。

**用户故事：**

作为一线工程师，我希望在割接执行完成后通过4项正常判定（割接前检查/割接执行/割接测试/割接是否无回退操作，每项单选是/否，选否展示详细说明，第4项选否展示回退结果及原因），上传割接后信息采集清单与割接实施承诺书，记录割接遗留项，选择割接结果后由平台内部更新项目状态和客户资产；ITR来源任务按需回传结果或生成故障单。点击提交按钮结束流程，以便确保割接按方案执行、问题可追溯、内部数据一致且遗留项不遗漏。V1阶段各角色统一填写闭环内容，V2阶段再按角色拆分填写字段。

**验收标准：**

- **WHEN** 一线工程师在P6页面点击“设备连接与采集”
- **THEN** 系统自动带入当前割接任务、项目和设备上下文，展示工程师有权使用的设备凭证、临时账号密码输入方式与CUT已发布命令模板
- **AND** 工程师选择认证方式并通过对应权限或输入校验后创建INT-12统一采集任务；现有采集平台回调的状态和结果关联至当前割接任务，任务及业务日志不得包含密码/密钥明文
- **WHEN** 工程师选择已保存凭证但不具备凭证权限，或不具备设备权限、命令模板权限
- **THEN** 系统禁止下发任务并记录不含敏感明文的拒绝原因和审计信息；临时输入模式仍不得绕过设备与命令模板权限
- **WHEN** 现有采集平台不可用、下发失败或在割接要求时间内无法返回必要结果
- **THEN** 系统保留原INT-12任务、失败状态和原始失败证据，允许具备CUT-06执行权限的工程师上传人工采集结果
- **AND** 人工采集结果必须关联项目、设备、割接任务、采集阶段、命令模板版本、上传人、上传时间和原失败任务编号，并标记结果来源为“人工上传”；人工结果不得覆盖或删除原失败任务证据
- **AND** 仅当当前阶段要求的执行证据已齐备且责任人完成结果确认后，系统才允许继续提交割接闭环
- **WHEN** 一线工程师进入P6割接跟踪与闭环页面
- **THEN** 页面展示4项正常判定（割接前检查是否正常/割接执行是否正常/割接测试是否正常/割接是否无回退操作），每项单选是/否，选"否"时展示详细说明输入框
- **AND** 第4项“割接是否无回退操作”选“否”时展示回退结果及原因详细说明输入框
- **WHEN** 一线工程师上传附件
- **THEN** 系统保存割接后信息采集清单和割接实施承诺书附件，并将附件ID、文件版本和上传人关联至闭环单
- **AND** 上传文件存储至基础平台附件存储，支持在线浏览/下载并保留文件版本；未来启用INT-11时可在不影响当前文件使用的前提下受控补归档
- **WHEN** 一线工程师记录割接遗留项
- **THEN** 系统创建包含问题描述、责任人和计划解决时间的遗留项记录，将状态置为“待处理”并生成责任人待办
- **WHEN** 执行步骤异常、验证失败或锁定方案中的停止/回退条件命中
- **THEN** 平台停止后续步骤并将执行状态标记为“已停止/待回退”，记录触发事实；选择回退时按锁定回退步骤逐项记录结果，任务不得判定为成功
- **WHEN** 全部执行步骤完成但稳定观察窗口未结束、任一验证项为否或必要证据缺失
- **THEN** 平台保持任务“执行中/待闭环”并阻止成功提交，展示剩余观察时间、失败验证项或缺失证据
- **WHEN** 割接执行完成，割接结果为"成功"
- **THEN** 平台通过内部项目服务更新项目档案割接节点状态并记录割接结果，通过内部客户资产服务刷新资产数据
- **AND** ITR来源任务同步结果至ITR；项目模块来源任务通过内部事件更新项目状态
- **AND** ITR来源任务预留结果回传接口，V1实现优先级最低；接口不可用时记录待回传状态并支持人工补录ITR处理结果
- **WHEN** 割接执行完成，割接结果为"失败"
- **THEN** 平台通过内部项目服务更新项目状态，并在ITR接口可用时自动生成ITR故障单
- **AND** ITR故障单与割接任务建立关联，故障单号回写割接任务
- **AND** 接口预留（ITR接口），V1实现优先级最低，不可用时通过手动操作回传结果替代
- **WHEN** 一线工程师点击"提交"按钮
- **THEN** 流程结束，割接任务状态变更为"已闭环"，遗留项进入待办跟踪
- **AND** 全部遗留项闭环后方可归档
- **WHEN** V1阶段各角色（一线工程师/二线/研发/用服经理）填写闭环内容
- **THEN** 系统统一展示闭环内容填写界面，暂不区分各角色具体填写字段
- **AND** V2阶段规划按角色拆分填写字段（V1暂不实现）

## CUT-08 割接备件集成

| 属性 | 内容 |
| ---- | ---- |
| 需求编号 | CUT-08 |
| 所属阶段 | 割接专项 |
| 用户角色 | 一线工程师 |
| 优先级 | P2 |
| 目标版本 | V2 |
| 复杂度 | 中 |
| 依赖条件 | 备件系统接口 |

**业务场景与需求描述：**

提供割接备件申请的快速集成能力，实现备件申请跳转装备件系统、申请结果回填至割接任务，避免一线工程师在多系统间切换。当CUT-02分级评估中"备件是否申请"维度取值为"是"时，标记为需要备件保障。**本需求为V2集成类需求，V1仅保留接口定义、数据模型和手工记录/确认能力，不计作CUT-08交付；V2实现备件系统跳转与结果自动回填，V3不再作为本需求的模糊兜底版本。**

**集成流程：**

1. **触发备件申请**：CUT-02评估结果中备件维度为"是"时，割接任务详情中显示"申请备件"入口。**V1支持手动记录备件信息（备件编号/型号/数量/到货时间/申请状态等字段），V2实现备件系统跳转集成（接口预留）。**
2. **跳转装备件系统（V2实现，V1接口预留）**：一线工程师点击"申请备件"，平台携带割接任务上下文（客户编码、设备序列号、所需备件类型等）跳转至装备件系统发起申请。
3. **结果回填（V2实现，V1接口预留）**：备件申请完成后，装备件系统回调平台或平台主动拉取申请结果（备件编号、备件型号、申请数量、到货时间、申请状态等），回填至割接任务详情。
4. **备件就位检查**：CUT-06执行闭环时，备件就位状态作为前置检查项。**V1支持手动确认备件就位，V2实现备件系统自动回填（接口预留）。**

**核心业务规则：**

1. 备件系统拥有申请、占用、领用、到货和归还结果，平台拥有割接任务的备件保障需求和门禁引用；以割接任务ID、申请ID和备件明细ID映射。
2. 外部返回申请单号才视为受理；逐明细到货数量满足需求且经确认后才标记“已就位”，部分到货不得解除全部门禁。
3. 请求按割接任务和申请版本幂等；手工记录必须标记来源、证明和核验人，恢复后与备件系统对账。

**用户故事：**

作为一线工程师，我希望在割接评估确认需要备件后，通过割接任务详情直接跳转装备件系统发起备件申请，申请结果自动回填至割接任务（V1通过手动记录备件信息，V2实现备件系统跳转集成（接口预留）），以便减少多系统切换、确保备件申请与割接任务关联、执行前可校验备件就位状态（V1支持手动确认备件就位，V2实现备件系统自动回填（接口预留））。

**验收标准：**

- **WHEN** CUT-02确认需要备件且工程师发起申请
- **THEN** 平台携带割接上下文跳转备件系统，收到申请单号后保存任务、申请和明细映射
- **WHEN** 全部必要备件明细到货数量满足需求并完成核验
- **THEN** 平台把保障项标记为“已就位”，CUT-06保存门禁检查记录后允许继续
- **WHEN** 接口失败、仅部分到货、回调明细冲突或用户无割接任务权限

**功能描述要点：**

- 调研项库：业务调研项的内容定义（含采集项ID、项命名、项含义、界面格式、反馈结果内容、动态多维关联关系等字段），为CUT-07统一采集项主数据中采集项类型=业务调研项的子集，由CUT-07维护。
- 动态多维绑定关系：每项调研项与一个或多个"割接类型×组网模式×设备类型×割接等级"（已知4维，可扩展）组合关联，管理员配置关联关系。
- 矩阵展示：后台以矩阵形式展示业务调研项与各组合的绑定关系，支持批量编辑。
- 必填项标识：每项调研项在特定绑定关系下可标识为必填或选填，确保关键业务调研点强制采集。
- 界面格式动态数据查询：统一采集项（采集项类型=业务调研项）配置支持动态数据查询，传入上下文信息调接口获取数据。

**字段依赖：**

- 采集项类型=业务调研项（筛选条件，来源于CUT-07统一采集项主数据，按采集项类型筛选出业务调研项子集）
- 调研项ID（主键，来源于CUT-07统一采集项主数据中采集项类型=业务调研项的子集）
- 调研项名称（项命名）
- 调研含义（项含义）
- 界面格式（支持多种数据类型：单选项/多选框/下拉框/输入框/表格/表单/文件上传按钮等）
- 界面格式动态数据查询（传入上下文信息调接口获取数据）
- 反馈结果内容（如：是/否+特殊情况备注；自定义文本；文件上传等）
- 割接类型（外键，来源于CUT-07割接类型10类）
- 组网模式（外键，来源于CUT-07组网模式5类）
- 设备类型（外键，来源于CUT-07设备类型主字典）
- 割接等级（外键，A/B/C/D）
- 其他维度（可扩展新增）
- 绑定关系ID（主键，唯一标识一条绑定关系）
- 是否必填（在该绑定关系下该项调研项是否必填）
- 是否启用（启用/停用）
- 维护人、维护时间

**核心业务规则：**

1. CUT-10不新建第二套调研项主数据，只提供CUT-07统一采集项中“采集项类型=业务调研项”的筛选视图和关联矩阵；调研项ID在两处必须一致。
2. 已知绑定维度为割接类型、组网模式、设备类型、割接等级；维度定义、选项和组合关系均配置化。新增维度须定义数据类型、取值来源、是否必填和匹配方式，不改变既有维度语义。
3. 一条有效绑定关系由调研项、维度组合、有效期唯一确定；相同有效期内禁止重复或互相冲突的绑定。具体组合优先于通配组合，优先级相同且结果冲突时清单生成失败并提示管理员处理。
4. 矩阵变更对新生成的CUT-03清单生效；已生成或执行中的割接清单保留配置版本快照，不因后台变更静默增删采集项。需要采用新矩阵时必须显式重新生成并展示差异。
5. 系统预置必选调研项不得被一线删除；一线只能在具体割接任务新增自定义项并标记来源。条件显示只控制界面展示，处于显示条件且标记必填的字段仍参与提交校验。
6. 外部动态数据查询只负责候选值或已知数据加载，查询失败不得自动跳过必填项；人工填写须标记数据来源。

**用户故事：**

作为系统管理员，我希望在后台维护业务调研项（含割接背景子表、涉及业务简述、割接动作影响范围、业务连续性要求、业务中断次数、现网拓扑图、设备部署位置规划、设备接口互联规划、设备IP地址与vlan规划、设备并发连接数/新建连接数/CPU使用率/内存使用率、业务连通性测试例核验、友商配置全量翻译检查等）的内容定义及动态多维绑定关系（已知4维：割接类型×组网模式×设备类型×割接等级，可扩展），调研项配置支持界面格式动态数据查询，以便CUT-03采集清单按动态多维绑定关系联动展示对应业务调研项、确保关键业务调研点强制采集、降低个人经验依赖。

- **THEN** 平台保存每项调研项在特定绑定关系下的必填/选填标识，并在生成清单时展示和校验该标识

- **WHEN** 相同调研项和有效期存在重复绑定、同优先级规则冲突或外部动态数据查询失败
- **THEN** 平台拒绝发布冲突矩阵或把清单标记为“生成失败/待处理”，不生成缺少必填项的正式割接清单
- **WHEN** 管理员发布新矩阵版本而已有割接清单正在执行
- **THEN** 既有清单继续关联原配置快照；重新生成时平台展示新增、删除、必填变化差异并由有权人员确认

**异常、降级及留痕要求：**

CUT-07主数据不可用、维度选项失效或矩阵冲突时禁止发布新版本，当前已发布版本继续有效；CUT-03生成失败时保留输入组合和命中轨迹，修正规则后可按原输入重试。外部数据源超时允许授权工程师人工填写但不得跳过必填校验。平台记录矩阵版本、调研项及维度前后值、发布人时间、命中规则、清单快照、冲突详情、人工来源和重试结果。
