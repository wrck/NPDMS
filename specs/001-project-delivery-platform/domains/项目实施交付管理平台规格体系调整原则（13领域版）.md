# 2. 领域需求规格原则

## 2.1 FR唯一归属原则

每项功能需求（FR）：

必须且只能：

> 在一个领域完整定义。

规则：

```text
FR
 |
 +-- Owner领域（完整定义）
 |
 +-- Consumer领域（引用）
```

例如：

## FR-IMP-023 配置调试

Owner：

```
IMP
```

定义：

- 配置过程
- 执行状态
- 完成条件
- 验收标准

AST只引用：

```
设备配置变化事件
```

不重新定义配置流程。

------

# 2.2 BR业务规则归属原则

业务规则（BR）跟随Owner领域。

例如：

设备唯一性：

错误：

```
PROJ:
设备必须唯一

SRV:
设备必须唯一
```

正确：

```
AST:

BR-AST-001

设备序列号全局唯一
```

其他领域：

引用：

```
依赖AST设备身份规则
```

------

# 2.3 AC验收标准归属原则

AC跟随FR。

即：

```
FR
 |
 BR
 |
 AC
```

不可跨领域复制。

例如：

CUT：

```
FR-CUT-011
割接执行记录

AC-CUT-011
执行成功生成记录
```

ACC：

只引用：

```
依赖CUT完成事件
```

# 3.3 割接工作台编排

CUT作为独立工作台。

原因：

割接不只属于项目。

来源：

```
项目
故障
运维变更
主动服务
```

结构：

```
割接工作台

├── 割接任务
├── 风险评估
├── 方案评审
├── 执行窗口
├── 回退管理
├── 稳定观察
└── 结果归档
```

Owner：

CUT

------

# 3.4 巡检工作台编排

服务工作台

├── 巡检任务
├── 在线采集
├── 离线采集

SRV

# 6. 页面设计原则

业务页面允许聚合。

领域不允许聚合。

即：

允许：

```
项目详情页

显示：

项目
合同
设备
服务
```

因为：

这是查询视图。

禁止：

```
项目表

保存：

合同字段
设备字段
服务字段
```
