# 领域化 SRS 来源台账

> 用途：登记本次直接迁移可使用的证据、证据等级和边界。未列入台账或无法定位的资料不得单独形成确定性业务承诺。
>
> 基线：当前工作区、当前会话明确决策和用户指定资料；禁止使用项目记忆。原始 Excel、HTML、DOCX、VSDX、DDL 及用户未跟踪文件保持只读。

## 1. 证据等级

| 等级 | 证据类型 | 使用边界 |
| --- | --- | --- |
| A | 当前会话中用户明确确认的业务决策 | 直接约束迁移；与旧规格冲突时优先 |
| B | 原始需求收集表、业务数据表、正式说明文档和经确认业务细节 | 支持业务需求、规则、数据和验收语义；仍需保留来源定位 |
| C | 当前 148 条来源需求、145 项正式 FR、7 项演进项及 BR/DR/AC | 迁移完整性基线；只做语义保持迁移，不静默扩写 |
| D | 页面 HTML、页面数据 Excel、流程图和原型 | 证明可见页面、动作、字段、步骤和门禁；不单独证明隐藏规则 |
| E | 领域迁移矩阵、历史归类和既有模块名 | 只作拆分方向和遗漏检查，不决定最终领域或 Owner |
| F | 目标表结构、迁移模型和技术设计 | 发现对象、关系和一致性缺口；不得直接升级为业务事实 |

## 3. 迁移使用规则

1. 冲突时按 A→B→C→D→E→F 的顺序处理，并在目标文档记录冲突和处置依据。
2. 正式 FR 的语义、来源、版本、优先级、角色、BR/DR/AC 编号保持不变；领域 Owner 按已确认 profile 调整。
3. `FR-RES-020`、`FR-ANA-003`～`FR-ANA-008` 仅登记为演进方向，统一标明“不纳入当前开发验收”。
4. 页面和原型只转换为有其他来源支持的场景、可见动作、信息结构和门禁；示例数据、配色、布局和占位内容不形成需求。
5. 目标表结构和技术证据只用于发现缺口；未经确认的推导标 `【建议】`，影响范围、规则、状态或验收的不确定内容标 `【待确认】`。
6. 除技术选型章节外使用“基础平台”这一稳定业务称谓，不在业务正文重复具体技术产品名。
