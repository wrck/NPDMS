## 测试证据记录规范

T-CP-009 起，每项任务的自动化测试证据以 JSON 记录形式登记，并由
`tests/e2e/verify-test-foundation.ps1` 的 `Test-TraceEvidenceFile` 函数强制校验。
证据文件默认输出到 `tests/evidence/<TASK-ID>-<TESTTYPE>-health.json`，并遵循以下字段约束：

| 字段 | 类型 | 约束 |
| --- | --- | --- |
| `taskId` | string | 形如 `T-CP-009`、`T-V1-PLT-001`，匹配 `^T-[A-Z0-9-]+$` |
| `frIds` | string[] | 至少一个，每个匹配 `^FR-[A-Z]+-\d+$` |
| `acceptanceIds` | string[] | 至少一个，引用任务验收编号或规格 AC 编号 |
| `testType` | string | 枚举：`unit`、`integration`、`contract`、`e2e`、`performance`、`security` |
| `command` | string | 复现证据所用的完整命令，不得为空 |
| `result` | string | 枚举：`passed`、`failed`、`blocked` |
| `executedAt` | string | ISO 8601 时间戳，可被 `DateTime.TryParse` 解析 |
| `evidence` | string[] | 至少一个仓库相对路径；不得越出仓库根；路径必须实际存在 |

证据记录写入后即视为该任务在对应 `testType` 维度的验收证据。任何任务在勾选完成前，
必须为其声明的每个 `testType` 至少登记一条 `result=passed` 的证据记录。
