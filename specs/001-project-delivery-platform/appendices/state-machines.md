# 附录B：状态机与流转规则

## 1. 项目状态

| 状态 | 定义 |
| --- | --- |
| 草稿 | 信息未满足启动条件，可编辑 |
| 待分派 | 等待服务经理或规则指派项目负责人 |
| 进行中 | 已启动并处于任一有效交付阶段 |
| 暂停 | 经授权暂停，暂停原因和恢复条件必填 |
| 待闭环 | 实施和验收已完成，等待闭环检查或审批 |
| 已闭环 | 闭环门禁满足，核心数据只读 |
| 维护中 | 项目交付结束，资产和服务进入持续维护 |
| 已取消 | 经审批取消，保留全部历史记录 |

## 2. 任务状态

| 状态 | 定义 |
| --- | --- |
| 草稿 | 任务尚未下发 |
| 待处理 | 已下发，等待责任人接收 |
| 进行中 | 责任人已开始执行 |
| 受阻 | 存在明确阻断原因和解除责任人 |
| 待验证 | 执行完成，等待发起人或验收人验证 |
| 已完成 | 完成条件满足并通过验证 |
| 已取消 | 经授权取消并记录原因 |

## 3. 公共流转规则

- 状态变化必须通过命名业务动作触发，并进行权限、前置状态和门禁校验。
- 驳回、撤回、终止、回退和取消必须填写原因。
- 已闭环、已归档对象原则上只读；确需重开时必须审批并生成新版本。
- 批量状态变化必须逐条校验并返回成功、失败明细，禁止无提示部分成功。

## 4. 专业流程状态

- 割接：草稿 → 准备中 → 待评审 → 待执行 → 执行中 → 稳定观察 → 已完成；异常为已回退或已终止。
- 巡检：草稿 → 准备中 → 执行中 → 报告生成 → 问题确认/整改 → 待闭环 → 已闭环。
- 方案：草稿 → 待评审 → 已通过/已驳回 → 已基线 → 已变更。
- 验收：草稿 → 待提交 → 确认/审批中 → 已通过/已驳回 → 已归档。
- 工单：待分派 → 待处理 → 进行中/受阻 → 待验证 → 已关闭。

【待确认】专业状态名称、可回退节点和重开权限需在原型及流程设计阶段由业务负责人最终确认。

## 5. 项目订单行实施范围状态【建议】

| 状态 | 定义 | 允许的后续动作 |
| --- | --- | --- |
| 待映射 | 已保留来源记录，但尚不能唯一确定订单行 | 补充证据后转为待数量确认或有效；无法处理时保持并进入问题清单 |
| 待数量确认 | 项目与订单行已确定，但项目分配数量未知 | 补录并校验数量后转为有效；不得计入已确认实施数量 |
| 有效 | 订单行及项目分配数量已确认并处于生效区间 | 调整时生成新版本/关系；结束后转为已失效 |
| 已失效 | 该范围不再作为当前实施依据，历史仍可追溯 | 经受控变更可生成新的有效关系，不直接恢复覆盖旧记录 |

流转门禁：

- 待映射不得直接计入项目实施数量或完成率。
- 待数量确认不得以整行订单量自动补齐多个项目。
- 【待确认】有效范围跨项目分配总量的校验公式、退货/取消影响、计量单位和精度。

## 6. 项目设备归属状态【建议】

| 状态 | 定义 | 允许的后续动作 |
| --- | --- | --- |
| 待确认 | 归属来源存在，但项目、时间区间或冲突尚未确认 | 补充证据后转为有效，或保留为问题记录 |
| 有效 | 设备在生效区间内归属于指定项目 | 转移/交接后结束原关系并建立新关系 |
| 冲突待处理 | 与既有有效区间或来源证据冲突 | 人工确认后转为有效或结束，不按最后记录覆盖 |
| 已结束 | 归属区间已经结束，保留完整历史 | 新归属通过独立关系建立 |

【待确认】同一设备同一时点是否只允许一个有效项目实施归属；确认前系统必须识别重叠区间并阻断静默覆盖。
