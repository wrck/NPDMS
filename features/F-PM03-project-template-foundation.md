## 1. 业务价值

建立版本化项目模板供给端：工程管理部按四维业务属性配置模板（阶段、任务、里程碑、交付件、门禁、流程引用），发布后供项目创建匹配使用。这是 PM-01 手动创建项目的硬前置——无生效模板时项目只能保持创建草稿、不得进入 S0。

## 2. Scope

1. 模板身份与版本：模板编码、名称、四维匹配条件、匹配优先级；草稿→生效→停用状态；发布生成不可变版本（revision，发布后只读）。
2. 模板内容定义：生命周期阶段（S0～S6）顺序、各阶段任务清单、里程碑、交付件要求、准入/准出门禁、流程定义ID+版本引用、满意度适用时点（字段级，任务生成由 ACC-02 消费）。
3. 发布校验：门禁引用的任务/交付件/状态/流程版本不存在时拒绝发布，保持草稿并列出失败项。
4. 四维匹配查询：按签约方式/项目类别/实施方式/重大项目级别独立条件命中生效模板；返回唯一命中或冲突清单（多匹配同优先级、无匹配），不静默选模。
5. 停用：仅禁止新项目使用，不解除已绑定项目门禁；重试用原版本号。
6. 留痕：每个版本的配置快照、适用范围、校验结果、发布/停用人与时间；被项目引用的历史版本不得物理删除。
7. 前端模板管理后台：列表、新建/编辑草稿、版本查看、发布/停用、匹配预演。

## 3. Out of Scope

- 项目创建时模板选择与实例化执行：F-PM01 消费端；
- 流程定义版本管理本身：只存储引用ID+版本，不校验流程内部（BPM 域）；
- 满意度任务生成、项目闭环入口开放：ACC-02/CLO 消费模板字段；
- 已建项目的模板变更流程与影响评估（PM-03 规则3后半）：后置 Feature；
- 直签工程类默认模板的预置内容集：通过本 Feature 的配置能力在验收时录入，不做代码种子；
- 模板跨租户共享：租户扩展模板仅本租户可见，基础模板系统保留编码保护即可。

## 4. Business Rules（本 Feature 执行的 PRD 规则）

| 规则 | 内容 | 来源 |
|---|---|---|
| BR-1 | 模板由编码+版本号唯一标识；状态至少草稿/生效/停用；四维条件独立引用字典，禁止拼装混合字段 | PM-03 规则1 |
| BR-2 | 版本必须完整定义适用条件、阶段顺序、阶段任务、里程碑、交付件、准入/准出门禁和流程定义版本引用；引用对象不存在不得发布 | PM-03 规则2 |
| BR-3 | 已生效模板不得原位修改；调整形成新版本重新发布；已建项目继续绑定创建时版本 | PM-03 规则3 |
| BR-4 | 匹配按四维+优先级；来源属性未映射、类别缺失、同优先级多匹配或无匹配时不得静默选模，返回人工处理冲突项 | PM-03 规则4 |
| BR-5 | 停用模板只禁止新项目使用，不解除已创建项目门禁；发布/停用失败重试用原版本号 | PM-03 规则5、留痕要求 |
| BR-6 | 模板内容是可版本化初始化配置，不得硬编码到项目状态机 | PM-03 规则6 |
| BR-7 | 二线审核/总部复审是可配置业务角色组（流程定义内），不是二级服务经理，本 Feature 不固化节点 | PM-03 规则7 |
| BR-8 | 权限：平台管理员维护技术状态与发布；授权模板负责人创建草稿/配置/提交发布；创建人员只读选择生效模板；系统保留编码不得删除/复用/改义 | PM-03 权限段 |

## 5. 验收标准

- **WHEN** 授权模板负责人创建/编辑模板草稿
- **THEN** 可配置名称、四维条件（分别引用字典/来源属性）、匹配优先级、业务场景、阶段S0～S6、各阶段任务、里程碑、交付件、准入/准出门禁、流程定义ID+版本
- **AND** 四维条件分别独立保存，不产生混合字段
- **WHEN** 提交发布且内容不完整或引用不存在的任务/交付件/状态/流程版本
- **THEN** 发布被拒，模板保持草稿，返回具体校验失败项
- **WHEN** 发布校验通过
- **THEN** 生成不可变版本（revision 递增），模板进入生效，版本发布后任何修改被拒绝
- **WHEN** 按四维条件查询匹配模板
- **THEN** 唯一命中时返回该生效模板及完整内容；同优先级多匹配或无匹配时返回冲突清单，不返回默认猜测
- **WHEN** 停用生效模板
- **THEN** 模板停止新项目匹配；已发布版本与其内容仍可被历史项目只读引用
- **WHEN** 无权限用户访问模板维护或发布
- **THEN** 服务端返回权限拒绝（非仅前端隐藏）
- **AND** 以上操作均留痕（版本快照、校验结果、操作人/时间）

## 7. 数据变更与存量处置

1. 新建目标表（下一个未占用 Flyway 版本）：
   - `proj_project_template`：模板身份、编码（租户内唯一，系统保留编码保护）、状态、匹配优先级、当前维护草稿指针；
   - `proj_project_template_revision`：发布版本完整定义（四维条件、阶段、任务、里程碑、交付件、门禁、流程引用、满意度适用时点），`uk(tenant_id, template_id, revision_no)`，发布后只读。
2. 模板内容明细（阶段/任务/里程碑/交付件/门禁行项目）作为 revision 定义的结构化存储；JSON 仅允许用于低频扩展快照，不承载唯一/过滤/门禁核心字段（09 原则7）。
3. 存量 `pms_project_template`/`pms_phase_template`（18 个 Java 文件 + 前端两页面）：迁移契约 `NEW_ONLY`，旧表冻结不迁移；存量运行入口（后端全链、前端页面、菜单）按 V50/V51 先例退役，前向迁移逻辑撤销菜单授权。
4. 历史迁移文件不改；旧表数据保留待 AI-MIG-000 证据判定。

## 8. 测试要求（P2 契约 Phase 3 类别）

- 业务规则/聚合单元测试：版本不可变、发布校验、四维匹配、优先级冲突；
- API 契约与输入边界测试：CRUD/publish/disable/match-preview、四维参数边界；
- 服务端授权拒绝测试：无维护权/无发布权/跨租户；
- 状态/异常恢复测试：发布失败保持草稿、重试原版本号；
- 幂等与并发冲突测试：并发发布同版本、重复发布；
- 数据库约束与迁移测试：uk 约束、迁移可重复执行；
- 真实浏览器验证：模板后台页面闭环（新建→配置→发布→匹配预演→停用），按项目 UI 验收要求执行。
