> Feature ID：`F-PM02`

> 规格基线：`docs/specification-baseline/manifest.json` @ `fd6728c`

## 1. 业务价值

承接 F-PM01 已交付的独立根项目，补齐 PM-02 的"主子项目自由拆分与进度汇总"骨架：工程管理部可将大型项目按业务需要持续拆分出任意层级子项目，系统维护非固定层级的项目树（父子关系 + 无环约束），提供按需加载的四类层级查询，并落地"父项目进度 = Σ（直接子项目进度 × 权重）"的汇总口径。子项目独立编码、独立交付，父项目进度逐级汇总，为后续闭环（CLO-01/02）和多级权限（PM-04）提供可靠的树事实与汇总口径。

## 2. Scope

1. **项目树关系维护**：基于 F-PM01 已落地的 `proj_project` 树邻接字段（`parent_id`/`root_id`/`tree_path`/`tree_depth`/`tree_sort`），在创建子项目与移动子树时由领域层同事务维护真值（根项目 `root_id=id`、`tree_path='/'`、`tree_depth=0`；子项目继承根、追加祖先路径）。
2. **下挂子项目**：以父项目为根，创建子项目并继承父项目的冻结模板版本（`lifecycle_template_id`/`revision`）及可继承主数据（客户、公司/部门、四维分类），按 ADR-0020 子项目序号生成独立编码（`<根项目编码>-SP<流水>`，`code_root_id` 继承根项目、`project_sequence>0`），实例化五要素与根项目一致。
3. **无环移动**：将某项目（及其子树）移动到新的直接父项目下，服务端校验新父项目合法（存在、同租户、非自身、非自身任一后代），拒绝跨租户与循环引用；移动后重建该子树 `root_id`/`tree_path`/`tree_depth` 缓存。
4. **四类层级查询**：直接下级（按 `parent_id`+`tree_sort`）、全部后代（`tree_path` 前缀）、完整上级链（`tree_path` 解析祖先）、指定业务层级（`business_level_code`）；默认按需加载直接下级，服务端先执行租户过滤再返回。
5. **进度汇总口径**：父项目进度 = Σ（直接子项目 `progress` × 归一化权重）；权重未配置时按直接子项目等权，手动配置时同一父下直接子项目权重合计必须为 100%；设备数量不参与权重。
6. **业务层级标签**：`proj_project` 前向扩列 `business_level_code`/`business_level_name`，与结构层级（`tree_depth`）分离；拆分/移动时可指定。
7. **项目详情独立页面**：顶部项目档案区 + 左侧导轨（项目概览 / 项目树 / 进度汇总）+ 右侧内容区，替代 F-PM01 的详情抽屉作为 PM-02 的项目工作台入口。

## 3. Out of Scope

- **拆分维度组合与方案预览**（订单行/数量/办事处/序列号维度自由组合、批量拆分方案预览、拆分范围不超过父项目可分配范围的校验）：依赖 COM-01 订单合同履约与 DeliveryScope 数据，本 Feature 仅支持"指定父项目单建子项目"，不校验订单/数量可分配范围；
- **权重与汇总口径的审批版本化**（PM-02 规则 4：审批、生成新版本、生效时间、批准人、历史快照按版本解释不追溯重算）：本 Feature 仅落等权兜底 + 手动设置 + 合计 100% 校验，不做审批流与版本化；
- **子项目进度来源**（阶段推进、任务闭环、`proj_project_stage_snapshot`）：属 PM-11 任务管理与阶段推进 Feature；本 Feature 只消费 `progress` 字段做汇总，`progress` 初始 0；
- **父项目闭环校验**（全部后代闭环为前提，驳回并列出未闭环清单）：属 CLO-01/02；
- **多级项目权限隔离**（ProjectTreeScope 深度数据范围、平级互不可见、含后代授权）：属 PM-04；
- **非树项目关系**（扩容/续采/改造，`proj_project_relation`）：本 Feature 不涉及，保持该表语义独立（工作区规则：项目组合与项目父子树是两个独立模型）；
- **自动拆分**（CRM/ERP 执行单驱动的拆分）：随 INT-01。

## 4. Business Rules（本 Feature 执行的 PRD 规则）

| 规则 | 内容 | 来源 |
|---|---|---|
| BR-1 | 项目树只由"直接父项目"关系形成；除根项目外每个项目同一时点只有一个直接父项目；不设业务层级深度上限；禁止项目以自身或任一后代作为父项目、禁止形成循环、禁止跨租户挂接 | PM-02 规则1 |
| BR-2 | 子项目具有独立项目编码，继承拆分时指定的模板版本及可继承主数据（客户、公司/部门、四维分类）；子项目编码按 ADR-0020 子项目序号生成（`code_root_id` 继承根、`project_sequence>0` 不回收复用） | PM-02 规则2、ADR-0020 |
| BR-3 | 父项目进度 = Σ（直接子项目进度 × 归一化权重）；同一父下全部直接子项目权重合计必须为 100%；未配置时按直接子项目等权分配；设备数量仅作统计指标，不自动决定权重 | PM-02 规则3、Q-29 |
| BR-4 | 结构层级（`tree_depth`）由父子关系自动计算，与业务层级标签（`business_level_code`）分离；一个业务层级标签可被不同结构深度使用，查询统计不得假设固定深度 | PM-02 规则6、PM-04 规则2 |
| BR-5 | 树查询支持直接下级/全部后代/完整上级链/指定业务层级四类，先执行租户过滤再返回；默认按需加载直接下级，测试深度 30 仅为性能验收规模，不是业务层级上限 | PM-02 规则6 |
| BR-6 | 移动子树必须校验新父项目合法（存在、同租户、非自身、非自身任一后代）；非法时整体回滚，不产生父子关系变更 | PM-02 异常段 |
| BR-7 | 直接子项目权重合计不为 100% 时不得生效；未配置等权时按直接子项目等权折算并校验合计 100% | PM-02 规则3、异常段 |
| BR-8 | 权限：工程管理部/获授权服务经理可下挂子项目、移动子树、设置初始权重；项目经理只读查看本人负责节点的进度与交付数据，无权改变父子关系或权重 | PM-02 权限段 |

## 5. 验收标准

- **WHEN** 工程管理部对某项目发起"下挂子项目"
- **THEN** 指定直接父项目后创建子项目，子项目继承父项目模板版本及关键属性，生成独立编码（`<根编码>-SP<流水>`），状态初始化 S0，实例化阶段/任务/里程碑/交付件/门禁
- **AND** 系统自动计算结构层级深度并维护 `root_id`/`tree_path`，不限制层级深度
- **WHEN** 用户查看多级项目结构
- **THEN** 支持查询直接下级、全部后代、完整上级链、指定业务层级四类查询；项目树默认按需加载直接下级，展开时再加载下一层，返回保留目标项目的层级路径
- **WHEN** 用户对某项目发起"子树移动"到新的父项目
- **THEN** 系统校验新父项目合法（存在/同租户/非自身/非自身后代），校验通过后重建子树 `root_id`/`tree_path`/`tree_depth`
- **AND** 指定父项目为自身或自身任一后代时拒绝移动，返回循环引用错误，父子关系不变
- **WHEN** 父项目下直接子项目进度或权重确定
- **THEN** 父项目进度按 Σ（直接子项目进度 × 归一化权重）计算；未配置权重时按直接子项目等权；配置权重时合计必须 100%，否则不生效
- **AND** 父项目详情页展示直接子项目进度列表与汇总进度
- **WHEN** 查看项目详情页
- **THEN** 顶部项目档案区展示编码/名称/状态/四维/模板绑定；左侧导轨提供项目概览、项目树（直接下级/展开）、进度汇总入口；右侧内容区按选择渲染
- **AND** 以上操作均留痕（操作人/时间、移动前后父项目、权重前后值）

## 7. 数据变更与存量处置

1. 前向迁移（V6x，编号待技术方案锁定）：
   - `proj_project` 扩列 `business_level_code`、`business_level_name`、`progress`（`DECIMAL(5,2) NOT NULL DEFAULT 0`）、`aggregation_weight`（`DECIMAL(5,2) NULL`，相对直接父项目的权重，NULL=等权）、`weight_source`（`VARCHAR(32) NULL`，`DEFAULT_EQUAL`/`MANUAL`）；
   - 字典登记：`pms_project_business_level`（业务层级标签，示例值，不预置权威来源映射）；菜单登记项目树页面（18067 段后续号段，技术方案锁定）。
2. 旧项目树运行面（旧 `project-tree/index.vue` 及其旧链写端点）冻结：旧链项目树基于已冻结的 `pms_project` 表，本 Feature 在新链 `proj_project` 上重建树能力，旧树页面/端点退役（只读或隐藏），参照 V58 先例。
3. 历史迁移文件不改；`pms_project` 表数据不迁移不删除。
4. 示例数据：新增子项目种子覆盖关键组合（多级深度 ≥3、业务层级标签复用不同结构深度、权重等权兜底 + 手动合计 100% + 合计≠100% 被拒、无环移动阻断、直接下级/全部后代/上级链/业务层级四类查询命中）。

## 8. 测试要求（P2 契约 Phase 3 类别，按本 Feature 裁剪）

- 业务规则/聚合单元测试：子项目编码序号、模板继承、树真值维护（root_id/tree_path/tree_depth）、无环移动（自身/后代/跨租户阻断）、权重归一化（等权兜底、合计 100% 校验）、进度汇总公式；
- API 契约与输入边界测试：树查询四类、移动、下挂子项目、进度汇总、参数边界；
- 服务端授权拒绝测试：无移动权/无下挂权/跨租户；
- 状态/异常恢复测试：移动失败整体回滚、权重合计≠100% 不生效；
- 数据库约束与迁移测试：扩列迁移可重复执行、索引命中；
- 真实浏览器验证：项目详情页 + 项目树按需加载 + 下挂子项目 + 子树移动 + 进度汇总，按项目 UI 验收要求逐菜单走查截图。

## 9. Open Questions

无阻塞性开放问题。以下为已裁决的设计决策（详见 Technical Plan，评审时可复议）：

1. 子项目编码按 ADR-0020：根项目 `PJT+年份+流水`，子项目 `<根项目编码>-SP<流水>`（`code_root_id` 继承根、`project_sequence>0`）；
2. 权重以 `proj_project.aggregation_weight`（相对直接父项目）承载，`NULL`=等权；审批版本化后置（Out of Scope）；
3. 进度以 `proj_project.progress`（0-100）承载，进度来源（阶段推进/任务闭环）属 PM-11，本 Feature 只做汇总口径；
4. 业务层级标签以前向扩列 `business_level_code/name` 承载，与 `tree_depth` 结构层级分离。
