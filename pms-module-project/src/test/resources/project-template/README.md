# 工前准备与父子项目交付样例

## 子项目独立选模请求样例

`independent-child-split.json` 展示同一父项目下，现场工勘交付与需求分析交付分别选择不同已发布版本。文件中的高段 ID 仅用于隔离契约测试，不代表环境中已有这些项目、模板或订单行；真实验收须从当前项目范围、已发布模板列表和 Commerce 权威订单范围中选择实际 ID，不能直接向共享库插入这些编号。

在项目拆分方案中逐项选择模板、保存草稿、重开核对，再预览和应用。选择非匹配模板须拥有 `pms:project-template:override` 且填写原因；权限通过现有角色配置，不自动授予。草稿未选模板允许保存接口持久化未完成设计，但不能通过预览或应用；界面在保存前提示补齐。停用或无效发布定义不能由覆盖权限放行。修改选定版本后须重新填写原因并保存、预览，不得使用旧预览应用新方案。

生效后核对两个子项目分别冻结所选版本与独立计划，父模板／计划不变；再组合下述子项目等待条件验收父项目独立求值。当前只有隔离自动化证据；V245 迁移、权限配置和真实浏览器场景仍须在获准使用的隔离后台执行。

## 相对等待设计样例

对应需求方批准的 LiteFlow 专项及相对等待起算语义，覆盖工前准备、现场工勘、需求分析。`preparation-relative-wait.json` 是可复用的 V2 **设计草稿**，不是已发布快照、数据库种子或已通过浏览器验收的模板。一分钟和半分钟仅用于短时验收，不是业务默认阈值。

只维护版本内条件树；EL 由现有编译器生成。工前准备是组织阶段，无额外手工确认；两个任务分别使用原模块业务事实。权限声明不限制整个节点，原模块仍逐项授权。这里不强制加入决策表、预设 S0～S6、审批或全局规则资产。

## 隔离环境使用

1. 在获准的隔离环境新建专用模板，例如 `LITEFLOW_PREP_WAIT_DEMO`；不要覆盖已有模板、计划或项目。新建同时产生草稿，不发布、不启动运行。
2. 使用现有 `PUT /api/v1/pms/project-templates/{新模板ID}/draft` 保存本 JSON（按环境网关添加前缀）。不直接写数据库，不手写冻结 EL。
3. 在节点侧栏分别选择环境中已发布的工勘、需求分析业务视图；需求分析选择精确的动态表单发布版本。JSON 故意不伪造 `businessViewRevisionId`、`dynamicFormTemplateRevisionId` 或冻结视图快照。保存后核对两个完成条件和需求分析等待条件仍与样例一致。没有这些环境配置时只保留草稿，不能声称业务发布验收完成。
4. 重开条件树并试算；通过实际绑定校验后，由授权用户发布、创建全新示例项目。任务操作必须从项目的交付流程动态阶段任务界面进入，不额外建立或解除业务关联。

## 联合验收路径（待实际执行）

- 新项目：工前准备和现场工勘准入；工勘未完成时需求分析等待结果未知，不激活。
- 新增工勘记录并真实确认：记录自动关联当前任务，任务完成；一分钟内需求分析不激活，到期由现有定时重评激活。
- 需求分析激活：等待从 admittedAt 起算，不从人工开始时间起算。即使时间已到，原模块未真实完成也不能完成任务；满足业务结果和时间后自动完成，阶段按两个任务结果结束，项目按收口规则关闭。
- 返工必须在项目未关闭时执行。可在需求分析尚未完成时预览并选择工勘返工；未选需求分析不隐式重开。新工勘轮次没有完成时间时，等待未知；新记录自动关联最新任务轮次，不复用旧完成标识。工勘新轮完成后重新计时，上一轮到期事件不能推进当前运行。
- 在独立的新项目中选择工勘及需求分析一起返工：两个新轮次重新判定；需求分析激活后自身半分钟等待也重新计时。对比历史，旧规则、旧轮次和未选节点结果不改写。

本样例的自动化测试直接读取同一 JSON，验证设计保存重开、编译冻结、规则发布检查、原生 LiteFlow 试算和当前轮次时间映射。测试中的业务提供方为元数据替身，不代表原模块办理、自动关联、Quartz 投递或真实浏览器已经验收。

## 子项目等待条件样例

`child-project-wait-rule.json` 是父模板／项目计划版本内的一条规则示例，不是全局规则资产或数据库初始化脚本。默认值已由需求方确认：直接子项目、认可正常关闭和异常关闭、全部满足、无子项目时满足。多个关闭类型是可接受结果的集合，每个子项目命中其中一种即可；不要求两种类型都出现。

在专用父模板节点侧栏添加“子项目等待条件”，即带入这些默认值；可切换为全部子孙项目、只认可某一关闭类型、任一满足或无子项目时不满足。规则若用于收口，应与父项目自身交付完成条件组合，不能用等待结果替代仍在办理的工作。跨模板默认复制，不修改已有冻结版本。

联合验收时分别创建正常关闭、异常关闭和未关闭的直接子项目，以及仍未关闭的孙项目：默认条件应认可前两类，未关闭直接子项目应阻止满足；仅等待直接子项目不要求孙项目关闭，切换全部子孙范围后应等待孙项目。空范围、无有效树投影和缺失关闭事实必须区分：明确无子项目按配置求值，后两类始终未知。试算输入每行填写一个关闭状态，明确无子项目填写“无”，留空是事实未提供。

关闭、异常重开、拆分和移动后通过专用 Outbox 重评父规则；重复通知不得重复推进，某个父节点未知不阻止独立节点运行，任何路径均不向子项目下发级联关闭命令。此处是待执行的环境验收步骤；当前仅有隔离自动化证据，未向共享数据库写入样例。
