## 2. 变更范围

| 项目 | 修订010结果 |
|---|---|
| COM地点Owner | 项目办事处部门发生时快照是DeliveryScope唯一地点事实 |
| IMP/AST边界 | `siteId/siteLocationId/locationText/locationResolutionStatus`只属于实施地点，不进入COM范围模型 |
| ERP降级 | 人工输入只形成不可变`PENDING_AUTHORITY`候选，必须与后续ERP Owner事实显式对账 |
| 范围一致性 | 每项目维护单调范围版本；当前范围查询支持期望版本重验 |
| 验收协作 | 项目进入验收阶段及阶段内新范围版本必须绑定精确范围版本 |
| PLT边界 | 历史迁移证据由PLT独立拥有，不挂靠F-COM-001完成 |
| 正式范围 | Requirement数量、目标版本切片、优先级和领域Owner均不变 |

## 3. 历史实现处置

- COM-A与COM-B没有Git继承关系，历史Gate和Done不能相互转记。
- 统一实现以COM-A纵向闭环为基础，仅按Requirement吸收COM-B非重复能力。
- 两个历史Feature模型均标记为被统一规格替代；旧接口只有在替代路径可用后才标记废弃，新能力不得继续建立在旧接口上。
- 本修订不批准ERP网络连接器、历史生产迁移、ACC报告流程、Deployment、SIT、UAT或Release。

## 4. 校验结论

- PRD源文件与冻结快照字节一致，SHA-256一致。
- COM领域规格由PRD重新生成；正式需求数量与Owner未变化。
- Feature Ready由统一F-COM-001规格维护，Implementation状态由master Feature Task维护。
- 本修订不转记任何分支Feature Done；统一实现须在master重新完成构建、MySQL和真实浏览器验证。
