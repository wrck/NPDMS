## I03. P1：最小配置、目录消歧和不可变模板版本

**目标：**不新增多层 Hash，不要求业务 DTO 增加技术版本，先使配置协议可用且不影响旧运行。

| 环节 | 代码/消费者 | 代码与测试出口 |
|---|---|---|
| P1.01 | 复用现有操作目录，登记原权限码；提供纯解析器，按 Owner/实体/权限和必要动作消歧；接入目录 API | 唯一、零匹配、共用权限、多版本、跨 Owner、冲突登记测试；目录查询无副作用；不是运行授权。不要求重写旧 Controller 业务命令。 |
| P1.02 | 新发布格式以模板发布版本保存完整冻结内容；接入编译、发布、读取、复制和计划直接消费者 | 已发布不可更新；准入/准出/收口变化只通过新发布版本生效；旧 Reader/旧 Hash 保持；缺任一新 Reader 不启用新发布。 |
| P1.03 | 最小操作/订阅/政策/页面模型；规则与操作解析结果随模板内联；复用业务输入描述 | 新字段保存重开无损、纯订阅不需操作/页面、NONE/缺失区分；没有新 policyHash/semanticDigest 等字段。 |
| P1.04 | 业务实体输入和 pageUrl 的公共边界校验，直接消费者编译接入 | 不接受任意实体类/任意写 URL；允许有效站内路由和独立编码参数；不原地修改业务 DTO/旧快照；对应测试齐备。 |

P1 完成须四环节全部集成；仅目录或模型存在不算完整新模板发布能力。P1.01 可先提交，旧操作版本在底层兼容保留，配置者不手动配多版本。

## I04. P2：普通业务独立与权威写路径

对 C0 每项先审计 Commands/Access/Provider、版本/表单/文件回调及原测试，再按以下次序交付：

- P2.01 确定业务自身配置来源，复用原已发布业务配置或实例冻结信息；无活动节点仍可解析。
- P2.02 将普通业务与项目办理分流落到真实应用边界，不仅换外层名称；原权限、内容、状态、范围和乐观并发不丢失。
- P2.03 明确 PROJECT_ENTRY_ONLY/ALL_ENTRIES；来源节点只作追溯，不能自动成为普通业务写前置。
- P2.04 复用已有版本/锁/路由保证一个实例一条权威写路径。只有确实不足时补最小切换记录，不默认所有实体加 writerEpoch。

出口：所有声称独立的 C0 操作具备真实独立配置和路径，实际入口/回调测试齐备。只消费结果的能力不必先迁移同 Owner 全部命令。跨域或旧实现保护冲突只阻断相关单元，不伪造已完成。

## I05. P3：按能力提供权威结果

- P3.01 定义真实对象、结果、可选业务修订及有效性语义；保存/上传/报告发布不冒充业务完成。
- P3.02 复用原业务事务/Outbox 和结果回读，明确唯一生产者，普通与受控入口不造两份同义事实。
- P3.03 按能力区分当前查询、指定结果、历史/变化读取；只有承诺历史复用/新结果政策的来源需要稳定边界与分页/游标。
- P3.04 核对删除、撤销、替代、乱序、保留期和旧结果转换；不能填造历史成功或递增计数假装版本。

出口：所声明能力有真实实现和相应测试；缺历史只禁用对应政策，不禁用不依赖它的合法业务操作。结果引用不要求业务提供项目轮次、政策 Hash 或事件 Schema 组合。

## I06. P4：独立订阅与恢复

- P4.01 新结果路径不以 operationContract 为前提；按 Owner/结果类型/对象范围匹配候选。
- P4.02 订阅按模板发布版本、节点局部键和执行轮次区分；不加 selectorHash/policyHash。
- P4.03 有历史能力时冻结本轮形成基线、分页核对、保存 checkpoint 并接续可靠变化流；证明提交边界，不把 MAX(id) 或到达时间当证明。
- P4.04 各目标独立持久恢复；新订阅可核对早于订阅的结果；游标过期明确进入恢复，不跳过缺口。

出口：纯订阅节点无命令/页面也能处理；接收 ACK、候选、证据和完成不混同。无实际来源能力的政策保持不可启用。

## I07. P5：证据政策与正式推进

- P5.01 按模板内联政策实现 REUSE_EXISTING / NEW_RESULT / PINNED_RESULT，历史事实与当前有效分开。
- P5.02 从新路径去掉“对象曾关联过即排除”；以真实结果和本轮政策判定，同对象新修订可再次采纳。
- P5.03 EXACT_ONE / ANY_MATCHING / ALL_EXPECTED 明确，选择和分页不默取第一项，目标集合变化用发布/执行版本解释。
- P5.04 撤销/替代/追溯纠正覆盖未采纳、已采纳未完成、已完成场景；只走正式异常/返工，不直接倒改历史状态。
- P5.05 转换前重验计划、轮次和事实，调用正式完成/准出/收口 Writer；证据与状态转换分别幂等。

出口：业务成功但项目不满足时保留业务回执并等待；所有声明政策的真实能力都有结果/并发/失效测试，不以对象关联代替证据。

## I08. P6：原输入、按需事实与受控事务

- P6.01 复用业务 SaveReq/Command DTO/实体引用，保留原字段约束、权限和归属检查；项目身份放通道上下文，不让普通业务填技术字段。
- P6.02 按需登记 PROJECT/BUSINESS/COMMAND_INPUT/TRANSACTION_RESULT；未声明字段不可访问，不支持事实禁止相应规则。
- P6.03 PRE → Owner → POST 在真实同事务中；POST 读更新后事实；外部不可逆动作/独立事务不得声明原子回滚。
- P6.04 全入口受控仅在真实应用写边界明确声明，覆盖内部/HTTP/系统入口；普通未声明操作不被全局拦截。
- P6.05 复用既有幂等/Scope/回调证明/追踪；同键不同请求冲突，未知结果不换键或新版本；不新增通用校验 Hash。

出口：声明的事实与事务能力实际接线，四类权限/版本/目标/回滚失败测试齐备。已有幂等组件内部摘要不要求业务维护，也不在本阶段重建。

## I09. P7：注册驱动通用分派

P7.01 用 P1 目录和原权限码绑定消除新公共分派的实体 switch；选择出的操作实际仍重验业务授权。
P7.02 对共用权限的多个动作保留原 operationCode，不合成通用 UPDATE；旧适配器的版本由发布结果承接，不默认增加各层独立版本。
P7.03 C0 逐项接线与契约测试；另一个对象形态的测试夹具证明公共代码无需新增实体分支，但夹具不算真实业务迁移完成。
P7.04 独立兼容升级保持旧模板解释；不能静默使用最新处理器。

出口：真实 C0 运行消费者全部使用对应受信绑定；目录存在不代表业务命令/回调已验证。

## I10. P8：页面 URL、实体交互与待办

P8.01 模板直接选择权限/动作、业务实体类型、pageUrl 和必要规则；隐藏技术版本组合，无 Hash 输入框。
P8.02 已登记站内路由安全加载，参数独立编码；URL 不作为 API，拒绝脚本/未登记外域/穿越/主体与凭据注入。
P8.03 页面复用业务输入与现有查询；权限、节点资格、前置、视图只读分轴展示，提交时重新核验。
P8.04 保留未保存表单，普通刷新不销毁客户端；身份变化明确重开，未知操作先恢复；文件写权限不从发布权限推导。
P8.05 待办只投影正式节点状态；重建和打开不产生业务写入，业务回执不等于节点完成。

出口：阶段直接办理、纯订阅、无页面节点和 C0 真实业务页全部覆盖；仅 URL helper 或纯函数不能标 UI 闭环。

### I17.3 R01：打通POST事实发布校验

**现状与修改入口：**`ProjectOperationResultFields`与操作编译/执行器已登记POST结果字段，但`ProjectRulePublicationValidator`仍统一使用`ProjectRuleFields`，导致发布时拒绝`transactionResult.resultCode/objectId/revisionId`。主要修改规则发布校验及其直接元数据消费者，复用现有规则集合和检查点能力判定。

**实施内容：**

1. 根据规则实际使用位置确定字段范围，覆盖模板匹配、收口、节点准入/完成/退出、依赖条件及操作PRE/POST。
2. 覆盖新`execution.operations`与旧`operationContract`中的规则引用，保留旧配置读取方式。
3. 将检查点限制传递到被引用的决策表；共享规则必须满足全部实际使用位置，不能因为其中一个位置为POST就对所有位置开放事务结果字段。
4. 复用明确登记的项目字段及事务结果字段元数据进行字段存在性、值类型和决策表输入校验，不只扩充字符串白名单。
5. 未引用规则不因缺少使用位置自动获得POST能力；保持既有草稿规则保留行为，并在实际引用和发布时准确诊断。
6. 不改变事务事实取值来源，不开放任意属性路径、BUSINESS/COMMAND_INPUT未登记字段或返回载荷反射。

**完成标准：**合法POST条件及决策表能通过发布、冻结与回读；同字段用于PRE、匹配或节点完成时仍拒绝；共享引用和字段类型校验有效；旧已发布版本不被改写。

### I17.4 R02：畸形响应保留原请求恢复能力

**现状与修改入口：**`operationClient.ts`在`transport.submit`返回后直接登记成功并清理隐式请求。主要修改客户端的回执确认位置，必要时接入C0受信适配器的正文校验。

**实施内容：**

1. 调整顺序为“收到响应→验证结果→确认成功→清理待确认记录→刷新展示”。
2. 公共层校验原结果封套的必要字段、值类型、Owner和实体身份，保留字符串ID精度；不通过操作编码前缀推测Owner或返回对象规则。
3. 业务返回正文由对应受信适配器按实际契约校验，并在客户端确认成功之前完成。校验方式随本次请求固定，恢复时不切换到最新适配解释。
4. 创建、复制可能返回新对象；不能统一要求返回对象等于输入对象，也不能为没有修订的业务强制补revisionId。
5. 畸形、身份不符或缺失必要字段时保留原请求、原计划/轮次、原业务版本及原幂等键，显示待确认并阻止新意图越过。
6. 原请求恢复仍执行现有服务端当前授权；恢复请求被拒绝不能被解释为原请求已回滚。刷新展示失败也不能推翻已校验业务成功。

**完成标准：**空对象、缺字段及身份错误不清除待确认记录；合法回执确认后才能发起新操作；创建/复制与普通更新各自遵守真实返回身份；无新增持久化敏感载荷或幂等摘要字段。

### I17.5 R03：完整捕获异步预检前的操作意图

**现状与修改入口：**`operationClient.ts`只复制了input，在异步获取版本和能力后仍读取原intent的操作和对象字段。

**实施内容：**

1. 第一次异步等待前捕获操作编码、对象身份、输入副本、预期版本来源、幂等键及适用的结果校验方式。
2. 意图比较、能力预检和请求构造统一使用捕获结果，不再读取调用方的可变intent。
3. 保留现有异步获取预期版本的入口，捕获其函数引用；首次取得版本后固定到提交封套，重试不再次获取版本或能力来改造原请求。
4. 保留同键异意图冲突、执行中请求合并和未知请求阻止新意图的既有规则。

**完成标准：**预检期间修改原对象的操作、目标或输入，不改变本次提交；指纹所表示的意图与实际提交一致；重试复用原封套和键。

### I17.6 R04：前端精确版本与业务动作登记

**现状与修改入口：**`operationClient.ts`过滤`operationVersion === 1`；`operationHost.ts`硬编码C0动作别名。主要修改这两个文件及已有受信视图适配登记，复用`registry.ts`的精确Owner/实体/组件匹配，不另建通用插件框架。

**实施内容：**

1. 删除客户端固定v1条件，使用冻结执行上下文返回的唯一操作绑定；零匹配、多匹配和不受支持版本均给出明确原因，不默取第一项或最大版本。
2. 版本来源仍由服务端原计划快照决定，前端不增加要求用户填写的技术版本，不新增可绕过服务端冻结选择的请求字段。
3. 将各业务动作与页面动作之间的映射移至对应业务的受信适配登记；公共宿主只按已选适配器读取映射，不维护C0枚举或业务实体分支。
4. 登记保持精确身份约束；现有C0动作完整迁入，未知映射不放行。新增实体只扩展自身适配登记，不修改公共宿主的业务判断。
5. 显示动作继续受Owner权限、项目执行资格、PRE和视图只读共同限制；服务端提交重新授权。文件写权限继续单独处理。

**完成标准：**合法非v1操作可以完成预检与提交；歧义不会静默选择；C0原动作无遗漏；旧轮次未知请求按原版本恢复；新增业务适配不要求修改公共宿主分支。

### I17.7 R05：实际订阅状态与等待原因

**现状与修改入口：**`ProjectTaskQueryService`工作台响应未包含订阅评估信息，`ProjectFlowPanel.vue`仅提供固定说明。复用现有订阅、证据扫描、证据项和规则评估记录，增加共用只读查询并接入任务及阶段消费者。

**实施内容：**

1. 先按现有任务/项目访问权限确定可读范围，再按租户、项目、计划、执行轮次和订阅身份读取记录，不接受客户端指定身份替代授权。
2. 返回必要摘要：订阅局部标识、扫描阶段、满足状态、合格数量、缺失对象和安全原因码；大集合采用有界查询或分页，不能把首页解释为完整集合。
3. 核对订阅配置版本、扫描检查点与读取时可观察的结果边界；旧扫描仅显示待更新，不能显示为当前已满足结论。
4. 区分正在扫描、尚无合格结果、多结果歧义、结果失效、来源不可用和评估待更新。完成/准出原因仅引用可关联到当前身份的既有评估；缺记录时明确“待评估”，不推测原因。
5. 优先扩展现有工作台与阶段查询响应中的可选观察字段，复用同一查询服务；不新增第二套任务状态或完成真值。
6. 页面显示业务提交回执与节点等待原因，刷新仅读取；不得调用扫描器、安装器、业务命令、返工或正式推进Writer。
7. 新查询遵守场景化Query对象和Mapper XML规范；不得用现有带写入或FOR UPDATE的方法实现普通展示查询。优先复用已有存储，不新增状态表。

**完成标准：**任务和阶段能区分实际等待原因，过期证据不误报满足，跨租户/项目/任务访问受限；打开和刷新不产生业务写入；业务成功仍不会被显示为节点已完成。
