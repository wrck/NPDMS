# S4 办理通道与显式执行注解：代码交付记录

> 基准：`089b5a1bba097cb4a11e47f5b7d11b615f900b74`
> 范围：本会话最新实施计划的 S4；代码及自动化测试源码完成，构建和真实环境验证待执行。

新增统一办理端点 `POST /api/v1/pms/project-execution/operations/{operationCode}`，由受信操作分派进入 14 个明确注解的方法；模板不配置 Java 类或任意 URL。原独立 Owner 入口未批量添加强制注解。

办理链路在同一事务中进行安全重放判定、项目/轮次锁定、Owner 动作和对象版本重验、PRE、业务命令、POST 与结果持久化。开始阶段时取得更新后的执行观察并传给业务命令，避免开始动作自身导致旧版本冲突。POST 重新读取业务可能改变的项目事实。

显式入口执行约束，缺失/冲突上下文不降级。功能权限在应用适配层重验，不依赖被绕过的 Controller 注解。原业务服务仍执行内容、状态、范围和版本规则；不复制业务正文或状态机。旧视图守卫仅在精确、服务端已验证的调用作用域内替换，其他旧调用原样委托。

操作目录的运行能力只有在唯一命令适配器和持久结果接收端均已提供时才可用。S5 尚未接入时，新操作契约保持不可发布/运行，不让旧执行器忽略规则。

自动化测试源码覆盖 PRE/POST 失败、Owner 拒绝、版本失配、无运行能力、幂等重放、真实 Spring 代理、嵌套作用域清理、14 个实际注解入口、阶段版本变化以及 JDBC 本地事务回滚。JDBC 测试使用隔离 H2，不替代 MySQL 并发验证。

本阶段未运行 JDK25/Maven/JUnit、API、MySQL 或浏览器测试；没有执行数据库迁移、部署或服务重启。测试源码不等于通过证据。S5、S6 及全阶段自审按顺序接续。
