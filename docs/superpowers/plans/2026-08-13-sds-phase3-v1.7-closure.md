# SDS Phase 3 V1.7 Closure Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 基于 PRD V1.7 补齐 P3-E09 的新增领域实体物理模型和评审证据，完成 Phase 3 独立门禁复审，并在门禁通过后发布 SDS 总册基线。

**Architecture:** 继续将 `project-order-physical-schema.mysql.sql` 定位为历史迁移所需的核心物理子集，不扩张为平台全量模型。V1.7 对象完整性复审的当前候选结果为 61 表（其中 11 张 V1.7 差量）；历史工单/工时空壳和目录快照均已按需求方决策移除。所有派生目录、漂移寄存器、MySQL 执行证据和 Phase 3 证据包必须由当前同一 DDL 哈希生成，不在计划中固定已过期哈希或列/约束规模。

**Tech Stack:** Markdown ADR/SDS、JSON 机器契约、MySQL 8.4 DDL、Python 3 生成与校验脚本、Docker 隔离执行、Git。

## Global Constraints

- 业务语义优先级：PRD V1.7 > 工程链 > SDS > Feature > Plan > Task > Code。
- 当前正式范围为 104 项 V1/V2；29 项 V3 和 9 项 OUT_OF_SCOPE 不得进入当前实施 DDL。
- 旧 `dppms` 只读；不得执行旧库 DDL/DML，不得使用跨数据库 SQL。
- 表名遵循 `<domain_code>_<完整领域对象名称>`；表名仅允许既有 `config`、`sn` 标准缩写，字段只使用已登记且无歧义的受控缩写。
- 跨 Context 仅保存逻辑引用；同一 Context 内聚合关系才允许物理外键。
- 状态字段保存稳定代码；字典不能绕过状态机，数据库 CHECK 不固定可扩展业务状态集合。
- 业务事实、审批历史和明确要求留痕的操作不得删除或覆盖；历史异常进入 `plt_migration_issue` 并保留来源证据。
- 每个任务通过实现复审与任务复审后提交一次；不得主动推送。
