# F-CUS-001 客户主档与本地生命周期前向迁移设计

## 1. 背景与目标

F-CUS-001 要求客户主档由 CUS 上下文独立拥有，目标实现载体为 `pms-module-customer` 与 `pms-module-customer-api`。当前客户主档仍由 `pms-module-project` 中的 `CustomerController`、`CustomerService`、`CustomerMapper` 和 `pms_customer` 表承载，管理端写路径仍为 `/pms/customer/create`、`/update` 和 `/delete`，不满足独立 Owner、稳定公开契约、生命周期治理和禁止双写要求。

本设计采用一次性前向迁移：建立独立 CUS 模块与新物理表，将存量客户按原 ID 迁移到新表，新 `/pms/customers` 路径承担全部当前读写；旧 `pms/cust`、`pms/ast` 及现有 `/pms/customer` 客户入口只保留列表和详情历史读取，停止所有写路由。迁移不设置双写期，不修改已执行 Flyway SQL，不允许旧模块继续写客户主档或客户地点。

## 2. 范围

### 2.1 包含

- 新建 `pms-module-customer-api` 和 `pms-module-customer`。
- 建立 CUS 客户主档、CRM 映射、字段历史、地点引用和 Outbox 物理载体。
- 将 `pms_customer` 存量记录迁移到 CUS 新表并保持客户 ID、编码、租户和审计时间。
- 新建 `/pms/customers` 资源接口，承接创建、查询、平台字段更新、停用、软删除、恢复和地点引用维护。
- 旧客户相关入口仅保留列表和详情读取，所有写操作返回稳定退役错误。
- CRM 权威字段与平台扩展字段分区治理。
- 平台创建客户和临时客户的来源、待对账和冲突规则。
- 组织范围、项目范围、字段权限、联系方式脱敏和跨租户隔离。
- 乐观锁、幂等、引用守卫、审计和 Outbox。
- 前端客户工作台迁移及旧页面只读化。
- 单元测试、契约测试、真实 MySQL、并发和浏览器验收。

### 2.2 不包含

- CRM 连接器、同步调度、对账、重试和自动合并。
- 客户服务等级维护、客户联系人完整迁移和用户资产库聚合。
- 项目或设备客户归属关系写入。
- AST Address、Site 或 SiteLocation 实体维护。
- Deployment、SIT、UAT、Release 和生产历史迁移执行。

## 3. 核心决策

### 3.1 独立 Owner 与一次性切换

CUS 新模块是客户身份、字段、来源、生命周期和地点引用的唯一写 Owner。PROJ、AST、INT 和其他上下文只能依赖 `pms-module-customer-api`，不得依赖 CUS 的 Service、Mapper、Repository 或业务表。

迁移完成后：

- 新 CUS 表是当前客户事实的唯一写入位置。
- `pms_customer` 及旧 AST/CUST 客户载体只用于历史读取。
- 不提供新旧表双写、反向同步或隐式写代理。
- 架构测试必须阻止旧模块对 CUS 新表和旧客户表执行写操作。

### 3.2 路由策略

新管理端路径采用复数资源语义：

- `GET /pms/customers`
- `POST /pms/customers`
- `GET /pms/customers/{id}`
- `PUT /pms/customers/{id}`
- `POST /pms/customers/{id}/actions/disable`
- `POST /pms/customers/{id}/actions/delete`
- `POST /pms/customers/{id}/actions/restore`
- `GET/POST/PUT /pms/customers/{id}/locations`
- `GET /pms/customers/{id}/projects`
- `GET /pms/customers/{id}/devices`
- `GET /pms/customers/{id}/history`

对外正式语义仍是规格冻结的 `/api/v1/pms/customers`，由当前网关统一补充 `/api/v1` 前缀。

旧 `pms/cust`、`pms/ast` 以及现有 `/pms/customer` 客户入口只允许：

- 列表或分页读取。
- 单条详情读取。

旧入口的创建、更新、删除、启停、恢复和地点维护全部停止。写请求返回统一错误码、只读退役说明和新路径，不转发到新应用服务。旧读取响应增加只读来源和数据截止时间，避免调用方误认为旧入口仍是当前写模型。

## 4. 模块设计

### 4.1 `pms-module-customer-api`

提供稳定跨上下文契约：

- `CustomerMasterDataApi`：CRM 权威字段受控写入、客户稳定查询和状态查询。
- `CustomerReferenceGuardApi`：供客户删除流程或其他上下文检查客户引用。
- `CustomerQueryApi`：按 ID、编码和批量 ID 查询必要客户摘要。
- DTO 和命令对象：客户来源、版本、状态、字段切片和引用守卫结果。

API 模块不暴露数据库实体，不依赖实现模块。

### 4.2 `pms-module-customer`

按职责拆分：

- `controller.admin.customer`：新资源控制器和旧只读兼容控制器。
- `domain.customer`：客户聚合、来源、状态、字段 Owner 和生命周期规则。
- `service.customer`：创建、更新、停用、删除和恢复应用服务。
- `service.location`：AST 地点引用维护。
- `service.guard`：聚合 PROJ、AST 和已登记 Owner 的引用守卫。
- `service.history`：字段历史和生命周期历史查询。
- `service.integration`：公开 API 实现。
- `dal.dataobject`、`dal.mysql`：CUS 独立持久化载体。
- `outbox`：客户事实事件的事务内写入与平台投递协作。

单个应用服务只编排一个业务用例，领域规则不依赖控制器或数据库实现。

## 5. 数据设计

### 5.1 客户主表

新客户主表保存：

- 稳定 ID、租户 ID、客户编码。
- CRM 权威字段：名称、CRM 等级、CRM 状态、归属销售和正式联系方式副本。
- 平台字段：标签、服务偏好、交付备注及批准扩展字段。
- 八个市场组合编码和名称字段。
- 来源类型、来源键、来源版本、数据截止时间和同步状态。
- 生命周期状态、待匹配标志、临时创建原因。
- 乐观锁版本、创建更新审计和软删除标记。

客户编码在租户内唯一，软删除不释放编码。CRM 当前映射在租户内保持一对一。

### 5.2 辅助表

- 客户外部映射表：保存 CRM 当前映射及历史映射。
- 客户字段历史表：只追加保存字段 Owner、前后值摘要、来源和操作信息。
- 客户地点引用表：保存 AST Address/Site 稳定 ID、类型、来源版本和有效区间。
- `cus_market_relation`：保存 CRM 同步的市场部、系统部、拓展部、子行业合法四级组合；客户只保存八个编码/名称快照字段，不保存或依赖 `relationId`。
- 客户权限切片表：保存用户或角色的办事处与市场行业复选范围；办事处统一使用 `department_code`，名称仅作展示快照。
- 客户 Outbox 表或平台 Outbox 关联：保存 `CustomerUpdated` 等事件。
- 幂等记录使用平台命令能力；若业务键需要独立索引，则在 CUS 表保存 operationId 关联。

### 5.3 办事处与市场行业字段裁决

办事处由 SYSTEM 的 Department 表达。客户主档只保存 `department_code/department_name`：`department_code` 是跨模块关联、授权和查询的唯一稳定标识，必须精确对应当前租户有效的 `system_dept.code`；`department_name` 仅为展示快照。CUS 不保存 `department_id`，也不新增 `office_code`、`office_department_code` 或 `dept_no` 等并行名称。

市场行业分类遵循 ADR-0021，由 `market_code/market_name`、`system_code/system_name`、`expend_code/expend_name`、`industry_code/industry_name` 四级八字段组成。四级值必须精确命中 `cus_market_relation` 中的有效合法组合，禁止根据名称猜测编码或将四个维度解释为组织部门。

### 5.4 前向迁移

新增 Flyway 版本完成：

1. 创建 CUS 新表、索引和约束。
2. 从 `pms_customer` 复制存量数据并保持原 ID。
3. 将旧地址文本保存为迁移快照，不伪造 AST 稳定引用。
4. 为旧记录标记明确来源和迁移 operationId。
5. 校验源目标数量、ID 集合、租户、编码和关键字段一致。
6. 初始化必要的菜单、权限和新前端入口。
7. 保留旧表供历史读取，不删除或改写已执行迁移。

迁移重复执行必须安全；发现编码、租户或 ID 冲突时失败并输出可定位记录，不静默覆盖。

## 6. 业务流程

### 6.1 创建

- 调用方必须提供幂等键。
- 服务端先校验租户、权限和数据范围。
- 校验客户编码与 CRM 当前映射唯一性。
- 业务身份只能创建 `PLATFORM_CREATED` 或 `PLATFORM_TEMPORARY` 客户。
- 临时客户必须填写原因和待对账标志，不能提交 CRM 来源键或版本。
- 在同一事务中写客户、初始历史、审计和 Outbox。
- 同键同请求返回首次结果；同键异请求失败。

### 6.2 更新

- 请求必须提供幂等键和 `If-Match`。
- 业务身份只能修改平台字段；CRM 字段存在正式映射后保持只读。
- CRM 集成身份只能通过 `CustomerMasterDataApi` 更新 CRM 字段，不能修改平台字段。
- 更新成功追加字段历史并递增版本。
- 旧版本、越权字段和跨租户请求不产生副作用。

### 6.3 停用、删除和恢复

- 停用阻止新项目、设备和联系人关系使用该客户，但保留历史展示。
- 删除前并行调用已登记引用守卫，但最终结论采用失败关闭：有效引用、未知、超时或不可用均拒绝删除。
- 删除是软删除，保留编码、映射、地点引用、字段历史和审计。
- 恢复使用原 ID、编码和映射，必须提供原因、版本和幂等键。
- 并发更新、删除或恢复最多一个基于当前版本成功。

### 6.4 地点引用

CUS 仅保存 AST Address/Site 引用。写入前调用 `AssetLocationApi` 校验：

- 引用存在。
- 租户一致。
- 类型为 Address 或 Site。
- 来源版本仍有效。
- 状态允许建立新引用。

CUS 不创建、更新或停用 AST 地点实体。

## 7. 权限与数据范围

权限拆分为查询、创建、更新、删除、恢复、敏感字段查看和导出。

- 服务经理可在授权客户范围创建和维护平台客户，并按权限删除或恢复。
- 项目经理只可在明确授权范围创建项目所需客户和维护允许的平台扩展字段，不可删除客户。
- CRM 集成身份只可调用 CRM 字段写入契约。
- 联系方式由服务端按字段权限返回明文、脱敏值或不返回。
- 列表、详情、导出、复制和审计查询使用相同裁剪规则。

客户数据范围由一个或多个独立权限切片组成。每个切片包含 `departmentCodes`、`marketCodes`、`systemCodes`、`expendCodes`、`industryCodes` 五个可复选维度；维度内多个值取并集，维度间取交集，多个切片之间取并集。四级市场行业选择必须经 `cus_market_relation` 裁剪为合法完整组合，不能把不同切片的维度集合展平后产生未授权交叉组合。

每个维度支持 `ALL`、`SELECTED`、`NONE` 三态：`ALL` 不限制该维度，`SELECTED` 使用非空编码集合，`NONE` 使整个切片不可用。`super_admin`、`tenant_admin`、`crm_admin` 在没有显式范围配置时五个维度默认 `ALL`；其他业务角色缺少任一必要维度授权时返回空结果。显式授权配置优先于管理员默认值，允许管理员降权。

分页和详情先过滤租户，再应用服务端解析的权限切片，最后应用用户提交的业务筛选。前端筛选只能缩小权限范围，不能提交或扩大授权集合；合法权限切片为空时必须直接返回空，不得因省略 SQL 条件扩大查询。创建和更新同样校验目标 `departmentCode` 与四级市场行业组合是否落在操作者有效权限切片中。

## 8. 跨域协作

- PROJ 拥有项目当前客户及历史归属；CUS 通过公开查询获取项目摘要。
- AST 拥有设备当前客户、历史关系和地点实体；CUS 通过公开查询获取设备摘要并校验地点。
- CUS 不写 PROJ 或 AST Repository、Mapper 和业务表。
- Owner 查询不可用时返回不可用切片和数据截止时间，不将缓存数量标记为完整事实。
- 删除守卫契约统一返回 `CLEAR`、`REFERENCED`、`UNKNOWN` 等明确状态。

## 9. 前端设计

新客户工作台只调用 `/pms/customers`，包含：

- 客户组合分页和状态筛选。
- 创建与编辑抽屉。
- CRM 权威字段只读区及来源状态。
- 平台扩展字段编辑区。
- AST 地点引用区。
- 项目与设备摘要区。
- 停用、删除和恢复操作。
- 字段历史与生命周期时间线。
- 临时客户和待匹配状态提示。

旧客户页面只保留列表和详情入口：

- 展示“历史只读入口”标识和新工作台链接。
- 不渲染创建、编辑、删除、启停和恢复按钮。
- API 客户端不再导出旧写方法。
- 即使绕过前端直接调用，服务端仍拒绝旧写请求。

页面在 320、768、1024 和 1440 宽度下无页面级横向溢出。

## 10. 错误处理与可观测性

新增稳定错误语义：

- 旧路由只读退役。
- 客户编码冲突。
- CRM 当前映射冲突。
- CRM 权威字段不可由业务身份修改。
- 临时客户来源非法。
- 客户版本冲突。
- 引用守卫阻止删除。
- 引用守卫未知或不可用。
- 地点不存在、跨租户、类型非法或版本过期。
- 幂等键异请求冲突。

审计记录操作人、身份类型、operationId、traceId、来源、动作和前后值摘要；敏感联系方式不写明文。指标覆盖创建、更新、生命周期动作、版本冲突、删除守卫、旧写路由调用和 Outbox 投递。

## 11. 测试设计

### 11.1 单元测试

- 客户身份、唯一性、字段 Owner 和临时来源规则。
- 生命周期状态转换和软删除恢复规则。
- 地点引用类型及版本规则。
- 联系方式脱敏与字段权限。

### 11.2 契约与架构测试

- 新 `/pms/customers` 请求响应契约。
- 旧路由列表、详情可读及全部写操作失败。
- `CustomerMasterDataApi` 和 `CustomerReferenceGuardApi` 契约。
- PROJ、AST 只依赖 customer API。
- 旧 project/ast 客户服务不能写新表或旧客户表。
- 前端旧 API 不再暴露写方法。

### 11.3 MySQL 与并发测试

- 租户内客户编码唯一和跨租户隔离。
- CRM 当前映射唯一。
- 软删除不释放编码。
- 恢复保持原 ID 和映射。
- 幂等重放不重复客户、历史、审计和事件。
- 旧版本并发更新、删除和恢复只有一个成功。
- 存量迁移数量、ID 和关键字段一致。
- 引用守卫失败时事务无成功副作用。

### 11.4 浏览器验收

- 创建平台客户和临时客户。
- CRM 字段只读和平台字段更新。
- 组织与项目范围负向验证。
- 联系方式脱敏。

- AST 地点引用及过期版本提示。

- 刷新后数据持久化及四档响应式。
