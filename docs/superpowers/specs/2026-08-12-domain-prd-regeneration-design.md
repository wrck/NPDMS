# 13领域PRD格式需求重建设计

## 1. 目标

依据最新《PRD-项目实施交付管理平台》和《PRD与13领域FR差异审查报告》，重新生成13份领域需求规格。领域文档保留领域编码和文件命名体系，正文以PRD当前需求格式为唯一业务规格表达，不复用旧领域规格的模板化正文。

## 2. 权威来源与取舍

1. PRD中的V1/V2正式需求块负责业务场景、规则、角色、数据、异常、依赖和验收标准。
2. 差异报告负责领域Owner、版本边界、确认结论、V3方向和OUT_OF_SCOPE处理。
3. 领域编码、领域名称和FR来源编号仅用于责任归属与历史追溯，不反向覆盖PRD业务细节。
4. 已确认排除项仅保留在领域文档的排除追溯表，不生成可开发的详细需求。

## 4. 文档结构

每份领域文档包含：领域目标与边界、需求清单、PRD格式的逐项详细需求、跨领域输入输出契约、V3演进索引、OUT_OF_SCOPE排除追溯和领域验收门禁。逐项详细需求原样保留PRD的属性表、业务场景与需求描述、核心业务规则、用户故事、业务验收标准、数据字段、权限与数据范围、异常降级留痕和依赖关系。

## 5. 版本与状态边界

- V1/V2需求保留完整业务规格和验收标准。
- V3仅保留范围、前置条件和演进方向，不生成当前验收承诺。
- 核心生命周期状态采用“初始化可扩展状态定义+受控状态机”；领域文档描述业务状态语义，PLT提供通用机制。
- 维保经营、续保、日报周报和平台通用割接时效继续作为排除项，不进入正式需求。

## 6. 生成与校验

生成器只读取PRD和差异报告，按上述归属规则提取PRD需求块并写入13个领域文件。校验必须证明：PRD正式需求无重复或遗漏、每项仅有一个领域Owner、V3和排除项未混入正式需求、状态机/权限/回访/工单版本边界在对应领域可见、领域文件不含旧模板的待确认填充。
