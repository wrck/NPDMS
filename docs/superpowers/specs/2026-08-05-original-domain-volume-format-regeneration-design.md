# 13 领域需求文档按原分卷格式重建设计

## 1. 目标

在保持 13 领域 Owner 划分不变的前提下，取消当前领域文档采用的通用 SRS 12 章结构，改为复用原 8 个需求分卷的 Markdown 结构重新生成 13 份领域需求文档。

本次不使用 `create-software-spec-docs` 技能及其通用 SRS 模板或模板校验器。

## 2. 文档结构

每份领域文档采用以下固定结构：

1. 领域目标与边界
2. 需求清单
3. 详细功能规格
4. V3 演进范围（仅存在演进项时输出）
5. 领域验收门禁

文档头保留原分卷使用的简要元数据：文档状态、实现模块或实现边界、技术约束、正式需求数和 V3 演进数。

## 3. FR 单元结构

每项正式 FR 使用二级标题，并保持原分卷的以下内容与顺序：

- 用例编号
- 来源需求
- 所属版本
- 优先级／复杂度
- 参与角色
- 业务场景
- 来源标识
- 业务目标
- 前置条件
- 主流程
- 分支与异常
- 状态流转
- 业务规则
- 数据要求
- 权限、通知与审计
- 输出与后置条件
- 验收标准

生成过程直接迁移现有来源分卷的 FR 内容，不将其扩展为“基本信息、输入、业务留痕”等通用模板结构，不新增无来源字段。

## 4. 领域归属

- 继续使用已确认的 13 领域唯一 Owner 映射。
- FR、BR、DR、AC 编号保持不变。
- `FR-ENG-021 到货签收管理` 唯一归属 `IMP 现场实施`。
- `AST 资产管理`只消费签收、安装等实施结果，不复制到货签收规则和验收标准。
- 跨领域页面编排、数据来源和事件关系继续由总体规格及迁移矩阵定义，不重复写入各领域 FR。

## 5. V3 范围

- V3 条目只在所属领域的“V3 演进范围”中出现一次。
- V3 条目不生成正式详细 FR，不纳入当前开发验收。
- 无 V3 项的领域不输出空的演进章节。

## 6. 生成与校验

- 修改现有迁移生成器，使其输出原分卷格式。
- 校验 13 份领域文档均具有原分卷固定章节。
- 校验 145 项正式 FR 唯一、完整，7 项 V3 演进内容唯一。
- 校验所有 BR、DR、AC 跟随所属 FR 且无跨领域重复定义。
- 校验到货签收仅在 IMP 中完整定义。
- 更新迁移测试和验证报告，不再运行通用 SRS 模板校验。

## 7. 不变范围

- 不调整 13 领域划分和 Owner 迁移矩阵。
- 不修改原始需求 Excel、HTML、DOCX、DDL 和用户未跟踪资料。
- 不改变总体规格中的项目交付、割接和服务工作台编排。
- 除技术选型外，业务文档继续统一使用“基础平台”称谓。

## 8. 完成标准

- 13 份领域文档均恢复为原分卷格式。
- 145 项正式 FR 覆盖率 100%，唯一 Owner 重复数为 0。
- `FR-ENG-021` 在 IMP 中定义一次，在 AST 中定义零次。
- 生成器、校验器和相关自动化测试通过。
- `git diff --check` 通过，用户未跟踪资料未被纳入变更。
