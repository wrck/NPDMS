## D00. 依据与替代范围

本版以当前会话已提交 v1.0、用户提供的调整方案和最新明确要求为依据：直接复用权限码对应操作、复用实体/业务输入、配置页面 URL；不增加多层校验 Hash，使用版本。最新要求替代 v1.0 中新增完整语义哈希、三类指纹、独立政策/选择器摘要及默认多重操作版本的设计。

v1.0 原文及验收定义保留于 Git 提交 `75dfa7d98cade30f708759720400e6b8c01e5ec0`。本版不是声称旧实现已删除这些字段。历史快照、现有 Git 标识、文件完整性和原幂等组件内部摘要不在本次批量删除范围。不得再新增此类摘要作为业务接入、模板配置或新契约的必填要求。

仍然保持：业务独立、按需同步控制、独立结果订阅、可配置证据采纳、视图和待办不持有第二套状态机。物理迁模块、复制全领域、换框架、改 PRD 业务语义不在本次范围。只依据当前代码盘点 C0，不导入其他会话记忆或另一分支迁移清单。

## D01. 不变量与完成口径

1. 普通独立业务以自己的配置、权限、状态和事实为准，不因仅有 projectId 就寻找活动任务。
2. 项目资格与业务权限取交集；权限码、页面可见、POST 成功都不能单独证明节点完成。
3. 操作、订阅、证据、呈现分别可选；纯订阅无需命令处理器、页面或虚拟任务。
4. 对象、结果、事件、项目证据不是同一身份；同对象的新结果可按政策再次采纳。
5. PRE/POST 在业务事务内；完成/准出在提交后的项目事务判断。业务提交后项目失败不得倒报业务回滚。
6. 一个已发布模板版本冻结全部执行配置；同版本不原地改规则、不在运行时获取最新预设。
7. 新实体接入不增加公共控制器或宿主的业务实体分支；业务差异留在受信适配边界。
8. 旧轮次、迟到消息和不确定请求不能偷偷换成新轮次、新版本或新幂等键。
9. 历史授权、当前角色和动态事实不冻结成永久许可。
10. 代码/测试源码齐备、已提交、测试通过、实际验收分别记录；确定缺陷不能记成仅待验证。

## D02. 职责和三条路径

| 职责 | 负责 | 不负责 |
|---|---|---|
| 业务 Owner | 类型化命令、业务配置、权限/范围、不变量、业务版本和结果 | 为通用接入提供项目轮次、政策摘要或技术 Hash |
| 适配边界 | 映射原权限码/操作/输入；补技术事件身份；明确能力支持范围 | 复制业务状态机、伪造业务修订或完成事实 |
| 项目执行中心 | 准入、项目额外约束、证据政策、正式状态推进 | 解释业务内部表或直接完整更新业务实体 |
| 业务视图 | 按 URL/路由展示、选实体、显示动作、保护编辑 | 依据 URL、HTTP 成功或页面打开完成节点 |
| 待办 | 投影当前义务、责任人、阻塞原因和入口 | 另建完成真值 |

普通独立入口 → 业务授权/配置 → 原业务命令与权威结果。
项目办理入口 → 真实身份/幂等 → 业务授权和节点资格 → PRE → 类型化业务命令 → POST → 业务与结果同事务提交。
已提交结果 → 独立订阅 → 证据判断 → 正式完成/准出 → 待办投影。

`PROJECT_ENTRY_ONLY` 与 `ALL_ENTRIES` 来自开发侧受信登记。全入口受控是明确例外，不因模板新增绑定而扩大到其他项目。项目入口缺上下文或校验失败不转独立入口。独立性按能力/操作验收，不要求迁完 Owner 全部业务。

## D03. 最小身份与版本：说明来源，不要求全业务加字段

| 信息 | 谁维护/何时必需 | 配置人员是否填写 |
|---|---|---|
| 模板身份与发布版本 | 模板发布服务；冻结节点、规则、操作选择、订阅、政策及页面配置 | 只选择/发布模板，不手配内部版本组合 |
| 草稿并发版本 | 原模板 CAS | 系统携带 |
| 权限码 | 复用原业务权限体系；作为授权/选择入口 | 可选择权限对应动作 |
| 操作标识 | 权限码在当前 Owner/实体内唯一对应操作时可省略；共用权限时使用原动作标识消歧 | 选择动作，系统保存；不再发明一套同义编码 |
| 已有接口版本 | 仅不兼容语义需要；由登记和发布服务解析并冻结，复用旧适配器已有版本 | 不默认新增 operationVersion/capabilityVersion 等多套必填项 |
| 实体身份 | 业务自己的实体类型/ID；创建时无 ID；服务端验证归属 | 选择/传入业务对象，不补 taskId |
| 业务修订/并发依据 | 有修订就复用；并发可用原行版本、ETag、条件更新或锁定重验 | 客户端保留实际看到的预期，不伪造统一整数版本 |
| 结果身份及有效性 | Owner 已有结果/修订/状态；适配只能转换真实事实 | 无结果历史就限制相应政策，不补假版本 |
| 项目计划/节点/轮次 | 项目执行中心 | 项目办理通道自动关联，不侵入普通实体 DTO |
| 事件/幂等/追踪身份 | 现有基础设施/适配层；同一次重试复用 | 不进入模板业务表单 |
| 订阅/证据身份 | 执行轮次、模板发布版本、节点局部键、真实结果 | 不再增加 selectorHash/policyHash/identityVersion |

字符串 ID 保持无损。格式版本仅用于真实序列化兼容，不作为每个业务输入必须填写的字段。相同事实换表示格式不产生新的业务结果身份。

## D04. 五类配置与最小配置体验

五类是逻辑职责，不是五套必建服务/表。节点和版本内局部键引用自己的规则、订阅和政策；发布时内联完整内容。

| 配置 | 主要内容 | 独立性 |
|---|---|---|
| 节点 | 依赖、准入、完成、准出、正式返工行为 | 阶段不伪造任务 |
| 操作 | permissionCode、必要时原 operationCode、对象选择、PRE/POST | 不自动绑定为完成证据 |
| 订阅 | resultType、Owner 对象范围、证据政策、数量/选择方式 | 没有操作或页面也合法 |
| 证据 | 复用/本轮新结果/指定结果、历史/当前有效、失效处理 | 不按 objectId 历史关联一刀切 |
| 呈现 | 内部 pageUrl、允许参数映射、只读和动作展示 | 不承担命令路由或业务授权 |

明确无附加规则使用 NONE；未知配置、引用缺失、事实不可用不变成 NONE。历史无新字段按历史格式读；新格式不能通过删除字段退成旧格式。

示例仅说明配置方式，不是新 API 或生产种子：

```json
{
  "entityType": "SITE_SURVEY",
  "operations": [{
    "permissionCode": "pms:eng-site-survey:update",
    "operationCode": "SOL.SITE_SURVEY.CONFIRM",
    "pre": {"mode": "RULE", "ruleKey": "ready"},
    "post": {"mode": "NONE"}
  }],
  "presentation": {"pageUrl": "/pms/delivery-business/site-survey", "query": {"projectId": "$project.id"}}
}
```

这里 CONFIRM 与 UPDATE/REJECT/ARCHIVE 共用权限时，不能只凭 update 权限选第一项操作。示例 pageUrl 必须经实际路由核实后才可发布。上述正文没有新的 Hash 或默认操作版本。

## D05. 发布版本、完整快照与旧格式

发布顺序：锁定草稿及 CAS → 校验引用/实际能力 → 解析全部规则与决策表闭包 → 保存完整不可变快照 → 分配/确认新的模板发布版本 → 原子提交。

完整快照包含准入、完成、准出、适用、收口、操作规则、订阅选择、证据政策及行为相关配置。不能只冻结 ruleKey 而继续读取可修改的规则。代码新增实际执行字段时必须加入冻结/回读测试，不再要求额外摘要投影。

同一个 `templateId + publishedVersion` 只对应一份发布内容。禁止更新已发布 JSON；复制产生新草稿，修订产生新发布版本；已运行项目继续引用原版本，升级经过显式计划变更。当前用户权限、实时业务值、游标当前位置不冻结成配置。

旧 executionSchemaVersion/compilerVersion/snapshot_hash 按原解释器兼容。新版本路径采用明确格式版本且不新增执行/呈现/产物 Hash。尚未接通新 Reader、数据库可空约束或直接消费者前，不删除公共旧哈希方法、不发布半接线新快照。历史算法继续使用不表示本轮又增加业务 Hash 要求。

IR-01 的新整改是“完整版本冻结及不可变发布”，不再建设完整语义 Hash。未知格式和同版本覆盖均拒绝；不得读失败后猜测 legacy 或切到 latest。

## D06. 权限与操作的受信对应

权限不是动作的天然唯一键。目录提供真实权限码与操作映射；配置界面在 Owner/实体范围内选择。仅当恰有一个可绑定操作时，允许用权限码简写；匹配零项/多项必须返回明确原因，不根据名称前缀、方法顺序、版本大小猜测。

共用权限的操作保留已有 operationCode。底层已有多个版本时，由明确部署预设选择供新模板绑定的实现，冻结入模板；没有明确预设就拒绝歧义，不让配置人员配版本组合，也不硬编码取最大版本。旧精确绑定保持不变。

受信目录登记类型化处理器、原权限/对象范围检查、输入类型、控制范围和实际事实能力。模板不能填写 Bean、反射方法、SQL 或调用 URL。公共宿主消费动作描述，不维护另一份业务动作权限表。

按需能力：当前事实读取、独立命令、不可变结果、历史读取、新结果基线分别声明。只有页面不算事实源；没有历史能力不妨碍合法独立操作/页面，只禁止无法支持的证据政策。权限查询和目录查询不执行任何业务写入。

## D07. 实体直接传入、事务及重试

“传实体”优先复用原业务 SaveReq/Command DTO 或实体引用；同进程可传已有受类型约束对象。HTTP 不接受客户端类名、任意实体反序列化或无差别 updateById。租户、主体、归属、可写字段、期望版本和状态由原业务代码校验。

项目上下文放在独立调用封套/服务端 Scope，不批量塞进普通实体。业务输入来源于用户原意图；异步预检不能读被随后修改的 operation/object/input。页面参数不是授权凭据。

PRE/POST 只附加规则；POST 必须在同一可回滚事务内，重新读取可能被业务修改的事实。独立新事务、跨服务及外部不可逆副作用不能靠注解冒充原子回滚。Scope 只承接同步源/成功派生对象回调，跨线程与过期证明无效。

继续复用已有幂等机制。原组件内部使用摘要可以保持，但不新增摘要规范/字段或要求业务提供。已发送结果不确定时保留原输入、原版本和原键；同键不同输入冲突；恢复仍执行当前读取授权，不能先换新轮次/新键。畸形成功响应不清除待确认信息。

## D08. 事实与检查点

复用原规则引擎，按需提供 PROJECT、BUSINESS、COMMAND_INPUT、TRANSACTION_RESULT 四类事实。业务字段须由 Owner 公开，不使用任意属性路径/反射读取敏感字段。项目事实与业务对象不会因实现方便统一成一个模型。

前置只使用此时已可取的事实；后置可使用本事务结果。异步结果/另一个节点未来完成不支持同步 POST。固定 true、NONE、确定不满足、UNKNOWN/ERROR 分开。权限和字段访问始终实时校验。

没有某类事实能力时，只禁止依赖它的规则，不要求所有业务补齐四类空接口。业务不变量不能在模板中关闭。

## D09. 独立结果订阅

业务成功在原事务记录真实结果并使用既有 Outbox；消息只是通知，不是自动完成证明。结果身份复用不可变结果 ID、修订或原业务可定位依据；适配可生成事件/追踪身份，不能用 UUID 伪造业务完成。

结果接收与操作绑定独立。纯订阅节点不要求 operationContract、页面或写处理器。接收事件、每目标证据和正式状态转换分别幂等；源事件曾接收不阻止后来订阅核对相同结果。

支持历史时：先持久化订阅和本轮基线，获得 Owner 可证明的稳定已提交边界，分页核对并保存 checkpoint，再接续变化流；扫描与事件可重叠但不漏。自增 MAX(id) 或消息到达时间不自动证明提交顺序。

没有可靠历史/游标时，可声明仅当前事实能力；不启用有保证的 NEW_RESULT 或无缺口历史补采。不造历史成功或强制所有业务建设相同结果日志。游标过期进入可恢复状态，不直接跳到现在。

## D10. 证据政策

首批获取方式：REUSE_EXISTING、NEW_RESULT、PINNED_RESULT。有效性区分 HISTORICAL_FACT 与 CURRENT_VALID。选择使用 EXACT_ONE、ANY_MATCHING、ALL_EXPECTED；多匹配不得默取第一项。指定结果不能自动替换为最新；全部满足必须知道完整目标集合，不以一页数据代替。

NEW_RESULT 根据本轮冻结的可信形成基线判定，不要求新建对象。同对象新修订可产生新结果；相同结果的新事件不是新结果。基线来自已声明业务能力，无此能力不能发布该政策。

证据记录引用模板发布版本、节点/订阅局部键、执行轮次和真实结果；不新增 policyHash/selectorHash。事实撤销或替代时，未完成节点重新等待或选替代；已完成节点记录影响并走正式异常/返工协议，不直接回写未完成、不删历史。追溯纠正应影响历史事实判断，不能被 HISTORICAL_FACT 忽略。

正式推进前重验计划、轮次、业务结果有效性和证据预期。只能调用现有正式 Writer。当前有效的强一致保证只在实际资源支持时提供；一次远程查询不是同事务断言。

## D11. 项目推进和待办

订阅候选、业务回执和待办均不是状态真值。阶段可直接办理、纯等待或聚合，不创建虚拟 taskId。业务成功但完成/准出不满足时保留成功回执，显示等待原因。一个目标失败不丢其他目标，不回滚已提交业务。

待办只展示节点/轮次、责任人、入口和阻塞原因；重建投影不触发业务命令。旧目标事件不改投新执行轮次，返工由正式引擎生成新身份。

## D12. 页面 URL 配置与交互

pageUrl 是页面展示地址，不是提交接口。首批只支持站内可解析的已注册路由/受控组件；动态查询参数通过独立键值映射编码。拒绝 javascript/data 协议、协议相对地址、反斜杠/路径穿越、未登记外域及把 token/主体/租户写进 URL。这里保留的是必要路由与权限校验，不是 Hash 校验。

页面加载复用原路由授权；权限码不能代替数据范围。外部页面可在未来明确配置成链接，但不被视作已经支持嵌入编辑、实体桥接或受控提交；未经声明不建立通用 iframe 消息授权。

直接实体输入与页面展示分开：URL 可以带业务 ID 供授权读取；大对象、敏感正文和项目令牌不放查询串。页面可继续复用自己的 API，受控办理由显式已登记集成接入，不通过 URL 推测写方法。

刷新能力只更新操作/原因/只读观察，不重置未保存表单。轮次或解释变化需明确重开；存在未确认命令时先恢复。业务发布与文件写权限分别检查。视图停用限制当前呈现，不使业务结果或其他合法独立入口自动失效。

## D13. 新旧权威路径

旧实例/旧 API 默认保留原语义，新路径按服务端契约和实例归属选择。业务复制、修订和切换保持可追溯的一份当前真值；优先复用已有原子条件/锁/版本，不默认给所有实体再加 writerEpoch。

只有实际发生双写权切换且原版本机制无法隔离在途请求时，才增加最小技术记录，并说明不能复用的原因。新校验/新能力失败不得尝试旧写接口。未知提交先恢复；切换/回滚保留证据、结果和幂等归属，不仅翻开关。

## D14. 存储、安全和运维

优先复用原模板版本、计划/执行契约、业务修订、Outbox、关联和幂等表。不为逻辑契约数量机械建表。新增字段/迁移必须在当前阶段证明必要性；提交迁移代码不授权运行迁移。

错误沿用原错误码体系并附安全 reason：权限拒绝、版本冲突、对象歧义、规则未知、事实不可用、回执待确认分别显示。仅输出所需事实/证据摘要，保护敏感正文；“摘要”作为展示概括不代表加技术 Hash。

## D15. 简化决策与边界

| 决策 | 采用 | 拒绝 |
|---|---|---|
| 完整性 | 不可变模板发布版本和完整快照 | 新增三类 Hash 及政策/选择器摘要 |
| 操作选择 | 原权限码 + 必要的已有动作消歧 | 权限共用时选第一条或全放行 |
| 业务接入 | 原 DTO/实体引用、已有版本/并发机制 | 所有实体强制项目字段/修订/事件版本 |
| 页面 | 已登记站内 pageUrl + 安全参数映射 | 把展示 URL 当任意业务写接口 |
| 能力 | 按需提供、只禁用不支持的政策 | 空 Provider、假版本、全业务统一重构 |
| 演进 | 新语义在显式新路径实现，旧历史可读 | 直接覆盖已发布版本或自动降级 |

## D16. 接口示意

```text
resolveBinding(owner, entityType, permissionCode, optionalExistingOperationCode)
  -> 唯一受信操作或明确歧义；不产生业务授权

publish(templateId, expectedDraftVersion)
  -> 新 publishedVersion + 完整快照；旧版本不可修改

executeBoundOperation(serverExecutionContext, existingTypedBusinessInput)
  -> 原业务授权/并发/状态校验 + 模板附加规则 + 提交回执

consumeResult(subscription, authoritativeResult)
  -> 证据政策判定 -> 正式完成/准出；与是否配置页面/操作无关
```

这些是语义边界，优先扩展/复用现有实际 API，不为示意名新增重复资源。部署元数据到旧版本操作的兼容选择在发布时解析，不让用户填写额外版本组合。
