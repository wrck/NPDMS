## 3. 文档体系

采用一份总体规格、八份领域分册和五份公共附录。每份领域分册可独立评审，公共规则只在总册或附录定义，分册通过编号引用。

## 4. 追溯规则

原始证据 → REQ-xxx → UC-领域-xxx → FR-领域-xxx → BR/DR/API/NFR → AC-领域-xxx → 后续测试用例。

## 5. 重要模型修订

- 项目组合与项目父子层级是两个独立概念。
- 项目和任务均采用非固定层级树，不设置一级、二级、三级等固定字段。
- 项目拆分、合并、子树移动、层级权限和全后代汇总由PMS核心模块负责。
- 割接、巡检是可挂接的专业子流程，不是所有项目的强制阶段。
- 首期模块化单体部署，但模块不得直接修改其他模块拥有的数据。

## 6. 规格边界

- V1、V2功能必须具备流程、规则、数据、权限、异常和验收标准。
- V3只描述目标、前提和风险，不构成当前开发承诺。
- 原始资料无法确定的内容标记【待确认】。
- 为补全闭环而新增的内容标记【建议】。
- 本规格及设计决策采用Git管理，Markdown文件是开发阶段的版本基线。
