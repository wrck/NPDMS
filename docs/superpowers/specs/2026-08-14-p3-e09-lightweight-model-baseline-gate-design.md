# P3-E09轻量模型基线门禁设计

> 状态：`APPROVED`<br>
> 日期：2026-08-14<br>
> 适用基线：PRD V1.7、SDS Phase 3<br>
> 关联门禁：P3-E09 / AI-MIG-000<br>
> 关联决策：ADR-0019～ADR-0028

## 1. 目标

本门禁只解决当前阶段的一个真实问题：已经确认的数据模型能否稳定进入SDS基线，并在DDL、逐项裁决或关键证据变化时及时失效。

它不建设迁移审批系统，不模拟未来生产发布，不引入OA、电子签名、四角色附件、双批准状态机或额外证据平台。

## 2. 直接收益

|收益|实现方式|
|---|---|
|避免带着未裁决的数据结构进入开发|要求1,883项裁决无`DEFER`|
|避免评审后DDL静默变化|绑定当前DDL、Items和Item ID集合哈希|
|证明DDL至少可以在目标数据库执行|复用当前MySQL 8.4隔离执行证据|
|避免SDS确认被误认为允许迁移|P3-E09不定义迁移批准哈希，历史迁移和切换仍阻断|
|提高追溯效率|用一次明确Git基线提交冻结当前正式制品|

如果某项控制不能直接提升设计正确性、减少返工、保护不可逆操作或提高业务交付质量，则不纳入当前门禁。

## 3. 通过条件

P3-E09模型基线只检查以下事实：

1. 当前DDL SHA-256与全部正式数据模型制品一致；
2. 逐项寄存器共1,883项，`DEFER=0`；
3. Q07、Q08、V1.7及Q09～Q14已按ADR-0028确认；
4. Q08的122项仍为候选索引，不代表性能验收完成；
5. MySQL 8.4隔离执行证据与当前DDL同哈希；
6. 核心契约、逐项寄存器、Phase 3证据和SDS校验全部通过；
7. 独立复审结论为GO；
8. 上述正式制品形成一次明确的Git基线提交。

通过结果只表示：当前数据模型可以作为SDS和后续Feature设计输入。

## 4. Git确认方式

Git只用于冻结可复现快照，不再建设独立签署证据体系。

- 使用一次明确的模型基线提交保存最终正式制品；
- 提交信息明确表达“发布P3-E09模型基线”；
- Git原生保存commit ID、作者、时间和文件版本，不在JSON中重复抄写这些字段；
- 校验以提交内的DDL和证据文件为准，不以未提交工作区内容为准；
- 后续DDL或逐项寄存器变化时，必须重新运行校验并形成新的基线提交；
- 不要求GPG签名、OA记录、电子签名或第三方审批系统。

## 5. 历史迁移边界

当前只保留以下硬规则，不实现迁移批准流程：

- 模型基线通过不授权历史数据迁移、数据切换或生产发布；
- P3-E09不定义迁移批准哈希；
- AI-MIG-000及历史迁移/数据切换门禁继续保持`OPEN`；
- 真实迁移批次形成后，再根据当时的源水位、迁移清单、环境、演练、对账和回退证据设计最小发布门禁；
- 不预建迁移批准模板、迁移状态机、责任人矩阵或外部审批集成。

## 6. 最小实现范围

1. 从SDS模型基线路径移除四角色外部签署和迁移批准哈希前置要求；
2. Phase 3寄存器根据当前模型事实和独立复审结论派生SDS Ready；
3. 保留历史迁移、数据切换和性能验收阻断；
4. 删除或停用只服务于当前过重方案的签署模板、附件规则和测试；
5. 更新工程链、SDS 08/09、门禁状态和移交说明中的现行口径；
6. 全量测试和独立复审通过后，创建一个模型基线提交。

## 7. 不在本次范围

- 不修改PRD、DDL、领域模型、API、权限、状态机或业务流程；
- 不执行历史迁移、数据切换或生产发布；
- 不实现迁移批次审批能力；
- 不新增通用审批平台、签名系统或证据管理系统；
- 不读取、生成、校验或提交两份受保护的未跟踪原始资料。

## 8. 验收标准

- 当前模型事实完整且无`DEFER`时，SDS Phase 3不再被P3-E09模型基线阻断；
- P3-E09不定义迁移批准哈希，历史迁移和数据切换仍不可执行；
- 修改DDL、Items或关键证据后，模型基线校验失败；
- Q08仍明确属于候选索引和后续性能验证范围；
- 不再要求四角色外部附件、OA、电子签名或额外批准记录；
- 现行实现、测试和文档不存在与业务功能或系统设计无关的重复治理结构。
