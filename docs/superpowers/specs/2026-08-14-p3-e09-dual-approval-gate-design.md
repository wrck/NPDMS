# P3-E09数据模型基线与迁移发布双门禁设计

> 状态：`APPROVED`<br>
> 日期：2026-08-14<br>
> 适用基线：PRD V1.7、SDS Phase 3<br>
> 关联门禁：P3-E09 / AI-MIG-000<br>
> 关联决策：ADR-0019～ADR-0028<br>
> 设计Owner：Engineering Governance

## 1. 背景与问题

当前P3-E09同时承担两种不同风险的控制：

1. 确认表、字段、约束和索引是否足以形成SDS数据模型基线；
2. 授权历史数据迁移、数据切换和生产发布。

现有实现把两者共同绑定到`approvedDdlSha256`和四角色外部签署，导致外部审批载体或实际责任人尚未确定时，SDS逻辑基线也无法关闭。签署载体不会改变当前数据模型，前置它不能进一步降低模型返工，因此不应阻断SDS基线；但历史迁移与数据切换具有不可逆风险，仍必须使用另一笔独立Git确认提交明确授权，不能复用SDS模型基线确认。

本设计不改变PRD业务语义、DDL内容、迁移范围或ADR-0028的九组决策，只拆分工程门禁和批准哈希的用途。

## 2. 已确认方案

采用“双门禁、双哈希”方案。

|门禁|目的|批准证据|最晚关闭点|
|---|---|---|---|
|模型基线批准|证明当前DDL和逐项裁决可作为SDS数据模型基线|仓库内结构化批准记录、需求方决策、独立复审、独立Git确认提交|SDS Phase 3基线前|
|迁移发布批准|证明具体批次可以执行历史迁移、数据切换或生产发布|绑定迁移批次及运行证据的另一笔独立Git确认提交|历史迁移、数据切换或生产发布前|

### 2.1 方案比较

|方案|结论|原因|
|---|---|---|
|所有阶段共用同一Git确认|不采用|SDS批准可能被误用为迁移或生产切换授权|
|SDS使用Git确认、迁移发布使用外部审批|不采用|引入当前项目未确定的外部依赖|
|SDS与迁移发布分别使用独立Git确认|采用|审计载体统一，同时通过不同提交、字段和门禁范围隔离授权|

## 3. 模型基线批准契约

新增`modelBaselineApproval`，它只批准当前数据模型进入SDS基线，不授权迁移执行。

必须绑定：

- 当前DDL SHA-256；
- 当前逐项寄存器Items SHA-256；
- Item数量和Item ID集合SHA-256；
- 当前表数、字段数、约束/索引数和表选项数；
- Q07、Q08、V1.7及Q09～Q14决策范围；
- ADR-0028需求方确认；
- 写回前Git提交、寄存器文件哈希、确认包文件哈希；
- 当前独立复审结论；
- 生成时间、生成器版本和Git提交。

批准记录由脚本生成，禁止人工逐项填写或手工复制1,883项。批准状态只能由机器校验结果和独立Git确认提交共同派生，不能直接编辑状态字段晋级。

Git确认必须记录并验证：

- 确认提交的完整commit ID、author、author email和commit time；
- 批准记录路径及该路径在确认提交中的blob SHA-256；
- 确认提交必须存在于当前仓库并且是当前HEAD的祖先；
- 确认提交中的批准记录必须与当前校验输入一致；
- 工作区中的未提交文件不得作为批准证据。

当前模型基线批准不要求：

- OA、电子签名或第三方审批系统；
- 生产环境、KMS或Telemetry实例；
- 迁移批次、源库水位或切换窗口；
- 逐项填写1,883条裁决。

## 4. 迁移发布批准契约

保留`approvedDdlSha256`作为迁移发布批准哈希。该字段在SDS模型基线批准时仍为空，只有具体迁移或切换批次形成独立Git确认提交后才能填写。

迁移发布批准必须额外绑定：

- `modelBaselineDdlSha256`；
- 具体`releaseId`和环境；
- 源结构哈希、抽取水位和迁移清单；
- 目标目录、映射、校验、回退制品哈希；
- Git确认提交的author身份及迁移责任人字段；
- 独立迁移复审结论、迁移批准记录路径及其commit/blob哈希；
- 演练、对账和回退验证结果。

迁移发布确认在实施阶段按具体批次生成。尚未形成独立Git确认提交时只保持`MIGRATION_RELEASE_APPROVAL_PENDING`，不得反向阻断已通过的SDS模型基线和无关Feature Spec。

## 5. 状态与门禁变化

### 5.1 P3-E09模型基线状态

```text
DECISIONS_ACCEPTED_REVIEW_PENDING
  -> MODEL_BASELINE_REVIEWED
  -> MODEL_BASELINE_APPROVED
```

进入`MODEL_BASELINE_APPROVED`必须满足：

- `DEFER=0`；
- 当前DDL、寄存器、确认包和执行证据同哈希；
- 模型基线批准记录通过机器校验；
- 独立复审为GO；
- `modelBaselineDdlSha256 = currentDdlSha256`。

此时：

- `phase3-evidence-register.overallStatus`可转为`READY_FOR_SDS_BASELINE`；
- P3-E09对`PHASE_3_BASELINE / DATA_MODEL_BASELINE`不再阻断；
- `approvedDdlSha256`仍为空；
- `HISTORICAL_DATA_MIGRATION / DATA_CUTOVER`继续阻断。

### 5.2 迁移发布状态

```text
MIGRATION_RELEASE_APPROVAL_PENDING
  -> MIGRATION_EVIDENCE_SUBMITTED
  -> MIGRATION_RELEASE_APPROVED
```

只有`MIGRATION_RELEASE_APPROVED`才能解除历史迁移、数据切换及对应生产发布门禁。

## 6. 自动化边界

### 6.1 自动生成

脚本负责自动读取并填充：

- DDL、Items和Item ID集合哈希；
- 当前规模与各决策组数量；
- ADR、确认包、执行证据和独立复审引用；
- Git HEAD、生成时间和生成器版本；
- Phase 3寄存器的派生状态。

### 6.2 人工输入

SDS模型基线阶段不新增人工字段。用户已经完成ADR-0028九组业务决策确认，后续只需审核自动生成的模型基线批准摘要。

迁移发布阶段才收集实际责任人和迁移批次，并生成独立Git确认提交；脚本验证但不伪造这些信息。

### 6.3 禁止行为

- 不得用需求ADR或SDS模型基线确认提交冒充迁移发布确认；
- 不得仅因任意Git提交存在就宣称迁移可执行；提交必须包含同批次批准记录并通过commit/blob/制品哈希校验；
- 不得把`modelBaselineDdlSha256`复制为`approvedDdlSha256`；
- 不得由可编辑状态字段单独将P3-E09改为`VERIFIED`；
- 不得因SDS基线通过而关闭性能、迁移演练、数据切换或生产发布门禁。

## 7. 现有资产调整

实施阶段将调整：

1. `core-migration-schema-contract.json`：增加模型基线批准结构并保留迁移发布批准结构；
2. `ddl-item-decision-register.json`：区分模型复审结果和迁移发布确认，不再要求SDS阶段填入四角色外部附件；
3. `phase3-evidence-register.json`：从模型基线批准证据派生SDS Ready，同时保留迁移与切换阻断；
4. P3-E09证据模板：拆分为模型基线自动批准记录和迁移发布Owner提交模板；
5. 生成器与校验器：分别校验两个门禁，禁止哈希和状态串用；
6. `gate-status.md`、SDS 08/09及迁移移交文档：统一双门禁含义。

现有`p3e09_approval_policy.py`中的四角色外部附件规则由Git确认契约替代；模型基线和迁移发布分别校验各自的提交、记录与哈希，禁止共享同一确认提交。

## 8. 测试与验收

必须覆盖以下正反用例：

1. ADR-0028、当前哈希和独立复审齐备时，模型基线批准可生成并通过；
2. 模型基线批准后，Phase 3可为SDS Ready，但`approvedDdlSha256`仍为空；
3. 模型基线批准不得解除历史迁移和数据切换阻断；
4. 任一DDL、Items、Item ID或数量变化时，模型基线批准自动失效；
5. 删除或篡改独立复审证据时，模型基线批准失败；
6. 仅填写`approvedDdlSha256`但缺少迁移发布Git确认时，迁移门禁失败；
7. 迁移发布Git确认不能反向修改SDS模型决策；
8. 模型基线与迁移发布引用同一commit ID时校验失败；
9. Q08候选索引继续受Feature查询计划和P3-E06性能验收约束；
10. 两份未跟踪原始资料不得进入生成、校验或提交范围；
11. 全量生成器、validator、单元测试和`git diff --check`通过。

## 9. 不在本次范围

- 不接入OA、电子签名或第三方审批产品；
- 不执行历史数据迁移或数据切换；
- 不修改当前60表DDL；
- 不改变PRD、领域Owner、API、状态机、权限或业务流程；
- 不把P3-E01～E08的部署与运行证据前置为SDS阻断。

## 10. 设计验收标准

- SDS模型基线批准与迁移发布批准具有不同字段、状态、证据和阻断范围；
- 当前不依赖外部审批系统，使用独立Git确认提交完成SDS Phase 3模型基线复审；
- 未形成绑定具体批次和运行证据的迁移发布Git确认提交时，历史迁移和数据切换仍不可执行；
- 所有状态均由证据和校验结果派生，不依赖人工直接修改；
- 文档、机器契约、生成器、校验器和测试对双门禁含义一致。
