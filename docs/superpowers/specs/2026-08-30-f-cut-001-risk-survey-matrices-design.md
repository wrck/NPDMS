# F-CUT-001风险与调研关联矩阵补全设计

> 状态：`APPROVED / 2026-08-30需求方确认`
> Requirement ID：`CUT-07@V1`、`CUT-09@V1`、`CUT-10@V1`
> 上游修订：`CHG-PRD-2026-08-30-008`
> 正式Feature Spec：`specs/features/F-CUT-001-cutover-unified-configuration-foundation.md`

## 1. 背景与目标

F-CUT-001已交付CUT-07配置根、统一采集项、动态维度与绑定规则三表基础，但其Feature Spec把CUT-09风险矩阵和CUT-10调研矩阵拆为后续Feature，与正式SDS“由同一Feature承接CUT-07/09/10首批配置基础”不一致。

本次重新打开F-CUT-001，在现有配置聚合内补齐风险与调研专用矩阵视图、正式配置内容、批量维护和发布校验。完成后F-CUT-001整体覆盖CUT-07/09/10；此前CUT-07实现与提交保留，不回滚、不复制新Owner。

## 2. 方案选择

采用“同一聚合、同一修订、专用投影视图”方案：

- `CutoverConfigurationRevision`继续是唯一配置版本根。
- 三类采集项继续保存在`cut_cutover_checklist_item_definition_revision`。
- 所有动态多维关系继续保存在`cut_cutover_checklist_binding_rule_revision`。
- 风险矩阵筛选`RISK`与`DUAL_MACHINE_CHECK`，调研矩阵筛选`BUSINESS_SURVEY`；专用页面不是第二套主数据。
- 草稿保存、发布、停用和复制继续使用现有聚合API与`If-Match`，不建立第二套矩阵生命周期。

不采用以下方案：

- 独立风险/调研主表：违反CUT-07单一Owner与ADR-0031三表边界。
- 分别发布风险和调研矩阵：会产生同一配置修订的部分发布状态。
- 另建F-CUT-002/F-CUT-003：无法在单一配置根的原子发布语义下独立完成，且与正式SDS的同一Feature约束不一致。

## 3. 数据与内容

### 3.1 风险配置

- 风险矩阵包含PRD列出的25+项风险配置义务，其中双机部署规范性检查作为专用分组承载97个`DUAL_MACHINE_CHECK`定义。
- 五类数量固定为：VSM双机17、静默双机25、DRP双机23、普通双机24、集群8。
- 其余风险定义使用`RISK`类型，覆盖技术公告、备份、日志、会话、版本、MD5、备件、动态表项、MTU/FEC、长连接、二次过设备、STP、F5/adware和承诺书等正式类别。
- “所有情况必选”规则必须覆盖所有启用割接类型、设备类型和A/B/C级，不能以空条件代替显式覆盖校验。
- 升级后版本技术公告只允许版本升级条件；五类双机项只能绑定自身组网模式。

### 3.2 调研配置

- 调研矩阵落实PRD的12类核心内容，全部使用`BUSINESS_SURVEY`类型。
- 割接背景使用结构化`interfaceSchema`表达六个字段及两组条件显示关系。
- 拓扑、连通性测试例和友商配置翻译使用文件引用控件，不直接保存任意文件路径。
- 必填性属于绑定结果；具体组合优先于通配组合，同优先级冲突阻止发布。

### 3.3 参考资料边界

- 已存在的本地XLSX/HTML可引用97项的名称、说明、界面格式和排序，不重复下载。
- 数量、类型、必填性、绑定规则、发布条件和完成结论只来自PRD/SDS/Feature Spec。
- 参考资料缺少或冲突的业务语义不得猜测；名称缺失时登记问题，不以占位名称发布。

## 4. 服务端设计

### 4.1 领域校验

在现有`CutoverConfigurationRules`上增加两个聚焦校验器，由根发布预检统一调用：

- `CutoverRiskMatrixRules`：校验25类风险义务、五类97项精确计数、专属组网、全覆盖必选项、升级后公告条件、重复和冲突绑定。
- `CutoverSurveyMatrixRules`：校验12类核心内容、割接背景Schema、条件显示引用、必填结果和规则优先级冲突。

校验返回现有`location + message`结构，位置精确到采集项、子表或绑定规则；任一错误保持草稿，当前已发布修订不变。

### 4.2 API

不增加第二套写API：

- `GET /api/v1/pms/cutover-config/revisions/{revisionId}`读取完整聚合。
- `PUT /api/v1/pms/cutover-config/revisions/{revisionId}`按`If-Match`保存完整草稿。
- `POST .../actions/validate`返回CUT-07/09/10联合预检结果。
- `POST .../actions/publish`只在三部分全部通过时原子发布。

专用页面只投影完整聚合中的目标类型。CAS冲突要求刷新，不允许风险页或调研页用旧版本覆盖另一页面的修改。

### 4.3 数据库

- 不新增Owner表，不修改V128～V131。
- 使用新的前向Flyway迁移创建完整示例修订，保留原修订历史，不原位修改已发布子项。
- 种子使用高段稳定ID或显式稳定键，覆盖97项双机检查、正式风险类别、12类调研内容、精确命中、部分限定、优先级让位、无匹配和停用不参与场景。

## 5. 前端设计

在现有割接配置编辑器中增加两个专用矩阵入口：

- 风险矩阵：按风险类别和五类双机子表筛选，显示每类`当前数/基准数`，支持批量设置维度、必填、优先级和启停。
- 调研矩阵：按12类核心内容展示绑定组合，提供割接背景条件Schema可视化编辑和批量必填设置。
- 发布校验页按“基础配置 / 风险矩阵 / 调研矩阵”分组展示错误及行定位。
- 已发布/已停用修订全部只读；320/768/1024/1440视口均保留项目名称、关键条件与错误文本。

## 6. 权限与审计

- 继续使用`pms:cutover-config:query/manage/publish/disable`，不新增角色或审批节点。
- 配置权限不授予割接任务、项目设备、外部数据原值或采集结果访问权。
- 草稿变更、发布、停用和失败预检复用平台操作日志；发布快照保留字典代码与显示名称。

## 7. 测试与验收

- 领域测试：五类数量逐类不足/超出、错误子表、必选覆盖缺口、公告条件错误、调研Schema引用错误、重复/冲突规则。
- 服务测试：联合校验失败零写入、CAS冲突、旧发布版本不提前停用、复制保留风险/调研子项。
- 迁移测试：MySQL 8.4空库与当前基线升级、`migrate/info/validate`、重复migrate、种子数量和分类查询。
- 前端测试：风险/调研过滤、批量编辑、计数提示、只读态、错误定位和CAS刷新。
- 真实浏览器：完整草稿复制、风险矩阵97项计数、调研12类、联合预检负向、成功发布与历史只读，覆盖四档视口且无控制台错误。

## 8. 排除范围

- CUT-01～CUT-06任务、评估、清单实例、方案、审批、执行和闭环。
- CUT-03运行时匹配、命中轨迹、重新生成和CollectionTask下发。
- CUT-08备件集成、V2自动指派、首页KPI、导出或流程跳转优化。
- 任何第二套风险/调研主数据、矩阵状态机或外部附件数量门禁。

## 9. 完成条件

F-CUT-001只有在CUT-07基础、CUT-09风险矩阵和CUT-10调研矩阵共同通过自动化、MySQL迁移、真实浏览器、自审和追溯生成后才能恢复`IMPLEMENTATION_COMPLETE`。局部页面、种子数量或单项校验通过均不产生Feature Done。
