# 安装记录自动关联与硬件实施任务完成验收

## 修复范围

用户确认：安装记录直接作为“硬件安装位置及实施记录”的业务成果，全部设备安装地址保存完成后自动关联，并由原任务状态机完成任务。

原项目992203060198有40/40台设备安装地址，硬件实施任务2107838747850678281已提交但停在PENDING_ACCEPT；冻结完成规则同时要求TASK_NATIVE_STATUS及D_INSTALL。D_INSTALL/2101716952857630524为PENDING且无提交历史。已有地址校验正确，缺少成果来源和归集接线。

新增IMP/INSTALLATION/INSTALLATION_COMPLETED原生来源，基础查询独立核验全部项目设备与当前已完成安装记录，保留租户、项目、精确身份、并发版本及历史边界。最新完成记录编号作为当前成果身份，全部设备当前记录的编号与版本构成观察版本；空项目、缺记录、缺地址、未完成和失效记录不能形成成果。未完成草稿不能替代有效完成记录，新增设备后原完整成果不再成立，不声明历史枚举或全部变更覆盖。

安装完成原事务追加事件及成果日志；部分完成不是项目成果形成。项目匹配层仅关联有效冻结计划中绑定安装页面、完成规则明确引用且允许BUSINESS_RESULT的交付件，或原显式自动来源。复用ACC统一提交和原任务完成命令，不改变冻结计划、直接写状态或覆盖历史。

## 实际验收

- 环境：npdms_domain_test，前端19191、后端59191，构建及部署成功，部署后健康UP。
- 真实浏览器在项目992203060198维护安装地址，对一台设备回填的原地址直接保存，未改地址文本。原批量命令生成安装记录2108347143896870978，原记录按正常业务关闭当前有效区间并保留历史；回读新旧地址文本一致。
- 没有调用项目材料提交或任务完成接口。正常成果日志、Outbox和归集自动生成D_INSTALL的BUSINESS_RESULT提交，交付件状态ACCEPTED、历史1条。
- 原任务通过正常状态机变为DONE、版本6；真实页面重新打开项目交付件显示已满足，材料弹窗显示业务成果。
- 没有人工上传替代材料、改冻结计划、改事件投递状态或直接改业务表。已有未完成/异常安装记录保留，仍仅认可全部设备的当前完成记录。
