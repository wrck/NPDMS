# 配置Log首次加载优化（2026-10-24）

需求方反馈设备条码多的项目首次打开配置Log慢。本次保持日志范围、租户/项目授权、历史记录及下载校验，仅调整读取时序和无日志项目的多余工作。

## 发现与修改

- 项目归档列表拿到数据后，仍await所有已归档设备的解析状态，再解除整个表格加载遮罩；即使每页仅20条也请求全部设备。改为列表完成即展示，解析状态按当前页异步加载，明确显示状态加载中，切页、筛选、刷新及离开时隔离旧响应。只对当前页处于处理中任务继续轮询，查询失败保留原列表和逐行错误。
- 设备配置Log抽屉原来等待归档和历史两路全部结束才显示。改为每路独立提交结果，有结果即显示；其余请求有加载提示，失败分别反馈，设备切换后旧响应不能追加到新设备。
- 后端latest在已授权项目没有归档文件时仍读取项目全部DeviceDO再过滤。改为归档候选为空后直接返回空列表，原项目范围和功能权限校验仍先执行；有日志项目的原设备筛选保持。

## 当前验证

- 真实浏览器使用当前周文成会话：84572空日志列表接口222ms；82522含84个设备条码，设备990201A3D265000160的归档历史请求150ms、旧配置日志1031ms。此为单次观测，不作为大数据项目P95或性能提升比例。
- 浏览器已加载前端改动，82522设备抽屉能显示加载其余日志提示，随后正确显示无日志结果。该样本没有实际日志，不能据此证明有日志的大项目完整首开耗时已验收。
- 前端DeviceLogArchive、DeviceLogUpload、ProjectDeviceConfigLogDrawer定向15项通过：覆盖列表不等慢解析、只查可见分页、旧分页/设备响应隔离、解析失败不吞列表、较快来源先展示与较慢来源错误保留。
- 后端DeviceLogArchiveServiceTest定向验证及依赖构建通过，日志`.run/config-log-performance-tests.log`。新增无归档时不读取设备清单、无权限时不读取归档或设备的回归。

本次没有重新打包、部署或重启后端；无日志项目跳过设备清单的后端改动尚未加载到59286。前端通过当前Vite开发服务生效。未修改运行数据、迁移或其他未提交工作。有大量已归档日志项目仍需进一步实测服务器列表接口，不将本轮读取时序修复宣称为全部加载瓶颈已消除。
