### 已确认的割接业务视图依赖缺口

五类已发布模板的割接审批BUSINESS_COMPONENT均在parameters.businessViewRevisionId引用上述草稿视图。来源库对应视图 `2102312818482794515` 的published_at为2026-10-15 23:11:15.652460，目标为空。

代码依据：`ProjectTaskBusinessService.historicalView()`调用`BusinessViewQueryApi.getRevision(HISTORICAL_REFERENCE)`；`BusinessViewApplicationService.getRevision()`对published_at为空的记录拒绝访问，即使历史引用也不放行。数据库及代码共同证明该依赖未就绪，尚未通过真实浏览器重现办理失败。

这些模板的businessViewSnapshot为空；当前`TemplateDesignerDependencyValidator.add()`跳过无快照绑定，因此“模板发布成功”不证明该参数引用的视图已发布。这也解释了先前模板内容比对及发布回执无法覆盖这项运行依赖。

后续应通过业务视图Owner的原生校验和发布入口补齐，核验组件Provider、依赖及权限，并验证模板任务的实际割接审批入口。此项不属于已确认的核心任务状态机默认规则，不能用V517顺带直接发布；本次按“检查其他缺口”记录发现，不扩大到视图发布/模板校验代码修复或远端数据变更。
