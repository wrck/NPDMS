## 收尾事务

INT 验证全部来源已经完成、本轮没有未承接或冲突行、运行归属及配置版本仍有效，才调用 COM `DppmsContractCompletionApi`。P24 必须存在同租户、同连接、当前配置的完整成功根运行，且来源为已批准的非项目限定、非合同号过滤读取。运行中、失败、部分读取或较新失败运行不能充当完整输入；原空合同号过滤仍属有效裁决，不算缺失输入。已有符合条件的数据直接复用。

INT 只读自身绑定并提供限定对象 ID；COM 只处理所属业务表，通过正式 SYSTEM API 一次读取组织目录，通过 Asset Owner 刷新设备组织投影。现有通用映射逐行写入机制不在本次重构，新增后置写入不通过 INT 直接更新 COM 表。

同一事务连接创建一次本轮 ID 范围、公司目录、唯一部门目录、全租户唯一合同目录；回填本轮合同公司、发货合同引用及包裹精确父引用。未唯一命中不猜测，不清空原引用。全租户合同号唯一性包含其他公司和其他来源的有效合同，不以仅查询 DPPMS 合同绕过歧义。

发货与回款各汇总一次，沿批准 SQL 的逐字段最新非空规则补充本轮 P15 合同：发货按原来源键 RPAD 64 位排序，回款按原更新时间前 19 位及原 ID 的 20 位补零键排序；发货优先字段、回款其他字段和 currency_code 沿 currency_name 的原规则均保持。只有实际变化时更新，临时表在 `finally` 逐一释放。

公司、部门采用不同临时表；每条语句只引用每张临时表一次，避免 MySQL 的重复打开限制。依据：[MySQL TEMPORARY Table Problems](https://dev.mysql.com/doc/refman/8.4/en/temporary-table-problems.html)。

COM 分批返回本轮最新投影，INT 只更新本轮绑定的 `_postCompletion`，不改原始来源、旧运行、审计或历史证据。后置写入或投影失败时，后置事务回滚且不标记 SUCCESS；此前已提交分块沿原流式语义保留，失败运行不能成为后续完整输入。
