# 直接设备日志结构化解析：实现与验证

需求方确认上传本地日志、选择已采集日志均支持，并要求 DAC 只提供通用 API。此记录不代表全 Feature、SIT/UAT 或发布完成。

## 实现范围与复用判断

- 原 `ParseTaskController` 接收规范化命令块，无法直接接收普通设备文本；保留原接口，新增 `/api/v1/log-parses` 文本适配入口。没有新增 `/npdms/` 路由，来源使用原生 `sourceCollectionId`。
- 复用已发布 `device-command-output` 解析引擎、版本固定、输入/结果存储和幂等任务服务；新增文本分块、命令回显去重及持久化前脱敏，不引入第二个解析引擎。
- NPDMS 新增无正文的 PLT 解析请求/来源投影，通过 INT API 调用独立 DAC。复用项目范围、业务来源适配器和文件下载权限；不访问 DAC 数据库，不写配置/联调业务状态，不重新执行设备命令。
- 从 DAC 复制语义结果展示组件到新的 `DeviceCollection/semantic` 目录后适配样式；原 DAC 页面、原采集解析摘要和原业务日志功能保留。
- 采集工作台增加“日志解析”；独立采集历史、配置调试与业务联调日志增加“结构化解析”。支持 UTF-8、GB18030，结果包含通用结构、设备实体、字段来源、识别情况和 JSON 导出。
- 复用既有菜单、权限和发布样例，没有新增业务角色或字典。V390 仅创建解析元数据表，不持久化上传正文。
