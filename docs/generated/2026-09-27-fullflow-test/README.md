## 二、发现与披露

### ① 缺陷（可复现）：工作区操作后立即"检验并完成任务"必报 项目任务版本冲突
- 现象：提交材料/签收/保存进度等任何使任务版本递增的操作后，立即点击"检验并完成任务"返回 `项目任务版本冲突`，页面横幅"任务操作未成功，可刷新核对或重试"（browser/26，DEPLOY_HARDWARE 第 3 次复现；DEPLOY_COORDINATE、DEPLOY_ARRIVAL 同样复现）。
- 服务端日志（只读）：`GlobalExceptionHandler serviceExceptionHandler → ProjectTaskLifecycleService.actOnce(ProjectTaskLifecycleService.java:135)`。
- 影响：对话框内重试无效（对话框持旧版本）；需关闭并重新打开"任务办理"对话框重新拉取版本后才可完成。操作链路被无谓打断，建议前端在冲突时自动重取版本或后端对同会话连续操作放宽。
- 本记录中的处理：关闭重开对话框（合法 UI 操作），未绕过任何校验。

### ② 模板完成依据缺口：PLAN_CONSTRUCTION / PLAN_SOLUTION 标注【待接入完成依据】
两任务（及对应交付件 D_CONSTRUCTION_PLAN、D_SOLUTION）的模板条件为空（无"计划审批通过/方案审核通过"完成依据），任务说明明示待接入；UI 仅能以"上传文件"通道满足交付件后走通用任务完成。功能可用但完成事实与真实审批脱钩——与模板声明的过渡状态一致，需模板侧补齐完成依据类型。

### ③ 数据缺口：项目无设备/订单数据
设备清单页签只读且"暂无数据"（来源为订单/物料，手工创建项目无此数据）。DEPLOY_ARRIVAL 登记到货的"关联设备"、DEPLOY_HARDWARE"新增安装"的"关联设备"下拉均为空；后者为必填（"设备编号不能为空"），导致硬件安装工作区无法登记，改走文件通道。属测试数据约束，非功能缺陷；但暴露"无设备项目在硬件安装环节无降级录入路径"的体验问题。

### ④ Q-004 实测确认（阻断项）：割接完成审批通道未接入
任务对话框明确禁止空表单替代、业务页面端点 404 且横幅声明待接入。按约束未修复、未绕过：未使用"关闭任务"（终止语义，会使割接在未完成情况下退出在办状态，属于绕过割接业务要求），未直写任何状态。S4 收口、S5 验收交维、S6 项目闭环在本构建因此不可达。
