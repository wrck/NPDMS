## 发现及修复

1. **全量类型检查基线为 60 处错误，涉及 24 个文件。** 先前的 4 处是默认页面及传递依赖的定向配置结果，称为“全量仅 4 处”不准确。本轮使用仓库主 `tsconfig.json`，包含全部 `src`，未排除测试、未关闭严格检查、未添加 `ts-ignore`。
   - 文件 ID/引用 ID/范围版本使用共享 `FileId`，保留 Java Long 字符串，未用 `Number(...)` 进行有损转换。
   - 必需文件事实的读取为空时明确拒绝拼装部分证据；纯名称回显为空时显示不可用。仍允许原 API 返回 null，没有用非空断言掩盖。
   - 无任务数组时给表格空数组；旧工勘先明确判断地点对象存在；缺少完整引用键时不发起文件查询。
   - 补齐验收时间字段类型，去掉未用变量；测试事件通过运行时验证的 handler 调用，保留 unknown 属性检查。
2. **普通默认页未保存编辑会被“返回列表/重新读取/路由离开”直接丢弃。** 补齐取消/确认保护；输入校验失败仍能明确选择保留或放弃，不强制提交。运行测试先失败后通过，真实浏览器脚本增加两个普通业务的取消/确认场景。
3. **默认交付件材料 ID 未拒绝超出 JavaScript 安全整数范围的数值。** 材料路径统一使用已有无损身份验证；新增失败回归先红后绿，字符串 ID 不受影响。
4. **内容版本页面只显示最近 100 条，没有继续读取入口。** 复用后端已有 `beforeId` 游标，增加“加载更早版本”；读取较早历史不替换当前编辑表单。101 条记录的组件测试先失败后通过，保留未保存内容。
5. **割接页面把所有读取错误一律解释成“端点未注册”。** 改为真实的请求失败提示，仍区别空列表，并保留服务异常时禁止创建及不请求概览的行为。增加网络错误反例，没有降低原业务断言。

## 项目创建来源的独立缺口

`ProjectCreationSource.vue` 访问了 `execution.finalCustomerName`，但后端 `ContractCreationSourceRespVO.ExecutionOrder` 没有该字段。不能只在 TypeScript 声明中编造字段，也不能把购货方当最终客户。本轮页面明确显示“当前来源接口未提供”，消除虚假取值假设；**最终客户来源数据补全仍未完成，按用户约束归本机项目创建任务处理**。本轮没有在云端改该业务后端或迁移数据。
