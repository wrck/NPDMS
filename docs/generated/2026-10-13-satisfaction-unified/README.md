# 满意度统一入口与客户单页确认

需求来源：2026-10-13需求方要求完工证明作为发起满意度调查的前提，全部统一到满意度调查中办理；客户推送链接将两部分连续展示在同一页，完工区域不显示客户签字；桌面与手机采用相同流程，并按指定frontend-design技能优化界面。

管理端复用既有完工证明保存、成套推送、权限、状态、版本与打印能力，显示尚未发起的草稿。项目独立完工证明导航移除，旧深链接转到满意度；旧独立调查仅通过只读历史入口保留。手机管理端显示记录卡片，桌面显示紧凑表格；操作使用同一组件与业务对象，沿用权限和状态条件。

客户页使用原DPtech品牌和工程表单内容，按完工内容、服务评价、统一签字顺序连续展示，页内导航仅滚动。没有完工/满意度页签，完工区域没有签字图片；页面末尾一次签字提交两份表单。原表、设备名称/数量、评分规则、受控文件、失败重试及提交后只读保留。无后端、迁移、种子、服务重启或旧文件改写。

## 真实运行结果

环境：宿主机前端19191、后端59191；项目 `992203060198`。真实Chromium登录办理，客户侧使用独立触屏浏览器上下文。

- 修改前：满意度入口没有完工证明创建能力，项目导航仍有独立完工证明项，见`before-result.json`。
- 自建记录30045：直接在满意度入口新建、保存及编辑重开证明，草稿期间无调查；发起时自动创建，重新推送复用同一任务，旧客户链接失效。设备保持7类40件。
- 320×568、390×844、768×1024、844×390与1440×1000均同时保留三个连续分区，没有页签；完工区域无签字图片，整页只有一个签字区，改变尺寸不丢失答案，无横向溢出。窄屏全部评分选项触控范围至少44px，大屏保留原矩阵。
- 未联合确认、缺必答评分或缺签字均零上传、零提交。实际触屏签字通过一次文件上传、一次联合提交完成两份表单，10项各80分得到80分达标，证明状态2；已签验证事实保留。
- 已提交入口重开只读，保持同一签字，评分禁用且无删除/提交操作；管理详情显示两份内容、10项评分和统一签字，两份Word打印预览可打开。未重新生成或登记业务PDF。
- 自建展示验证记录30046仅用于手机视口显示、桌面表格可视宽度与原生驳回验证；未签字、未提交。最终证明状态4，刷新客户链接显示不可用。
- 最终只读复核30025/30031/30034/30036/30037/30038/30039/30040前后相同；展示验证另检查30045的已签事实保持不变。管理页面无未处理异常。
