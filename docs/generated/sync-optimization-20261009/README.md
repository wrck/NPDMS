# 400 万级同步优化实施记录

## 范围与基线

- 需求：设备序列号、发货记录约 400 万规模，优先降低同步耗时及无效数据增长。
- 基线：`fix/visio-template-followup`，`686809ec67dbfb541fea18f2386e897b52182562`。
- 单表或合计 400 万尚未明确；压力验证按单链路 400 万条设计。
- 由主会话编写实现与测试，独立验证环境只应用明确补丁并执行指定命令。
- 不修改真实 DPPMS/CRM 数据，不删除历史证据，不启用未经授权的 CDC 或扩大数据库权限。

## 本轮实现

1. 通用同步引擎不再逐行复制整块 overlay。共用已读取目标缓存，每行只保留自身待写差量；成功合并、失败丢弃，避免失败行污染后续记录。
2. 可从来源直接求值、属于服务端授权业务键的关联查询按分块预取并去重。任意非键谓词、依赖前序步骤的键以及本任务会写入的关联表继续保持原执行语义。多个匹配目标仍视为歧义，同一目标因等价查询键重复返回不视为多个目标。
3. 表结构元数据按一次绑定执行缓存，跨流式分块复用，不做永久全局缓存。
4. 增加显式 `evidencePolicy=REUSE_UNCHANGED`。仅限通用流式同步、保留策略。所有记录仍经过业务目标校验；完整源事实、转换后事实、目标身份全部相等且已有落证绑定时，复用既有证据，不追加重复 PLT 记录，不触碰绑定。
5. 未复用数据仍走现有证据接口。异常、跳过、源字段变化、目标事实变化或缺少历史来源事实必须新留证。`FULL` 和旧任务保留原行为，不后台修改任务配置。
6. 新策略下需要写入的绑定采用可逆紧凑编码，去掉顶层源字段与 `_syncSourcePayload` 的重复保存。查询 API 和内部消费均还原原结构；不原地重写旧记录。
7. 每轮运行保留完整读取和动作计数。`EVIDENCE_REUSED` 为 `UNCHANGED` 的子集，不能重复计入处理总数。复用记录的 `last_run_id` 指向最近真正落证批次。
8. 业务写入、必要证据、绑定及分块断点同事务提交，失败回滚。
9. 绑定存在性检查由整批计数改成 XML 中的 `LIMIT 1` 查询，保留租户、任务与逻辑删除范围。
10. 执行单分块存在无效来源时明确失败，不再出现“整块未写入但正常记录报 CREATED、断点继续前移”。保留原先整块不写的安全边界，修复错误成功语义。
11. 核对 V378 和现行订单行实体后修复旧通用目录的 `item_code` 残留：新模板使用 `product_code`；旧任务仅在绑定执行时生成兼容副本，不修改持久化配置或来源字段。V402 为关联复合键及绑定分页补充前向索引，已有同列同序索引时跳过。尚未应用真实库，部署前必须核对磁盘空间和 DDL 窗口。
12. 非整数字符串转换到整数时，通用引擎正确标记该行异常，丢弃该行预备写入，正常行继续处理。

## 验收标准

- 老任务默认 FULL，配置往返一致；不兼容的策略组合服务端拒绝。
- 成功行、失败行、同块同目标更新、重复键、租户隔离、逻辑删除、关联歧义、不可变历史等回归通过。
- 首次导入保留证据；重复不变同步读取数完整且重复证据/绑定写入为零；变化仍留证。
- 证据失败时目标、绑定、断点共同回滚；预览不修改目标、绑定、正式检查点。
- 前端配置读写、类型检查、构建通过；真实浏览器单独记录，不以组件测试代替。
- 大规模测试区分 CPU 内核基准、隔离数据库基准、真实业务端到端实测。不得混淆数据集、硬件、SQL、索引、总耗时、吞吐和峰值内存。

## 不属于本轮已完成能力

- 源端 CDC、迟到提交/关联表更新的严格变更捕获。
- 大型合同 SQL 的集合化重写及真实源库执行计划比较。
- 多任务/分区并行与锁范围调整。
- 旧证据清理、历史索引版本复用和真实库迁移。
