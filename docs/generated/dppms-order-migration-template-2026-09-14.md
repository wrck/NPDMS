## 映射与处理规则

| 来源 | 目标 | 业务身份 |
|---|---|---|
| `pm_order_data_from_erp` | `com_sales_order` | ERP 来源、公司、订单类型、订单号 |
| `pm_order_line_from_erp` | `com_sales_order_line` | 所属订单业务身份、行号 |

源 `id` 是独立追溯键，目标使用自己的主键。多个源 ID 的订单主档内容一致时，可对应同一个目标订单，每个源 ID 均保留映射和原始记录。例如源订单 `9132`、`9133` 都是 `SMS / 01 / 0 / SO074723-L`；重复的是业务键，源主键没有重复。

- 通过商务权威接收 API 写入，保留原有租户、事务、来源版本和不可变证据保护。
- 订单类型 `0` 为销售、`1` 为退货；退货数量保留原始负数，不取绝对值或改成零。普通销售行继续执行原有非负校验。
- 两张源表均没有计量单位。订单行保留原始数量，单位为 `NULL`，标记 `PENDING_AUTHORITY`，并提示“计量单位缺失，保留为空并待核对”。确认数量仍要求单位完整。
- 同一业务键内容冲突、缺少父订单等记录进入问题清单，不任意选一条覆盖，也不创建虚构父订单。
- 使用同一业务键的最大 `syncTime` 作为规范化来源版本；原始行的全部字段仍保存在迁移证据中。
- 合同号、执行号、`customInfo` 等未进入订单主档的原始字段保留在来源证据中；本模板不额外创建合同关系或项目关系。
- 加载策略为 `UPSERT`，来源缺失策略为 `RETAIN`；不清空业务表、不接管其他来源、不启用源主键覆盖目标主键。

## 自动分页

在“调度与限额”中启用“自动分页”，设置“单批最大行数”（默认 2,000，允许 1～10,000）。启动一次后，由模块按配置的来源顺序处理：先完成全部订单，再处理订单行，无须修改 `afterId` 或 `pageSize`。保存配置不会执行迁移。

- 启动时读取并持久化各来源查询的最大 ID；按 `id > 已提交游标 AND id <= 固定上界 ORDER BY id LIMIT 单批最大行数` 读取，支持稀疏 ID。超过固定上界的新插入记录留待下次运行。
- 每页独立提交，内存中仅保留当前页。业务写入、来源映射、该页证据完成和主运行游标推进在同一事务中执行。字节容量仍作为单页上限，超限则该页失败，不截断数据。
- 每页有独立批次编号和明细。主运行显示累计已完成页的行数、结果及分页批次入口；所有来源完成后才标记整体成功并推进任务检查点。
- 页面出现失败后停止；已成功页及历史证据保留。对**主运行**创建关联重试，从上次已提交游标继续，沿用原固定上界。配置版本或预览方式改变时拒绝断点重试，应重新创建运行。子页不能单独重试。
- 完整预览也会自动分页，但不写商务数据、来源映射或任务检查点。订单行预览使用源查询验证的父订单存在性；正式接收仍强制要求目标父订单真实存在。
- 自动分页适用于正整数 Long 来源主键、独立记录的一次迁移或全量快照及保留策略；整树同步、清空目标、重置映射及时间增量继续使用原路径。各页读取各自的一致性快照，不宣称所有页面共享同一个数据库事务快照。
- 旧的 `scripts/run_dppms_order_migration.py` 手动分页循环对新版自动分页模板明确停止，防止重复遍历；使用工作台即可。
