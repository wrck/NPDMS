# 工勘地址引用保存修复

2026-10-06，用户授权修复工勘保存的 `detail_address` 数据库异常。

## 原因与改动

`PmsLocationSelector` 初次加载客户信息时将已有地址的 `id + expectedVersion` 引用替换为只有国家信息的新地址输入；工勘已有站点引用使前端新地址校验被跳过，后端尝试插入缺少详细地址的 `ast_address`。

- 将清除旧客户地址引用的操作移至项目切换 watcher，初次加载保留已保存的地址引用。
- 资产地址 API 在新建地址前校验详细地址和完整地址，缺失时返回既有结构化引用不完整业务错误；不调整数据库约束、已有引用、版本冲突与状态规则。

## 验证

- 前端运行时测试先复现挂载后引用丢失，修复后地点选择器及工勘字段映射共 6 项通过，覆盖初次加载保留地址、项目切换清除旧客户地址。
- `mvn.cmd -pl pms-module-asset -am test -Dtest=AssetLocationApiImplTest -Dsurefire.failIfNoSpecifiedTests=false -DfailIfNoTests=false`：9 项通过，包含不完整新地址拒绝且不写库、地址复用、版本冲突与来源重放；输出 `.run/site-survey-address-tests.log`。
- ESLint 检查本次前端文件通过。
- 真实浏览器使用现有 `http://10.210.0.11:19191` 登录会话，在 `F-SOL-003动态表单浏览器验收项目` 创建独立草稿 `地址引用修复验证-20261006`，引用杭州数据中心A站，保存成功；重新编辑再次保存出现“保存成功”；刷新列表仍为同一地点及 `RESOLVED`。保留该验证草稿，未改动既有工勘或执行确认/归档。
