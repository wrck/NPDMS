## 需要补齐而不是重复建表的部分

1. 空地址来源的明确项目/设备关系不能丢弃；复用安装领域模型时需要区分来源关联与安装完成事实。
2. 当前P33目标只保存安装字段，旧contractNo、转移项目/合同/标记等仅参与指纹，没有保存为可供业务查询的字段。恢复旧清单须补齐这些缺失来源事实，不能从哈希还原，也不能从设备当前归属猜测。
3. 公共设备列表目前以当前设备项目为核心，需通过Owner公开查询契约接入来源关联和发货规则；不从AST直接跨表读取IMP/COM业务表，不改ast_device.project_id及指派历史。
4. 现有安装历史防接管、来源指纹和有效区间保护继续保留。空地址行加入后可能比既存当前安装更新，不能覆盖旧当前区间以使导入成功。

## 待明确的业务语义

`BLOCKED_BY_SPEC`：空地址旧记录已经明确项目关联，但是否代表安装完成尚无明确契约。现有P33统一写status=2（已完成），且目标current_equipment_id由status=2、effective_to为空、未删除共同生成。直接放开地址过滤会把项目关联同时变成安装完成和当前安装事实，存在越界。旧表转移INSERT也可在未填写安装地址时建行，更不能仅据该行存在推定安装完成。

在这一点明确前，可以继续缺失来源字段和既有Owner查询边界设计，但不落空地址安装状态、不执行同步。此前“空地址过滤”历史裁决保留原记录，本次用户已明确要求项目关联不因地址为空丢失；尚需区分该关联要求与安装状态的映射。
