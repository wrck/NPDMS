# P33 普通安装历史及获准当前位置

本页列当前已保存配置、最新批准承接规则和实现缺口；不是可直接提交的生产任务配置。

- 业务Owner：IMP / AST；主要目标：`imp_eng_installation`、`ast_device_location`、`ast_address`、`ast_device`。
- 前置：P04、P17、P30；准备状态：TASK_ENTRY_MISSING。
- 业务/来源身份：原安装行id＋原项目；设备SN精确核实，位置历史以正式区间保护。
- 当前适配器：尚无已保存独立全量任务。
- 完整结构化配置与业务LOOKUP：[P33.json](../configurations/P33.json)。
- 原任务版本：只有既有Owner/材料入口，无统一全量任务。

## 适配器与通用任务的取舍

尚无独立全量任务，已有IMP安装及AST地址/位置Owner。安装记录、地址目录和当前设备位置需跨Owner原子衔接并保护较新位置，通用多步骤插表不等于完成该业务。

此项仍须补统一任务入口，复用现有领域Owner；不能把已有试点命令误报为可编辑、可全量分页的迁移任务。

## 承接顺序及处理规则

1. 保留原普通安装范围，原5项串货/转移字段按已批准暂缓列明。
2. 原SN只用于精确解析设备，原地址完整进入安装位置/快照及地址Owner。
3. 有地址使用已批准状态2，原createTime作为安装/生效时间；原更新时间NULL按既定规则回退。
4. 已有较新位置保留，仅补获准缺失当前位置；20/928试点数量不泛化到生产。

本项边界：

- 旧DppmsInstallationAddressImportService对非空命令直接拒绝；DppmsInstallationRecordMigrationService只处理已有DPPMS-来源键安装记录及完整baseline。生产首次创建/地址快照接入尚待补齐，不能仅复制现纠正任务。
- 原产品名称不再依赖DPPMS目录扩展；产品码关系按P12正式目录核对。
- 空/超长地址和多项目SN仍须逐源处理。

全任务共同规则见[processing-rules.md](../processing-rules.md)。

## 当前实现差异与验收

沿32列安装实体及正式位置Owner补首次迁入任务；旧DppmsInstallationAddressImportService对非空命令已拒绝，现DppmsInstallationRecordMigrationService要求已有安装及完整baseline，不能作为首次创建入口。须接正式安装/地址Owner完成首次创建与快照，再复用已批准的历史状态/区间和位置保护规则。空地址、超长地址另受既有未决约束，串货本轮不迁。

每条安装的项目、设备、原地址、区间及审计准确；历史承接与当前位置写入分别对账，不覆盖较新位置。
