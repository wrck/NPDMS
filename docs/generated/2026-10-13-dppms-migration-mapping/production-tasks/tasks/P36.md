# P36 设备软件版本历史

本页列当前已保存配置、最新批准承接规则和实现缺口；不是可直接提交的生产任务配置。

- 业务Owner：AST / PLT；主要目标：`ast_device_software_version_record`、`plt_entity_extension_value`。
- 前置：P04、P17、P35；准备状态：TASK_ENTRY_MISSING。
- 业务/来源身份：原软件记录id＋原项目；logId经P35来源绑定解析正式批次。
- 当前适配器：尚无已保存独立全量任务。
- 完整结构化配置与业务LOOKUP：[P36.json](../configurations/P36.json)。
- 原任务版本：只有既有Owner/材料入口，无统一全量任务。

## 适配器与通用任务的取舍

尚无独立全量任务，已有AST软件历史Owner与PLT扩展接入。原批次、8项Bak/Change、历史设备可空、原审计和当前版本保护不能用通用表写入替代。

此项仍须补统一任务入口，复用现有领域Owner；不能把已有试点命令误报为可编辑、可全量分页的迁移任务。

## 承接顺序及处理规则

1. 读取全部28原字段，按P17/P35核实项目与变更批次。
2. 版本、日期、状态及原customInfo进入正式31列表；8项Bak/Change进入已批准SoftwareVersionRecord扩展。
3. 有精确设备时补device_id，没有则保留原SN，历史不要求当前设备仍归本项目。
4. 不刷新当前设备版本，不生成升级/任务完成；后续人工变化或批次漂移阻断。

本项边界：

- 生产需发布自己的8属性扩展定义，不能复制旧definitionId。
- 旧software_observation/network_version_event不再承接。

全任务共同规则见[processing-rules.md](../processing-rules.md)。

## 当前实现差异与验收

沿正式31列、28原字段及8项批准扩展补一次性任务；重建扩展定义引用，logId精确关联P35。正式设备ID仅精确核实，缺失按批准保留SN。

历史版本、原Bak/Change和审计完整；不使用旧software_observation/network_version_event承接，不刷新当前设备版本。
