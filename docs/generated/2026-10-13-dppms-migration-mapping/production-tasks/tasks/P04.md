# P04 账号与任职资料

本页列当前已保存配置、最新批准承接规则和实现缺口；不是可直接提交的生产任务配置。

- 业务Owner：SYSTEM；主要目标：`system_users`。
- 前置：P01、P02、P03；准备状态：ADAPT_FIRST_IMPORT。
- 业务/来源身份：经批准的规范username；每个t/fnd来源身份分别绑定同一正式用户。
- 当前适配器：`DPPMS_USERS`。
- 完整结构化配置与业务LOOKUP：[P04.json](../configurations/P04.json)。
- 原任务版本：A04 / 2108524822998773762 v0。

## 适配器与通用任务的取舍

有专用适配器。三份来源合并、FND优先、真实EHR员工核验、历史共用联系方式和普通账号唯一性边界均属于IAM Owner；不能用通用UPSERT按姓名/电话合并账号或迁入旧密码。

专用适配器也是统一INT任务框架的业务提供方；“不用通用TABLE_MAPPING直写”不等于另起一套采集、分页、运行或回执系统。

## 承接顺序及处理规则

1. 联合读取t_user、t_user_info、fnd_user_info及EHR参考，排除密码字段。
2. 按已裁决账号范围合并：FND为主，t_*补缺；重复FND登录名按既定较新记录裁决。
3. 通过公司/部门/岗位与EHR真实工号核对，保留3个已批准员工例外；SYSTEM Owner保存正式账号及原审计。
4. 为每个来源身份维护独立绑定；不在本任务授予系统角色、项目访问或启用密码登录。

本项边界：

- 原isSysUser不是超级管理员标记；userCustom3/4等旧缺项不伪装为已迁。
- 迁移允许已裁决的历史共享邮箱/手机号，普通维护仍检查唯一；多账号手机号登录/找回不能任选。
- 当前旧配置对原admin审计引用的正式ID必须在生产重解；NULL审计首次即正确写入。

全任务共同规则见[processing-rules.md](../processing-rules.md)。

## 当前实现差异与验收

保留已批准账号范围、合并优先级和三项EHR例外；不读取旧密码。旧admin审计关联的正式身份须在生产核实，不能照搬ID1。首次写入即保留原NULL审计，不重放557项旧纠正证明。

账号资料和来源别名完整；原NULL/历史日期不被自动填充改写；角色、项目访问及认证激活分别受控。
