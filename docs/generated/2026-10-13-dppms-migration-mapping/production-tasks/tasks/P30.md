# P30 设备主档及项目归属衔接

本页列当前已保存配置、最新批准承接规则和实现缺口；不是可直接提交的生产任务配置。

- 业务Owner：AST / PROJ；主要目标：`ast_device`、`ast_device_project_relationship`。
- 前置：P12、P14、P17、P18、P28；准备状态：TASK_ENTRY_MISSING。
- 业务/来源身份：正式设备按租户＋SN；项目归属通过正式设备指派版本和Owner维护。
- 当前适配器：尚无已保存独立全量任务。
- 完整结构化配置与业务LOOKUP：[P30.json](../configurations/P30.json)。
- 原任务版本：只有既有Owner/材料入口，无统一全量任务。

## 适配器与通用任务的取舍

尚无已保存的独立全量DataSyncAdapter任务，已有正式导入/指派Owner。普通通用表写入不能替代最新发货核验、设备身份锁、现有项目归属及指派事务；缺的是统一任务接入，不是缺设备业务能力。

此项仍须补统一任务入口，复用现有领域Owner；不能把已有试点命令误报为可编辑、可全量分页的迁移任务。

## 承接顺序及处理规则

1. 以P28已迁发货事实和原项目来源关联核对SN、合同及全部发货内容。
2. 已有设备若已删除、当前项目不同或合同不一致则保留冲突；缺失设备还须核实最新发货。
3. 新设备采用既有IN_STOCK初始化，不推断安装/验收完成；产品名应按P12正式目录。
4. DeviceProjectAssignmentService维护设备与项目关系；后写入不抢占已有较新归属。

本项边界：

- 当前importShipment还可补缺ast_device_shipment既有字段；本包明确其辅助写入，不把P30仅列主表误认为没有副作用。
- 指派时刷新设备公司/部门投影；项目客户与设备客户同时非空且不一致时创建待对账记录，不覆盖设备客户。
- 旧通用条码主档自动投影不恢复。

全任务共同规则见[processing-rules.md](../processing-rules.md)。

## 当前实现差异与验收

现C01的DEVICE_SN只写发货事实，不能计为设备主档完成。复用已有DppmsAssetEntityImportApi和正式设备指派Owner边界，补统一任务入口；不得复活C05/C06旧通用条码写法。

SN身份、最新发货及当前项目归属分别核对；多项目竞争、较新归属或已删除主档冲突阻断，不按任务先后抢占SN。
