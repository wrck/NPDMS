## 为什么列表为空

ProjectManualCreationServiceImpl#getProjectPage调用ProjectTreeScopeService#resolveAllFullProjectIds。普通账号候选来自：有效且已确认的项目成员、本人创建项目、有效PROJECT_VIEW或PROJECT_MANAGE显式授权。目标两账号这三条路径都为空，因此discoverCurrentScopeTrees在anchors.isEmpty()处直接返回空集，尚未进入当前树批量读取。菜单权限和SYSTEM公司部门范围本身不是这段算法的项目候选来源。

具体代码：pms-module-project/.../service/projectscope/ProjectTreeScopeService.java的discoverCurrentScopeTrees及discoverGrantAnchors；ProjectMemberAssignmentMapper#selectActiveByUser明确要求authorization_confirmed=true并按区间过滤。缺主责引用还会影响后续办理，不能只靠人为范围授权让列表出现。

## 历史迁移与当前授权的边界

BASE_P31的P31MemberContactSyncTask明确只承接memberCode等历史字段，设置authorizationConfirmed=false，不给userId赋值。这与当前目标数据相符，是历史只读承接规则，不应改为“凡能按工号匹配就自动授权”。docs/decisions/open-questions.md的Q-LEGACY-MEMBER-20261008-001保留了独立批准的10项目主责/确认授权试迁记录；它和后续历史全量承接是不同义务。来源26条当前关系包含试迁及后续业务改派，须逐条追溯，不批量翻转381195条历史。

来源唯一显式授权ID2102348599087796225，主体970000000000091006，项目992203060019，PROJECT_VIEW/CURRENT_PROJECT；不是z01010/y06496，不能为修复经理列表复制该行。
