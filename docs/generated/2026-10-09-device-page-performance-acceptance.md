# 设备管理加载性能验收

- 用户请求：设备管理页面加载很慢。复用现有资产工作台与接口，不改变业务语义及授权范围。
- 环境：npdms_domain_test，前端19191、后端59191，实际路由 `/customer-asset/devices`。后端已部署，PID30236。
- 原因：百万级设备的合同权限候选及精确总数查询选择租户SN索引回表；权限OR条件先查询项目关系，组织已授权设备也产生大量相关子查询。
- 实现：组织投影权限优先判断；V416在线创建权限覆盖索引；仅无业务筛选的合同候选和总数扫描指定该索引，列表排序及有筛选查询沿用优化器。租户、软删除、合同大小写、有效项目关系及空权限拒绝全部保留。
- 修改前同一首页接口两次10.812/12.276秒，总数1,060,736；优化后两轮首页1.718/1.689秒，第二页2.030/1.606秒。项目1002优化后0.029秒，总数11。浏览器设备列表接口约1.595秒，包含资源加载及networkidle的进入耗时2.811秒。
- 验证：8项SQL/服务权限回归通过，后端package通过；真实Chromium登录，首页10行、下一页设备变化、精确SN一条、未知SN空结果、重置恢复全量列表均通过。没有创建、删除或改写业务记录。
- 迁移：真实数据库已执行V411～V415，与当前工作树文件不同；未repair或改写历史。使用Compose Flyway限定本次V416目录并忽略未提供的历史脚本，迁移成功。该结果不代表仓库全部历史迁移校验通过；其他环境部署此SQL前须先执行V416。
- 可复现入口：`.run/dac-host/accept-device-page-performance.py`，数据与截图在 `.run/dac-host/device-page-performance-acceptance/`；测试、构建、部署、迁移日志为 `.run/device-page-performance-*.log`。上述运行产物为本地验收证据。
- 范围限制：此次性能数字针对当前测试库与账号，不承诺其他数据规模或并发下相同耗时；不变更F-AST-001总体实施状态。
