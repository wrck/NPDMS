## 失败路径和接续升级

- **直接 SQL 非空库保护**：把整合 SQL 再送入非空验证库，命中 `chk_npdms_release_requires_empty_database`，没有覆盖表或数据。
- **Flyway 非空库保护**：新建仅含 `existing_marker=42` 的专用验证库，执行迁移被拒绝；仍只有原标记表及原值，没有通过自动 baseline 绕过。
- **不可变历史保护**：删除已发布割接配置 `970000000000442001` 被 `CUT_IMMUTABLE_HISTORY` 触发器拒绝。
- **管理员初始化失败**：不提供必需变量时拒绝执行，管理员仍停用且没有新增文件存储；修复了未定义 MySQL 用户变量以 binary 类型参与 REGEXP 的兼容问题后，该失败路径重测通过。
- **管理员初始化成功**：在验证库中使用临时随机密码生成的全新 BCrypt 哈希和验证地址执行，管理员启用，数据库存储数量为 1。随机明文和哈希未写入发布资产或验证报告。
- **初始化重复执行**：命中 `chk_bootstrap_refuses_existing_admin`，原密码哈希保持不变，没有重置已有管理员。
- **后续版本接续**：只在本次验证副本中加入 `V499__release_forward_probe.sql`，成功新增探针表；历史记录为 B498 和 V499 两条成功记录，validate 通过，再次 migrate 无待执行项。探针迁移不在正式发布包中。
