# 本机项目来源创建审计

日期：2026-10-07。基线：fda3bb55b0fb8e1fbd6f44f44cf4dbc21d015721。本报告只保留规则与源码定位，不包含旧源码正文、真实名单或凭据。

## 旧实现证据

- 旧 ProjectAction.insertProject:373 检查合同已建项目后调用服务；ProjectServiceImpl:150、418 在提交时重新查询来源，初始化项目、组、合同、成员与产品关系。旧 Spring 事务代理对 insert* 使用 PROPAGATION_REQUIRED。
- ProjectDaoImpl:155、sql-map-project-config.xml:1317 证明合同下有效订单通过 orderExecNumber 关联执行单。旧实现按订单行 ID 倒序取值；新同步模型没有同等旧 ID。用户明确创建只需订单和执行单基本信息，因此新入口选择合同下订单头，执行单随关系自动解析，不制造旧 ID。
- 名称、公司、销售类型及下单时间由订单和执行单来源提供；执行单带入销售、办事处、市场、系统、拓展、行业、客户项目名称与重大级别。源码规定的名称优先级由 CreationSourceResolver 复用并覆盖测试。
- 旧 projectcreate.jsp:309–310 的最终客户字段可编辑，非空检查处在注释块；不把注释当成旧系统强制规则。用户另行批准新项目独立选择最终客户 CUS 主档，同时保留合同、订单购货方。
- 旧 Project.java:90 的开始时间为指派项目经理时产生，不用订单日期伪造；旧状态、组关系、人员、角色和完成记录不直接转换为新生命周期、父子树、项目组合或 Gate 完成事实。

## 新旧路径与复用边界

仓库旧 `/pms/project` 路径不承接新功能。本次增强 `/pms/projects` 及 `/api/v1/pms/projects` 的既有新入口，共用来源预览组件，保留旧接口、旧数据和旧系统源码。

服务端复用现有公司及办事处联合授权、客户身份验证、模板匹配、模板实例化、状态初始化和平台幂等事务。新增合同/订单归属、公司一致性、唯一执行单关系、来源指纹及执行单占用锁校验；歧义或过期来源拒绝，不能靠前端传入值绕过。跨来源同号执行单没有可靠来源系统关联键时仍标为 BLOCKED_BY_SPEC。

重大级别保留来源值，不自行创造字典映射。购货方详情继续受商务敏感字段权限控制。最终客户不由合同购货方覆盖，来源刷新、切换与失败均保留人工独立选择。

唯一公共文件变更是用户精确批准的 DeclaredBusinessDeliveryBridge 显式构造器及两个 @Lazy 参数；不启用全局循环依赖，不改统一框架业务方法。
