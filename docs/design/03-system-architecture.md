# SDS Phase 1：系统架构

## 1. 架构结论

【建议】采用“模块化单体 + 领域模块 + 内部事件 + 外部适配器”的起步架构，基础平台提供认证、组织、字典、文件、待办、审计和工作流能力；业务域在同一系统内保持清晰边界。现有采集平台作为子应用或模块集成，不重复建设设备连接与原始采集引擎。

## 2. 系统上下文

| 系统/参与者 | 方向 | 平台职责 |
|---|---|---|
| CRM | 双向/事件 | 接收项目、客户、销售执行信息；回写项目关联结果 |
| ERP | 入向/回写 | 接收合同、订单行和交付范围；回写履约事实 |
| ITR | 双向 | 接收版本/故障/割接触发；回传割接结果 |
| 现有采集平台 | 双向 | 接收凭证/临时认证派生的任务授权，回调状态、日志和结果引用 |
| UMC | 按需 | 提供巡检结果解析或报告生成能力 |
| 钉钉/HR/OA/LDAP/AD | 双向或入向 | 协作、考勤、审批通知、身份和组织同步 |
| 用户浏览器/未来桌面端 | 入向 | 响应式 Web 工作台和后续多端复用 API |

## 3. 容器视图

1. 基础平台层：身份、组织、租户、字典、文件、待办、工作流、审计、通知。
2. 业务应用层：项目交付、割接、巡检服务、客户资产、设备档案、合同履约、资源外包、经营分析。
3. 集成适配层：CRM/ERP/ITR/采集平台/UMC/OA等适配器，负责协议、幂等、重试和对账。
4. 数据层：业务交易库、文件对象存储、审计日志和异步消息；具体表结构在 Phase 2 设计。

## 4. 依赖规则

- 业务模块不得直接访问其他模块 Repository。
- 集成适配器不得直接写业务表，必须调用目标域应用服务。
- 分析模块只读业务事实或快照，不参与交易状态变更。
- 采集平台执行身份不继承用户全量权限，只接受任务级短期授权。
- 前端优先响应式布局；桌面客户端作为后续端复用，不改变领域 API 契约。
