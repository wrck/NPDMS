# SDS Phase 3：性能与容量设计

> 文档状态：`IN_REVIEW`
> 适用基线：PRD V1.6
> Requirement ID：NFR-01、NFR-02、NFR-03、PM-02、PM-11、PLT-02、INT-12及全部核心页面/接口
> Owner：SDS Phase 3性能架构
> 前置设计：08、09、15、17、18分册

## 1. 量化门禁

| 指标 | PRD门禁 | 统计边界 |
|---|---|---|
| 核心页面/主要交互 | P95≤2秒 | 真实浏览器导航/交互；按场景、浏览器、视口分别统计 |
| 稳态服务端错误率 | ≤0.5% | 50个并发登录用户、持续30分钟、累计≥10000有效业务请求 |
| 并发 | ≥50用户 | 独立账号/会话，覆盖多办事处、多项目并行 |
| 文件 | 50MB完整上传/下载；超过50MB拒绝 | 文件传输单独统计，不混入页面P95；前后SHA-256一致 |
| 项目规模 | `max(迁移量×2, 20万)` | 实际迁移量和生成规则随dataSetVersion登记 |
| 任务规模 | `max(迁移量×2, 200万)` | 同上 |
| 树形 | 单项目树1万、单任务树5万、直接子节点2000、测试深度30 | 深度30是基准样本，不是业务限制；更深合法结构验证正确性和按需加载 |
| 巡检命令 | V2默认≤30秒，可配置 | 单命令执行；外部设备耗时单独记录，不作为V1门禁 |
| 通知/进度 | 到达率≥99%；项目进度≤60秒 | delivered/valid sent；事件发生至对应状态版本可读 |

任一核心场景P95、错误率、树查询、文件完整性或权限结果不达标即本轮失败；不得删除慢请求、改成功口径或用局部重跑替代整轮结果。

## 2. 测试环境与可比性

性能验收使用接近生产的独立环境、生产同版本制品和规定数据规模。每轮记录：

- releaseId/buildId、Git提交、JDK/Node/pnpm、应用/DB/Redis/文件/Telemetry版本；
- 节点数量和CPU/内存/磁盘/网络规格、数据库参数、连接池、缓存配置；
- 浏览器/驱动/负载工具版本、负载机规格和网络时延；
- dataSetVersion、迁移项目/任务量、树形分布、租户/组织/权限/设备/文件数据量；
- 预热/稳态/探索阶段、脚本hash、场景权重和随机种子。

【方向已确认：P3-E06】按ADR-0004建设独立近生产性能环境。测试、运维、数据Owner仍须提供环境规格及与生产差异、实际迁移量、网络条件、专用租户/账号和数据集生成证据；开发机空库或单用户结果不能作为发布验收。

## 3. 数据集模型

| 数据 | 最小分布 |
|---|---|
| 租户/组织/用户 | 多租户隔离样本；多办事处；项目经理、服务经理、工程师、外协、审计/管理员及无权账号 |
| 项目 | 总量按公式；含根/多层/宽节点/深链、主子项目、多期群组、组合和归档项目 |
| 任务 | 总量按公式；含5万节点树、2000直接子节点、依赖、不同状态和责任人 |
| 设备 | 当前唯一归属、历史归属、祖先投影、跨期复用、配置Log和维保客观事实 |
| 业务 | 到货/安装/风险/质量安全、交付件、验收闭环、割接、巡检、工单、合同范围 |
| 文件 | 小/中/50MB/超限、重复hash、中断会话、隔离和多版本引用 |
| 事件/集成 | Outbox/Inbox、重复/乱序/失败/待对账；CRM/ERP/ITR/DAC等响应时延和失败模拟 |

数据生成不得使用真实生产客户联系方式或设备凭证；安全场景使用唯一标记测试秘密。数据集生成完成后校验数量、树无环、设备唯一归属、订单不超分配、权限矩阵和来源版本。

## 4. 负载阶段

1. **环境校验**：运行健康、迁移、Telemetry、数据集和单用户业务正确性。
2. **预热**：使JIT、连接池、必要缓存和静态资源进入稳定状态；预热结果不计门禁，但时间和请求量必须记录。
3. **基线稳态**：50并发登录用户持续30分钟，累计不少于10000有效业务请求；不足请求量时该轮无效，不能延长后拼接不同环境数据。
4. **重复轮次**：相同环境/脚本/数据重复，比较运行波动；变化超过噪声需定位后重测。
5. **容量探索**：超过50并发逐级增加，记录错误、P95/P99、资源饱和和降级拐点；探索结果不替代50并发门禁。
6. **故障/恢复**：Redis、外部接口、消息、回调、文件扫描和投影延迟故障，验证降级、恢复和积压清理。

## 5. 核心场景模型

| 场景组 | 操作 | 关键测量/断言 |
|---|---|---|
| 登录/工作台 | LDAP/AD模拟登录、权限加载、待办/项目列表 | 页面P95、认证/权限耗时、拒绝正确性 |
| 项目/任务树 | 直接下级、全部后代、完整上级链、业务层级、节点定位、移动后查询 | P95≤2秒；无N+1；treeVersion稳定；权限过滤正确 |
| 项目交付 | 创建/查询、准备、方案、到货、安装、证据、验收闭环 | 页面/API分段延迟、状态守卫、DB/文件/事件耗时 |
| 合同/设备 | DeliveryScope分配、设备归属/祖先汇总、档案查询 | 锁等待/冲突、索引命中、去重口径 |
| 割接 | 任务、评估、方案、审批、步骤执行、观察 | 页面P95、命令/事件/文件延迟；不包含平台通用时效 |
| 巡检/DAC | 任务创建、授权校验、下发、回调、业务消费；V2命令超时 | 平台处理时间与外部执行时间分离；结果不提前完成 |
| 文件 | 50MB上传/下载、超限、中断/重试、hash | 完整性、吞吐、内存/临时空间；单一有效版本 |
| 通知/事件 | 五节点通知和巡检进度事件 | delivered比率≥99%，进度≤60秒，重复/乱序正确 |

实际场景权重由已批准业务流量/验收脚本登记；无生产数据时使用明确的验收权重并保存，不声称代表生产分布。

## 6. 测量边界

- 浏览器端：DNS/TLS、TTFB、资源加载、Vue渲染、API waterfall、主要交互完成时间分别记录；PRD P95以用户可感知完成为准。
- 服务端：按routeTemplate统计处理P50/P95/P99、错误类别、DB/Redis/文件/外部/队列span；不能只看平均值。
- 外部系统：平台排队/调用与外部自身耗时分离；外部故障按12/16降级单独验收，不把外部慢请求删除后计算平台成功。
- 文件：传输时间、扫描、提交版本分别统计；50MB不混入普通页面P95。
- 冷启动：单独报告；稳态门禁不以冷启动失败掩盖，发布启动时间在18验证。

## 7. 瓶颈诊断顺序

1. 先确认业务/权限结果正确及Telemetry完整，避免“少做工作”的伪优化。
2. 浏览器慢：检查API waterfall、包/资源、长任务、重复渲染和页面级大DOM；保留四视口响应式正确性。
3. API慢：通过Trace定位DB、锁、Redis、文件、外部、队列；检查N+1、无界列表和无索引排序。
4. 树慢：核对路径投影/水位/分页和permissionScopeHash，禁止改成固定深度或绕过权限。
5. 并发慢：检查连接池、行锁/死锁、乐观冲突、热点key和Outbox积压；不能放宽唯一键/状态守卫。
6. 每项优化先保存基线，单一变更后以同环境/脚本/数据重测；未超过运行噪声或破坏测试则撤回，并登记尝试。

## 8. 报告与发布判定

报告包含环境、数据、脚本、样本量、每场景成功/失败、错误率、P50/P95/P99、资源、慢请求/Trace、文件hash、树正确性、浏览器/视口和容量拐点。原始结果不可覆盖；复验生成新reportId并引用整改项。

| 结论 | 条件 |
|---|---|
| PASS | 全部V1/V2适用门禁达到，权限/数据/状态正确，无内存溢出或持续不可恢复增长 |
| FAIL | 任一门禁失败、环境/数据不合规、Telemetry缺失、脚本改口径或原始结果不完整 |
| INCONCLUSIVE | 外部/环境故障使有效样本不足；保留失败证据并完整重跑，不判PASS |
