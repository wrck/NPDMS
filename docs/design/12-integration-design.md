# SDS Phase 2：集成设计

> 文档状态：`BASELINE`
> 适用基线：PRD V1.8（`docs/baseline/prd-v1.8.md`）
> Requirement ID：INT-01～INT-07、INT-09～INT-10、INT-12，以及 COM-01、EQP-04、CUT-08、INS-05、AUT-01～02 等关联业务需求
> Owner：SDS Phase 2 集成架构；业务数据 Owner 继承 `02c-data-ownership-matrix.md`
> 前置设计：`08-data-model.md`、`10-api-design.md`、`11-event-design.md`

## 1. 集成原则

1. 每个接口登记系统 Owner、方向、权威字段、来源键、版本、幂等键、超时、重试、补偿、对账、降级和审计。
2. 必要主数据同步到平台本地副本，日常查询不依赖逐次远程调用；页面展示来源和数据截止时间。
3. 协议成功不等于业务完成。必须收到契约规定的业务单号、回调、状态或对账结果后推进平台状态。
4. 集成适配层只做协议、映射、验签、幂等、重试和对账，不拥有领域业务状态。
5. 外部字段映射版本化；未知字典值进入待映射，不用默认值静默吞掉。
6. CRM 是统一系统名称，不再使用 SMS 表示另一客户系统。
7. 400 热线和外部文档管理系统属于 V3 演进，不进入当前实施契约。

## 2. 通用接口配置档案

【方向已确认：P3-E07】按ADR-0004建立平台级接口配置注册表，Feature仅引用已批准的不可变配置版本；注册表保存配置元数据与秘密引用，不保存秘密值。各接口的真实地址、认证、白名单、数值型超时/重试和联调结果仍按Feature提交证据。

每个接口实例必须注册：

| 分类 | 配置项 |
|---|---|
| 身份 | `interfaceCode`、系统 Owner、技术 Owner、环境、版本、方向 |
| 地址 | base URL/topic、网络区、DNS/TLS、代理、允许来源 |
| 认证 | OAuth/client credential、mTLS、签名或服务账号；秘密只存配置中心/密钥服务 |
| 映射 | schemaVersion、字段 Owner、字典映射版本、时区/单位/精度 |
| 可靠性 | connect/read timeout、最大尝试、退避、熔断、并发上限、限流 |
| 幂等 | sourceKey、eventId/requestId、业务版本、回调 ID |
| 恢复 | 查询结果接口、补偿命令、对账频率、人工待办、降级入口 |
| 审计 | 请求/响应摘要、状态码、批次、重试、操作者、脱敏规则、证据引用 |

【待接口联调登记】具体 URL、认证材料、数值型 timeout/retry/limit 和网络白名单由各外部系统技术 Owner 在 Feature 实施前登记到环境配置及接口证据清单；本分册不臆造外部 SLA。未登记的接口不得进入联调或生产门禁。

## 3. 通用处理链

```text
触发/拉取/回调
→ 来源身份与签名校验
→ Schema与必填校验
→ 来源键/事件ID/版本幂等
→ 字典与字段映射
→ Owner Context应用命令
→ 记录批次/单项结果
→ 发布同步结果事件
→ 对账与隔离处理
```

- 入向旧版本：记录并忽略，不回退本地副本。
- 入向同版本不同内容：隔离为来源冲突，不覆盖。
- 出向超时：先查询外部结果；不能确认未处理时不得盲目重发产生重复业务。
- 批量部分失败：成功项提交，失败项保持原批次关联并逐项重试；汇总状态为部分失败。
- 人工补录：显式 `sourceSystem=PLATFORM_MANUAL`、原因、证据和待对账标识，不伪造外部标识。

## 5. CRM / ERP：项目、客户、合同订单与履约

适用 Requirement：INT-01、INT-03、COM-01、CUS-01～04、EQP-03。

### 5.1 权威字段

- CRM：客户核心字段、项目销售执行信息、商机、产品停产停维及 CRM 合同经营状态/履约回执；CRM 保存的合同订单引用用于与 ERP 来源键关联，不得覆盖 ERP 核心值。
- ERP：正式合同、销售订单、订单行、产品明细、数量和金额等核心来源事实；合同业务身份优先使用“所属公司+合同编号”。
- 平台：项目交付状态、团队、项目/任务树、订单行到项目的 DeliveryScope、实施/验收事实和平台扩展字段。

冲突按字段 Owner 处理，不做整对象“最后写入覆盖”。该边界以 PRD 已确认 Q-02 及 INT-01 的字段 Owner 为准：COM-01/02 中出现的“CRM合同订单”在 ACL 中解释为 CRM 经营引用/履约接口，ERP 合同订单核心副本仍是分配数量和商务字段的权威来源。CRM客户权威字段只读；平台交付联系人、服务偏好、标签和备注独立版本。

### 5.2 可靠性

F-PROJ-004只冻结实际消费的属性来源/版本和匹配决策，不实现CRM自动建项、来源定位或INT重试。未来自动创建编排必须在Project、INITIAL_CREATE历史、模板冻结和实例化的同一事务中消费判定结果；预置项目不能作为INT端到端完成证据。

INT完成来源定位后可按稳定`projectId`调用PROJ内部`ProjectAttributeSourceCorrectionCommand`，只提交CRM Owner字段及来源键/事件/版本/发生时间/原值摘要；命令以服务身份和幂等键原子更新当前值并追加SOURCE_CORRECTION历史。该命令不承担来源定位、传输重试或对账，INT不得直接访问PROJ表或Service/Mapper/Repository。

- 入向以对象ID、事件ID和源版本去重；旧版本忽略，同版本内容冲突隔离。
- 项目/合同/订单无法匹配时进入待核对，不能以空关联创建完整项目。
- 对账比较订单数量、已分配量、履约数量、状态和日期；差异由授权人确认关闭。
- CRM不可用时展示最近成功值、截止时间和异常标记；不阻断平台交付扩展字段维护。平台不因CRM经营回执缺失而伪造履约事实或建立COM-02对象。

## 6. ITR / MES / 技术知识与设备

适用 Requirement：INT-02、INT-04、EQP-04、CUT 外部来源能力。

- ITR版本与技术公告按 ITR ID + sourceVersion 实时同步；产品、版本、公告级别未知值进入映射队列。
- KNO V2 只保存只读公告镜像和业务引用；邮件/钉钉补录只作为通知/待核对证据，不成为权威公告。
- INT-04唯一拥有技术公告同步、镜像和引用；INT-02只承接V1设备版本/割接任务入向及V2故障入向、ITR来源CUT归档结果出向，不以公告能力关闭INT-02。
- MES设备按序列号和 MES对象ID幂等；序列号冲突时隔离，不自动合并设备。
- ITR触发割接任务时保存来源事件、设备/项目匹配结果；匹配失败任务不进入评估。
- ITR出向结果仅在对应 V2 Feature 启用后使用；接口预留不等于业务已交付。

## 7. 钉钉 / HR / OA / LDAP-AD

适用 Requirement：INT-05、INT-09、AUT-01、SUB-01～05、NFR-01～02。

### 7.1 钉钉与 HR

- HR组织、人员、岗位和在离职必要主数据同步到基础平台本地副本；来源恢复后以来源版本校准，不静默覆盖本地临时映射历史。
- 人员或组织不能唯一匹配时进入待处理，不自动绑定同名记录；离职不删除历史责任、审批和操作证据。
- 钉钉只承接平台待办/通知链接和送达状态；钉钉不可用时使用站内消息，通知结果不推进审批或业务状态。
- 打卡、通用工单和工时事实不属于INT-05当前V1/V2契约；未来只能按P3独立需求重新评审。

### 7.2 OA

- 授权再次申请：平台拥有申请状态，OA拥有审批实例和结果，授权系统拥有最终授权结果；三者必须分别确认。
- 转包：平台内独立审批，OA只接收代办链接，不得用 OA 待办完成替代平台审批。
- V2领料/外采：平台按业务对象和版本创建OA流程引用、展示办理链接并同步结果；OA结果只能回填对应申请事实，不得直接改写平台审批或业务状态。
- OA不可用时申请保持待审批/待通知，平台内可继续的审批按 PRD 运行；不伪造OA实例号。

### 7.3 LDAP/AD

- 认证成功后建立平台会话并加载平台 RBAC 与数据范围；目录组不直接等同于项目业务角色。
- 回调/断言校验 issuer、audience、时效、签名和重放；账号映射唯一。
- 受控本地账号降级由安全策略启用，不能共享管理员账号；恢复后不自动合并不确定身份。

## 8. 备件 / 授权 / UMC

适用 Requirement：INT-06、CUT-08、AUT-01～02、INS-05、AST-01。

### 8.1 备件

外部系统拥有申请、库存、发货、借还、补库、调拨和 RMA 事实；平台只保存申请映射、RMA替换关系、门禁、回调和对账。失败走线下申请后补录，必须关联原业务单据和核验结果。

CUT-08由CUT保存平台请求、外部申请引用、原始状态版本和人工证据；INT-06 Integration ACL拥有连接器、认证、超时及第三方字段映射。CUT发起使用稳定平台requestId和Idempotency-Key，携带任务、项目、设备及冻结需求来源；INT-06接受发起时必须返回不可变externalRequestId，并可返回launchUrl、externalApplicationNo和原始状态。只有跳转地址时保持`REQUEST_PENDING`；后续由INT-06按受信tenantId、platformRequestId、externalSystemCode和externalRequestId调用`bindExternalReference`首次绑定申请号，并在同一CUT事务内原子迁移为`EXTERNAL_REFERENCED`，同值重放返回既有`EXTERNAL_REFERENCED`且不写业务行，身份错配、不同申请号或已绑定仍为`REQUEST_PENDING`均失败关闭。只有非空外部申请号才允许状态回调或显式刷新；超时/结果未知保留`RETRY_PENDING`并按同一平台requestId查询或重试，不创建第二个意图。

回调身份固定为受信租户、externalSystemCode、externalApplicationNo、eventId和正数单调statusVersion。同eventId同载荷重放、异载荷冲突；同申请同版本同载荷重放、异载荷冲突；低版本只审计，高版本追加并成为当前快照。原始状态不映射为CUT库存、审批、到货、领用或P6门禁。生产INT-06尚未实现时，CUT实现只保留端口并在测试域用确定性替身完成正向闭环；线下证据经PLT文件事实关联，恢复后必须按外部申请号核验，不冒充接口成功。

### 8.2 授权系统

平台保存授权申请、OA审批引用和授权ID掩码；授权系统保存 License/授权结果。接口响应、日志、事件和报表不含完整授权码。超时按申请ID查询结果后再重试。

历史 `pms_eng_authorization.license_key` 不能直接迁移为设备连接凭证或外部授权真值；必须先按来源和用途分类并能够安全重加密，否则只保留隔离证据。

### 8.3 UMC

UMC只负责巡检结果解析和报告文件生成；设备连接和原始采集统一由 INT-12。平台以报告任务ID下发，回调验签并按版本幂等；UMC不可用时使用 INT-12 回调结果生成基础报告或转人工，不重复采集。

## 9. 财务集成

适用 Requirement：INT-07、SUB-04～05。

- 只有已批准费用版本且付款门禁满足时允许出向。
- 幂等键为费用单ID+批准版本；财务业务单号是外部结果引用。
- 金额、币种、供应商、项目、合同或阶段不一致进入待核对，不自动覆盖。
- 超时先查询财务结果；无法确认时保持未知/待核对，不重复入账。
- 降级导出保存 FileArtifact版本、SHA-256、导出范围和操作者；人工回填需财务凭证和复核。

## 10. 短信 / 邮件与通知

适用 Requirement：ACC-01@V2、ACC-02@V2、CUT-05@V2、INT-10、NFR-03。

- 通知幂等键为业务对象+节点+渠道+接收人+模板版本。
- 模板变量白名单渲染；禁止设备密码、密钥、完整授权码和非必要客户敏感信息。
- 接口受理、渠道送达与业务完成分别记录；未知送达状态不重复轰炸。
- 渠道失败时站内消息立即保留，按策略使用钉钉兜底；通知失败不延长或改变业务节点状态。

F-CUT-008对每次P5节点激活继续保留F-CUT-005站内通知，并追加`SMS/EMAIL/DINGTALK`三条渠道记录。CUT只传受信租户、recipientUserId、内部任务链接、白名单变量、deliveryKey和correlationId；手机号、邮箱、钉钉账号及密钥由INT-10/INT-05物理Owner解析。第三方接口只预留消费端口，生产Provider缺失时外部投递Job保持暂停；CUT以受控替身验证受理、明确失败和未知结果，不注册生产Fake。精确合同见`specs/features/F-CUT-008-external-notification-contract.json`。

## 11. Device Access & Collection 子应用集成

适用 Requirement：INT-12、EXE-03～04、CUT-03、CUT-06、INS-02/04、NFR-02。

### 11.1 信任边界

- 平台 DAC 持有 DeviceCredential、CredentialGrant、CollectionTask、DispatchAttempt 和 CallbackRecord。
- 采集子应用持有实际连接、命令执行和原始采集过程；不取得用户/管理员全量权限。
- 每次下发签发任务级、短期、不可复用的执行授权，绑定平台任务ID、设备、协议、命令模板版本和失效时间。
- 凭证明文只在经认证且获当次任务授权的执行进程内临时使用；临时密码不持久化、不记录日志、不进入消息。

### 11.2 下发契约

平台请求包含：平台任务ID、设备连接目标、协议、命令模板及版本、执行授权、回调地址/主题、幂等键；认证材料通过受控秘密通道传递。外部平台以平台任务ID幂等，返回外部任务ID和受理状态。

### 11.3 回调契约

回调包含：外部任务ID、平台任务ID、callbackId/序号、外部状态原值、结果引用、哈希、执行时间、失败分类和签名。平台校验来源、签名、授权任务、顺序和幂等；状态未知时保留原值并进入映射，不默认成功。

### 11.4 恢复

- 下发超时先按平台任务ID查询；确认未创建后才重试。
- 回调丢失通过状态查询/对账补偿；重复回调不重复消费。
- 失败重试创建新 CollectionTask 并引用原任务；临时密码重新输入。
- 子应用不可用时任务保持失败/待下发；IMP/CUT/INS 不伪造结果或绕过强制门禁。
- NFR-02@V2在线巡检命令超时时，当前命令必须终止并标记失败；后续命令是否继续只读取任务冻结的已发布规则，记录规则版本、继续/停止决定和实际执行结果，不固定假设全部继续。

### 11.5 割接 P3 工作台消费

- CUT-03 在 P3 动态清单工作台中创建 `CollectionTask`，不得另建“采集阶段”或跳转到通用采集任务壳。
- DAC 回调只形成原始采集结果和技术执行状态；CUT 根据清单项、设备、规则版本及业务校验形成 `CutoverChecklistItemResultLinked`，回填到当前清单项。
- 回调成功不等于清单项业务通过；验签、哈希、任务/设备匹配、结果解析或人工复核任一失败时，清单项保持未完成并展示失败原因与可用人工补录入口。
- 条件变更触发重新匹配时，已回填结果仅可由稳定清单项标识复用；退出适用范围的旧结果保留历史引用，不得静默挂接到新项目。

## 12. 对账与运维接口

每个集成至少提供或实现等价能力：

- 按 sourceKey/requestId 查询外部处理结果；
- 按时间水位拉取变更或全量校准；
- 查看同步批次和失败单项；
- 原批次/原幂等范围重试；
- 导出差异和导入人工核验结果；
- 隔离来源冲突、未知字典和验签失败；
- 按关联 ID 查询脱敏请求/响应摘要。

集成管理员可处理映射、重试和对账，但不能修改外部权威业务值、代业务审批或读取秘密。

## 13. 审计与敏感数据

记录接口代码、方向、批次、来源键、版本、请求/响应摘要、状态码、耗时、尝试次数、错误分类、对账结果、操作者/执行身份和 traceId。姓名、电话、邮箱、金额、授权ID按字段权限脱敏；密码、私钥、Token、License全文和认证头永不落入业务日志。

## 14. 集成门禁结论

| 门禁项 | 结论 | 说明 |
|---|---|---|
| 系统/字段 Owner 明确 | PASS | 第 4～11 节 |
| 来源键、版本和幂等明确 | PASS | 各系统契约与通用处理链 |
| 补偿、对账、降级明确 | PASS | 第 3、5～12 节 |
| 敏感信息边界明确 | PASS | 第 11、13 节 |
| 数值超时/重试及环境端点 | DEFERRED_TO_FEATURE_INTEGRATION | 由各外部技术 Owner 在对应 Feature 联调前登记接口配置档案，不阻断 Phase 2 结构契约 |

业务集成结构已经具备进入 Feature 设计的条件；任何具体外部接口在未完成配置档案和联调证据前不得宣称 READY_FOR_PRODUCTION。
