# ADR-0022：核心迁移模型边界与键策略

## 状态

ACCEPTED

## 日期

2026-08-13

## 适用范围

- Requirement：全部需要历史数据迁移的V1/V2需求、INT-04；KNO-V3-01～KNO-V3-08仅作排除边界。
- 门禁：P3-E09 / AI-MIG-000。
- 前置决策：ADR-0001、ADR-0019、ADR-0020、ADR-0021。

## 背景与证据

当前`project-order-physical-schema.mysql.sql`来自项目—合同—订单—设备迁移设计，虽已扩展到多个领域，但不能据此宣称已经穷尽平台全部领域表。PRD同时明确：INT-04在V2提供ITR技术公告同步与只读引用；KNO-V3-01～08才建设公告编写、会签、命中、治理任务和统计闭环。

旧库存在一源多目标、同一业务键多义、重复SN生命周期事件、可空结束时间及逻辑删除记录。若把这些事实简化为单目标映射、可复用业务键或`UNIQUE(..., effective_to)`，会产生不可追溯归并或无法约束“仅一条当前记录”。跨领域物理外键还会把不同Owner的发布、迁移和删除生命周期强耦合。

## 决策

1. 当前物理DDL是`CORE_MIGRATION_SUBSET`，不是平台全量模型。后续Feature可在正式需求和SDS约束下使用前向迁移增加领域表。
2. `kno_technical_advisory`、`kno_technical_advisory_read_record`、`kno_technical_advisory_product_relation`、`kno_device_technical_advisory_match`属于V3治理设计，不进入V1/V2核心迁移DDL。
3. INT-04的`TechnicalNoticeReference`逻辑契约继续有效。V2 Feature只实现ITR权威数据的同步副本、来源版本、发布状态和业务引用；不得借此提前实现V3编写、会签、命中治理或统计。其最终物理表由INT-04 Feature前向迁移单独评审。
4. 同领域、同聚合内部允许物理外键；跨领域统一保存逻辑ID与必要快照，通过Owner服务校验、同步对账、拒绝场景和审计保证一致性，不建立物理外键或跨域级联写入。
5. `plt_external_key_mapping`支持一条来源映射多个目标。每个目标保存`target_role`和从0开始的稳定`target_sequence`；角色默认`PRIMARY`，同一来源下目标顺序不得因重跑改变。
6. 需要约束“仅一条当前记录”时，使用由有效状态、`deleted`和`effective_to is null`计算的生成标记列建立唯一键；不直接依赖MySQL可空列唯一键语义。
7. 业务编码入库前执行`trim + uppercase`；外部不透明ID、来源键和哈希按原值精确匹配；名称使用支持中文的Unicode不区分大小写排序规则。不可修改逐源行原始载荷来满足归一化规则。
8. 项目编码、合同业务键、销售订单业务键、设备SN和来源稳定键一经占用，在删除、停用或关闭后均不得复用。其唯一键不得包含`deleted`作为释放键位的手段。
9. 历史数据违反目标唯一性、外键解析或归一化规则时，写入`plt_migration_issue`并引用不可变`plt_migration_source_record`；禁止修改旧库、静默删除、猜测目标或临时放宽目标约束。

## 影响

- 迁移核心DDL将移除4张V3治理表和跨领域物理外键，但保留逻辑引用列、查询索引及Owner校验责任。
- 外部键映射增加目标角色与稳定顺序，允许一源多目标和多源归并同时追溯。
- 目标表数量下降不代表需求或领域对象被删除，只代表核心迁移子集边界更准确。
- P3-E09的1,883项表、列、同域约束、索引、CHECK及表选项均已有决策证据；当前新候选待fresh review核对制品哈希和整体一致性，上一轮GO不覆盖本轮复审校验变更，不要求数据架构、业务Owner和迁移Owner逐项签署。P3-E09不定义迁移批准哈希；AI-MIG-000、历史迁移和数据切换继续阻断。

## 拒绝的替代方案

### 将当前DDL认定为平台全量模型

拒绝。会把后续Feature表误判为遗漏，并诱导在迁移阶段提前实现V3。

### 保留跨领域物理外键

拒绝。会将不同Context的迁移顺序、删除策略和发布节奏耦合，绕过Owner服务的一致性规则。

### 业务键唯一索引包含`deleted`

拒绝。逻辑删除后可复用同一编码，会破坏历史审计、外部回调、旧链接和来源映射的稳定含义。

### 直接用`effective_to`建立当前唯一键

拒绝。MySQL唯一索引允许多个NULL，无法保证仅一条当前记录。
