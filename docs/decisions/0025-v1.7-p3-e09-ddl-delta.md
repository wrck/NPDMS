# ADR-0025：V1.7 P3-E09 物理模型差量

> 2026-08-14割接增量说明：本文中`CUT-11`、`CutoverSupportTask`、`ResponsibilityInterval`及其三张候选表已由ADR-0027取代；其余领域差量与排除规则继续有效。当前有效割接物理模型以ADR-0027为准。

## 状态

`PROPOSED_FOR_REVIEW`

P3-E09当前模型为`MODEL_BASELINE_READY`。本ADR曾固化61表候选，后由ADR-0027纠偏并重建为当前60表DDL；整体一致性独立复审已`GO`。该结论不替代`AI-MIG-000`真实批次验证，也不授权历史迁移或数据切换。

## 日期

2026-08-13

## 需求依据

PRD V1.7：`ACC-02`、`CLO-01`、`CLO-02`、`SUB-03`、`SUB-04`、`CUT-11`、`EQP-01`、`EQP-02`、`EQP-03`、`EQP-05`、`EQP-07`、`EXE-03`。INT-05/INT-09 的人员、部门、岗位主数据复用基础平台现有主数据，并由已有 `plt_sync_batch` 和 `plt_external_key_mapping` 承载同步批次/水位及来源键映射，不新建目录快照表。

## 决策

核心迁移 DDL 从 50 表扩展为 61 表，V1.7 当前差量为 11 表：

| 对象 | 新增目标表 |
|---|---|
| ConfigurationCollectionResult | `imp_configuration_collection_result`、`imp_configuration_collection_parse_attempt`、`imp_configuration_component_candidate` |
| SatisfactionCollection | `acc_satisfaction_collection_task`、`acc_satisfaction_questionnaire`、`acc_satisfaction_response`、`acc_satisfaction_result` |
| CutoverSupportTask | `cut_cutover_support_task`、`cut_cutover_support_history` |
| ResponsibilityInterval | `cut_cutover_support_responsibility_interval` |
| DeviceComponentRelation | `ast_device_component_relation` |

- 配置采集结果保存任务、项目/设备快照、脚本/解析器版本、原始整机 Log 文件引用与哈希、结果版本和来源；解析尝试与候选归属结果根，候选另存 parse revision、板卡配置引用和证据。
- 满意度任务唯一粒度包含项目、来源对象及版本、业务用途、适用时点、可空付款阶段生成键和任务 revision；冻结交付范围、问卷规则及逐项校验，保存答卷/签字有效性、阻断原因与归档事实，不新增审批。
- CUT-11 只由当前平台受控命令创建；任务保存项目、设备范围快照、当前责任人、当前处理人和当前责任区间。责任区间以 `effective_to IS NULL` 生成当前标记并唯一，应用层在同一事务内执行不重叠守卫；状态值保持可扩展。
- 设备组件关系保存机框、槽位、板卡、关系来源、证据和生效区间；当前槽位唯一，换板关闭旧关系并追加新关系。

## 明确排除与后置

需求方于 2026-08-13 明确确认 `pm_project_maintenance` 全表不迁移。不得因字段相似将任何行归类到 CUT-11 或其他业务对象，不生成字段级绑定、状态映射或目标写入。机器契约仅在顶层 `excludedSources` 保留 `EXCLUDED/NO_MIGRATION` 表级审计；行数和提取批次 SHA-256 在取得可核验证据前保持空值和 `PENDING_EXTRACTION_AUDIT`。

PRD 第 8.2 节“历史业务事实不可删除”仅作为治理规则保留。当前未识别并确认真实历史工单/工时来源，因此不建立历史工单、历史工时对象或空壳表；将来只有在来源识别且需求方确认迁移后，才通过独立变更重新建模、评审和执行。

`plt_directory_sync_snapshot` 不进入当前对象或 DDL。INT-05/INT-09 复用基础平台主数据、`plt_sync_batch` 与 `plt_external_key_mapping`；该决策不触发任何替代表新增。

机器禁止清单覆盖 V3/OOS/已后置/已排除表，包括通用工单及 SLA、历史工单/工时空壳、续保、日报/周报、KNO 治理表和目录快照表。当前每张 DDL 表必须精确回指至少一个 V1/V2 Requirement 或 ADR-0022 已接受的公共迁移技术规则。

## 边界与批准条件

- 跨 Context 只保存逻辑引用，不新增跨 Context 外键；旧 `dppms` 只读，不执行旧库 DDL/DML，不使用跨数据库 SQL。
- 全部派生迁移证据必须与同一 DDL SHA-256 一致，并在隔离 MySQL 8.4 执行成功。
- 当前DDL、逐项裁决、隔离执行和整体一致性独立复审已完成，形成P3-E09模型基线输入。`AI-MIG-000`、历史迁移和数据切换继续`OPEN`，未经真实批次验证不得执行。
