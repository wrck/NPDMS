# ADR：模板执行采用版本优先和业务原生接入

日期：2026-09-17。状态：需求方本会话明确要求后的技术设计决定，待按计划实施。适用 PM-03；不改 PRD 业务权限、状态、Owner 或生命周期语义。

## 依据

需求方要求：权限码对应业务操作，复用实体/业务输入，页面 URL 配置；不要增加多层校验 Hash，使用版本；先修改方案提交指定分支，再按新计划实施。旧基线位于提交 75dfa7d98cade30f708759720400e6b8c01e5ec0。

## 决定

1. 一个模板发布版本冻结完整执行配置。新增执行/呈现/产物 Hash、hashProfile、policyHash、selectorHash 不再实施。旧快照及既有基础设施摘要按旧协议保留，不将其升级为业务侧字段。
2. 权限码复用现有授权体系，不天然等于唯一命令。Owner/实体范围内唯一直选；共用权限使用已有动作标识消歧。目录选择不是授权结果，提交仍核对真实权限/范围。
3. 不默认给所有操作加能力/操作/输入/输出的独立版本组合。底层已存在版本兼容保留，由发布解析冻结；真实不兼容升级才独立区分，不能默选最新。
4. 复用原业务 DTO 或实体引用；业务提供自己的身份、真实并发依据和结果。项目维护自己的计划、节点、轮次、证据；适配生成事件/追踪，不让业务补造修订、历史或技术 Hash。
5. pageUrl 仅作为展示路由。首批为已登记站内页面；安全参数映射、路由授权保留，不允许任意 URL 调用业务写入、不传主体/凭据进查询串。
6. 结果订阅独立于操作和页面；能力缺少历史只限制相应证据政策，不要求每个业务实现一套事件/游标平台。

## 与现行 SDS 的衔接

`docs/design/04a-template-compilation-runtime.md` 的 5.3、8.1 中 snapshot_hash 及相应测试继续约束历史已实施格式。本决定规定新版本路径不新增多层 Hash，必须用完整快照、不可变发布和版本 Reader/Writer 实现相同的历史解释要求。P1.02 在改实际发布/读取契约前同步修订受影响 SDS 段落与数据/API 定义；未接线前不移除旧方法或强行发布新格式。

本阶段权限目录的原响应与运行 API 先保持兼容，新增配置解析能力不得绕过原命令。确有新增/改变公开接口时，在该环节同提交修订适用 API 设计，不借本 ADR 自动批准任意新端点。

## 取舍及验证

减少独立技术配置，换取发布版本不可原地修改的强约束。权限共用必须明确动作，不能简化为宽泛 writable。版本不能代替业务授权、旧轮次隔离或幂等键；不加 Hash 不等于取消安全检查。

设计/实施详见现有路径下 v1.1 两份文件。按完成环节提交，实际测试与真实验证分开。未知能力、确定失败、发布未接线均不能标验收通过。
