# ADR-0026：割接业务流程基线纠偏

## 状态

`ACCEPTED`

## 日期

2026-08-14

## 需求依据

- 需求方确认以`需求/割接0807需求分析报告.md`第七部分“业务流程设计”为本次割接流程纠偏的高置信来源；本次不读取原始Excel。
- PRD V1.7：`EXE-06`、`CUT-01`～`CUT-10`、`INT-12`。
- 需求方确认：`CUT-01`即贯穿P1～P6的割接核心任务；原`CUT-11`属于把工单语义整体改名迁入割接的错误设计，应退出CUT和当前V1/V2，后置到工单领域。

## 决策

1. `CUT-01 / CutoverTask`是割接领域唯一核心任务，承载P1任务接入、P2等级确认、P3调研及风险考察、P4方案、P5审批、P6跟踪闭环与归档。
2. 删除当前正式需求`CUT-11`及`CutoverSupportTask`、责任区间、接管、转单、挂起等工单语义。`WO-06`作为工单领域V3候选保留来源追溯，未来须重新批准Owner、角色、状态、责任、证据和关闭规则，不得复用CUT对象或状态。
3. P2采用问卷形式。平台项目上下文提供输入，一线工程师提交问卷与人工等级，用服经理仅在P5审批中复核，不增加P2审批节点；自动建议等级保持V3演进。
4. P3未匹配配置规则时，一线工程师可补充自定义项并标记配置缺口，不阻断整个割接流程。
5. P4上传完整方案只校验文件、安全、方案归属和人工确认，不强制解析或填充全部在线模板字段。操作、验证、回退步骤属于批准方案内容，不形成平台逐步骤执行状态机。
6. P5任一合理性评审项为“否”时必须驳回并填写原因。A/B级专项提前时间规则按割接类型匹配、按自然日计算，属于CUT-05的V2审批参考，不是平台通用SLA，不单独触发自动驳回。
7. 保障联系人、联系方式和到位时间可在审批后修改且不重审，但须记录前后值、操作人、时间和原因；角色或任务职责变化必须生成新方案版本并按原等级重新进入P5。
8. P6保存最终闭环记录和INT-12连接/采集证据；遗留项只作为闭环快照文本，不形成独立生命周期或归档门禁。提交P6即归档并结束本次割接；项目仅在最终结果成功时消费事件完成S4门禁。
9. 备件生命周期仍由外部备件系统负责，CUT只保存跳转/引用、必要只读状态快照和证据。

## 对现有设计的影响

- 103项V1/V2正式需求：V1 55项、V2 48项；P0 43项、P1 58项、P2 2项。
- V3/跨需求演进追溯由29项增为30项，新增`WO-06`工单领域候选。
- `ADR-0024`中“WO-06迁移为CUT-11”的当前承载结论被本ADR覆盖；其余业务反馈决策继续有效。
- `ADR-0025`中`CUT-11`及其三张物理表候选不再成立，须在数据库差量任务中删除并重建同一哈希证据链；P3-E09继续`BLOCKED_BY_REVIEW`。

## 禁止性边界

- 不得把通用工单换名为割接任务或割接保障任务。
- 不得新增派单、接管、转单、挂起、责任区间、稳定观察、逐步骤执行引擎或遗留项持续跟踪聚合。
- 不得将CUT-05专项提前时间判断扩展为平台通用时效/SLA流程。
- 不得因通知、外部接口HTTP成功或采集任务下发成功直接判定割接完成。
