# ADR-0004：Phase 3生产与发布保障方向

## 状态

Accepted（方向已批准，生产证据待提交）

## 日期

2026-08-13

## 适用范围

PRD V1.7的NFR-01～NFR-03、INT-01～INT-12适用项、INT-12设备凭证与采集，以及全部需要历史数据迁移的V1/V2需求。V1.6是本ADR首次批准时的历史输入，现行范围按V1.7与ADR-0024收敛。

## 背景

Phase 3的安全、可观测、部署、性能和测试逻辑设计已经形成，但生产入口、数据服务、恢复、密钥、Telemetry、性能环境、外部接口配置和DDL迁移基线存在多种实施路径。若各Feature自行选择，将产生不一致的网络边界、秘密管理、恢复目标、接口参数和迁移证据，无法形成统一发布门禁。

本ADR只批准实施方向，不声称对应企业设施已经存在、容量已经满足或演练已经通过。P3-E01～E07和P3-E09仍需由实际Owner在各自最晚安全门禁前提交可复核证据，但实际环境事实不前置阻断SDS逻辑设计。

## 决策

需求方确认采用组合`A、A、A、A、A、A、B、A`：

| 门禁 | 已批准方向 | 尚需生产Owner证明 |
|---|---|---|
| P3-E01 | 复用企业现有网关/LB、证书和网络区 | 实际平台、域名、TLS终止、拓扑、端口流向、证书及运维Owner |
| P3-E02 | 使用企业托管MySQL/Redis HA服务 | 服务产品、版本兼容、节点规格、容量、连接上限、持久化及故障切换 |
| P3-E03 | 业务Owner先批准RPO/RTO，再由DBA/运维设计并演练；数值见ADR-0005 | 备份介质/频率/保留、恢复顺序和隔离恢复报告 |
| P3-E04 | 使用企业KMS/Secrets Manager | 具体设施、算法/模式、访问主体、密钥版本、轮换/吊销/应急及审计 |
| P3-E05 | OpenTelemetry统一采集并接入企业现有后端 | 日志/指标/Trace/安全事件后端、访问、脱敏、采样、留存、告警和runbook |
| P3-E06 | 建设独立近生产性能环境 | 与生产的规格差异、网络、数据集、账号、依赖沙箱、负载脚本及监控 |
| P3-E07 | 建立平台级接口配置注册表，Feature引用不可变版本 | 各外部系统逐操作endpoint引用、认证、白名单、映射、timeout/retry、沙箱和上线批准 |
| P3-E09 | 逐表、逐列、逐索引/约束生成差异并逐项裁决 | `approvedDdlSha256`、全部制品同哈希、Owner签署和重新验证结果 |

## 边界

1. 方向确认不等于证据通过；`OPEN`不能因本ADR直接变为`VERIFIED`。
2. 企业现有平台必须登记受控引用，不在仓库保存生产密码、Token、私钥、连接串或内部敏感拓扑正文。
3. P3-E03的RPO/RTO必须由业务Owner给出数值，不能以基础设施默认值代替业务批准。
4. P3-E07注册表保存接口配置元数据和秘密引用，不保存秘密值；Feature只能引用已批准的不可变版本。
5. P3-E09继续只读生成审查输入；在批准哈希形成前，不生成生产迁移放行声明、不写旧库、不执行跨库SQL。
6. P3-E08前端类型质量不属于本次方案组合，仍按独立质量工作包清零后验证。

## 备选方案及未采用原因

### 为NPDMS新建独立入口、网络区和自建数据HA

当前没有证据证明现有企业平台无法承接。提前新建会扩大运维、证书、网络和故障切换责任；若后续容量/隔离证据证明现有设施不适用，应新增ADR变更，而不是静默偏离。

### 直接采用基础设施默认RPO/RTO

默认值不能证明项目交付、设备凭证、文件和迁移数据的业务损失容忍度，因此拒绝。

### 各信号和各Feature自行配置

会导致Telemetry无法跨信号追溯、外部接口参数漂移和秘密散落，拒绝作为默认治理方式。

### 整体恢复旧DDL

当前领域模型已演进，整体恢复可能删除已确认实体；但当前DDL也不能未经裁决直接接受，因此采用逐项差异裁决。

## 影响

- Phase 3的架构方向不再是开放问题，正式SDS可据此细化实施边界。
- 依据ADR-0018及最晚安全门禁原则，P3-E01～E06属于部署、专项验收或生产发布证据，P3-E09属于历史迁移/切换证据，均不因尚未产生实际运行值而阻断SDS逻辑设计。机器登记的`blocks`决定各证据真实阻断范围。
- P3-E07按Feature阻塞联调/上线；P3-E08继续阻塞前端Feature验收和发布。
- 证据提交统一使用`evidence-submission-template.json`并通过`validate_phase3_evidence_submission.py`，独立复核通过后才允许更新机器状态。

## 变更方式

任一方向发生变化必须新增ADR并标明替代关系，同时更新14/17/18/19/20分册、12集成设计、开放问题和Phase 3 Gate；不得只修改环境配置绕过决策记录。
