# ADR-0020：项目编码身份与命名空间规则

## 状态

Accepted

## 日期

2026-08-13

## 适用范围

- PRD 基线：V1.6 基线补充，不直接改写历史快照
- Requirement ID：PM-01、PM-02、INT-01、COM-01
- 数据模型门禁：P3-E09 / AI-MIG-000

## 背景

CRM 默认提供项目编码，但一个交付项目可以同时关联多个合同、CRM执行单、ERP订单及订单行。如果按合同或订单追加序号生成项目编码，会把项目身份与商业交易关系混为一体，并在改单、拆单、合单或订单行重新分配时导致项目改号。

主子项目又允许任意层级和受控移动，因此编码也不能包含当前层级路径。否则移动项目后必须修改编码，并同步修改文档、接口、审计和外部引用。

## 决策

### 1. 项目身份与商业关系分离

- 同一CRM项目关联多个合同、执行单或ERP订单时，默认仍为一个项目，`project_code`保持CRM项目编码，不追加合同或订单序号。
- 项目—合同、合同—订单保持多对多关系；订单行到项目的实施范围由`DeliveryScope`记录。
- 只有形成独立负责人、实施地点、计划、验收或闭环边界时，才创建独立子项目。

### 2. 项目编码规则

- `id`是平台内部永久技术身份；`project_code`是租户内唯一、创建后默认不可变的项目业务编码。
- CRM创建的项目默认直接使用CRM项目编码；CRM来源身份同时保存在来源映射中。
- 手工项目使用基础平台编码生成能力创建平台编码；后续关联CRM时只新增来源映射，默认不自动改号。
- 子项目编码采用`<编码命名空间根项目编码>-SP<永久流水号>`，例如`CRM202600123-SP001`。
- 流水号只用于保证命名空间内唯一，不表达当前父节点、层级或订单/合同含义，不得回收复用。
- 项目移动不修改`project_code`、`code_root_id`、`project_sequence`或`code_rule_version`。

### 3. 编码命名空间

- `root_id`表示当前项目树根节点，是可随项目移动重建的层级投影。
- `code_root_id`表示创建时确定的编码命名空间根项目，是不可变业务事实，不随项目移动改变。
- `project_sequence=0`表示项目自身建立独立编码命名空间；派生子项目使用大于0的永久流水号。
- `code_rule_version`冻结编码生成规则版本。基础平台按`tenant_id + code_root_id`原子分配流水号，数据库唯一约束负责最终防重。

### 4. 唯一性

- 项目编码唯一键为`(tenant_id, project_code)`，项目类型不得成为允许项目编码重复的条件。
- 编码流水唯一键为`(tenant_id, code_root_id, project_sequence)`。
- 软删除、关闭、归档、转销或项目类型变化均不释放项目编码和流水号。

## 不采用的方案

### 项目编码追加订单或合同序号

不采用。订单、合同可能拆分、合并或重新关联，不能成为项目永久身份的一部分。

### 编码包含完整项目层级路径

不采用。项目允许受控移动，层级变化不得引起项目改号。

### 删除后复用项目编码

不采用。业务事实、审批历史、文件引用和审计记录必须持续指向唯一项目身份。

## 结果

- 多合同、多订单不会制造重复项目或不必要的项目编码。
- 子项目仍具有独立编码、负责人、阶段、验收和闭环结果。
- 项目移动只重建层级投影，不修改编码与历史引用。
- 数据迁移必须区分CRM项目编码、平台项目编码、当前树根和编码命名空间根；无法证明的历史关系进入迁移问题池。
