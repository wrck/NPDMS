# ADR-0027：割接流程物理模型纠偏

## 状态

`PROPOSED_FOR_REVIEW`

P3-E09继续保持`OPEN / BLOCKED_BY_REVIEW`。本ADR只修正割接领域候选DDL及迁移证据，不构成DDL批准。

## 日期

2026-08-14

## 需求依据

- PRD V1.7：`CUT-01`、`CUT-04`、`CUT-06`、`INT-12`。
- ADR-0026：`CUT-01 / CutoverTask`是P1～P6唯一割接核心任务；`CUT-11`退出CUT领域和当前V1/V2，`WO-06`仅保留为后续工单领域V3候选。
- 《割接0807需求分析报告》业务流程设计：P4方案包含保障人员安排，P6填写闭环结果并结束当前割接流程。

## 决策

1. 删除`CutoverSupportTask`、`ResponsibilityInterval`及其三张物理表，不以割接标题承载派单、接管、转交、挂起、责任区间或工单状态机。
2. 删除逐步骤执行和稳定观察的当前物理表候选：`cut_execution`、`cut_execution_step`、`cut_observation`。P4操作、验证和回退步骤仅作为已批准方案版本内容。
3. 新增`cut_cutover_support_arrangement`，作为P4方案版本下的保障人员安排明细。它不是独立任务，不具有状态机、当前责任人或责任区间。
4. 新增`cut_cutover_closure`，保存P6一次性闭环快照：割接前检查、割接执行、业务测试、回退、附件/采集结果引用、遗留项文本、最终结果和归档事实。提交归档后不可覆盖，不建立稳定观察或遗留项生命周期。
5. 保障人员在P5批准后，联系人、联系方式、到位时间可修改且不重审，但必须记录修改前后值、操作者、时间和原因；角色或任务职责变化生成新方案版本并重新执行P5，沿用原等级。
6. `pms_cut_execution`只有能逐字段证明属于P6闭环事实的字段才可迁移至`cut_cutover_closure`；步骤状态、观察状态和其他无法证明的字段不得改名迁入。`pm_project_maintenance`继续全表排除，不迁移。

## 影响

- ADR-0025中`CUT-11`、`CutoverSupportTask`、`ResponsibilityInterval`及三张候选表的结论被本ADR取代；ADR-0025其他领域和排除规则继续有效。
- V1.7物理差量由11张表调整为10张表；总表数和DDL哈希必须重新生成，并以同一哈希完成隔离MySQL 8.4执行证据。
- 对象—表映射、字段目录、迁移合同、漂移清单、逐项决策寄存器和Phase 3证据包必须同步重建。

## 明确排除与后置

- 当前不建立任何`CUT-11`、通用工单、责任区间、逐步骤执行、稳定观察或遗留项跟踪表。
- `WO-06`仅保留来源和V3演进追溯；未来进入工单领域时必须独立完成需求批准、Owner确认、状态机、权限、数据和迁移设计。
- 本ADR不解除P3-E09独立评审门禁，不填写`approvedDdlSha256`。
