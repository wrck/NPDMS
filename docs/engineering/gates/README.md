# 工程门禁与审查证据

本目录保存工程链各阶段的门禁状态、独立评审结论、评审输入和历史证据。它是过程治理区，不是业务需求或系统详细设计的替代物。

## 当前使用方式（2026-09-08需求方批准）

Phase 1/2为设计分类和可选全量审计，不再是日常变更的阶段准入；不要求修订全部分册、重签全阶段或更新所有摘要。按工程链的变更级实质审查规则，在现有Task/DU/提交中记录相关Requirement、Owner、接口/表/消费者、实际检查及结果。业务、安全、数据和发布/迁移的实际条件不取消。

默认Phase 1/2命令仅提示审计未运行；显式`--audit`（或原`--technical`）才运行全量内容审计，其发现只按本次实际影响路由，不授予下一阶段权限。历史GO/NO-GO/FAIL不改写成新通过。

## 原阶段基线状态（历史，不作为当前准入）

PRD V1.8已更新至修订015。Phase 1、Phase 2和Phase 3此前的`APPROVED`结论仅覆盖修订007；由于修订008—015改变了阶段编排、项目状态、闭环、范围追加和全集统计等工程契约，三个当前`gate-status.md`均为`REVALIDATION_REQUIRED`。旧评审、自审和机器结果继续作为历史证据，但不得作为修订015的当前放行依据。

差量重开只阻断受影响范围；无关Feature事实不自动撤销。当前状态以各Phase唯一`gate-status.md`为准。

## 目录规则

- `phase-1/`、`phase-2/`、`phase-3/`：按工程阶段隔离门禁证据。
- Phase 1/2的 `gate-status.md`：保留原状态与证据的非阻断历史记录；其他适用门禁仍记录实际范围与结果。
- `input/`：外部或上游提交的评审材料，保留原始内容，默认只读，不在原文件上修改。
- `archive/`：已失效、已替代或仅供历史追溯的审查材料，不能作为当前放行依据。

## 权威性边界

1. 业务语义以 PRD 基线为准，系统设计以 `docs/design/` 为准。
2. 实质评审意见须回写其权威设计；变更范围、审阅者、提交和结论在当前Task/DU/提交中记录一次，不依赖Phase 1/2历史文件更新。历史评审不得扩大为未审范围的批准。
3. 任何审查稿、输入稿或历史稿都不能单独改变需求范围、数据归属、接口契约或状态机。
4. Phase 1/2历史NOT_READY、全文PRD身份不一致或缺整阶段批准不阻断日常工作；本次范围内的真实未决契约、失败验证及必要的操作授权仍必须解决。

当前 Phase 1 入口见 [`phase-1/README.md`](phase-1/README.md)。
