## 用户确认

“指派服务经理和项目经理可以同时指派，也可以在指派服务经理之后，单独指派项目经理。指派成员不是固定的任务，可以在项目任何阶段都可以进行调整，只要有对应的权限。”

“项目经理可以指派多个，所以不能绑定单项目经理。”

“可以保留当前主责项目经理。”

“相同项目角色的操作权限相同。”

## 批准语义及不变边界

1. 成员指派与调整是项目级能力，不是固定ProjectTask。支持服务经理与项目经理同次指派，以及先服务经理后单独指派项目经理；后续可在项目各业务阶段按对应权限调整。
2. 同一项目允许多名有效项目经理，分别保留成员身份和责任区间，并保留一个当前主责项目经理。主责引用必须指向有效项目经理成员；单个manager_id及其显示字段只能表达当前主责，不得代替完整成员集合或作为所有项目经理操作的统一资格判据。不额外创造“协同项目经理”等业务角色。
3. 同一次联合指派逐项校验相应操作权限、人员资格和项目范围，整体提交或回滚；调整保留前后责任区间、原因、操作者与时间，不覆盖历史。
4. 双主责状态继续表达有效主责服务经理与当前有效主责项目经理是否均存在，不因项目经理成员为多人而丢失主责。成员调整和主责切换分别留痕，不默认删除其他项目经理；指派本身不推进阶段、不改变生命周期、不创建或自动完成T-ASSIGN-PM等任务。不能把固定任务存在或完成作为成员操作前置。
5. “任何阶段”不修改已有项目退出/关闭保护，不授予跨租户、跨项目或审批历史改写权。已发布模板、已冻结执行契约、历史成员、审批和审计不原位覆盖；确需处理旧项目的固定任务配置时另行确定前向兼容范围。
6. PM-09仍仅承接V2跨项目批量变更，不阻断单项目成员管理。服务经理层级、主责/协同及其原有候选范围保持原批准规则，不把这些限制类推给项目经理。
7. 同一项目内相同项目角色的操作权限相同。主责和其他有效PROJECT_MANAGER成员具有相同的该角色操作权限；主责只是责任标识，不额外授权或降权。实际操作继续服从租户、数据范围及通用状态/版本守卫，不能以单manager_id比较排除其他有效经理。
