# PRD V1.8批准修订009：验收范围时序与合同管理员公司范围

> 修订编号：`CHG-PRD-2026-08-29-009`<br>
> 批准日期：2026-08-29<br>
> 状态：`APPROVED`<br>
> 前置基线：`CHG-PRD-2026-08-29-008`

## 1. 权威来源

- 需求方确认：按项目设定阶段，项目进入验收阶段即进入验收范围；进入先手是项目阶段，验收完成时验收单完备。
- 需求方确认：合同管理员采用方案B，以SYSTEM当前有效公司—部门授权事实中的公司编码作为合同订单数据范围；空范围失败关闭，商务敏感字段另行校验字段权限。
- 适用对象：COM-01当前有效DeliveryScope分配版本、ACC-03的AcceptanceScopeBinding及初验/终验报告完备时点。

## 2. 批准结论

1. 项目进入其设定的验收阶段时，该项目当时全部当前有效DeliveryScope分配版本同步进入验收范围。
2. 项目已经处于验收阶段时，新增或调整形成的新当前分配版本在生效时同步进入验收范围，不能通过“先进入阶段、后新增范围”绕过验收锁定。
3. 每条验收范围绑定保存精确DeliveryScope标识及分配版本；任一范围锁定、版本校验或绑定失败时，项目阶段进入或范围版本生效整体不成功，不保留部分绑定。
4. 不得把既有验收单的提交、审批、报告或项目级验收状态反推为历史AcceptanceScopeBinding。
5. 项目退出或回退验收阶段时是否关闭既有绑定，不在本次确认范围；登记为`Q-FCOM-002 / BLOCKED_BY_SPEC`，在获得正式业务规则前不得自动解锁或关闭绑定。该问题只阻断退出/回退关闭路径，不阻断本次已确认的进入绑定规则。
6. 项目阶段进入是验收范围绑定的先手事实：进入验收阶段时不要求创建或补齐初验/终验单，报告尚未形成不得阻断已满足其他门禁的阶段进入。
7. 初验或终验活动申请标记完成时，对应验收单/报告必须形成验收时间、结论、验收人和附件完备的当前有效版本；任一缺失时，对应验收活动不得标记完成。
8. 合同管理员首次合同可见性和项目—合同关系维护以SYSTEM当前有效用户公司—部门授权事实为权威来源，仅按授权公司编码与ERP合同所属公司编码精确匹配；部门上下文不得推导或扩大到其他公司，同一公司多条有效授权去重合并。
9. 无有效公司范围、授权事实未知或不可用、合同缺少可核实所属公司编码时，列表返回空，详情和写操作拒绝；关系维护写入前重新校验当前授权并记录授权事实稳定ID和版本。撤权或到期立即禁止后续查询和维护，但不删除既有关系、范围历史或审计证据。
10. 公司数据范围不授予商务敏感字段权限；合同金额及其他已定义敏感字段仍须独立字段权限，未授权时脱敏或不返回。不得回退为租户全量、组织树推断、既有项目关系或技术默认值。

## 3. 影响边界

- 直接影响：COM-01、ACC-03正文及其下游SDS、Feature、API、权限、状态、并发、数据和验收设计。
- 下游必须把项目阶段进入、验收范围绑定和验收报告完备分成三个有序事实；不得在阶段进入时伪造初验或终验报告，也不得继续把旧`submitAcceptance`状态当作触发事实。
- 本修订不决定`AcceptanceScopeBinding`物理字段、`acceptance_id`去留、Owner接口、事务和锁顺序；这些须在PRD Gate通过后按SDS复核。
- 本修订关闭`Q-FCOM-001`的业务选择，但不批准SDS中的消费接口、授权缓存、事务或实现细节；下游只可复用既有SYSTEM授权事实，不新增合同授权表，不修改Yudao基础平台。
- 本修订不批准F-COM-001 Feature Ready、Technical Plan、产品代码、Flyway、历史生产迁移、SIT、UAT或Release。
- 本修订不改变正式Requirement数量、优先级、目标版本、项目阶段定义、领域Owner或Yudao基础平台。
