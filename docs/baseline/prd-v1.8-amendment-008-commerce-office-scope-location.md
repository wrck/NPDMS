# PRD V1.8批准修订008：COM订单范围办事处地点语义

> 修订编号：`CHG-PRD-2026-08-29-008`<br>
> 批准日期：2026-08-29<br>
> 状态：`APPROVED`<br>
> 前置基线：`CHG-PRD-2026-08-29-007`

## 1. 权威来源

- 需求方确认：订单范围地点是拆分时子项目所属办事处，不是订单、订单行或AST站点事实。
- 既有一致事实：F-PROJ-002按办事处部门编码拆分，组织部门由平台主数据校验，并保存稳定引用及发生时快照。

## 2. 批准结论

1. COM-01范围地点以拆分或分配发生时目标项目所属办事处部门为权威事实。
2. 范围保存目标项目ID及办事处部门稳定ID、编码、名称和部门版本的发生时快照；项目后续组织或项目树变化不追溯覆盖既有范围。
3. 需要改变既有范围办事处时，必须通过受控范围调整关闭原有效区间并追加新版本，不直接改写历史。
4. COM-01不依赖AST的`siteId/siteLocationId`，不得通过地址、站点、办事处名称或订单字段推断办事处。
5. V70既有`office_department_code`是必须保留的办事处来源证据；转换不得据此伪造AST站点或平台部门ID，无法核验稳定部门事实时的具体处置须由下游设计另行锁定。

## 3. 影响边界

- 直接影响：COM-01正文、COM领域派生规格及F-COM-001的地点规则、API、物理差量、迁移转换和验收设计。
- SDS须删除COM对`AssetLocationApi`的地点依赖，并把办事处发生时快照写入数据、API、权限、并发和测试契约。
- 本修订不改变项目自身站点模型、AST Owner、正式需求数量、优先级、目标版本或领域Owner。
- 本修订不批准F-COM-001 Feature Ready、Technical Plan、代码、Flyway、历史生产迁移或数据切换。
