# PRD V1.8批准修订003：PM-07模板匹配决策历史与影响识别

> 修订编号：`CHG-PRD-2026-08-25-003`
> 状态：`APPROVED`
> 日期：2026-08-25
> 需求方结论：复用项目既有四属性，以单一模板匹配决策历史承接创建与属性变化影响追溯
> 影响Requirement：`PM-07`；关联`PM-01`、`PM-03`、`INT-01/03`、`CHG-01`

## 1. 变更原因

PRD V1.8的PM-07原文包含待分类/待选模Project、独立属性历史和CHG影响清单等跨阶段语义。需求方确认当前F-PROJ-004只建设模板匹配前属性判定、模板匹配决策历史和创建后属性变化影响识别，不在正式Project上增加分类状态轴，也不提前建设INT来源编排或CHG工单。

## 2. 批准后的业务规则

1. 签约方式、项目类别、项目实施方式和CRM重大项目级别继续复用`proj_project`既有列，作为TemplateMatcher的四项确定输入，不新增同义当前值字段。
2. 手工项目的CRM重大项目级别保存为`NULL`，界面显示“不适用”；不新增或臆造`NOT_APPLICABLE`字典码。
3. 模板候选结果与最终决策方式分开：候选结果为`NO_MATCH/UNIQUE/MULTIPLE_MATCHES`，决策方式为`AUTO_UNIQUE/EXPLICIT_SELECTION`。无匹配拒绝创建；唯一候选可自动决定；多个合法候选仅在授权用户显式选择其中一个模板修订后允许创建。
4. 所有成功的正式Project创建路径必须在同一事务写入Project、`INITIAL_CREATE`模板匹配决策历史、模板冻结和全部实例要素；任一步失败整体回滚，不持久化Project或项目草稿。
5. 创建后发生来源修正或人工调整时，更新既有当前值列，调用相同Matcher只读判定影响，并分别追加`SOURCE_CORRECTION`或`MANUAL_ADJUSTMENT`历史；不得自动更换冻结模板或重新实例化交付事实。
6. 唯一新增业务表为`proj_project_template_match_history`。不新增通用项目属性历史、分类案例、独立影响处理表、重新实例化接口或CHG事件；未来CHG-01从历史派生工单时独立立项。

## 3. 权威历史与审计关系

模板匹配决策历史自身永久、只追加地保存四属性前后快照、属性Owner、来源与映射版本、匹配器版本、候选结果、决策方式、最终模板修订、影响结论、操作者、原因、时间、请求摘要、幂等标识和稳定`operationId`。`traceId/auditLogId`只作可选关联。

现有`system_operate_log`经核验不支持按项目和属性维度结构化查询，采用异步尽力写入，且未验证永久保留，因此不能替代本业务事实。公共审计增强须独立立项，不夹带进F-PROJ-004。

## 4. 对原条款的替代

本修订替代PM-07中下列冲突语义：

- “待分类/待选模”不再是正式Project或项目草稿状态；输入或模板决策未完成时直接拒绝创建。
- “来源历史和项目类别变更记录”在本Feature中由模板匹配决策历史的前后快照承接，不新增通用属性历史表。
- “生成影响清单”收敛为保存只读影响结论；不产生独立影响表、CHG事件或工单。

INT自动建项、来源定位、传输重试与对账仍由INT Feature承接；CHG分派、处理和关闭仍由CHG-01 Feature承接，均不得计入F-PROJ-004完成度。

## 5. 权威关系

`docs/baseline/prd-v1.8.md`继续作为不可变快照。本文件是需求方批准的PM-07正式增量；PM-07及其与PM-01/PM-03的模板创建交叉语义冲突时，以本修订为准，其他V1.8条款不变。
