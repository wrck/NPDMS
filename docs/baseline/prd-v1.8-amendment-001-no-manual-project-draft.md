# PRD V1.8批准修订001：手动项目创建失败不保留草稿

> 修订编号：`CHG-PRD-2026-08-21-001`
> 状态：`APPROVED`
> 日期：2026-08-21
> 需求方结论：采用方案B，不持久化手动项目创建草稿
> 影响Requirement：`PM-01`、`PM-03`

## 1. 变更原因

PRD V1.8一方面规定正式Project创建必须绑定生效模板并初始化为`ACTIVE / S0`，另一方面在PM-01、PM-03异常条款中要求无模板或多匹配时“项目保持创建草稿”。当前SDS没有Project草稿状态或独立创建草稿聚合。为避免引入无模板Project、额外草稿业务对象和未批准状态机，需求方确认不建设手动项目创建草稿。

## 2. 批准后的业务规则

1. 手动创建只产生两类结果：
   - 全部校验和实例化成功，生成正式`Project`及完整模板实例；
   - 创建失败，不持久化Project或任何项目创建草稿。
2. 无匹配模板、同优先级多匹配、显式模板不再适用、模板引用失效、必填字段或主数据校验失败时，服务端返回明确错误和可修正项，不生成项目编码，不进入S0，不实例化阶段、任务、里程碑、交付件或门禁。
3. 页面可在当前未刷新会话内保留用户已经输入的表单值，便于修正后重新提交；平台不承诺刷新后恢复，不写服务端草稿、浏览器持久化存储或离线草稿。
4. 正式创建继续使用`Idempotency-Key`。失败请求按幂等状态和错误分类处理；修正业务输入后使用新Key重新提交，不用同Key不同摘要覆盖原operation。
5. 模板自身的草稿、发布和停用生命周期不受本修订影响。

## 3. 对原条款的替代

本修订替代PRD V1.8中以下冲突语义：

- PM-01异常条款“没有可用模板时项目保持创建草稿且不得进入S0”；
- PM-03验收与异常条款中“项目保持创建草稿”的项目侧分支。

替代文本统一为：

> 没有可用模板、存在多个同优先级默认模板或模板引用失效时，平台拒绝创建正式项目，返回具体冲突项供创建人修正；不持久化项目或项目创建草稿，不生成项目编码，不进入S0，也不实例化阶段任务。模板自身不完整时仍保持模板草稿并由模板维护人修正。

## 4. 影响分析

- Requirement数量、Owner、版本和优先级不变。
- Project状态模型保持`ACTIVE / NORMAL_CLOSED / EXCEPTION_CLOSED`，不新增`DRAFT`。
- 不新增`ProjectCreationDraft`聚合、表、API、事件或迁移。
- 正式Project、模板冻结、WorkBinding、CompletionRule和原子实例化SDS契约不变。
- F-PROJ-001按本修订形成失败语义、负向测试和真实浏览器错误恢复验收。

## 5. 权威关系

`docs/baseline/prd-v1.8.md`继续保留为不可变V1.8快照。本文件是其经需求方批准的正式增量；当且仅当PM-01、PM-03的“项目创建草稿”语义冲突时，以本修订为准。其他PRD V1.8条款不变。
