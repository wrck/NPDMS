# 项目全流程功能清单与流转关系（2026-09-19）

- 性质：参考清单（原始分析），依据《[2026-09-19-项目交付全流程操作清单核对.md](2026-09-19-项目交付全流程操作清单核对.md)》派生整理，不回写 PRD/SDS/Feature/Task/DU/Gate 状态。
- 事实来源：核对文档（Demo 21 页 + PRD 36 项需求逐项核对结果）、主档详情页 rail 配置 `project-master-detail/components/businessModules.ts`、项目生命周期常量 `pms-module-project/.../domain/projectmanual/ProjectRules.java`、`StagePlanBatchServiceImpl`。
- 范围与口径：项目实施交付全流程（S0~S6 + 割接）；项目模板域排除；状态承接状态以核对文档为准（已闭环/部分/未接通/外部未接入/V2标注）。**退役链只读**：`pms_project`、`/pms/project-detail`、`ProjectPanoramicServiceImpl` 不承接任何新功能，主档链唯一落点为 `proj_project` 与 `/pms/project-management/project-master-detail`。
- 状态推进硬约束：业务状态一律经服务端状态机推进，不得直写生命周期状态；通知送达与外部 HTTP 成功不等于业务完成。

## 一、全流程业务流转总览（阶段主线）

```
S0 立项与指派 ──► S1 工前准备 ──► S2 施工计划 ──► S3 实施方案 ──► S4 部署与割接 ──► S5 验收交维 ──► S6 闭环 ──► MAINT 维护期
```

| 阶段 | 业务主线 | 关键门禁/推进条件 |
|---|---|---|
| S0 立项与指派 | 合同订单关联 → 项目创建向导（匹配预演→确认→保存）→ 服务经理指派 → 团队/主子项目拆分/任务 | 创建初始状态 S0（BR-1）；首次指派授权（Q-FPROJ-011，部分场景 OPEN） |
| S1 工前准备 | 工勘分工（10 项表单+确认/驳回/归档）→ 需求分析（11 项动态表单+完成冻结）→ 工期基线录入 | S1 准出读取冻结模板：有效工期存在、工勘/需求分析完成、人员/物料/领料/外采等准备项就绪或取得有效豁免（实施就绪聚合门禁） |
| S2 施工计划 | 工期基线版本化 → 阶段施工计划批次自动推算 → 明细调整 → 提交 BPM 审批 → 生效基线 | 计划生效（BPM `pms-sol-stage-plan`）作为后续部署基准；工期紧张提示（<3 个月） |
| S3 实施方案 | 方案编制 → 提交评审 → 服务经理审核（通过/驳回/撤回）→ 重大项目复审（待接入） | 方案审核通过是部署前序（方案→交付件归档未接通） |
| S4 部署与割接 | 到货签收 → 硬件安装（位置回填 AST）→ 配置调试（Log 入 EQP-02）→ 业务联调 → 割接上线 | 割接实施就绪门禁：四里程碑就绪校验，前序未完成不能发起（READINESS_NOT_READY）；S4 完成还须 CUT-06 成功结果并集 100% 覆盖需割接范围或有效不适用依据（覆盖率聚合判定） |
| S5 验收交维 | 现场培训（外发→客户签字）→ 满意度调查 → 初验&终验报告 → 交付件归集汇总 | 验收报告版本发布/满意度达标判定；交付件归档（部分自动同步） |
| S6 闭环 | 闭环条件校验（跨模块校验部分占位）→ 闭环申请 → BPM 审批 → 归档 | NormalClosure check/submit + 闭环审批 BPM；审批完成回调占位（P1-13）；终态三分：NORMAL_CLOSED / NO_TRACKING_CLOSED（仅代理商自服+显式申请）/ EXCEPTION_CLOSED（PM-10），闭环保留 closed_from_stage |

阶段推进由项目阶段实例 + 里程碑/门禁事实驱动（`PROJECT_STAGE_ADVANCE_INVALID`/`PROJECT_STAGE_GATE_UNSATISFIED` 服务端校验）。
