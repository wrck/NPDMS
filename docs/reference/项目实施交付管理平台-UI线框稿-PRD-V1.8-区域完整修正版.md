# 0. 文档定位与设计标准

## 0.1 页面区域划分标准

本版所有实际交互界面必须先给出“页面区域划分”，再给出字段和业务规则。

统一区域语义：

| 区域 | 典型内容 |
|---|---|
| A 页面头 | 页面/对象名称、项目上下文、状态、版本、负责人、主动作 |
| B 导航/摘要/筛选 | Stage/Task、Tab、KPI、查询条件、步骤条 |
| C 主工作区 | 表单、列表、树、编辑器、动态采集项、审批材料 |
| D 辅助工作区 | 来源引用、详情、版本差异、证据、Drawer入口 |
| E 状态/门禁/异常 | 业务判定、失败原因、数据质量、外部降级、历史 |
| F 操作区 | 保存、提交、审批、发布、重试、归档、审计 |

原则：

```text
区域骨架
→ 决定同屏信息架构
→ 区域内部再定义字段、表格和操作
```

因此字段清单、表格和追溯矩阵不再被视为“线框图本身”。

## 0.2 中保真视觉与信息层级（【建议】）

本稿面向工程管理部、服务经理、项目经理、工程师和平台管理员，采用“高信息密度交付控制台”而不是通用卡片门户。视觉建议不新增业务语义；品牌规范确定后可替换色彩与字体，但不得改变状态、权限和门禁表达。

| 角色 | 建议 Token | 用途 |
|---|---|---|
| 画布灰 | `#F3F6F9` | 页面背景与层级分隔 |
| 工程墨 | `#1D2A36` | 正文、表格主数据、关键编号 |
| 行动蓝 | `#0B5CAD` | 主操作、当前导航、可点击引用 |
| 完成绿 | `#16835B` | 已完成且业务事实有效 |
| 预警琥珀 | `#A96000` | 待确认、将过期、外部延迟 |
| 阻断红 | `#C43D4B` | 门禁失败、拒绝、冲突；不得仅靠颜色表达 |

```text
标题/页签：Microsoft YaHei UI Semibold / Noto Sans CJK SC，20/28 与 16/24
正文/表格：Microsoft YaHei UI / Noto Sans CJK SC，14/22
编号/版本/Hash：JetBrains Mono / Consolas，12/18
```

内部工作台默认面向桌面端：全局导航 + 业务上下文导航 + 事实工作区 + Sticky 动作条。AC-03 客户问卷和 DA-06 扫码是移动优先页面；其他复杂配置页在窄屏仅支持安全查看或提示转桌面办理，不压缩成不可操作的小表格。

本产品的识别性元素是“事实链条”：所有关键工作台在同一位置展示 `Owner / 来源 / 数据时点 / 业务版本 / 当前状态 / 审计入口`。它用于解释业务结论，不作为装饰，也不允许把外部技术成功显示成业务完成。

## 0.3 PRD 完整性标准

本版采用以下发布门禁：

1. PRD 11 个核心业务对象必须全部有可操作界面。
2. PRD 100 项 V1/V2 正式需求必须逐项映射到 UI 页面、组件、系统配置或明确的非界面约束。
3. 对有用户交互的正式需求，不允许只写“已覆盖”，必须至少给出：
   - 页面/组件入口；
   - 承载方式（EMBED / DRAWER / STANDALONE / EXTERNAL-LIMITED）；
   - 主要字段/表格；
   - 主要操作；
   - 状态、门禁或版本；
   - 权限与异常；
   - 关键跨域联动。
4. V3 与 OUT_OF_SCOPE 不得提前出现在 V1/V2 菜单、页面、角色、状态机或正式按钮中。
5. 外部系统不可用时，只阻断必须依赖外部权威事实的具体动作；PRD 已定义的手工、上传、站内待办、待补偿和最近有效值路径必须保留。
6. 页面可复用，但业务事实 Owner 不合并。

## 0.4 单页设计完成定义

每个正式交互页面在进入中保真原型前，必须能回答以下问题；可复用全局规则，但不得只引用需求编号：

| 设计问题 | 页面必须给出的答案 |
|---|---|
| 用户来这里完成什么 | 一个明确主任务及其当前对象上下文 |
| 用户依据什么判断 | Owner、来源、数据时点、版本、当前状态和适用规则 |
| 用户可以做什么 | 服务端返回的允许操作、主次动作和动作后业务结果 |
| 为什么不能继续 | 具体未满足项、责任对象、定位入口和可恢复方式 |
| 失败后数据是否安全 | 草稿是否保留、事务是否回滚、能否重试及是否需要重新输入敏感信息 |
| 历史如何解释 | 不可变版本、状态前后值、操作人时间和审计入口 |

这里的加载、空态、无权、冲突、降级等仅是 UI 呈现状态，不创建新的业务状态码或状态机。

同理，“失败/待重试”“待补偿”“待重算”等跨页面提示默认是初始化、集成或处理结果标签；只有PRD已明确把它定义为某个业务对象状态时，才进入该对象状态机。页面必须同时写明所属对象，避免与项目生命周期、任务状态或审批状态混用。

## G-02 权限模式

同一业务组件由服务端返回允许操作，前端只负责呈现：

```text
VIEW      只读查看
EDIT      编辑草稿/当前可编辑业务事实
CREATE    创建业务对象/实例
APPROVE   冻结版本 + 审批意见 + 通过/驳回
CONFIG    配置草稿/发布
NO_ACCESS 隐藏或拒绝
```

权限判定顺序：

```text
身份/租户
→ 功能权限
→ 组织/项目树/设备/专项任务范围
→ 对象当前状态
→ 具体操作权限
→ 字段/文件/凭证专项权限
→ 临时授权/候选人有效期
```

权限模式由服务端随对象状态一起返回，前端不得提供“切换为编辑/审批模式”的客户端开关。

| 返回结果 | 界面呈现 | 禁止行为 |
|---|---|---|
| `VIEW` | 字段只读，显示来源、版本及本人数据范围摘要 | 仅隐藏按钮后仍调用写接口 |
| `EDIT/CREATE/FILL` | 只开放服务端返回的字段和动作，保存前显示业务影响 | 根据路由参数扩大项目、设备或任务范围 |
| `APPROVE` | 显示冻结材料、流程版本、当前节点和审批意见 | 在任务层另造审批人或改写目标流程 |
| `CONFIG` | 只编辑草稿版本，发布动作独立授权 | 原位修改已发布字典、模板、规则或状态机 |
| `NO_ACCESS` | 显示通用无权提示和返回入口；已知对象也不泄露敏感摘要 | 暴露对象是否存在、凭证名称、人员、商务字段或文件正文 |

菜单不可见解决“无功能权限”；对象页的通用拒绝面板解决“通过合法入口进入但当前对象无数据权限”。两者都不能替代服务端拒绝和审计。

### 角色术语呈现

- “服务经理”是角色族；“用服经理”“客服/服务经理”等上下文别名必须由服务端按项目责任关系、所属领域和冻结流程候选规则解析，不因页面文案自动等同一级或二级服务经理。
- “工程管理部关闭岗”是工程管理部内部的受控操作权限组，不新增一类业务角色；页面显示用户在当前对象上的动作权限，不允许前端自行授岗。

## G-03 通用 Drawer

统一用于：

- 人员选择；
- 客户/联系人选择；
- 设备查看；
- 文件上传/版本；
- 凭证选择/临时认证；
- CollectionTask 创建/详情；
- 版本差异；
- 审计历史；
- 门禁失败明细。

```text
┌ A Drawer头：动作名称 / 当前业务对象 / 关闭 ───────────────────────────────┐
├ B 上下文：项目 / Task / 设备 / 来源版本 ─────────────────────────────────┤
├ C 主工作区：选择、表单、明细或差异 ───────────────────────────────────────┤
├ D 依据区：Owner / 权限范围 / 冻结版本 / 影响摘要 ─────────────────────────┤
├ E 反馈区：字段错误 / 冲突 / 降级 / 可恢复方式 ────────────────────────────┤
├ F Sticky动作：取消 / 次操作 / 唯一主操作 ─────────────────────────────────┤
└───────────────────────────────────────────────────────────────────────────┘
```

- 打开 Drawer 时冻结来源对象键和必要版本；提交前重新校验，版本变化则进入差异确认，不静默覆盖。
- 关闭含未保存内容的 Drawer 时提示“继续编辑 / 放弃本次修改”；已提交事实不提供“撤销关闭”伪回退。
- 选择器先按权限过滤再搜索；搜索无结果、无权和外部来源不可用使用不同提示。
- 提交中禁用重复点击；超时后先查询原业务键结果，再决定是否允许重试。

## G-04 事实链条与页面状态

关键页面统一在标题下或工作区顶部显示：

```text
Owner：项目治理 │ 来源：ERP订单 SO-001 │ 数据时点：10:05 │ 版本：v12 │ 状态：待核对 │ [查看审计]
```

| UI 状态 | 呈现要求 | 可用动作 |
|---|---|---|
| 加载中 | 保留页面骨架和对象上下文，不先显示“无数据” | 取消、返回 |
| 合法空态 | 说明当前为何为空，并给出获权用户的首个动作 | 创建、导入、刷新之一 |
| 来源未到达 | 显示来源系统、最近成功时间和影响范围 | 重试、人工录入或查看补偿入口，按PRD适用 |
| 只读历史 | 显示版本、生效区间、替代版本和只读原因 | 比较、下载、审计；不得保存 |
| 版本冲突 | 显示本人草稿与当前版本差异 | 重新加载、复制为新草稿；不得强制覆盖 |
| 门禁阻断 | 逐项显示未满足事实、Owner、来源版本和定位入口 | 定位处理、重新校验 |
| 无权 | 不展示受保护正文和敏感对象存在性 | 返回、查看本人权限说明 |
| 外部降级 | 显示仍可办理与被阻断的具体动作 | 需求允许的手工、上传、最近有效值、待补偿路径 |

加载失败、没有数据、没有权限和业务上“不适用”不得使用同一个空白页。

字段呈现按用途分层：业务人员需要判断和操作的字段进入主工作区；来源键、规则版本、状态前后值进入事实链条或详情；幂等键、回调序号、Hash和候选人快照进入审计/技术详情。密码、私钥、Token及其明文不属于任何可见层级。

## G-05 动作、确认与结果反馈

- 每个工作区只保留一个当前主动作，名称直接描述结果，例如“创建项目”“提交P3”“发布模板”“通过闭环审批”。
- “保存草稿”不推进状态；“提交/发布/通过/关闭”必须在确认区展示将冻结的版本、将推进的状态以及不会被自动改变的关联对象。
- 破坏性或终态动作二次确认时展示对象编码、当前状态和影响清单，不使用只有“确定/取消”的模糊文案。
- 成功反馈复用动作名称并给出业务对象编号、结果状态和下一入口；失败反馈保留用户输入，定位到具体字段或业务事实。
- 长任务提交后立即返回平台任务编号和可追踪状态；HTTP成功、通知已发送、外部已受理都不能显示为业务完成。

## G-06 桌面、移动与无障碍

- 内部复杂表格和树在 1280px 以上完整呈现；1024～1279px 收起全局菜单并保留业务上下文，核心列不可被水平裁掉且无替代入口。
- AC-03、DA-06 在 360px 宽度下保持单列、44px 最小触控目标、签字/扫码失败后的明确重试入口。
- 当前项、成功、预警和阻断同时使用文字/图标/颜色；键盘焦点可见，Drawer 打开后焦点留在内部，关闭后回到触发控件。
- 表格排序、筛选、分页和导出使用同一权限范围与统计口径；不允许屏幕显示过滤后数据、导出却返回更大范围。

### WorkBinding 加载与完成反馈

| 场景 | 右侧工作台 | Sticky 动作区 |
|---|---|---|
| `TASK_NATIVE` 可办理 | 通用任务字段、状态历史、本人责任区间 | 仅显示服务端允许的保存、转派、状态命令和“完成任务” |
| 非 `TASK_NATIVE` 可办理 | 通用基础区 + 真实业务执行区 + 事实链条 | 先使用目标业务动作名，例如“提交验收”“完成P3”；目标事实满足后，仅在服务端返回允许操作时显示“判定并完成任务” |
| 目标只读 | 显示目标状态、版本、只读原因和审计入口 | 隐藏写动作，保留查看/比较 |
| 目标不存在或引用失效 | 通用基础区仍按权限显示；执行区显示目标引用、失效版本及责任Owner | 禁止完成；提供重新加载、定位配置或联系负责人 |
| 目标无权 | 不加载目标摘要，不暴露敏感对象是否存在 | 禁止完成；只显示返回和通用权限说明 |
| 组件暂不可用 | 显示失败时间、影响范围和可恢复入口 | 禁止完成；允许安全重试，不用通用字段替代业务事实 |
| Owner事实已完成、任务仍未完成 | 显示“业务事实已完成 / ProjectTask待判定”、Owner事实版本和上次判定结果 | 服务端允许时显示“重新判定并完成”；重放原幂等结果或以新请求键重试，不重复执行Owner业务动作 |
| 完成规则未满足 | 显示规则版本、事实版本和逐项缺口 | “重新读取事实并判定”；定位到缺失业务组件 |
| 任务/契约版本冲突 | 显示本人草稿与当前版本差异 | 重新加载或复制草稿，不强制覆盖 |

目标业务动作由对应 Owner 领域先形成业务事实；ProjectTask 完成命令随后携带任务版本、execution contract/规则版本、事实对象键、事实版本和幂等键，由项目任务服务重新读取当前事实并写入完成判定。两步不是跨 Owner 的分布式同事务；Owner 已完成而任务判定失败时必须保留真实事实并进入可重试判定态，不能回滚或重复执行业务动作。

完成成功反馈必须显示新的任务状态、完成判定快照编号及使用的任务/绑定/规则/事实版本；完成失败保持任务原状态和用户已保存内容，并展示本次失败的完成判定记录。

### 动作权限与结果预览

| 动作 | 发起/确认 | 界面必须展示的影响 |
|---|---|---|
| 回退 | 本人主责项目的服务经理发起 | `lifecycle_status` 保持 ACTIVE；阶段回到S0；指派变为待指派；原责任区间结束；任务、设备、文件和历史保留 |
| 异常关闭 | 工程管理部关闭岗确认 | 关闭依据、遗留事项快照、未关闭后代/审批/采集/CUT/INS检查；成功后只读且不计入正常闭环 |
| 重开 | 工程管理部关闭岗对 EXCEPTION_CLOSED 项目确认 | 恢复到关闭前可恢复阶段，展示服务端返回的新责任处理事项引用；已终止外部任务仍保持终止 |

- 关闭检查列表按对象类型、编号、Owner、当前状态和处理入口展示；用户不能在确认框内直接改关联对象状态。

- 仅当服务端对当前阻断对象返回“允许线下处理”操作时，页面才显示证据上传；复核后必须重新执行完整关闭检查，不能用“忽略阻断”直接关闭，也不能把证据上传等同关联对象已完成。
- “责任处理事项”的对象类型、编号与处理入口以重开命令返回的正式契约为准，本线框不预设新的通用工单或服务跟踪对象。
- 执行成功页展示状态前后值、责任区间、审计编号和重新进入项目只读档案的入口。


### 移动端提交状态

| 场景 | 页面反馈 |
|---|---|
| 链接有效 | 只展示该问卷实例的项目摘要、冻结题目、有效期和隐私说明 |

| 验签或保存失败 | 不显示提交成功；保留本页输入供安全重试，服务端不写入答卷事实 |
| 提交成功 | 显示问卷实例、提交时间和不可修改说明；不返回完整访问令牌 |

### 审批期间的快照有效性

| 场景 | 页面处理 |
|---|---|
| CLO-01及材料快照持续有效 | 当前候选审批人可查看冻结材料并处理本节点 |
| 条件、满意度或交付件版本失效 | 顶部显示“审批已暂停”，列出失效事实和新旧版本，禁用通过 |
| 当前用户不是候选人或已失权 | 不显示审批动作；冻结材料仍按独立文件/数据权限裁剪 |
| 任一节点驳回 | 当前实例结束为待整改，显示驳回节点、意见和整改入口，不提供原节点继续按钮 |
| 重复提交闭环申请 | 返回现有进行中实例，不创建第二个流程 |
| 待办创建或状态更新部分失败 | 整体回滚，项目保持 ACTIVE，不显示“闭环完成” |

“通过”确认区必须显示流程版本、当前节点、CLO-01快照、材料快照及本动作结果。通知失败只在消息状态中提示并保留站内待办，不改变审批结果；只有全部配置节点通过且快照有效时才显示 `NORMAL_CLOSED` 成功页。

### 自定义项与配置缺口

- 一线工程师可在当前任务新增自定义调研项/风险项，并在提交前删除本人新增且未被引用的项。
- 系统预置必填项不显示删除或改选填动作；没有任何适用项时显示“配置缺口”，允许新增自定义项但不伪造系统规则已匹配。
- 新增项 Drawer 必须填写名称、类型、界面格式、必填性、事实说明和来源；任务级自定义项不回写 CUT-07/09/10 全局配置。

### 当前结果选择与人工降级

```text
采集项：CPU使用率
结果历史：
  v1 自动采集失败  COL-1001  10:01  [证据]
  v2 人工录入 35%  附件 E-22  10:08  [当前选择]
业务判定：正常  判定人：张三  规则：ITEM-v7
```

- 同一采集项只能有一个当前选择；切换来源时先显示将关闭的旧选择区间和将启用的新版本。
- 自动采集失败后可按服务端返回的允许操作重试；只有当前采集项已发布版本的 `workMode/allowedOperations` 允许人工降级时，授权工程师才可追加 MANUAL 证据并切换当前选择。`COLLECTION` 类型不默认出现通用人工兜底；原任务、失败原因和回调证据始终保留，不得把原 CollectionTask 改成成功。
- 技术结果可用后仍需由 CUT 按采集项规则完成业务判定；“回调成功”只显示为技术状态。
- 提交后答案与清单锁定；修改关键条件或结果必须创建新P3版本，并在确认前预览对P4/P5的影响。

| 下游状态 | 新P3版本的界面处理 |
|---|---|
| P4草稿或尚未发起P5 | 标记旧P4来源已失效并阻止提交；下游未审批方案按PRD失效，提示基于新P3创建P4新版本 |
| P5审批中 | 显示“审批已暂停”，列出P3新旧版本和失效原因；禁止继续通过，通知责任人创建并重提P4版本 |
| P4已批准 | 不静默改写或覆盖批准版本；若变化影响执行范围，标记当前方案来源失效并要求创建P4新版本、按原等级重走P5；其他变化显示冻结版本差异并以服务端门禁结果为准 |

### P3完成门禁

所有 `required` 适用项必须：

- 已直接填写；
- 或已上传；
- 或采集形成可用结果并完成业务判定；
- 或当前采集项规则明确允许、且已由授权工程师提交可审计的人工降级证据。


### 任务提交

同时校验：

```text
业务对象操作权限
+ 项目数据权限
+ 设备权限
+ 命令模板权限
+ 凭证使用权限（仅凭证模式）
```

提交前在 Drawer 内显示“本次执行授权摘要”：用户、设备、协议、命令模板版本、认证方式和有效期；摘要不展示凭证明文或临时密码。独立中心不得出现任意命令输入框。

| 校验/提交结果 | Drawer 行为 |
|---|---|
| 凭证无权、过期或范围不匹配 | 不下发；字段旁显示不匹配的授权维度，不暴露无权凭证详情 |
| 临时模式必填缺失 | 不下发；保留用户名，密码字段保持仅内存输入且不自动填充 |
| 任务创建成功 | 清空密码输入，返回平台TaskID并打开 DC-04A |
| 外部下发超时 | 显示“受理结果未知”，先按平台TaskID查询，不允许直接重复创建 |
| 子应用不可用 | 保留失败任务和业务上下文，返回原业务页的手工上传/离线降级入口（按来源需求适用） |
| 批量设备部分失败 | 按设备显示独立状态、认证方式和失败原因，不把批次整体显示为成功 |

用户勾选“保存为设备凭证”后，成功结果必须明确区分“已创建凭证”和“已创建采集任务”；新凭证默认仅当前用户可用，不因当前项目成员关系自动扩大授权。

### 补偿与对账操作约束

- “重试”先展示原请求业务键、来源版本、已重试次数和幂等方式；重试产生新技术尝试记录，不覆盖原失败证据。
- 外部结果不确定时主动作是“查询外部结果”，不是“再次发送”。只有确认未受理后才开放受控重试。
- “人工补录/人工对账”必须选择依据类型、上传证据、填写外部单号和责任人；它只能形成待核对事实，不能把财务付款、ERP数量或ITR问题等外部Owner事实直接改为成功。
- 对账差异页并列显示平台值、外部原值、映射版本、差异字段、裁决Owner和处理状态；批量处理前冻结差异清单。
- 普通业务用户从源页面只看到与本人对象相关的降级与恢复状态；完整脱敏请求/响应、补偿和对账操作仅向获权运营人员开放。

# 19. 关键端到端交互线框

## E2E-01 项目创建 → Stage/Task初始化

```text
CRM/ERP输入 或 手动创建
→ PD-11 四维属性
→ PM-03唯一模板匹配/人工选模
→ 生成/携带创建请求 Idempotency-Key
→ 冻结 TemplateVersion + FlowVersion
→ 实例化 Stage / ProjectTask / Milestone / Deliverable / Gate
→ 任一初始化节点失败：显示“项目任务初始化失败/待重试”，不发布完整初始化成功事实
→ 初始化成功：lifecycle_status=ACTIVE / current_stage=S0
→ 主责服务经理或项目经理任一尚未完成指派：assignment_status=UNASSIGNED
→ V1按受控流程依次完成服务经理、项目经理指派
→ 两类主责均完成：assignment_status=ASSIGNED
→ PD-02 Stage→ProjectTask 工作区
```
