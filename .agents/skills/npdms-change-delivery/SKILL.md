# NPDMS变更交付

交付用户指定单元，不把小变更升级为多轮全套治理。权威与边界遵循[AGENTS.md](../../../AGENTS.md)，执行方式以[工程链6.2](../../../docs/engineering/00-engineering-chain.md#62-delivery-unit认领实施与交接)为准；本技能不新增Gate或外部操作授权。

## 定位与收敛

- 从用户指定主线定位Requirement和当前Task；并行Feature/Task按工程链6.2直接读取master已提交的相关活动DU（`git show master:路径`），再定位提供方契约和来源Task。工作树未提交DU及本分支副本不改变认领边界，不因本分支缺少代码判定无人实施。
- 先搜索再读任务相关章节，复用已读且前提未变的事实。局部接口扩展不触发整模块/整阶段复审；对应旧API、实现、运行入口、数据和测试仍须足以判断直接复用、复制增强或不可复用。
- 一次简述交付物、修改边界、Owner/消费者、验证及真实风险。纯治理任务用本次批准和治理文件，不加载无关业务材料。
- 真正影响业务结果的缺口直接问用户并给建议；连续澄清先保留短要点，收敛后一次回写必要正式契约。已解决问题不重复问，不在答案未定时扩写全部分册、计划与投影。

## 实施与按需协作

- 单任务串行局部改动复用当前Task和无冲突工作树，不强制独立计划或DU。复杂任务短计划放在现有Task；不按对话轮次或函数拆计划/DU。
- 同仓库多个Feature/Task同时实施时，即使只有一个操作者、文件不重叠，也先由同一协调者核对业务义务/API的唯一Owner、依赖和边界，并把认领提交到master再开工；一批DU可集中提交。Owner、业务职责、排他边界或交接后的来源位置变化同样先提交再生效。不要求实施分支合并/包含认领提交、激活历史验真或全量DU校验，普通进度不要求逐次提交；已有认领继续保护。
- 消费者只实现自身职责，契约明确时可写调用和测试范围内替身，不补写提供方Service/Mapper/表或生产替代实现。协调记录或提供方进展不可读时只暂停相关部分，不退回旧副本猜测。提供方在契约变更、可用增量、阻塞或Owner交接时告知协调者和直接消费者；接入前重读相关来源，不持续轮询。
- 契约变化先修其权威位置再编码；契约不变不制造规格修订。按已确认范围完成可独立使用的基础闭环，再接动态适配；保留旧功能和不可变历史。
- 先做最小正向实现，再按风险验证并修复本次引入的失败；不因“第一版完成”停止，也不顺手重构无关代码。

## 验证与收口

- 新查询才读[查询规则](../../../docs/coding/database-query-interface.md)，运行才读[开发说明](../../../docs/development.md)。使用指定的测试环境；核对实际连接和数据保护，不另建第二环境或默认测试数据可清理。
- 保留相关权限、状态、幂等/并发、失败回滚、历史保护；UI用真实浏览器，DDL按原迁移义务。既有有效证据不因普通文档/元数据变化重跑，不重复hash核对。
- 默认自审；跨Owner契约变化由相关Owner确认，真实高风险或用户指定范围才安排独立复核，整改只复核新增差异。Skill不自动授权创建审阅任务或使用子代理。
- 已验证的相关代码、依赖、配置、Schema和消费者前提未变时复用证据，不因普通合入重跑全套；不运行与本次风险无关的SDS/DU/时间线审计。
- 依赖所需的独立可用基础增量完成后，按授权先合入master，再由消费者同步并真实联调；不等待提供方整个Feature Done，不把来源未提交代码直接复制成第二套实现。
- 一个可验证增量完成后一次记录真实结果、未执行的适用验证及限制，不为无关项填N/A表；索引/矩阵只在相关来源字段变化时收口生成。提交/合并须获授权，提交前加载git-commit，不自动推送。
- 按[DoD](../../../docs/engineering/00-engineering-chain.md#8-definition-of-done)报告完成层级：查询/接口/单测/DU交付不等于Feature Done。真实缺口只停止依赖部分，不新增批准或重复确认常规下一步。
