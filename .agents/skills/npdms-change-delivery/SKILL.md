# NPDMS变更交付

交付用户指定单元，不把小变更升级为多轮全套治理。权威与边界遵循[AGENTS.md](../../../AGENTS.md)，执行方式以[工程链6.2](../../../docs/engineering/00-engineering-chain.md#62-delivery-unit认领实施与交接)为准；本技能不新增Gate或外部操作授权。

## 定位与收敛

- 从用户指定主线定位Requirement、当前Task和DU；索引仅导航，不从分支名或历史Done推定当前工作。
- 先搜索再读任务相关章节，复用已读且前提未变的事实。局部接口扩展不触发整模块/整阶段复审；对应旧API、实现、运行入口、数据和测试仍须足以判断直接复用、复制增强或不可复用。
- 一次简述交付物、修改边界、Owner/消费者、验证及真实风险。纯治理任务用本次批准和治理文件，不加载无关业务材料。
- 真正影响业务结果的缺口直接问用户并给建议；连续澄清先保留短要点，收敛后一次回写必要正式契约。已解决问题不重复问，不在答案未定时扩写全部分册、计划与投影。

## 认领与实施

- 复用现行Task/计划和有效DU。即将开工的新DU可一次CLAIMED提交master；保持认领已提交、目标分支已包含、写入无冲突，不按对话轮次或函数拆DU。
- 默认复用无并行写入冲突的当前工作树；确需隔离或用户指定时再创建。元数据提交前不运行必然失败的未提交认领校验，实施前及真实边界变化后按工程链检查。
- 契约变化先修其权威位置再编码；契约不变不制造规格修订。按已确认范围完成可独立使用的基础闭环，再接动态适配；保留旧功能和不可变历史。
- 先做最小正向实现，再按风险验证并修复本次引入的失败；不因“第一版完成”停止，也不顺手重构无关代码。

## 验证与收口

- 新查询才读[查询规则](../../../docs/coding/database-query-interface.md)，运行才读[开发说明](../../../docs/development.md)。使用指定的测试环境；核对实际连接和数据保护，不另建第二环境或默认测试数据可清理。
- 保留相关权限、状态、幂等/并发、失败回滚、历史保护；UI用真实浏览器，DDL按原迁移义务。既有有效证据不因普通文档/元数据变化重跑，不重复hash核对。
- 简单变更自审；必要的独立复核覆盖最终相关设计/代码差异，整改后只复核新增差异，不重复审已确认事实，不把每次文字修改变成新审批。
- 一个可验证增量集中提交和交接；当前Task/DU记录一次真实结果、未执行项及限制，索引/矩阵只在来源字段变化时于master收口生成。提交前仍按宿主要求加载git-commit，不自动推送。
- 按[DoD](../../../docs/engineering/00-engineering-chain.md#8-definition-of-done)报告完成层级：查询/接口/单测/DU交付不等于Feature Done。真实缺口只停止依赖部分，不新增批准或重复确认常规下一步。
