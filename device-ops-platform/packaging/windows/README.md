# SDP DAC Windows 客户端

网页采集窗口提供“下载并安装 DAC”或“下载更新 DAC”，保留连接和重新检测，不将探测失败认定为未安装。当前安装包为网页同源的 `/downloads/dac/SDP-DAC-1.1.8-x64.msi`（支持前端 BASE 路径）；网页下载 ZIP 同时附带当前后端地址和网页来源。请完整解压后运行 MSI，核对自动填入的环境地址，再点击一次安装。

部署网页前运行 `scripts/publish-dac-download.ps1 -PackageDirectory <已校验的1.1.8产物目录>`，将安装包发布至前端 public 目录，再执行既有前端构建/部署；Vite 开发服务无需重启。MSI 作为发布载荷忽略，不提交到 Git；正式部署须随前端 dist 一起发布，不能只部署源码链接。

1.1.8 的程序目录为 `C:\Program Files\SDP\DAC`，网页协议启动器为 `SdpDac.exe`，服务包装器及宿主为 `SdpDacService.exe`、`SdpDacHost.exe`。升级识别原 NPDMS 安装并替换程序，沿用原受保护数据目录和稳定服务标识；不搬迁或改写旧环境数据、连接、凭据及安装身份。

1.0.6 使用本机协议2，新增设备优先的保存连接范围：有设备时按设备及当前协议匹配，没有设备时按项目与协议匹配，继续隔离环境、租户和用户。单条连接在重新打开采集窗口后自动选中，多条由用户选择；密码不回显。历史无归属连接保留但不自动关联。须配套更新NPDMS服务端票据接口和网页；旧客户端提示升级，旧服务端没有范围的票据会被拒绝。升级只新增本机V26关联表，不改写旧连接或凭据。

1.0.5 增加只读本机状态页 `http://127.0.0.1:48182/desktop-status`，显示本机服务就绪状态和所配置的服务/网页地址。交互式安装成功后自动等待页面可访问并使用默认浏览器打开；静默安装、取消、失败或卸载不打开浏览器。状态页不提供设备命令入口，原任务票据校验和本机 Host 限制继续生效。

安装包包含 DAC、精简 Java 25 和 WinSW 2.12.0。适用 Windows 10/11 x64，需系统 .NET Framework 4.6.1 或更新版本；终端用户无需另装 Java、Node.js、Python 或数据库。

运行 MSI，核对 SDP 后端 API 地址（HTTP/HTTPS，可带端口）和网页来源。安装完成后 DAC 服务以 LocalService 身份自动启动，只监听回环地址，候选端口为 `8280～8289`。安装及升级均应用本次确认的地址；旧环境数据保留在原目录。开始菜单“DAC 设置”也可修改环境，保存并重启前会确认对正在执行任务的影响。

升级会自动停止并启动本机 DAC 服务，请先结束正在执行的采集。正常升级不需要重启电脑；安装器不会自动重启 Windows。只有 Windows 确实报告文件等待替换时，完成页才提示保存工作后自行重启，无需重复安装。MSI 失败回滚恢复原配置及原先运行的服务。

两项均需填写完整的协议、主机和端口；前后端地址相同时第二项可留空。只有 `IP:端口` 的输入无效。前后端分离时，第一项必须是 API 服务地址，不能用网页端口替代。1.0.1 起会在安装前显示具体配置错误并允许返回修改；静默安装同样在写入文件之前校验。1.0.2 支持当前内网 HTTP 环境，新安装默认预填后端 `http://10.210.0.11:59191`、网页 `http://10.210.0.11:19191`。网页配置的后端地址须与客户端一致；HTTPS 和 localhost 开发地址同样可用。

网页使用 `/api/v1/desktop/status` 检测就绪状态和服务器环境；用户点击“启动 DAC”时打开 `sdp-dac://start/`。浏览器可能要求允许访问本地网络或打开本机应用。探测失败也可能由浏览器权限造成，不能仅据此判断未安装。启动器只允许固定服务启动，不接受命令、服务器地址或秘密参数。

内网 HTTP 网页接入时，安装器为所填网页来源（包含端口）添加 Chrome/Edge 的 `LocalNetworkAccessAllowedForUrls` 授权；安装后刷新网页，策略尚未刷新时重新打开浏览器。只允许该来源，不使用通配符，不关闭浏览器安全校验。客户端记录自己添加的条目，修改环境、首次安装回滚或卸载时仅移除仍属于自己的旧条目，保留组织已有或之后修改的配置；组织的禁止策略仍优先。其他浏览器的内网 HTTP 接入尚未验证。策略说明见 [Edge 本地网络访问授权](https://learn.microsoft.com/en-us/deployedge/microsoft-edge-policies/LocalNetworkAccessAllowedForUrls) 和 [Chrome 本地网络访问说明](https://developer.chrome.com/blog/local-network-access)。HTTPS 服务器使用 Windows 本机根证书信任库，企业证书应按现有组织管理方式受信任。

在 NPDMS 采集窗口选择“本机 DAC”，连接信息和命令由服务器按当前用户权限冻结，密码仅发送到本机。保存连接属于当前 NPDMS 用户并在本机加密；可以在原采集窗口选择。现有 SSH/Telnet 执行引擎、取消和原结果回传继续使用。执行时服务器断网不打断当前命令组；恢复后重发原结果，收到匹配的业务回执后才确认投递。切换环境后原环境结果仍留在其数据目录，切回并联网后继续补传。

新环境初始化使用随包附带的 `device-command-output-1.4.0` 解析包，执行已有验证、发布、工作节点能力检查和激活流程。已有日志类型或激活版本不会被安装初始化覆盖；不修改任何历史解析记录。

NPDMS 服务端需包含本次本机执行/授权/回传接口并按既有迁移入口应用 V511；旧服务端仅安装客户端不能提供这些接口。原“服务器 DAC”路径继续可用。1.1.0 客户端从 `8280～8289` 中选择端口；原 1.0.x 固定端口 48182 的书签不再作为新客户端入口，请使用开始菜单“DAC 本机状态”。独立服务器 DAC 的端口和启动方式不变。

程序位于 Program Files，配置与运行数据位于 `%ProgramData%\NPDMS\DAC`。设备凭据由原 DAC AES-GCM 存储加密，主密钥通过 Windows DPAPI 保护并限制为服务和管理员可读。不同服务器地址使用独立数据目录；更新、卸载不删除数据和主密钥。不得复制单个数据库文件到其他电脑后丢弃对应密钥。

1.0.3 补齐安装期间的 Windows Application 事件源注册，LocalService 运行时无需创建事件源或取得管理员权限；服务启动、停止事件可正常记录。

1.0.4 修复不同 DAC 数据库的本地事件编号相同导致回传冲突的问题：本机回调编号按命名空间、平台任务号和原事件编号稳定隔离；原事件、日志正文及已有服务器回执保持不变。升级后未确认回传的原结果继续补传，不重新执行设备命令。

开发打包先用 `scripts/worktree-build.ps1 -Target dac` 产生冻结清单，再运行 `scripts/package-dac-desktop.ps1 -Manifest <清单绝对路径>`。打包脚本持有同一工作树锁，不安装、不启动服务。WiX/WinSW可通过参数指定固定官方工具副本。安装包尚无组织代码签名时，Windows可能显示发布者确认；是否完成正式安装与业务验收以本次交付记录为准。

## 1.1.0：候选端口、首次配对与两种安装器

- Windows 宿主先持有服务实例文件锁，再尝试上次成功端口，首次优先 8280；仅当 Java 明确以端口绑定冲突码 98 退出时尝试下一端口。其他启动错误原样失败；不停止占用端口的其他进程。全部候选失败写入服务日志，由既有 WinSW 失败策略处理。
- Java 写入无秘密的 `runtime/endpoint.properties`，启动器核对存活进程、产品、公钥、启动实例及 READY 后打开实际状态页。运行记录原子更新；旧记录不代表服务在线。
- 1.1.0～1.1.3首次从开始菜单打开“DAC 本机状态”，将页面上的32位十六进制公钥指纹输入NPDMS采集窗口；此旧流程已由下文1.1.4的点击连接替代。既有浏览器按环境保存的公钥继续有效，不保存设备密码或私钥。
- 最新网页同时探测十个固定候选地址，使用随机挑战验证Ed25519签名、实际端口、运行实例、协议3、精确环境及已保存公钥；首个有效候选立即返回并取消其他探测，不再等待所有端口响应。身份异常或未确认均不能发送业务票据和设备密码，首次仍通过原生启动器确认安装身份。每次业务请求独立复核，原任务查询及语义结果不依赖此前是否打开探测组件。HTTP网页验证使用纯JavaScript密码库，不依赖仅安全上下文可用的`crypto.subtle`。
- 不改变 `environments/<原服务器地址哈希>`、H2 数据库、DPAPI 主密钥、保存连接范围和 Outbox；只在原环境目录新增 AES-GCM 加密的身份文件。升级或卸载不删除这些文件。新建身份失败或已有身份损坏时不自动覆盖。
- MSI 与原生 Inno EXE 共用同一冻结 JAR、精简 Java 25、WinSW 和 251 项载荷。Inno 不内嵌或调用 MSI 安装。1.1.1 支持自动卸载：MSI 升级旧 MSI 沿用 MajorUpgrade；MSI 安装前自动卸载已登记的旧 Inno，Inno 安装前自动卸载已登记的旧 MSI 或 Inno。只处理本产品注册记录及经过校验的卸载入口；卸载失败、需要重启、未知服务归属、多个旧安装器或降级均中止，不继续覆盖。ProgramData 中的配置、凭据、连接、配对身份和任务历史保留。比较包尚未完成实际安装、卸载、升级和故障恢复验收，不作为已验收发布包。
- 两者交互安装成功后打开实际状态页，静默安装不弹浏览器。MSI 静默参数沿用 `/qn /norestart`；Inno 使用 `/VERYSILENT /SUPPRESSMSGBOXES /NORESTART /SERVERURL="<API地址>" /WEBORIGIN="<网页来源>"`，日志可用 `/LOG="<文件>"`。可切换两种安装器，但不要并发运行；由新安装器先完成旧版卸载，再安装新程序。

Inno 打包在 MSI 载荷校验完成后运行：

```powershell
./scripts/package-dac-inno.ps1 -PackageDirectory <MSI产物目录> -Compiler <ISCC.exe绝对路径> -OutputDirectory <全新输出目录>
```

编译器使用 Inno Setup 6.7.3；中文语言文件来自其[官方翻译入口](https://jrsoftware.org/files/istrans/)对应 `Files/Languages/ChineseSimplified.isl`，放入编译器 Languages 目录。打包记录包含编译器与安装脚本 SHA256，既有产物目录禁止覆盖。

Linux 后续可复用 Java 身份加密和签名发现协议；免输码流程还需 Linux 原生协议桥。尚需实现 systemd/用户服务启动编排、候选端口退出码重试、单实例锁、服务账号和文件权限、主密钥保护及相应 JRE；Windows 的 DPAPI、WinSW、浏览器注册表策略和快捷方式不迁移为 Linux 依赖。本轮未提供 Linux 安装包。

### 1.1.1 自动卸载边界

MSI 清理旧 Inno 使用嵌入式延迟、提权 CustomAction，在新包完成校验后、InstallFiles 前执行固定 `/VERYSILENT /SUPPRESSMSGBOXES /NORESTART` 卸载；只读取 HKLM64 的固定本产品注册键，校验版本、标准安装目录及 `uninsNNN.exe`，不执行任意注册表命令行。对跨类型旧 JRE 相同版本文件强制重新复制，避免旧卸载删掉文件后新 MSI 因版本相同而跳过。失败不忽略，旧记录与服务未清除也不继续。修复或卸载现有 MSI 不触发跨安装器清理。

Inno 在 PrepareToInstall 中先校验配置，再重新确认旧版身份及版本；旧 MSI 由系统 msiexec 按本产品 UpgradeCode 枚举出的 ProductCode 卸载，旧 Inno 使用其登记的受限卸载入口。只有退出码0且注册记录、服务均消失后才复制新程序；3010 不自动重启，须重启后重新安装。取消安装前的只读初始化不卸载；执行安装后原服务会中断，不能保证执行中的设备命令不中断。

跨安装器以及 Inno 的旧版卸载与新包安装不是一个事务：旧版已经卸载而新包随后失败时，保留本机数据，但不承诺自动恢复旧程序；应查看日志并重新运行完整的新安装器。MSI 同类型升级继续使用既有事务回滚。此版本只完成代码、测试及构建，不声明真实自动卸载/升级验收通过。

### 1.1.2 安装失败修复

用户实机日志显示1.1.1已卸载旧MSI，但WinSW创建本机宿主进程时被Windows拒绝访问；Inno还在服务初始化前执行了打开浏览器，随后失败仍留下安装登记。1.1.2在程序目录显式为LocalService增加只读/执行权限，保留原ACL和拒绝规则，不给服务修改程序的权限；程序目录权限处理不进入ProgramData，不放宽密钥及历史权限。WinSW工作目录固定为安装目录。

Inno服务初始化移至最后一个程序文件安装完成的AfterInstall回调，在写入注册信息及Run之前完成；只有服务初始化成功才允许打开本机状态页，静默仍不弹浏览器。失败时按原新服务清理路径退出，不将服务失败当成成功安装。原生安装操作错误只向受保护的 `logs/installer-native.log` 记录动作名、异常类型和Win32错误码，不记录URL、命令参数或凭据。

这属于代码与比较包阶段修复：权限处理已在隔离目录验证，未修改当前实际安装目录；实际LocalService启动及安装/升级验收仍需授权。MSI 1603的具体失败动作尚未取得完整日志，只读的卸载预检目前通过，不能据此认定实际卸载已通过。

### 1.1.3 普通用户打开状态页修复

1.1.2在实机已成功注册启动服务，候选端口8280返回READY；普通用户运行启动器仍弹通用错误，原因是Process.HasExited查询LocalService进程句柄被拒绝（Win32 5）。1.1.3去掉这项不必要的跨账户查询，以受保护的运行记录、公钥、实例和随机挑战签名验证实际端点；不要求管理员打开状态页，也不放宽票据或身份校验。

`DesktopStatusLauncherTests.exe <已安装程序目录>`为显式只读回归入口：先复现旧进程查询被拒绝，再调用新验证路径取得状态页地址；不安装、启停服务或打开浏览器。打包参数 `-VerifyRunningDesktopDirectory <目录>`可在已有运行实例的普通用户环境执行此检查；默认打包不依赖已安装服务。本轮在实际1.1.2运行实例验证通过，不据此宣称已经安装1.1.3。

### 1.1.4 首次点击连接，免输码

采集窗口提前准备短时连接链接；首次只需点击“连接本机 DAC”，允许浏览器打开已安装客户端。启动器核验受保护运行记录与签名后，将证明交给其配置的 NPDMS 服务端；原网页核验并仅保存公钥，以后自动检测8280～8289。无需默认浏览器与业务浏览器相同。旧已确认公钥继续生效，连接、密码密文、任务历史、Outbox和身份密钥的存储位置不变。

必须配套本轮服务端 connections API 和网页；仅安装新包而后端未更新，无法完成首次连接。旧客户端不支持免输码时提示更新。取消、过期、用户/租户不符、环境不符、错误签名或安装身份变化均不能建立新信任；不通过关闭校验实现免输码。仅用户点击才能唤起客户端，后台轮询不唤起程序；静默安装仍不弹浏览器。

完整免输码验收需部署后端/网页并升级客户端，当前构建阶段不代表已经部署或验收。Windows 系统协议注册是原生启动器的信任入口；不假设可以抵御拥有同一用户执行权限并能改写浏览器或协议处理器的恶意软件。Linux 安装器与原生协议桥尚未实现。
