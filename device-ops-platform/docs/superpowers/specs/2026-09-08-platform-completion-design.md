# Device Ops 平台管理闭环设计

日期：2026-09-08

状态：本会话已批准实施；不授权自动提交、推送或生产操作。

## 目标与架构

在独立 Device Ops 平台内完善现有能力的使用闭环。保留 Java core/port、JDBC、Spring Web 分层，以及 Vue 3 / Element Plus 工作台。复用已有采集、输出、保存连接、解析发布、任务及结果能力，不重建执行器或版本系统。

## 统一界面设计约束

用户补充要求：界面使用统一设计语言，复用 Element Plus。管理页沿用现有 AppShell、平台颜色与间距 token；表单、表格、筛选、分页、确认弹窗、状态标签及加载/空/失败反馈优先使用 Element Plus 和共享组件。重复的管理布局与查询样式集中复用，不为每页增加独立主题或无必要的自绘控件。该约束不扩大为全仓视觉重构。

## 阶段一：工作台与授权

项目 SSH 采集保留 EXEC/SHELL 选择；采集完成但解析进行时可恢复查看；停止查看不取消执行。历史恢复不伪造提交时间或缺失的脚本证据。主数据请求防止旧响应覆盖新项目。解析版本选项失败可重试，空版本与失败分开呈现。

管理授权统一 scope、namespace、project 和保存连接/凭据 subject 限制。针对疑似不一致先验证，再补充回归和实现；列表、统计和详情在数据库查询前确定同一可见范围。

## 阶段二：任务、记录、总览

增加采集摘要分页与 namespace、project、device、status、from/to 筛选，createdAt/id 稳定倒序，页大小有上限。摘要不载入 stdout、脚本或凭据。历史缺失字段显示未知，不伪造回填。必要新迁移同时支持 H2/MySQL，不修改 V17/V18。

任务中心区分采集、解析和到期通知调度；记录中心支持历史检索、详情、关联语义结果和安全导出；总览仅显示服务端授权范围统计。复用现有结果组件。解析取消/终止复用既有 API 并确认，不新增采集硬取消/自动重试。

## 阶段三：管理控制面

解析控制台提供日志类型和 release 列表、草稿、验证、发布、激活/撤销、节点运行状态和离线输入解析。草稿以已有 JSON 契约为准；激活保留 expectedCurrentReleaseId，重要操作确认；不自动激活在线版本。

脚本库展示有授权采集归属的不可变版本元数据。仅可证明授权且受支持的安全存储版本允许读取并显式载入工作台；不在普通历史详情开放脚本，不公开无归属全局制品，不删除历史版本。

调度管理明确 SCHEDULE_DUE 是到期通知而非无人值守 SSH；保留首次停用约束。设置只展示白名单身份/范围/能力及有权限的运行信息，不返回 token、秘密或完整配置，不提供危险配置写入口。

## 边界

不扩展 NPDP、本地 CMDB、主档写入、交互终端、无人值守巡检、文件传输、新协议、采集硬取消、自动重执行、密钥轮换、清理运行数据或新解析 DSL。生产 IdP、设备、回调和数据库不可作为自动验收目标。data/ 与工作区外脑暴文件不触碰。

## 测试与交付

各子系统独立实施计划，行为修改先运行失败测试再实现。定向测试后运行 Vue 单测、类型检查、lint、build 和 Maven clean verify。浏览器以受控输入验证新增管理旅程；区分模拟 API 与真实测试后端证据。先构建新前端再打包 JAR，验证 static/index.html。报告 Docker 测试执行/跳过、生产环境未验收项。交付代码、迁移、API 与验收记录，不自动 Git 提交。
