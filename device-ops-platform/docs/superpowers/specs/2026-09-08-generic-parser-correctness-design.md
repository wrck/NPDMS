# 通用日志解析正确性优化设计

依据：`docs/reviews/2026-09-08-generic-log-parsing-review.md`。用户已授权按审查报告优化。

## 目标与范围

修复真实三日志中会话统计误空、接口记录空壳、温度表错列、混合结构丢失，并修复审查确认的脱敏、配置、事实遍历和预算问题。保持七类结构契约，不引入不具备验收样本的 CSV/JSONL/XML 等新格式，不改变采集协议、数据库或前端布局。

## 兼容决策

新增引擎及发布 `1.4.0`，仍输出 schema `1.1.0`。现有 `1.3.0` 和更早发布制品不改写，既有历史结果不重算。改变可观察输出的算法使用明确的 enhanced 构造参数，默认构造保持旧行为；SemanticEngine 根据冻结引擎坐标选择路径。在线工作节点注册新能力，但不擅自修改已经活动的数据库发布。

考虑过原地修复及复制整套解析器：前者破坏固定版本重放，后者制造长期重复实现。因此采用按组件构造参数隔离受影响算法，保持主调用链共享。

## 组件和数据流

1. 安全证据：增强脱敏器按敏感字段和跨行 PEM 块处理，原文行数不变，保留缩进；只用合成秘密验证。纯装饰标题在形成内嵌边界前过滤。
2. 结构解析：所有模式循环消费输入；未匹配剩余区间回退 text。记录正文由同一混合分段器解析，限制嵌套深度，身份和字段保持原行号。
3. KV：紧凑冒号、单行多 KV、缩进父子值、续行；拒绝时间/MAC/IPv6/URL/事件前缀造成的假键。
4. 表格：验证多行列边界，区分装饰线与列分隔线，支持单数据行、Tab、缩进、管道外框；遇结构变化停止，保留不确定行。列 ID 继续稳定，重复标签不覆盖。
5. 质量与预算：递归检查 text/unparsed/空壳记录；各预算独立，记录字段参与节点预算，深度限制在递归前检查，遗漏按源行集合去重。
6. 事实复用：增强路径递归遍历记录内结构，消歧最终列名；候选数量在构造阶段受限，不能先创建无界对象列表。
7. 版本交付：新发布复制脱敏输入但不复制错误预期；先添加语义正确性断言，再生成新 golden。旧 golden 必须逐字节通过。

## 验收

- 125 项既有 core/semantic 测试继续通过；旧引擎所有黄金结果不变。
- 新版真实三日志有 50 内嵌命令、12 EMPTY；session statistic 不空且包含父子统计。
- 23 接口记录均保留正文区间，含 KV 的记录有可访问字段，不再全为空壳；文本残余报告 PARTIAL。
- environment 温度表恰为 5 列且温度数值不碎裂；route summary 三个紧凑 KV 与真正表格分离；CPU/ARP/MAC 短表可辨识。
- TEXT/FORCE、配置前导、记录正文的内容保留守恒；错误提示不丢尾。
- 合成多词秘密、PEM 正文不会出现在新结构、投影、错误或原文副本。
- 独立预算、记录内部节点、列名冲突、空列表项、重复键、负例均有失败后修复的回归测试。
- 运行相关模块测试、完整后端 package、前端现有类型检查与构建。接口记录展示补充现有子sections递归渲染，保持旧entries兼容；以组件测试和合成数据浏览器点击验证，不进行整体视觉重设计。

## 实施核对

所有范围内修复已完成并交付新1.4目录；详细验收见 `docs/reviews/2026-09-08-generic-log-parsing-delivery.md`。结构预算仍在section构造后裁剪，候选流式限制仅保证FactExtractor自身对象分配，未把DelimitedSectionParser改为流式。记录容器和KV构造前有深度保护；不宣称任意大小输入的流式处理。此边界已明确记录，不隐藏为完整流式支持。

## 交付边界

不提交/推送 Git；不连接真实设备，不修改运行中数据库，不上传日志到外部服务。只在被忽略 target 内保存验证产物；文档不得包含真实秘密或客户标识。
