# CRT 风格设备连接工作台设计

## 1. 目标

在独立 Device Ops Platform 中提供接近 SecureCRT 常用连接方式的轻量设备连接工作台，用于：

- 通过项目设备、快速连接或最近连接进入设备连接流程；
- 使用 SSH2 或 Telnet 测试设备连通性；
- 连接后直接下发命令或外部脚本并采集输出；
- 查看并下载输入记录或完整执行记录；
- 为后续交互式终端保留稳定入口与扩展契约。

设备连接不依赖项目或设备主档。项目、设备及回调信息仅在集成方明确下发、需要建立业务指向或需要回传结果时使用。

## 2. 边界

### 2.1 本期范围

- 三种连接入口：项目设备、快速连接、最近连接。
- 两种连接协议：SSH2、Telnet。
- 连接测试和脚本采集。
- 项目、设备和回调上下文可选。
- 当前页面内凭据复用。
- 输入记录和完整记录下载。
- 交互式终端入口占位及扩展契约。

### 2.2 非目标

- 不建设项目、设备或凭据主档。
- 不保存密码、私钥或私钥口令。
- 不实现 SSH1、RLogin、串口或客户端 COM 口代理。
- 本期不实现 WebSocket 交互式终端。
- 不建设完整的 SecureCRT 会话目录、宏、端口转发或文件传输功能。

## 3. 用户界面

工作台保留一个“连接设备”区域，按照“连接来源 → 协议与端点 → 凭据 → 操作”的顺序组织。

### 3.1 连接入口

| 入口 | 行为 |
|---|---|
| 项目设备 | 通过只读主档代理选择项目和设备，并将返回信息冻结为本次请求快照 |
| 快速连接 | 直接填写协议、IP、端口、用户名及本次凭据，不要求项目或设备存在 |
| 最近连接 | 从当前浏览器恢复脱敏连接参数，凭据仍由用户重新输入 |

最近连接最多保留 20 条，记录协议、IP、端口、用户名、主机指纹和可选设备提示，不记录凭据。用户可以单条删除或全部清空。

### 3.2 协议字段

SSH2 显示：

- IP 或主机名；
- 端口，默认 22；
- 用户名；
- 密码或私钥认证；
- 可选私钥口令；
- 主机密钥指纹。

Telnet 显示：

- IP 或主机名；
- 端口，默认 23；
- 用户名；
- 密码；
- 可选登录名提示符、密码提示符和命令提示符规则。

Telnet 明文传输风险必须在选择协议时明确展示。Telnet 由部署配置显式启用，默认关闭。

### 3.3 操作

- `测试连接`：只验证 DNS/TCP、协议握手、认证和登录提示符，不创建采集任务。
- `连接并执行采集`：使用当前连接信息和脚本创建采集任务。
- `清除凭据`：立即清除当前页面内的密码、私钥和私钥口令。
- `交互式终端`：本期显示为预留入口并说明尚未启用，不创建终端会话。

## 4. 凭据生命周期

密码、私钥和私钥口令只保存在当前工作台页面的内存状态中：

- 允许连续执行连接测试和多次采集，无需每次重新输入；
- 不进入数据库、浏览器持久化存储、URL、任务快照、日志、错误响应或回调；
- 用户点击“清除凭据”时清零；
- 页面刷新、关闭、路由离开或工作台组件卸载时清零；
- 最近连接恢复时不恢复凭据。

后端在请求完成或连接上下文释放时主动清除可变凭据缓冲区，并继续使用现有请求日志清理与输出脱敏机制。

## 5. 接口设计

### 5.1 连接测试

`POST /api/v1/connections/test`

请求由以下部分组成：

- `protocol`：`SSH2` 或 `TELNET`；
- `endpoint`：主机、端口、用户名、主机指纹及协议提示符选项；
- `credential`：一次性密码或私钥；
- `context`：可选项目和设备快照。

响应包含：

- `reachable`；
- `stage`；
- `durationMillis`；
- `errorCode`；
- `safeMessage`。

连接测试不返回底层异常、认证报文或凭据片段。

### 5.2 通用采集

`POST /api/v1/collections`

该接口接受可选项目/设备上下文，供快速连接和最近连接使用。认证只校验采集执行 scope；当请求携带项目上下文时，再校验项目 claim。

`GET /api/v1/collections/{collectionId}?namespace={namespace}`

该接口按任务自身标识查询通用采集证据，不要求调用方提供虚构的项目键。

现有 `POST /api/v1/projects/{projectKey}/collections` 继续保留，供集成方按明确项目上下文下发。路径项目键、请求项目快照和令牌项目 claim 必须一致。

### 5.3 兼容性

现有项目级查询、回调和任务证据结构保持兼容。通用任务没有项目上下文时使用任务自身的不可变 `collectionId` 查询，不伪造项目或设备数据。

## 6. 协议适配器

核心层定义统一的连接能力：

- `testConnection`；
- `execute`；
- 统一连接阶段和错误结果。

### 6.1 SSH2

复用现有 Apache MINA SSHD 适配器：

- 支持密码和私钥认证；
- 强制校验主机密钥指纹；
- 使用 EXEC 通道执行完整脚本；
- 保留现有连接、命令、解析和租约超时。

### 6.2 Telnet

新增独立 Telnet 适配器：

- 建立 TCP/Telnet 会话；
- 识别登录名和密码提示符；
- 登录后识别命令提示符；
- 按行发送命令并使用 `CRLF`；
- 每条命令读取到命令提示符或超时；
- 合并为统一 stdout，协议或提示符错误进入 stderr 和安全错误码。

默认规则兼容常见网络设备，用户可在高级选项中覆盖：

- 登录名提示符：`(?i)(login|username)\s*:\s*$`
- 密码提示符：`(?i)password\s*:\s*$`
- 命令提示符：`[>#\$]\s*$`

### 6.3 运行时关闭

采集 dispatcher 按 Oracle JDK 25 `ExecutorService` 的两阶段模型关闭，并由一个单调时钟绝对 deadline 约束全部阶段：

1. orderly 阶段停止 intake 和新的 maintenance 调度，允许已接纳任务在 `shutdown-graceful-period` 内排空；
2. claim 在取得数据库连接后即为 target 与 attempt 建立相同的 `shutdown-recovery-lease` 短恢复基线；dispatcher-owned 批量 heartbeat 同时覆盖 WAITING、DISPATCHED 和 RUNNING，且只延长、不缩短租约。每批在取得连接并完成 owner 检查后才计算完整的新租约窗口；`shutdown-recovery-lease` 至少为 heartbeat interval 的三倍，并覆盖总 shutdown deadline 加两个 heartbeat interval，避免批处理延迟或 graceful drain 让 live work 过早被恢复；
3. graceful slice 到期后，worker 与 maintenance 都进入 `shutdownNow()` forced 阶段，未启动任务由返回队列精确识别。forced 路径不再新取 JDBC 连接或提交事务，而是停止 owned heartbeat，依赖已经持久化的短基线完成有界 recovery handoff，并同步关闭瞬态上下文；
4. `CollectionRuntimeLifecycle` 在 forced 阶段调用 SSH `forceClose()` 帮助活动 I/O 响应中断，然后用总 deadline 的剩余时间再次等待 worker 和 maintenance 终止；
5. 活动任务的持久化取消、输出收口和凭据清理只在原任务 wrapper 的 `finally` 中同步执行；executor 已终止即表示这些 finalizer 已完成；
6. `shutdownNow()` 只有 best-effort 语义。若任务或 maintenance 忽略中断，关闭按时返回但明确报告 `terminated=false`；若 shutdown 撞上尚未完成 claim、短基线尚未持久化，则报告 `failedHandoffs`/`unfinishedWork`。不得把 Future 已取消、虚拟线程不阻止 JVM 退出、SSH 已 force-close 或仅完成内存态移除误报为完整终止。

因此这里没有“SSH 一定在所有 JDBC/任务之后停止”的广义 stop-last 保证。orderly 关闭使用正常 SSH close；forced close 是主动取消手段。`ShutdownResult` 区分 orderly、forced、worker/maintenance termination、恢复 handoff、未完成任务和 shutdown 调用线程中断，供生命周期日志与恢复流程判断。

## 7. 数据流

1. 用户选择连接入口。
2. 页面构建协议、端点和可选上下文。
3. 用户输入凭据；凭据只保留在组件内存。
4. 可选执行连接测试。
5. 用户选择或粘贴本地/外部脚本。
6. 页面提交通用或项目级采集请求。
7. 核心服务冻结脱敏连接、项目、设备和脚本身份快照。
8. 协议适配器执行命令并返回输出。
9. 输出经过限长、脱敏和解析后持久化。
10. 页面轮询任务结果，可选向集成方回传。

## 8. 错误模型

对外统一使用以下错误码：

| 错误码 | 含义 |
|---|---|
| `UNREACHABLE` | 地址无法解析或网络不可达 |
| `CONNECT_TIMEOUT` | TCP 或协议连接超时 |
| `AUTH_FAILED` | 用户名、密码或私钥认证失败 |
| `HOST_KEY_MISMATCH` | SSH2 主机密钥指纹不匹配 |
| `PROMPT_NOT_FOUND` | Telnet 未识别登录或命令提示符 |
| `PROTOCOL_DISABLED` | 部署未启用所选协议 |
| `EXECUTION_TIMEOUT` | 命令执行超过限制 |
| `CONNECTION_CLOSED` | 设备提前断开连接 |

响应和日志只包含安全信息，不回显设备原始认证提示、凭据或底层堆栈。

## 9. 文件下载

### 9.1 保存输入记录

生成 UTF-8 文本文件：

`{设备标识}_{yyyyMMdd-HHmmss}_input.txt`

内容仅包含本次输入的命令或脚本正文。

### 9.2 保存完整记录

生成 UTF-8 日志文件：

`{设备标识}_{yyyyMMdd-HHmmss}_session.log`

内容包含：

- 开始和结束时间；
- 协议及脱敏端点；
- 可选项目和设备提示；
- 命令输入；
- stdout；
- stderr；
- 执行状态和安全错误码。

文件由浏览器根据已获得的任务证据直接生成并下载，平台不创建额外文件存储。密码、私钥、口令和认证报文不得进入文件。未来交互式终端复用相同的会话记录格式。

## 10. 安全与授权

- OAuth2 仍是生产默认模式。
- 通用连接和采集需要对应 scope。
- 只有携带项目上下文时才执行项目 claim 校验。
- Telnet 默认关闭，并通过配置和界面双重提示风险。
- 主机、端口、提示符规则和导出文件名均需要严格校验。
- 最近连接不得包含凭据或脚本内容。
- 输出继续执行脱敏、限长和安全日志策略。

## 11. 必要验证

本期不采用测试驱动扩展实施时间，只进行与风险相称的验证：

- 前后端构建检查；
- SSH2 和 Telnet 模拟服务的连接成功、认证失败、提示符缺失和超时断言；
- 通用采集不要求项目、项目级采集继续校验项目 claim；
- 页面完成快速连接、最近连接、协议切换、连接测试和文件下载冒烟；
- 验证页面关闭或离开后凭据不再存在；
- 验证下载文件及任务证据均不包含凭据。

## 12. 验收标准

1. 用户不选择项目或设备也能测试 SSH2/Telnet 连接并提交采集。
2. 用户可通过主档代理选择项目设备，任务证据和回调包含明确快照。
3. 最近连接可恢复脱敏参数，但不会恢复凭据。
4. 同一页面内凭据可以复用，页面关闭、刷新或离开后被清除。
5. SSH2 和 Telnet 输出进入统一任务证据和解析流程。
6. Telnet 未启用时返回明确的 `PROTOCOL_DISABLED`。
7. 用户可以下载输入文本和完整会话日志，文件不包含凭据。
8. 交互式终端入口可见但明确标识为未启用。
9. 原有项目级集成接口保持兼容。
